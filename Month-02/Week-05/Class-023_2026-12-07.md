# ক্লাস ২৩: ALTER TABLE, DROP, TRUNCATE ও RENAME

**তারিখ:** ৭ ডিসেম্বর ২০২৬, সোমবার
**সময়:** সন্ধ্যা ৭:০০ থেকে রাত ১০:০০
**সপ্তাহ:** ৫ | **ধাপ:** ২ (Oracle SQL)

---

## আজকে কী শিখব

- `ALTER TABLE` দিয়ে কলাম যোগ, বদল, নাম পরিবর্তন, বাদ
- Constraint যোগ, বাদ, বন্ধ, চালু
- `RENAME` দিয়ে টেবিলের নাম বদলানো
- `DROP`, Recycle Bin আর `FLASHBACK`
- `TRUNCATE`
- `DELETE`, `TRUNCATE`, `DROP`-এর পার্থক্য

> **সাবধান:** আজকের কমান্ডগুলো DDL। `ROLLBACK` দিয়ে এগুলো ফেরানো যায় না। বাস্তবে এগুলো চালানোর আগে দুইবার ভাবো, আর আগে ব্যাকআপ নাও।

## ১. কলাম বদলানো (৫০ মিনিট)

গতকালের `w5_buyer` টেবিল ব্যবহার করব।

### কলাম যোগ: ADD

```sql
ALTER TABLE w5_buyer ADD (contact_email VARCHAR2(100));

-- একসাথে কয়েকটা
ALTER TABLE w5_buyer ADD (
    contact_mobile  VARCHAR2(20),
    credit_days     NUMBER(3) DEFAULT 30
);

DESC w5_buyer
SELECT * FROM w5_buyer;
```

পুরনো রো-তে `contact_email` খালি, কিন্তু `credit_days`-এ `30` বসেছে। DEFAULT দিয়ে কলাম যোগ করলে পুরনো রো-তেও সেই মান আসে।

### ডাটা আছে এমন টেবিলে আবশ্যক কলাম

```sql
ALTER TABLE w5_buyer ADD (buyer_code VARCHAR2(10) NOT NULL);
```

```
ORA-01758: table must be empty to add mandatory (NOT NULL) column
```

পুরনো রো-তে কী বসবে, Oracle জানে না। সমাধান: `DEFAULT` দাও, অথবা আগে NULL চলে এমন কলাম বানিয়ে ডাটা ভরে তারপর `NOT NULL` করো।

```sql
ALTER TABLE w5_buyer ADD (buyer_code VARCHAR2(10) DEFAULT 'NA' NOT NULL);
```

### কলাম বদল: MODIFY

```sql
-- সাইজ বাড়ানো
ALTER TABLE w5_buyer MODIFY (contact_email VARCHAR2(150));

-- DEFAULT বদলানো
ALTER TABLE w5_buyer MODIFY (credit_days DEFAULT 45);

-- Not Null করা
ALTER TABLE w5_buyer MODIFY (country_name NOT NULL);

-- আবার NULL চলবে এমন করা
ALTER TABLE w5_buyer MODIFY (country_name NULL);
```

`DEFAULT` বদলালে পুরনো ডাটা বদলায় না, শুধু নতুন `INSERT`-এ নতুন মান বসে।

### যা সহজে বদলানো যায় না

`Ctrl + Enter` দিয়ে একটা একটা করে চালাও:

```sql
-- ডাটার চেয়ে ছোট সাইজ
ALTER TABLE w5_buyer MODIFY (buyer_name VARCHAR2(2));

-- ডাটা আছে এমন কলামের ধরন বদল
ALTER TABLE w5_buyer MODIFY (country_name NUMBER);

-- ডাটা আছে এমন NUMBER কলামের সাইজ কমানো
ALTER TABLE w5_style MODIFY (fob_price NUMBER(6,2));
```

| কাজ | ফলাফল |
|---|---|
| `VARCHAR2` বড় করা | সবসময় চলে |
| `VARCHAR2` ছোট করা | চলে, যদি সবচেয়ে বড় মানটা আঁটে। না হলে `ORA-01441` |
| ডাটাসহ Data Type বদল | `ORA-01439`, কলাম খালি থাকতে হয় |
| ডাটাসহ `NUMBER` ছোট করা | `ORA-01440`, কলাম খালি থাকতে হয় |

ডিজাইনের সময় একটু বড় সাইজ দিলে পরে এই ঝামেলা হয় না।

### কলামের নাম বদল

```sql
ALTER TABLE w5_buyer RENAME COLUMN contact_mobile TO mobile_no;
```

> APEX পেজ, View, Package কলামের নামের উপর নির্ভর করে। নাম বদলালে সেগুলোও ঠিক করতে হয়।

### কলাম বাদ: DROP COLUMN

```sql
ALTER TABLE w5_buyer DROP COLUMN buyer_code;

-- একসাথে কয়েকটা
ALTER TABLE w5_buyer DROP (mobile_no, credit_days);

DESC w5_buyer
```

কলামের ডাটাও মুছে যায়, ফেরানো যায় না। এখন `w5_buyer`-এ `contact_email` রয়ে গেছে, ক্লাস ২৪-এ লাগবে।

বড় টেবিলে `DROP COLUMN` অনেক সময় নেয়। তখন `SET UNUSED` দিয়ে কলামটা সাথে সাথে অদৃশ্য করে, রাতে মোছা হয়। এটা নাম জেনে রাখো।

## ২. Constraint বদলানো (২০ মিনিট)

```sql
-- যোগ
ALTER TABLE w5_buyer ADD CONSTRAINT w5_buyer_email_uk UNIQUE (contact_email);

-- নাম বদল
ALTER TABLE w5_buyer RENAME CONSTRAINT w5_buyer_email_uk TO w5_buyer_contact_email_uk;

-- বাদ
ALTER TABLE w5_buyer DROP CONSTRAINT w5_buyer_contact_email_uk;
```

### বন্ধ আর চালু

পুরনো সিস্টেম থেকে অনেক ডাটা আনার সময় Constraint সাময়িক বন্ধ করা হয়। কিন্তু **চালু করার সময় পুরনো ডাটা ঠিক না থাকলে Oracle মানে না।**

একটা একটা করে চালাও:

```sql
-- FK বন্ধ
ALTER TABLE w5_style DISABLE CONSTRAINT w5_style_buyer_fk;

-- এখন Buyer 99 না থাকলেও ঢুকে যাবে
INSERT INTO w5_style VALUES (99, 'XX-TS-999', 'Orphan Style', 99, 1);
COMMIT;

-- চালু করতে গেলে এরর ORA-02298, Orphan আছে
ALTER TABLE w5_style ENABLE CONSTRAINT w5_style_buyer_fk;

-- ভুল ডাটা মুছে আবার চালু
DELETE FROM w5_style WHERE style_id = 99;
COMMIT;

ALTER TABLE w5_style ENABLE CONSTRAINT w5_style_buyer_fk;

-- অবস্থা দেখো
SELECT constraint_name, status
FROM   user_constraints
WHERE  table_name = 'W5_STYLE';
```

## ৩. RENAME (১০ মিনিট)

```sql
RENAME w5_buyer_copy TO w5_buyer_old;

SELECT * FROM w5_buyer_old;
```

`ALTER TABLE w5_buyer_old RENAME TO w5_buyer_bak;` একই কাজ করে।

টেবিলের নাম বদলালে Oracle FK ঠিক রাখে। তবে যে View, Procedure বা APEX পেজ পুরনো নাম ব্যবহার করে, সেগুলো কাজ করা বন্ধ করে দেয়।

## ৪. DROP ও Recycle Bin (২৫ মিনিট)

`DROP TABLE` টেবিল, ডাটা, Index, Constraint সব মুছে দেয়। তবে সাধারণত Oracle সাথে সাথে পুরোটা মোছে না, **Recycle Bin**-এ রাখে।

একটা একটা করে চালাও:

```sql
DROP TABLE w5_buyer_old;

-- মুছে গেছে
SELECT * FROM w5_buyer_old;

-- Recycle Bin-এ দেখো
SELECT object_name, original_name, droptime FROM user_recyclebin;

-- ফিরিয়ে আনো
FLASHBACK TABLE w5_buyer_old TO BEFORE DROP;

-- ফিরে এসেছে, ডাটাসহ
SELECT * FROM w5_buyer_old;
```

> **এর উপর ভরসা করবে না।** জায়গা লাগলে Oracle Recycle Bin খালি করে দেয়। ডাটাবেসের সেটিংয়ে এটা বন্ধও থাকতে পারে। আর `SYSTEM` Tablespace-এর টেবিলের জন্য এটা কাজ করে না।

### PURGE: পুরোপুরি মোছা

```sql
DROP TABLE w5_test PURGE;     -- Recycle Bin-এ যায় না, ফেরানো যায় না

PURGE RECYCLEBIN;             -- আমার পুরো Recycle Bin খালি
```

### Parent টেবিল DROP

```sql
DROP TABLE w5_buyer;
```

```
ORA-02449: unique/primary keys in table referenced by foreign keys
```

`DROP TABLE w5_buyer CASCADE CONSTRAINTS;` দিলে টেবিল মুছে যায়, আর Child-এর FK বাদ যায়। Child-এর ডাটা থাকে, কিন্তু সম্পর্ক আর থাকে না। **এখন চালাবে না।**

## ৫. TRUNCATE (২৫ মিনিট)

**TRUNCATE** টেবিলের **সব রো** মুছে দেয়, কিন্তু টেবিল রাখে।

```sql
SELECT * FROM w5_buyer_old;

TRUNCATE TABLE w5_buyer_old;

SELECT * FROM w5_buyer_old;     -- কোনো রো নেই

ROLLBACK;

SELECT * FROM w5_buyer_old;     -- এখনো নেই। ফেরানো যায়নি
```

Parent টেবিলে Child-এর FK থাকলে `TRUNCATE` চলে না, Child খালি থাকলেও:

```sql
TRUNCATE TABLE w5_buyer;
```

```
ORA-02266: unique/primary keys in table referenced by enabled foreign keys
```

### তিনটার তুলনা

| | `DELETE` | `TRUNCATE` | `DROP` |
|---|---|---|---|
| ভাগ | DML | DDL | DDL |
| কী মোছে | বাছাই করা বা সব রো | সব রো | টেবিল আর সব ডাটা |
| টেবিল থাকে? | হ্যাঁ | হ্যাঁ | না |
| `WHERE` | হ্যাঁ | না | না |
| `ROLLBACK` | **হ্যাঁ** | **না** | **না** (Recycle Bin থাকলে `FLASHBACK`) |
| গতি | ধীর, প্রতিটা রো ধরে | খুব দ্রুত | খুব দ্রুত |
| Trigger চলে? | হ্যাঁ | না | না |
| জায়গা খালি হয়? | সাধারণত না | হ্যাঁ | হ্যাঁ |

**কখন কোনটা:**
- কিছু রো মুছতে, বা ফেরানোর সুযোগ রাখতে: `DELETE`
- অস্থায়ী বা পরীক্ষার টেবিল পুরো খালি করতে: `TRUNCATE`
- টেবিলটাই আর না লাগলে: `DROP`

> ইন্টারভিউতে **"DELETE, TRUNCATE আর DROP-এর পার্থক্য কী?"** খুব সাধারণ প্রশ্ন।

### এই ক্লাসের এরর

| এরর | কারণ |
|---|---|
| `ORA-01758` | ডাটা আছে এমন টেবিলে DEFAULT ছাড়া আবশ্যক কলাম |
| `ORA-01441` | `VARCHAR2`-এর সাইজ ডাটার চেয়ে ছোট |
| `ORA-01439` | ডাটাসহ কলামের Data Type বদল |
| `ORA-01440` | ডাটাসহ `NUMBER` ছোট করা |
| `ORA-01430` | এই নামে কলাম আগেই আছে |
| `ORA-02298` | Orphan ডাটা, তাই FK চালু হচ্ছে না |
| `ORA-02449` | Child আছে, Parent টেবিল DROP হচ্ছে না |
| `ORA-02266` | Child-এর FK আছে, Parent টেবিল TRUNCATE হচ্ছে না |

## ৬. হাতে-কলমে প্র্যাকটিস (৫০ মিনিট)

গতকালের `w5_supplier` আর `w5_po` ব্যবহার করো। না থাকলে ক্লাস ২২-এর কাজ ২ আগে চালাও।

**কাজ ১:** `w5_supplier`-এ এই বদলগুলো করো:
1. `email` কলাম যোগ (১০০ অক্ষর)
2. `payment_days` কলাম যোগ, DEFAULT ৩০
3. `address`-এর সাইজ ৫০০ করো
4. `mobile_no`-র নাম `contact_mobile` করো
5. `email`-এ Unique Constraint দাও
6. `payment_days`-এর DEFAULT ৪৫ করো
7. `payment_days` কলাম বাদ দাও

প্রতিটার পরে `DESC` দেখো।

**কাজ ২:** `w5_po`-এর `w5_po_amount_ck` Constraint বন্ধ করো। `total_amount = -100` দিয়ে একটা রো ঢুকিয়ে `COMMIT` দাও। আবার চালু করার চেষ্টা করো। এরর দেখো, ডাটা ঠিক করো, আবার চালু করো।

**কাজ ৩:** `w5_style`-এর কপি বানাও `w5_style_tmp` নামে। তারপর পর্যায়ক্রমে করো, আর প্রতিটার পরে রো-র সংখ্যা দেখো:
1. একটা রো `DELETE` করো, তারপর `ROLLBACK`
2. `TRUNCATE` করো, তারপর `ROLLBACK`
3. `DROP` করো, তারপর `FLASHBACK`
4. শেষে `DROP ... PURGE`

**কাজ ৪:** নিচের প্রতিটায় `DELETE`, `TRUNCATE`, `DROP` বা `ALTER`-এর মধ্যে কোনটা ব্যবহার করবে?
1. পুরনো ডেমো টেবিলটা আর লাগবে না
2. বাতিল হওয়া একটা অর্ডার মুছতে হবে
3. প্রতি রাতে রিপোর্টের অস্থায়ী টেবিলের ১০ লাখ রো খালি করে আবার ভরা হয়
4. `item` টেবিলে `hs_code` কলাম লাগবে

## ৮. কুইজ

1. কলাম যোগ করার কমান্ড কী?
2. ডাটা আছে এমন টেবিলে `NOT NULL` কলাম যোগ করতে কী লাগে?
3. `TRUNCATE` কি `ROLLBACK` করা যায়? কেন?
4. `DROP` করা টেবিল কীভাবে ফেরানো যায়?
5. `DROP TABLE t PURGE` কী করে?

<details>
<summary>উত্তর দেখো</summary>

1. `ALTER TABLE t ADD (কলাম DataType);`
2. `DEFAULT` মান
3. না, কারণ এটা DDL, নিজে থেকে `COMMIT` হয়
4. `FLASHBACK TABLE t TO BEFORE DROP;`, যদি Recycle Bin-এ থাকে
5. টেবিল পুরোপুরি মুছে দেয়, Recycle Bin-এ রাখে না

</details>

## সারাংশ

- `ALTER TABLE`: `ADD`, `MODIFY`, `RENAME COLUMN`, `DROP COLUMN`, আর Constraint-এর `ADD`, `DROP`, `DISABLE`, `ENABLE`
- `RENAME`: টেবিলের নাম বদলায়, তবে নির্ভরশীল কোড ঠিক করতে হয়
- `DROP`: টেবিল মোছে, Recycle Bin থেকে ফেরানো যেতে পারে
- `TRUNCATE`: সব রো মোছে, দ্রুত, `ROLLBACK` হয় না
- `DELETE`: DML, `WHERE` চলে, `ROLLBACK` হয়

**পরের ক্লাস:** INSERT, UPDATE, DELETE।
