# ক্লাস ২৮: AND, OR, NOT, IN ও BETWEEN

**তারিখ:** ১৪ ডিসেম্বর ২০২৬, সোমবার
**সময়:** সন্ধ্যা ৭:০০ থেকে রাত ১০:০০
**সপ্তাহ:** ৬ | **ধাপ:** ২ (Oracle SQL)

---

## আজকে কী শিখব

- `AND`, `OR`, `NOT` দিয়ে শর্ত জোড়া
- কোনটা আগে হয়, ব্র্যাকেট কেন জরুরি
- `IN` আর `NOT IN`, NULL-এর ফাঁদ
- `BETWEEN`

---

## ১. AND, OR, NOT (৩৫ মিনিট)

### AND: দুইটা শর্তই সত্য

```sql
-- বিভাগ ৬০ এবং বেতন ৫০০০-এর বেশি: Hunold, Ernst
SELECT last_name, department_id, salary
FROM   employees
WHERE  department_id = 60
AND    salary > 5000;
```

### OR: যেকোনো একটা সত্য

```sql
-- বিভাগ ৩০ অথবা ৯০: ৯ জন
SELECT last_name, department_id
FROM   employees
WHERE  department_id = 30
OR     department_id = 90;
```

বাংলায় বললে "৩০ আর ৯০ বিভাগের কর্মী", কিন্তু SQL-এ লিখতে হবে `OR`। `department_id = 30 AND department_id = 90` দিলে কোনো রো আসবে না, কারণ একজন একসাথে দুই বিভাগে থাকে না।

### NOT: উল্টো

```sql
SELECT last_name, job_id
FROM   employees
WHERE  NOT job_id = 'SA_REP';     -- job_id <> 'SA_REP' এর মতো
```

### সত্য-মিথ্যার ছক

SQL-এ শর্তের ফল ৩ রকম: **সত্য, মিথ্যা, অজানা (NULL)।**

| A | B | A AND B | A OR B |
|---|---|---|---|
| সত্য | সত্য | সত্য | সত্য |
| সত্য | মিথ্যা | মিথ্যা | সত্য |
| মিথ্যা | মিথ্যা | মিথ্যা | মিথ্যা |
| সত্য | অজানা | অজানা | সত্য |
| মিথ্যা | অজানা | মিথ্যা | অজানা |
| অজানা | অজানা | অজানা | অজানা |

`NOT অজানা` = অজানা। `WHERE`-এ শুধু **সত্য** হলেই রো আসে।

## ২. কোনটা আগে হয় (২৫ মিনিট)

**ক্রম: `NOT` → `AND` → `OR`।** অঙ্কে গুণ যেমন যোগের আগে হয়, এখানে `AND` তেমনি `OR`-এর আগে হয়।

**কাজ:** "বিভাগ ৬০ বা ৯০-এর যাদের বেতন ২০০০০-এর বেশি।"

```sql
-- ভুল
SELECT last_name, department_id, salary
FROM   employees
WHERE  department_id = 60
OR     department_id = 90
AND    salary > 20000;
```

ফল ৬টা রো: বিভাগ ৬০-এর ৫ জন **সবাই**, আর King। কারণ Oracle এটাকে এভাবে পড়ে:

```
department_id = 60  OR  (department_id = 90 AND salary > 20000)
```

```sql
-- ঠিক
SELECT last_name, department_id, salary
FROM   employees
WHERE  (department_id = 60 OR department_id = 90)
AND    salary > 20000;
```

ফল ১টা রো: King।

**নিয়ম: `AND` আর `OR` একসাথে থাকলে সবসময় ব্র্যাকেট দাও,** দরকার না হলেও। পরের জন পড়তে পারবে, আর ভুল হবে না।

> APEX-এ সার্চ ফিল্টারের কোডে এই ভুলটা খুব হয়, আর এতে অন্য Buyer বা অন্য ইউনিটের ডাটা দেখা যেতে পারে। তাই এটা শুধু রিপোর্টের নয়, নিরাপত্তারও প্রশ্ন।

## ৩. IN (২৫ মিনিট)

অনেকগুলো `OR`-এর সহজ রূপ।

```sql
-- লম্বা
WHERE department_id = 10 OR department_id = 20 OR department_id = 30

-- সহজ
WHERE department_id IN (10, 20, 30)
```

```sql
-- বিভাগ ১০, ২০, ৩০: ৯ জন
SELECT last_name, department_id
FROM   employees
WHERE  department_id IN (10, 20, 30);

-- লেখা দিয়ে
SELECT last_name, job_id
FROM   employees
WHERE  job_id IN ('IT_PROG', 'AD_VP');

-- তারিখ দিয়ে (learn_freepdb1)
SELECT issue_id, issue_date
FROM   lib_book_issue
WHERE  issue_date IN (DATE '2026-09-01', DATE '2026-09-02');
```

### NOT IN

```sql
-- SA_REP আর ST_CLERK বাদে: ৫৭ জন
SELECT last_name, job_id
FROM   employees
WHERE  job_id NOT IN ('SA_REP', 'ST_CLERK');
```

### সবচেয়ে বিপজ্জনক ফাঁদ: NOT IN আর NULL

```sql
SELECT last_name FROM employees WHERE department_id NOT IN (60, 90);    -- রো আসে

SELECT last_name FROM employees WHERE department_id NOT IN (60, NULL);  -- একটাও না!
```

কেন? `NOT IN (60, NULL)` আসলে:

```
department_id <> 60 AND department_id <> NULL
                         └── সবসময় অজানা
```

`AND`-এর এক পাশ অজানা হলে পুরোটা কখনো সত্য হয় না। তাই কোনো রো আসে না, **আর কোনো এররও আসে না।**

তালিকায় NULL সরাসরি কেউ লেখে না, কিন্তু Subquery-র ফলে NULL এলে একই ঘটনা ঘটে (সপ্তাহ ১০)। মনে রাখো।

এছাড়া `NOT IN (60, 90)`-তে Kimberely Grant নেই, কারণ তার `department_id` NULL।

## ৪. BETWEEN (২৫ মিনিট)

একটা সীমার মধ্যে। **দুই পাশের মানসহ।**

```sql
-- ১৭০০০ থেকে ২৪০০০: King, Kochhar, De Haan
SELECT last_name, salary
FROM   employees
WHERE  salary BETWEEN 17000 AND 24000;
```

এটা `salary >= 17000 AND salary <= 24000`-এর মতো।

### ক্রম: আগে ছোট, পরে বড়

```sql
SELECT last_name FROM employees WHERE salary BETWEEN 24000 AND 17000;
```

কোনো রো আসে না, এররও আসে না। `salary >= 24000 AND salary <= 17000` কখনো সত্য হয় না।

### তারিখ আর লেখায়

```sql
-- সেপ্টেম্বরের ইস্যু (learn_freepdb1): ১–১১ নম্বর
SELECT issue_id, issue_date
FROM   lib_book_issue
WHERE  issue_date BETWEEN DATE '2026-09-01' AND DATE '2026-09-30';

-- A থেকে C
SELECT last_name FROM employees WHERE last_name BETWEEN 'A' AND 'C';
```

### দুইটা ফাঁদ

**১. তারিখে সময় থাকলে শেষ দিনের রো বাদ পড়ে।**

`BETWEEN DATE '2026-09-01' AND DATE '2026-09-30'` মানে ৩০ তারিখ **রাত ১২:০০:০০** পর্যন্ত। ৩০ তারিখ দুপুরের রো আসবে না।

লাইব্রেরিতে আমরা সময় ছাড়া তারিখ রেখেছি বলে ঠিক ফল পেয়েছি। `SYSDATE` দিয়ে ভরা কলামে এভাবে লেখো:

```sql
WHERE entry_date >= DATE '2026-09-01'
AND   entry_date <  DATE '2026-10-01'
```

**২. লেখায় শেষের মান।** `BETWEEN 'A' AND 'C'`-তে `Cambrault` আসে না, কারণ `'Cambrault'` বর্ণক্রমে `'C'`-এর পরে। শুধু `'C'` লেখা থাকলে আসত।

### NOT BETWEEN

```sql
-- ৩০০০-এর কম অথবা ২০০০০-এর বেশি
SELECT last_name, salary
FROM   employees
WHERE  salary NOT BETWEEN 3000 AND 20000;
```

## সারাংশ

- `AND` দুইটাই সত্য, `OR` যেকোনো একটা। ক্রম: `NOT` → `AND` → `OR`
- `AND` আর `OR` একসাথে থাকলে ব্র্যাকেট দাও
- `IN` হলো অনেক `OR`-এর সহজ রূপ
- `NOT IN` তালিকায় NULL থাকলে কোনো রো আসে না
- `BETWEEN` দুই পাশসহ, আগে ছোট মান। সময়সহ তারিখে `>=` আর `<` ভালো

**পরের ক্লাস:** LIKE, IS NULL, IS NOT NULL।
