## আজকে কী শিখব

- `ORDER BY`: `ASC`, `DESC`, একাধিক কলাম
- Alias আর কলামের অবস্থান দিয়ে সাজানো
- `NULLS FIRST`, `NULLS LAST`
- SQL-এর অংশগুলো কোন ক্রমে চলে
- `FETCH FIRST` দিয়ে টপ রো আনা, `OFFSET` দিয়ে পেজিং

## ১. ORDER BY (৪৫ মিনিট)

**ORDER BY ছাড়া রো-র ক্রমের কোনো নিশ্চয়তা নেই।** আজ যে ক্রমে আসছে, কাল ভিন্ন ক্রমে আসতে পারে। ক্রম দরকার হলে সবসময় লিখে দিতে হবে।

```sql
SELECT last_name, salary
FROM   employees
ORDER  BY salary;           -- ছোট থেকে বড়, Olson (2100) প্রথমে
```

| লেখা | মানে |
|---|---|
| `ASC` | ছোট থেকে বড়, ডিফল্ট |
| `DESC` | বড় থেকে ছোট |

```sql
SELECT last_name, salary
FROM   employees
ORDER  BY salary DESC;      -- বড় থেকে ছোট, King (24000) প্রথমে
```

### ধরন অনুযায়ী ক্রম

| ধরন | `ASC` |
|---|---|
| সংখ্যা | ছোট থেকে বড় |
| লেখা | বর্ণক্রমে (A থেকে Z) |
| তারিখ | আগের থেকে পরের |

```sql
SELECT last_name FROM employees ORDER BY last_name;

SELECT last_name, hire_date FROM employees ORDER BY hire_date DESC;   -- নতুন কর্মী আগে
```

### একাধিক কলাম

প্রথম কলামে একই মান হলে দ্বিতীয় কলাম দিয়ে সাজায়।

```sql
SELECT department_id, last_name, salary
FROM   employees
ORDER  BY department_id ASC, salary DESC;
```

বিভাগের ক্রমে, আর প্রতিটা বিভাগের ভেতরে বেশি বেতন আগে। `DESC` শুধু তার আগের কলামের উপর কাজ করে। ERP রিপোর্টে এই ধরনটাই বেশি দরকার হয়: Buyer-wise, তারপর Style-wise।

### Alias দিয়ে সাজানো

```sql
SELECT last_name, salary * 12 AS annual_salary
FROM   employees
ORDER  BY annual_salary DESC;
```

`WHERE`-এ Alias চলে না, কিন্তু `ORDER BY`-তে চলে। কারণ দেখবে পরের অংশে।

### কলামের অবস্থান দিয়ে

```sql
SELECT last_name, salary
FROM   employees
ORDER  BY 2 DESC;           -- SELECT-এর ২ নম্বর কলাম
```

চলে, কিন্তু কোডে লিখবে না। `SELECT`-এ কলাম বদলালে ক্রম বদলে যায়, কোনো এরর আসে না।

### SELECT-এ নেই এমন কলাম দিয়ে

```sql
SELECT last_name FROM employees ORDER BY salary DESC;
```

চলে। তবে `DISTINCT` থাকলে চলে না:

```sql
SELECT DISTINCT department_id FROM employees ORDER BY salary;
```

```
ORA-01791: not a SELECTed expression
```

## ২. NULL কোথায় যায় (১৫ মিনিট)

| সাজানো | NULL কোথায় |
|---|---|
| `ASC` | শেষে |
| `DESC` | **শুরুতে** |

Oracle NULL-কে সবচেয়ে বড় মান হিসেবে ধরে।

```sql
SELECT last_name, commission_pct
FROM   employees
ORDER  BY commission_pct DESC;      -- প্রথমে ৭২ জনের ফাঁকা ঘর!
```

"সবচেয়ে বেশি কমিশন" চাইলে উপরে ফাঁকা দেখায়। ঠিক করতে:

```sql
SELECT last_name, commission_pct
FROM   employees
ORDER  BY commission_pct DESC NULLS LAST;
```

`NULLS FIRST`-ও আছে।

## ৩. SQL কোন ক্রমে চলে (১৫ মিনিট)

**যে ক্রমে লেখো, সেই ক্রমে চলে না।**

| লেখার ক্রম | চলার ক্রম |
|---|---|
| ১. `SELECT` | ১. `FROM` |
| ২. `FROM` | ২. `WHERE` |
| ৩. `WHERE` | ৩. `SELECT` |
| ৪. `ORDER BY` | ৪. `ORDER BY` |
| ৫. `FETCH FIRST` | ৫. `FETCH FIRST` |

> সপ্তাহ ৮-এ `GROUP BY` আর `HAVING` যোগ হবে, `WHERE`-এর পরে।

এই ক্রম থেকেই বোঝা যায়:

- **`WHERE`-এ Alias চলে না:** Alias তৈরি হয় `SELECT`-এ, `WHERE`-এর পরে
- **`ORDER BY`-তে Alias চলে:** এটা `SELECT`-এর পরে চলে
- **`FETCH FIRST` সাজানোর পরের রো নেয়:** তাই "টপ ৩" ঠিকমতো আসে

## ৪. FETCH FIRST ও OFFSET (৪০ মিনিট)

### টপ N

```sql
-- সবচেয়ে বেশি বেতনের ৩ জন: King, Kochhar, De Haan
SELECT last_name, salary
FROM   employees
ORDER  BY salary DESC
FETCH  FIRST 3 ROWS ONLY;
```

এটা Oracle 12c থেকে আছে। `ORDER BY` না দিলে "যেকোনো ৩টা" রো আসবে, "টপ ৩" না।

### সমান মান থাকলে: WITH TIES

```sql
-- ২ জন চাইলাম: King আর ১৭০০০-এর একজন
SELECT last_name, salary
FROM   employees
ORDER  BY salary DESC
FETCH  FIRST 2 ROWS ONLY;

-- সমান মানের সবাইকে নাও: King, Kochhar, De Haan
SELECT last_name, salary
FROM   employees
ORDER  BY salary DESC
FETCH  FIRST 2 ROWS WITH TIES;
```

প্রথমটায় Kochhar আর De Haan দুজনেরই ১৭০০০, কিন্তু একজন বাদ পড়ল। কোনজন, তার কোনো নিশ্চয়তা নেই। পুরস্কারের তালিকায় এটা অন্যায় হবে, তাই সেখানে `WITH TIES`।

### শতকরা

```sql
-- উপরের ১০%
SELECT last_name, salary
FROM   employees
ORDER  BY salary DESC
FETCH  FIRST 10 PERCENT ROWS ONLY;
```

### পেজিং: OFFSET

একটা রিপোর্ট পেজে পেজে দেখানো:

```sql
-- পেজ ১: ১–১০ নম্বর
SELECT employee_id, last_name
FROM   employees
ORDER  BY employee_id
FETCH  FIRST 10 ROWS ONLY;

-- পেজ ২: ১১–২০ নম্বর
SELECT employee_id, last_name
FROM   employees
ORDER  BY employee_id
OFFSET 10 ROWS FETCH NEXT 10 ROWS ONLY;

-- পেজ ৩: ২১–৩০ নম্বর
SELECT employee_id, last_name
FROM   employees
ORDER  BY employee_id
OFFSET 20 ROWS FETCH NEXT 10 ROWS ONLY;
```

**সূত্র:** `OFFSET (পেজ - 1) * পেজের_সাইজ`

**পেজিংয়ে `ORDER BY` একটা ইউনিক কলামে হতে হবে।** শুধু `salary`-তে সাজালে সমান বেতনের কর্মীরা এক পেজে দুইবার আসতে বা বাদ পড়তে পারে। তাই `ORDER BY salary DESC, employee_id`।

> APEX-এর রিপোর্ট পেজিং নিজেই করে দেয়। পেছনের ধারণাটা এটাই।

### পুরনো পদ্ধতি: ROWNUM

পুরনো কোডে (11g বা আগের) `ROWNUM` দেখবে। একটা সাধারণ ভুল আছে:

```sql
-- ভুল: "টপ ৩" না
SELECT last_name, salary
FROM   employees
WHERE  ROWNUM <= 3
ORDER  BY salary DESC;
```

`WHERE` আগে চলে, তাই আগে যেকোনো ৩টা রো নেয়, তারপর সাজায়। ঠিক উপায়ে Subquery লাগে (সপ্তাহ ১০):

```sql
SELECT *
FROM  (SELECT last_name, salary FROM employees ORDER BY salary DESC)
WHERE  ROWNUM <= 3;
```

ইন্টারভিউতে এই প্রশ্ন প্রায়ই আসে।

## সারাংশ

- `ORDER BY` ছাড়া ক্রমের নিশ্চয়তা নেই। ডিফল্ট `ASC`
- `DESC`-এ NULL শুরুতে আসে, `NULLS LAST` দিয়ে শেষে নেওয়া যায়
- চলার ক্রম: `FROM → WHERE → SELECT → ORDER BY → FETCH FIRST`
- টপ N: `ORDER BY` + `FETCH FIRST n ROWS ONLY`, সমান মানের জন্য `WITH TIES`
- পেজিং: `OFFSET` + `FETCH NEXT`, ইউনিক কলামে সাজিয়ে
