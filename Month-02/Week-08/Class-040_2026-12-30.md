**তারিখ:** ৩০ ডিসেম্বর ২০২৬, বুধবার

## আজকে কী শিখব

- `HAVING` দিয়ে দল বাছাই

- দুইটা একসাথে ব্যবহার
- পুরো `SELECT`-এর ক্রম
- ডুপ্লিকেট ডাটা খোঁজা

## ১. HAVING (৩৫ মিনিট)

কালকের ক্লাসের ২২ নম্বর প্রশ্ন: "৫ জনের বেশি কর্মী আছে এমন বিভাগ।"

```sql
-- ভুল
SELECT department_id, COUNT(*) AS headcount
FROM   employees
WHERE  COUNT(*) > 5
GROUP  BY department_id;
```

```
ORA-00934: group function is not allowed here
```

`WHERE` চলে দল করার **আগে**, তখনো `COUNT(*)` হিসাব হয়নি। দল করার **পরে** বাছাই করে **HAVING**।

```sql
-- ঠিক: ৩০ (৬), ৫০ (৪৫), ৮০ (৩৪), ১০০ (৬)
SELECT department_id, COUNT(*) AS headcount
FROM   employees
GROUP  BY department_id
HAVING COUNT(*) > 5;
```

```
সব ১০৭টা রো
     │ GROUP BY
     ▼
১২টা দল: 10, 20, 30, ... , NULL
     │ HAVING COUNT(*) > 5
     ▼
৪টা দল: 30, 50, 80, 100
```

### আরো উদাহরণ

```sql
-- গড় বেতন ১০০০০-এর বেশি: ৯০, ১১০
SELECT department_id, ROUND(AVG(salary), 2) AS avg_salary
FROM   employees
GROUP  BY department_id
HAVING AVG(salary) > 10000;

-- মোট বেতন ৫০০০০-এর বেশি: ৫০, ৮০, ৯০, ১০০
SELECT department_id, SUM(salary) AS total_salary
FROM   employees
GROUP  BY department_id
HAVING SUM(salary) > 50000;

-- যে পদে মাত্র ১ জন: ১০টা পদ
SELECT job_id, COUNT(*) AS headcount
FROM   employees
GROUP  BY job_id
HAVING COUNT(*) = 1;
```

`HAVING`-এ এমন Aggregate-ও দেওয়া যায়, যা `SELECT`-এ নেই:

```sql
SELECT department_id
FROM   employees
GROUP  BY department_id
HAVING MAX(salary) > 15000;     -- বিভাগ ৯০
```

### লাইব্রেরিতে (`learn_freepdb1`)

```sql
-- ৪-এর বেশি বই আছে এমন প্রকাশক: ২, ৪
SELECT publisher_id, COUNT(*) AS books
FROM   lib_book
GROUP  BY publisher_id
HAVING COUNT(*) > 4;

-- একাধিক কপি আছে এমন বই: ১, ২, ৩, ৪, ৫
SELECT book_id, COUNT(*) AS copies
FROM   lib_book_copy
GROUP  BY book_id
HAVING COUNT(*) > 1;
```

## ২. WHERE বনাম HAVING (৪০ মিনিট)

| | `WHERE` | `HAVING` |
|---|---|---|
| কী বাছে | **রো** | **দল** |
| কখন চলে | `GROUP BY`-এর আগে | `GROUP BY`-এর পরে |
| Aggregate | চলে না | চলে |
| `GROUP BY` লাগে? | না | সাধারণত হ্যাঁ |

### দুইটা একসাথে

**কাজ:** "বিভাগ ৯০ বাদে, যেসব বিভাগের গড় বেতন ১০০০০-এর বেশি।"

```sql
-- ফল: বিভাগ ১১০, গড় ১০১৫৪
SELECT department_id, ROUND(AVG(salary), 2) AS avg_salary
FROM   employees
WHERE  department_id <> 90         -- ১. রো বাদ
GROUP  BY department_id            -- ২. দল
HAVING AVG(salary) > 10000;        -- ৩. দল বাদ
```

### একই প্রশ্ন, ভিন্ন জায়গায়, ভিন্ন ফল

```sql
-- ক: যাদের বেতন ১০০০০-এর বেশি, তাদের নিয়ে বিভাগভিত্তিক গণনা
SELECT department_id, COUNT(*) AS headcount
FROM   employees
WHERE  salary > 10000
GROUP  BY department_id;

-- খ: যেসব বিভাগে সর্বোচ্চ বেতন ১০০০০-এর বেশি, সেখানকার মোট কর্মী
SELECT department_id, COUNT(*) AS headcount
FROM   employees
GROUP  BY department_id
HAVING MAX(salary) > 10000;
```

বিভাগ ৫০-এ `খ`-তে ৪৫ জনের দল বাদ পড়ে, কারণ সর্বোচ্চ বেতন ৮২০০। বিভাগ ৩০-এ `ক`-তে শুধু ১ জন (Raphaely), `খ`-তে ৬ জন। **`WHERE` গণনাটাই বদলে দেয়, `HAVING` শুধু দল বাদ দেয়।**

### সাধারণ কলামে HAVING

```sql
-- চলে, কিন্তু ভালো না
SELECT department_id, COUNT(*) FROM employees
GROUP  BY department_id
HAVING department_id <> 90;

-- ভালো
SELECT department_id, COUNT(*) FROM employees
WHERE  department_id <> 90
GROUP  BY department_id;
```

ফল একই, কিন্তু প্রথমটায় Oracle আগে বিভাগ ৯০-র হিসাব করে তারপর ফেলে দেয়। বড় টেবিলে ধীর।

**নিয়ম: যে শর্ত রো-র উপর, সেটা `WHERE`-এ। শুধু Aggregate-এর শর্ত `HAVING`-এ।**

### HAVING-এ Alias

```sql
SELECT department_id, COUNT(*) AS headcount
FROM   employees
GROUP  BY department_id
HAVING headcount > 5;
```

পুরনো ভার্সনে এটা `ORA-00904` দেয়, কারণ Alias তৈরি হয় পরে। নতুন ভার্সনে নিয়ম কিছুটা শিথিল হলেও **`HAVING COUNT(*) > 5` লেখার অভ্যাস রাখো,** সব ভার্সনে চলে।

## ৩. পুরো SELECT-এর ক্রম (১৫ মিনিট)

| লেখার ক্রম | চলার ক্রম | কাজ |
|---|---|---|
| ১. `SELECT` | ৫ | কলাম, Alias |
| ২. `FROM` | ১ | টেবিল |
| ৩. `WHERE` | ২ | রো বাছাই |
| ৪. `GROUP BY` | ৩ | দল করা |
| ৫. `HAVING` | ৪ | দল বাছাই |
| ৬. `ORDER BY` | ৬ | সাজানো |
| ৭. `FETCH FIRST` | ৭ | টপ রো |

এই ক্রমই সব বলে দেয়:
- `WHERE`-এ Aggregate নয়: তখনো দল হয়নি
- `HAVING`-এ Aggregate চলে: দল হয়ে গেছে
- `WHERE`-এ Alias নয়: `SELECT` পরে
- `ORDER BY`-তে Alias চলে: `SELECT` আগে

### সব একসাথে

**কাজ:** "কমিশন পান এমন কর্মী বাদে, ৫ জনের বেশি কর্মী থাকা বিভাগগুলোর মোট বেতন, বেশি আগে, শীর্ষ ২টা।"

```sql
-- ফল: ৫০ (১৫৬৪০০), ১০০ (৫১৬০৮)
SELECT department_id,
       COUNT(*)    AS headcount,
       SUM(salary) AS total_salary
FROM   employees
WHERE  commission_pct IS NULL
GROUP  BY department_id
HAVING COUNT(*) > 5
ORDER  BY total_salary DESC
FETCH  FIRST 2 ROWS ONLY;
```

## ৪. ডুপ্লিকেট খোঁজা (১৫ মিনিট)

বাস্তবে ডাটার মান যাচাইয়ের সবচেয়ে কাজের কোয়েরি:

```sql
-- একই last_name একাধিকবার (যেমন King, Grant)
SELECT last_name, COUNT(*) AS name_count
FROM   employees
GROUP  BY last_name
HAVING COUNT(*) > 1
ORDER  BY last_name;
```

Excel থেকে ডাটা ইমপোর্টের আগে আর পরে এটা চালানো হয়।

```sql
-- একই ইমেইল দুইজনের? (learn_freepdb1) Unique আছে, তাই কোনো রো আসবে না
SELECT email, COUNT(*)
FROM   lib_member
WHERE  email IS NOT NULL
GROUP  BY email
HAVING COUNT(*) > 1;

-- একই বই একাধিকবার একই মেম্বার নিয়েছে কি না, Copy ধরে
SELECT member_id, copy_id, COUNT(*) AS times_taken
FROM   lib_book_issue
GROUP  BY member_id, copy_id
HAVING COUNT(*) > 1;
```

কাজের প্রশ্ন: ক্লাস ১৬-র `order_flat`-এ একই Buyer কয়টা ভিন্ন দেশে আছে? ডাটা ঠিক থাকলে প্রতিটা Buyer-এর ১টাই।

```sql
-- Update Anomaly খোঁজা: কোনো রো না আসারই কথা
SELECT buyer_name, COUNT(DISTINCT buyer_country) AS country_count
FROM   order_flat
GROUP  BY buyer_name
HAVING COUNT(DISTINCT buyer_country) > 1;
```

## ৬. হোমওয়ার্ক

1. কাল বিভাগভিত্তিক ২০টা রিপোর্ট। ক্লাস ৩৬–৪০-এর সারাংশ পড়ে আসো।
2. `WHERE` আর `HAVING`-এর পার্থক্য একজন নতুন মানুষকে বোঝাও, গার্মেন্টসের উদাহরণ দিয়ে। (যেমন: "৫০০০ পিসের বেশি অর্ডার" নাকি "মোট ১ লাখ পিসের বেশি অর্ডার দেওয়া Buyer"।)
3. `SELECT` না দেখে পুরো ক্রম লেখো, আর প্রতিটা অংশের কাজ ১ লাইনে।

## সারাংশ

- `HAVING`: দল করার পরে দল বাছাই, Aggregate চলে
- `WHERE`: দল করার আগে রো বাছাই, Aggregate চলে না
- রো-র শর্ত `WHERE`-এ, Aggregate-এর শর্ত `HAVING`-এ
- ক্রম: `FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → FETCH FIRST`
- `GROUP BY ... HAVING COUNT(*) > 1`: ডুপ্লিকেট খোঁজার কৌশল

**পরের দিন (বৃহস্পতিবার):** সপ্তাহ ৮-এর প্র্যাকটিস: বিভাগভিত্তিক ২০টা রিপোর্ট কোয়েরি।
