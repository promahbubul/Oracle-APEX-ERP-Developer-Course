## আজকে কী শিখব

- `GROUP BY` দিয়ে দল করে হিসাব
- `GROUP BY`-এর নিয়ম
- একাধিক কলামে দল
- হিসাব বা ফাংশন দিয়ে দল: বছর, মাস, CASE

## ১. GROUP BY (৪০ মিনিট)

কাল পুরো টেবিলের একটা ফল পেয়েছ। কিন্তু ERP-তে প্রশ্ন হয়: **"প্রতিটা বিভাগে কতজন?"**, **"Buyer-wise মোট অর্ডার কত?"**

```sql
SELECT department_id,
       COUNT(*)    AS headcount,
       SUM(salary) AS total_salary
FROM   employees
GROUP  BY department_id;
```

ফল: প্রতিটা বিভাগের একটা রো, মোট ১২টা (১১টা বিভাগ আর NULL)।

### কীভাবে কাজ করে

```
আগে                              দল করার পরে
DEPT   SALARY
60     9000  ┐
60     6000  │  ──► 60   COUNT 5   SUM 28800
60     4800  │
60     4800  │
60     4200  ┘
90     24000 ┐
90     17000 │  ──► 90   COUNT 3   SUM 58000
90     17000 ┘
```

Oracle `department_id`-এর প্রতিটা মানের জন্য একটা দল বানায়, আর প্রতিটা দলে Aggregate চালায়।

### মিলিয়ে দেখো

| DEPARTMENT_ID | HEADCOUNT | TOTAL_SALARY |
|---|---|---|
| 10 | 1 | 4400 |
| 20 | 2 | 19000 |
| 30 | 6 | 24900 |
| 40 | 1 | 6500 |
| 50 | 45 | 156400 |
| 60 | 5 | 28800 |
| 70 | 1 | 10000 |
| 80 | 34 | 304500 |
| 90 | 3 | 58000 |
| 100 | 6 | 51608 |
| 110 | 2 | 20308 |
| NULL | 1 | 7000 |

সবগুলো যোগ করলে: ১০৭ জন আর ৬৯১৪১৬ টাকা, ক্লাস ৩৮-এর সাথে মিলে যায়।

### সবচেয়ে জরুরি নিয়ম

**`SELECT`-এ যে কলাম Aggregate-এর ভেতরে নেই, সেটা `GROUP BY`-তে থাকতে হবে।**

```sql
-- ঠিক
SELECT department_id, COUNT(*) FROM employees GROUP BY department_id;

-- ভুল: job_id দলে নেই
SELECT department_id, job_id, COUNT(*) FROM employees GROUP BY department_id;
```

```
ORA-00979: not a GROUP BY expression
```

একটা বিভাগে অনেক `job_id`, দলের রো একটাই। কোনটা দেখাবে, Oracle জানে না।

উল্টোটা চলে: `GROUP BY`-র কলাম `SELECT`-এ না থাকলেও চলে, তবে ফল বোঝা যায় না।

```sql
SELECT COUNT(*) FROM employees GROUP BY department_id;
```

### WHERE আর ORDER BY-র সাথে

```sql
SELECT department_id,
       COUNT(*)              AS headcount,
       ROUND(AVG(salary), 2) AS avg_salary
FROM   employees
WHERE  department_id IS NOT NULL    -- ১. আগে রো বাছাই
GROUP  BY department_id             -- ২. তারপর দল
ORDER  BY avg_salary DESC;          -- ৩. শেষে সাজানো
```

ফল ১১টা রো, প্রথমে বিভাগ ৯০ (১৯৩৩৩.৩৩)।

`ORDER BY`-তে Alias চলে। `GROUP BY`-তে পুরনো ভার্সনে চলে না, তাই হিসাবটাই লেখো।

### লাইব্রেরিতে (`learn_freepdb1`)

```sql
-- কপির অবস্থা: AVAILABLE 13, ISSUED 5, DAMAGED 1, LOST 1
SELECT copy_status, COUNT(*) AS copies
FROM   lib_book_copy
GROUP  BY copy_status;

-- প্রকাশকভিত্তিক বই: ১→৩, ২→৫, ৩→৪, ৪→৫, ৫→৩
SELECT publisher_id, COUNT(*) AS books
FROM   lib_book
GROUP  BY publisher_id
ORDER  BY publisher_id;

-- মেম্বারের ধরন: ১→১২, ২→৪, ৩→৪
SELECT member_type_id, COUNT(*) AS members
FROM   lib_member
GROUP  BY member_type_id;
```

নামসহ দেখাতে JOIN লাগবে: `publisher_name`। সেটা আগামী সপ্তাহে।

## ২. একাধিক কলামে দল (২০ মিনিট)

```sql
SELECT department_id, job_id, COUNT(*) AS headcount, SUM(salary) AS total_salary
FROM   employees
GROUP  BY department_id, job_id
ORDER  BY department_id, job_id;
```

এখন প্রতিটা **জোড়ার** জন্য একটা দল। যেমন বিভাগ ৫০-এ `ST_MAN`, `ST_CLERK`, `SH_CLERK` আলাদা তিনটা রো, আর তাদের কর্মী সংখ্যা মিলে `5 + 20 + 20 = 45`।

বাস্তবের ERP রিপোর্ট: **Buyer-wise, Style-wise মোট অর্ডার।** এটা ঠিক এভাবে হয়।

## ৩. হিসাব বা ফাংশন দিয়ে দল (২৫ মিনিট)

`GROUP BY`-তে শুধু কলাম না, হিসাবও চলে।

### তারিখ দিয়ে

```sql
-- বছরভিত্তিক নিয়োগ
SELECT TO_CHAR(hire_date, 'YYYY') AS hire_year, COUNT(*) AS hired
FROM   employees
GROUP  BY TO_CHAR(hire_date, 'YYYY')
ORDER  BY hire_year;

-- মাসভিত্তিক ইস্যু (learn_freepdb1): 2026-09 → 11, 2026-10 → 4, 2026-11 → 5
SELECT TO_CHAR(issue_date, 'YYYY-MM') AS issue_month, COUNT(*) AS issues
FROM   lib_book_issue
GROUP  BY TO_CHAR(issue_date, 'YYYY-MM')
ORDER  BY issue_month;
```

(সপ্তাহ ৫-এর প্র্যাকটিসের ২১ নম্বর ইস্যুটা তুমি যে মাসে চালিয়েছ, সেই মাসে আরেকটা রো যোগ করবে।)

`YYYY-MM` আকারে লিখলে বর্ণক্রম আর তারিখের ক্রম একই হয়, তাই সাজানো ঠিক থাকে। `Mon-YYYY` হলে হয় না।

### CASE দিয়ে

```sql
-- ইস্যুর অবস্থা ধরে গোনা
SELECT CASE
           WHEN return_date IS NULL    THEN 'Not returned'
           WHEN return_date > due_date THEN 'Late'
           ELSE 'On time'
       END AS issue_status,
       COUNT(*) AS issues
FROM   lib_book_issue
GROUP  BY CASE
              WHEN return_date IS NULL    THEN 'Not returned'
              WHEN return_date > due_date THEN 'Late'
              ELSE 'On time'
          END;
```

```sql
-- বেতনের স্তর ধরে কর্মী সংখ্যা (hr_freepdb1)
SELECT CASE WHEN salary < 5000  THEN '1. Low'
            WHEN salary < 10000 THEN '2. Medium'
            ELSE '3. High'
       END AS salary_band,
       COUNT(*) AS headcount
FROM   employees
GROUP  BY CASE WHEN salary < 5000  THEN '1. Low'
               WHEN salary < 10000 THEN '2. Medium'
               ELSE '3. High'
          END
ORDER  BY salary_band;
```

`CASE`টা দুইবার লিখতে হলো। CTE দিয়ে এই পুনরাবৃত্তি কমানো যায় (সপ্তাহ ১৩)।

## ৪. পাশাপাশি রিপোর্ট ও LISTAGG (২০ মিনিট)

### SUM(CASE ...) ও COUNT(CASE ...)

একটা রো-তে কয়েকটা শর্তের হিসাব পাশাপাশি:

```sql
SELECT department_id,
       COUNT(*)                                       AS total_staff,
       COUNT(CASE WHEN salary >= 10000 THEN 1 END)    AS high_paid,
       COUNT(CASE WHEN salary < 10000 THEN 1 END)     AS others,
       SUM(CASE WHEN salary >= 10000 THEN salary END) AS high_paid_total
FROM   employees
GROUP  BY department_id
ORDER  BY department_id;
```

`CASE`-এ `ELSE` নেই, তাই না মিললে NULL, আর `COUNT` NULL গোনে না।

```sql
-- জরিমানা: পরিশোধ আর বাকি (learn_freepdb1): 100, 65
SELECT SUM(CASE WHEN is_paid = 'Y' THEN fine_amount END) AS paid_total,
       SUM(CASE WHEN is_paid = 'N' THEN fine_amount END) AS due_total
FROM   lib_fine;
```

**গার্মেন্টসে:** একটা রো-তে Style, আর পাশাপাশি `S`, `M`, `L` সাইজের মোট পরিমাণ। ক্লাস ১৭-এর Excel-এর মতো দেখানো। `PIVOT` দিয়েও হয়, সপ্তাহ ১৩-এ শিখবে।

```sql
SELECT order_no,
       SUM(CASE WHEN size_code = 'S' THEN order_qty END) AS size_s,
       SUM(CASE WHEN size_code = 'M' THEN order_qty END) AS size_m,
       SUM(order_qty) AS total_qty
FROM   order_size_qty
GROUP  BY order_no;
```

ক্লাস ১১-এর `order_size_qty` থেকে: `ORD-001`, S = 800, M = 800, মোট 1600।

### LISTAGG: একটা ঘরে তালিকা

```sql
-- বিভাগ ৬০: Austin, Ernst, Hunold, Lorentz, Pataballa
SELECT department_id,
       LISTAGG(last_name, ', ') WITHIN GROUP (ORDER BY last_name) AS staff_list
FROM   employees
GROUP  BY department_id;
```

ড্যাশবোর্ড বা রিপোর্টে "এই লাইনে কে কে" দেখাতে কাজে লাগে। শুধু **দেখানোর** জন্য। ডাটা এভাবে জমা রাখবে না (1NF)।

## ৫. SQL চলার ক্রম (১৫ মিনিট)

| চলার ক্রম | অংশ | কাজ |
|---|---|---|
| ১ | `FROM` | টেবিল |
| ২ | `WHERE` | রো বাছাই |
| ৩ | `GROUP BY` | দল করা |
| ৪ | `SELECT` | কলাম, Aggregate, Alias |
| ৫ | `ORDER BY` | সাজানো |
| ৬ | `FETCH FIRST` | টপ রো |

(কাল `HAVING` যোগ হবে, `GROUP BY`-এর ঠিক পরে।)

```sql
-- সবচেয়ে বেশি মোট বেতনের ৩টা বিভাগ: ৮০, ৫০, ৯০
SELECT department_id, SUM(salary) AS total_salary
FROM   employees
WHERE  department_id IS NOT NULL
GROUP  BY department_id
ORDER  BY total_salary DESC
FETCH  FIRST 3 ROWS ONLY;
```

13. প্রতিটা বিভাগের কর্মীদের নামের তালিকা।

## ৭. হোমওয়ার্ক

1. `SELECT`-এর ৬টা অংশ চলার ক্রমে লেখো। ক্লাসের টেবিল না দেখে।
2. ভাবো: "Buyer-wise মোট অর্ডার পরিমাণ" রিপোর্টে কোন কোন টেবিল লাগবে? JOIN ছাড়া এখন কতটুকু করা যায়? `w5_order`-এ `style_id` দিয়ে শুরু করো।
3. `order_size_qty`-তে `ORD-001`-এর `Black` আর `White` রঙের মোট পিস পাশাপাশি দেখাও।

1. `GROUP BY`-এর সবচেয়ে জরুরি নিয়ম কী?
2. `GROUP BY department_id`-এ NULL কি একটা দল হয়?
3. `ORA-00979` কখন আসে?
4. `WHERE` আগে চলে, না `GROUP BY`?
5. `COUNT(CASE WHEN salary > 1000 THEN 1 END)` কাদের গোনে?

<details>
<summary>উত্তর দেখো</summary>

1. `SELECT`-এ যে কলাম Aggregate-এর ভেতরে নেই, সেটা `GROUP BY`-তে থাকতে হবে
2. হ্যাঁ, সব NULL মিলে একটা দল
3. `SELECT`-এর কোনো কলাম Aggregate বা `GROUP BY`-তে না থাকলে
4. `WHERE`
5. যাদের বেতন ১০০০-এর বেশি

</details>

## সারাংশ

- `GROUP BY` প্রতিটা মানের জন্য একটা দল বানায়, প্রতিটায় Aggregate চলে
- `SELECT`-এর সাধারণ কলাম `GROUP BY`-তে থাকতেই হবে, নাহলে `ORA-00979`
- একাধিক কলাম, তারিখ, `CASE` সব দিয়েই দল করা যায়
- `SUM(CASE ...)`: পাশাপাশি রিপোর্ট
- `LISTAGG`: দলের মান এক ঘরে, শুধু দেখানোর জন্য

**পরের ক্লাস:** HAVING; WHERE আর HAVING-এর পার্থক্য।
