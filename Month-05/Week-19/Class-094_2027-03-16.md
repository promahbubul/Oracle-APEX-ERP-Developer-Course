# ক্লাস ৯৪: Package Initialization

**তারিখ:** ১৬ মার্চ ২০২৭, মঙ্গলবার
**সময়:** সন্ধ্যা ৭:০০ থেকে রাত ১০:০০
**সপ্তাহ:** ১৯ | **ধাপ:** ৩ (PL/SQL)

---

## আজকে কী শিখব

- Body-র শেষের `BEGIN` অংশ: Session-এ একবার চলে
- সেটিং টেবিল: স্যালারির নিয়ম কোড থেকে টেবিলে
- Session-এর শুরুতে সেটিং লোড, পরে দ্রুত পড়া (Cache)
- টেবিল বদলালে কী হয়: `reload`, `DBMS_SESSION.RESET_PACKAGE`
- Initialization-এ এরর হলে সাবধানতা

## ১. Initialization অংশ (৩০ মিনিট)

Package Body-র শেষে, সব Procedure-এর পরে, `END`-এর আগে একটা `BEGIN` দেওয়া যায়:

```sql
CREATE OR REPLACE PACKAGE w19_init_demo_pkg
IS
    PROCEDURE hello;
END w19_init_demo_pkg;
/

CREATE OR REPLACE PACKAGE BODY w19_init_demo_pkg
IS
    g_started_at DATE;

    PROCEDURE hello IS
    BEGIN
        DBMS_OUTPUT.PUT_LINE('Hello, package started at ' || TO_CHAR(g_started_at, 'HH24:MI:SS'));
    END hello;

BEGIN
    -- Initialization: এই Session-এ প্রথমবার Package ছোঁয়ার সময় একবার
    g_started_at := SYSDATE;
    DBMS_OUTPUT.PUT_LINE('>> initializing w19_init_demo_pkg');
END w19_init_demo_pkg;
/
```

```sql
SET SERVEROUTPUT ON

EXEC w19_init_demo_pkg.hello;
-- >> initializing w19_init_demo_pkg
-- Hello, package started at 19:05:12

EXEC w19_init_demo_pkg.hello;
-- Hello, package started at 19:05:12          (initializing আর আসে না, সময়ও একই)
```

| বৈশিষ্ট্য | মান |
|---|---|
| কখন চলে | Session-এ প্রথমবার Package-এর যেকোনো কিছু (Procedure, Function, Constant) ছোঁয়ার সময় |
| কতবার | প্রতি Session-এ একবার (বা Package Compile/Reset-এর পরে আবার) |
| কোথায় লেখা | Body-র একদম শেষে, `END pkg;`-এর ঠিক আগে |
| Parameter | নেই, কেউ ডাকে না, Oracle নিজে চালায় |

`g_hits NUMBER := 0;`-এর মতো ঘোষণার সাথে মান দেওয়াও আসলে Initialization-এর অংশ। জটিল কাজ (টেবিল পড়া, হিসাব) ঘোষণায় লেখা যায় না, তাই `BEGIN` অংশ।

## ২. সেটিং টেবিল (৪০ মিনিট)

সপ্তাহ ১৬ থেকে স্যালারির নিয়ম কোডে লেখা:

```sql
c_house_pct  CONSTANT NUMBER := 0.5;
c_medical    CONSTANT NUMBER := 750;
c_transport  CONSTANT NUMBER := 450;
```

সরকার ন্যূনতম মজুরি বদলাল, বা কোম্পানি চিকিৎসা ভাতা বাড়াল। প্রতিবার প্রোগ্রামারকে ডেকে কোড বদলাও, Compile করো (আর সবার `ORA-04068`)। HR নিজে APEX-এর একটা পেজ থেকে বদলাতে পারলে ভালো।

**নিয়ম কোড থেকে টেবিলে:**

```sql
CREATE TABLE w19_payroll_setting (
    setting_code  VARCHAR2(30)  CONSTRAINT w19_payroll_setting_pk PRIMARY KEY,
    setting_value NUMBER        NOT NULL,
    description   VARCHAR2(200),
    updated_at    DATE          DEFAULT SYSDATE NOT NULL
);

INSERT INTO w19_payroll_setting (setting_code, setting_value, description)
VALUES ('HOUSE_PCT',  0.5,  'House rent as fraction of basic');
INSERT INTO w19_payroll_setting (setting_code, setting_value, description)
VALUES ('MEDICAL',    750,  'Medical allowance per month');
INSERT INTO w19_payroll_setting (setting_code, setting_value, description)
VALUES ('TRANSPORT',  450,  'Transport allowance per month');
INSERT INTO w19_payroll_setting (setting_code, setting_value, description)
VALUES ('MONTH_DAYS', 30,   'Days used for absent deduction');
INSERT INTO w19_payroll_setting (setting_code, setting_value, description)
VALUES ('MIN_WAGE',   8000, 'Minimum basic salary');
COMMIT;
```

### Package: Session-এর শুরুতে লোড

```sql
CREATE OR REPLACE PACKAGE w19_setting_pkg
IS
    FUNCTION house_pct  RETURN NUMBER;
    FUNCTION medical    RETURN NUMBER;
    FUNCTION transport  RETURN NUMBER;
    FUNCTION month_days RETURN NUMBER;
    FUNCTION min_wage   RETURN NUMBER;

    FUNCTION  loaded_at RETURN DATE;
    PROCEDURE reload;
END w19_setting_pkg;
/

CREATE OR REPLACE PACKAGE BODY w19_setting_pkg
IS
    g_house_pct  NUMBER;
    g_medical    NUMBER;
    g_transport  NUMBER;
    g_month_days NUMBER;
    g_min_wage   NUMBER;
    g_loaded_at  DATE;

    ---------------- Private ----------------
    FUNCTION read_setting (p_code IN VARCHAR2) RETURN NUMBER
    IS
        v_val w19_payroll_setting.setting_value%TYPE;
    BEGIN
        SELECT setting_value INTO v_val
        FROM   w19_payroll_setting
        WHERE  setting_code = p_code;
        RETURN v_val;
    EXCEPTION
        WHEN NO_DATA_FOUND THEN
            RAISE_APPLICATION_ERROR(-20909, 'Payroll setting ' || p_code || ' is missing');
    END read_setting;

    PROCEDURE load
    IS
    BEGIN
        g_house_pct  := read_setting('HOUSE_PCT');
        g_medical    := read_setting('MEDICAL');
        g_transport  := read_setting('TRANSPORT');
        g_month_days := read_setting('MONTH_DAYS');
        g_min_wage   := read_setting('MIN_WAGE');
        g_loaded_at  := SYSDATE;
    END load;

    ---------------- Public ----------------
    FUNCTION house_pct  RETURN NUMBER IS BEGIN RETURN g_house_pct;  END house_pct;
    FUNCTION medical    RETURN NUMBER IS BEGIN RETURN g_medical;    END medical;
    FUNCTION transport  RETURN NUMBER IS BEGIN RETURN g_transport;  END transport;
    FUNCTION month_days RETURN NUMBER IS BEGIN RETURN g_month_days; END month_days;
    FUNCTION min_wage   RETURN NUMBER IS BEGIN RETURN g_min_wage;   END min_wage;
    FUNCTION loaded_at  RETURN DATE   IS BEGIN RETURN g_loaded_at;  END loaded_at;

    PROCEDURE reload IS
    BEGIN
        load;
    END reload;

BEGIN
    load;          -- Initialization
END w19_setting_pkg;
/
```

```sql
SELECT w19_setting_pkg.medical, w19_setting_pkg.min_wage FROM dual;     -- 750, 8000
```

- Function গুলো Parameter ছাড়া, তাই SQL-এ বন্ধনী ছাড়াই লেখা যায় (`w19_setting_pkg.medical`)
- `load` Private, Initialization আর `reload` দুই জায়গা থেকে ডাকা
- সেটিং না থাকলে পরিষ্কার এরর (`-20909`), চুপচাপ NULL না

### Gross এখন টেবিলের নিয়মে

```sql
CREATE OR REPLACE FUNCTION w19_gross (p_basic IN NUMBER) RETURN NUMBER
IS
BEGIN
    RETURN p_basic
         + p_basic * w19_setting_pkg.house_pct
         + w19_setting_pkg.medical
         + w19_setting_pkg.transport;
END w19_gross;
/

SELECT SUM(w19_gross(basic_salary)) FROM w16_emp WHERE status = 'ACTIVE';     -- 178800
```

## ৩. Cache আর টেবিলের বদল (৩০ মিনিট)

### কেন প্রতিবার টেবিল পড়ি না?

`w19_gross` স্যালারি শিটে ৫০০০ কর্মচারীর জন্য চলবে, প্রতিজনে ৩টা সেটিং। প্রতিবার টেবিল পড়লে ১৫০০০ বাড়তি Query। Package Variable-এ একবার লোড করে রাখলে ৫টা Query, বাকিটা মেমোরি থেকে।

একে বলে **Cache**: ধীর জায়গা (টেবিল) থেকে একবার এনে দ্রুত জায়গায় (মেমোরি) রাখা।

### দাম: পুরনো মান

HR চিকিৎসা ভাতা বাড়াল:

```sql
UPDATE w19_payroll_setting SET setting_value = 1000, updated_at = SYSDATE
WHERE  setting_code = 'MEDICAL';
COMMIT;

SELECT w19_setting_pkg.medical FROM dual;       -- 750! পুরনো
```

তোমার Session আগেই লোড করেছিল। টেবিল বদলেছে, Cache জানে না।

| উপায় | কী করে |
|---|---|
| `EXEC w19_setting_pkg.reload;` | এই Session-এ আবার লোড |
| নতুন Session (Disconnect/Connect) | নতুন Session, নতুন Initialization |
| `EXEC DBMS_SESSION.RESET_PACKAGE;` | এই Session-এর **সব** Package-এর মান মুছে দেয়, পরের কলে সব আবার Initialize |

```sql
EXEC w19_setting_pkg.reload;
SELECT w19_setting_pkg.medical FROM dual;       -- 1000
```

`RESET_PACKAGE` চলমান কল শেষ হওয়ার পরে কাজ করে, আর অন্য Package-এর Variable-ও (যেমন `w19_counter_pkg`-এর `hits`) মুছে দেয়। সাবধানে।

**আসল প্রজেক্টে:** সেটিং বদলানোর APEX পেজ সেভের পরে `reload` ডাকে। অন্য ব্যবহারকারীদের Session পরে নতুন করে লোড হয় (APEX-এ সাধারণত দ্রুতই হয়)। স্যালারি প্রসেসের Procedure শুরুতে নিজে একবার `reload` ডাকলে নিশ্চিত হয় সর্বশেষ নিয়ম ব্যবহার হচ্ছে।

ফিরিয়ে দাও:

```sql
UPDATE w19_payroll_setting SET setting_value = 750 WHERE setting_code = 'MEDICAL';
COMMIT;
EXEC w19_setting_pkg.reload;
```

## ৪. সাবধানতা (২০ মিনিট)

### Initialization-এ এরর

```sql
DELETE FROM w19_payroll_setting WHERE setting_code = 'MIN_WAGE';
COMMIT;
```

নতুন Session-এ:

```sql
SELECT w19_setting_pkg.medical FROM dual;
-- ORA-20909: Payroll setting MIN_WAGE is missing
```

`medical` চাইছিলাম, কিন্তু Initialization পুরোটা চলে, আর `MIN_WAGE`-এ আটকে যায়। একটা সেটিং না থাকলে পুরো Package অচল।

আরো বড় ফাঁদ: Initialization একবার ব্যর্থ হলে Oracle অনেক ক্ষেত্রে পরের কলে সেটা **আবার চালায় না**। তখন Variable NULL থেকে যায়, আর কোনো এরর ছাড়াই ভুল হিসাব: Gross-এ চিকিৎসা NULL, পুরো Gross NULL।

**নিয়ম:**
1. Initialization ছোট আর নিরাপদ রাখো
2. Getter-এ NULL যাচাই:

```sql
FUNCTION min_wage RETURN NUMBER IS
BEGIN
    IF g_min_wage IS NULL THEN
        load;                        -- আবার চেষ্টা; না পেলে load নিজে এরর দেবে
    END IF;
    RETURN g_min_wage;
END min_wage;
```

3. সেটিং টেবিলের রো মোছা বন্ধ রাখো (APEX পেজে শুধু Edit, Delete না)

ফিরিয়ে দাও:

```sql
INSERT INTO w19_payroll_setting (setting_code, setting_value, description)
VALUES ('MIN_WAGE', 8000, 'Minimum basic salary');
COMMIT;
```

### Initialization-এ কী রাখবে না

| রাখো | রেখো না |
|---|---|
| সেটিং পড়া | `INSERT`/`UPDATE`/`COMMIT` |
| ছোট হিসাব | লম্বা Query (Session-এর প্রথম কল ধীর হবে) |
| | `DBMS_OUTPUT` (ডেমো ছাড়া), APEX-এ কেউ দেখে না |

## ৫. হাতে-কলমে প্র্যাকটিস (৬০ মিনিট)

সব `learn_freepdb1`-এ।

1. `w19_init_demo_pkg` বানাও। দুইবার `hello`, `>> initializing` কয়বার? নতুন Unshared Worksheet-এ আবার।
2. `w19_init_demo_pkg`-এর Body আবার Compile করে পুরনো Worksheet-এ `hello`। কী হয়? (`ORA-04068`, তারপর আবার Initialize)
3. `w19_payroll_setting` বানাও, ৫টা রো।
4. `w19_setting_pkg` বানাও। SQL থেকে ৫টা মান আর `loaded_at`।
5. `w19_gross` বানাও, মোট মিলাও। (১৭৮৮০০)
6. চিকিৎসা ১০০০ করো (`COMMIT`)। `w19_gross(11000)` এখনো কত? (১৭৭০০) `reload`, আবার? (১৭৯৫০) মোট এখন? (১৮১০৫০) ফিরিয়ে ৭৫০ করো, `reload`।
7. একটা দ্বিতীয় Worksheet খোলা রেখে ৬ করো। দ্বিতীয়টায় `w19_gross(11000)` কত দেখায়? কখন বদলাবে?
8. `DBMS_SESSION.RESET_PACKAGE` চালিয়ে `w19_counter_pkg.hits` (ক্লাস ৯৩) দেখো। কী হলো?

10. Getter-গুলোতে NULL যাচাই যোগ করো (ক্লাসের মতো)। ৯ আবার করো। `MIN_WAGE` ফিরিয়ে দাও।
11. নতুন সেটিং `ATTEND_BONUS` (৫০০) যোগ করো: টেবিলে রো, Package-এ Variable, Getter, `load`-এ পড়া। সপ্তাহ ১৬ প্র্যাকটিস ১৫-এর হাজিরা বোনাস SQL-এ: যাদের অনুপস্থিতি ০, তাদের মোট বোনাস। (৩০০০)

## ৭. কুইজ

1. Initialization অংশ কোথায় লেখা হয়?
2. কখন চলে?
3. সেটিং টেবিল বদলালে চলমান Session কি নতুন মান পায়?
4. এক Session-এর সব Package-এর মান মুছতে কী চালাও?
5. Initialization ব্যর্থ হলে কী বিপদ?

<details>
<summary>উত্তর দেখো</summary>

1. Body-র শেষে, `END pkg;`-এর আগে `BEGIN` দিয়ে
2. Session-এ প্রথমবার Package ছোঁয়ার সময়, একবার
3. না, `reload` বা নতুন Session লাগে
4. `DBMS_SESSION.RESET_PACKAGE`
5. Variable NULL থেকে যেতে পারে, পরে এরর ছাড়াই ভুল হিসাব

</details>

## সারাংশ

- Body-র শেষের `BEGIN ... END pkg;` প্রতি Session-এ একবার চলে
- নিয়ম কোড থেকে সেটিং টেবিলে, Session-এর শুরুতে Package Variable-এ লোড (Cache)
- টেবিল বদলালে Cache পুরনো, `reload` বা নতুন Session
- Initialization ছোট রাখো, সেটিং না পেলে পরিষ্কার এরর, Getter-এ NULL যাচাই
- Initialization-এ DML বা `COMMIT` না

**পরের ক্লাস (বুধবার):** ভালো Package ডিজাইন: এক Package এক কাজ, Spec স্থির রাখা, Utility Package।
