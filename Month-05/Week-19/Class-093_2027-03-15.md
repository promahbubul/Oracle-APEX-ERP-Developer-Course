## ১. Package Variable (৪০ মিনিট)

Procedure-এর ভেতরের Variable Procedure শেষ হলেই মুছে যায়। প্রতিবার নতুন করে শুরু।

Package-এর Body-তে (কোনো Procedure-এর বাইরে) ঘোষণা করা Variable **Session শেষ না হওয়া পর্যন্ত** থাকে।

```sql
CREATE OR REPLACE PACKAGE w19_counter_pkg
IS
    PROCEDURE hit;
    FUNCTION  hits RETURN NUMBER;
    PROCEDURE reset;
END w19_counter_pkg;
/

CREATE OR REPLACE PACKAGE BODY w19_counter_pkg
IS
    g_hits NUMBER := 0;          -- Package Variable (Private)

    PROCEDURE hit IS
    BEGIN
        g_hits := g_hits + 1;
    END hit;

    FUNCTION hits RETURN NUMBER IS
    BEGIN
        RETURN g_hits;
    END hits;

    PROCEDURE reset IS
    BEGIN
        g_hits := 0;
    END reset;
END w19_counter_pkg;
/
```

```sql
SET SERVEROUTPUT ON

EXEC w19_counter_pkg.hit;
EXEC w19_counter_pkg.hit;
EXEC w19_counter_pkg.hit;

BEGIN
    DBMS_OUTPUT.PUT_LINE(w19_counter_pkg.hits);      -- 3
END;
/
```

তিনটা আলাদা `EXEC`, তিনটা আলাদা ব্লক। তবু মান মনে আছে।

- নাম `g_` দিয়ে (Global), যাতে Local `v_` থেকে আলাদা চেনা যায়
- প্রথমবার Package ছোঁয়ার সময় `:= 0` বসে, তারপর আর না

### কাজের উদাহরণ: এই Session-এ কতগুলো ইস্যু

`w19_stock_pkg`-এর Body-তে:

```sql
g_issue_count NUMBER := 0;
g_issue_qty   NUMBER := 0;
```

`stock_issue`-এর শেষে:

```sql
g_issue_count := g_issue_count + 1;
g_issue_qty   := g_issue_qty + p_qty;
```

আর Spec-এ একটা রিপোর্ট:

```sql
PROCEDURE session_summary;
```

```sql
PROCEDURE session_summary IS
BEGIN
    DBMS_OUTPUT.PUT_LINE('This session: ' || g_issue_count || ' issue(s), ' || g_issue_qty || ' pcs');
END session_summary;
```

রাতের একটা Job ১০০০টা ইস্যু প্রসেস করল, শেষে সারাংশ। প্রতিটা ইস্যুর জন্য টেবিলে লেখা লাগল না।

### Public Variable: Spec-এ সরাসরি

```sql
CREATE OR REPLACE PACKAGE w19_bad_pkg
IS
    g_min_stock NUMBER := 20;
END w19_bad_pkg;
/

BEGIN
    w19_bad_pkg.g_min_stock := -999;      -- যে কেউ বদলাতে পারে!
END;
/
```

Spec-এ Variable রাখলে যে কেউ পড়তে আর **বদলাতে** পারে। কে কখন বদলাল, খুঁজে পাওয়া অসম্ভব।

**নিয়ম:** Variable Body-তে (Private), বাইরে থেকে লাগলে Function দিয়ে পড়ো (Getter), Procedure দিয়ে বদলাও (Setter), আর Setter-এ যাচাই রাখো।

```sql
PROCEDURE set_min_stock (p_value IN NUMBER) IS
BEGIN
    IF p_value IS NULL OR p_value < 0 THEN
        RAISE_APPLICATION_ERROR(-20908, 'Minimum stock cannot be negative');
    END IF;
    g_min_stock := p_value;
END set_min_stock;
```

Constant (`CONSTANT`) Spec-এ রাখা ঠিক আছে, কারণ কেউ বদলাতে পারে না (ক্লাস ৯২)।

## ২. Session আর তার ফাঁদ (২৫ মিনিট)

### প্রতিটা Session-এর আলাদা কপি

SQL Developer-এ একটা **Unshared Worksheet** (`Ctrl+Shift+N`) খোলো, সেটা আলাদা Session (ক্লাস ৮০)।

| | Worksheet A | Worksheet B |
|---|---|---|
| | `EXEC w19_counter_pkg.hit;` ×৩ | |
| | `hits` → **৩** | `hits` → **০** |
| | | `EXEC w19_counter_pkg.hit;` |
| | `hits` → ৩ | `hits` → **১** |

Package Variable কোনো টেবিলে না, প্রতিটা Session-এর নিজের মেমোরিতে। দুইজন ব্যবহারকারী একে অপরের মান দেখে না।

ভাগাভাগি করা মান (সবাই দেখবে) লাগলে **টেবিল**।

### ORA-04068

Worksheet A-তে `hits` ৩। এখন Body-তে ছোট বদল করে আবার Compile করো (যেকোনো Worksheet থেকে)। তারপর A-তে:

```sql
EXEC w19_counter_pkg.hit;
-- ORA-04068: existing state of packages has been discarded
-- ORA-04061: existing state of package body "LEARN.W19_COUNTER_PKG" has been invalidated
```

আবার চালাও: চলে, কিন্তু `hits` এখন ১, ৩ না।

Package Compile হলে চলমান সব Session-এর মান হারায়, আর প্রথম ডাকে এই এরর একবার আসে। লাইভ সিস্টেমে দিনের বেলা Package Compile করলে ব্যবহারকারীরা এটা দেখে। তাই বড় পরিবর্তন রাতে, বা ছুটির দিনে।

Package-এ কোনো Variable না থাকলে (শুধু Constant আর Procedure) এই এরর আসে না। আরেকটা কারণ Variable কম রাখার।

### APEX-এ সাবধান

APEX-এ প্রতিটা পেজ খোলা বা বাটন চাপা আলাদা রিকোয়েস্ট, আর রিকোয়েস্টগুলো আলাদা ডাটাবেস Session পেতে পারে। এক রিকোয়েস্টে Package Variable-এ রাখা মান পরের রিকোয়েস্টে থাকবে, **এর উপর ভরসা করবে না।** একই রিকোয়েস্টের ভেতরে (যেমন এক Process থেকে আরেক Process) চলে।

পেজ থেকে পেজে মান রাখতে APEX-এর নিজের Item আর Session State আছে (ক্লাস ১৪৫)।

### কোথায় মান রাখবে

| দরকার | কোথায় |
|---|---|
| এক Procedure চলাকালীন | Local Variable (`v_`) |
| এক Session-এ কয়েকটা কলের মাঝে | Package Variable (`g_`), Body-তে |
| কখনো বদলায় না | Constant (`c_`), Spec বা Body-তে |
| সবাই দেখবে, স্থায়ী | টেবিল |

## ৩. Overloading (৪০ মিনিট)

Oracle নিজেই করে:

```sql
SELECT TO_CHAR(16967),           TO_CHAR(SYSDATE, 'DD-Mon-YYYY')  FROM dual;
```

একই নাম `TO_CHAR`, একবার সংখ্যা, একবার তারিখ। আসলে দুইটা আলাদা Function, Oracle Parameter-এর ধরন দেখে ঠিকটা বেছে নেয়।

**Overloading:** একই Package-এ একই নামে কয়েকটা Procedure/Function, Parameter আলাদা।

### কর্মচারী খোঁজা: ID দিয়ে বা নাম দিয়ে

```sql
CREATE OR REPLACE PACKAGE w19_hr_pkg
IS
    -- আগের সব (emp_name, gross, show_emp ...) এখানে থাকবে

    PROCEDURE find_emp (p_emp_id   IN NUMBER);
    PROCEDURE find_emp (p_emp_name IN VARCHAR2);
END w19_hr_pkg;
/
```

Body-তে দুইটা আলাদা কোড:

```sql
    PROCEDURE find_emp (p_emp_id IN NUMBER)
    IS
        r w16_emp%ROWTYPE;
    BEGIN
        SELECT * INTO r FROM w16_emp WHERE emp_id = p_emp_id;
        DBMS_OUTPUT.PUT_LINE(r.emp_id || ': ' || r.emp_name || ', ' || r.dept_name || ', ' || r.basic_salary);
    EXCEPTION
        WHEN NO_DATA_FOUND THEN
            RAISE_APPLICATION_ERROR(-20201, 'Employee ' || p_emp_id || ' not found');
    END find_emp;

    PROCEDURE find_emp (p_emp_name IN VARCHAR2)
    IS
        v_cnt NUMBER := 0;
    BEGIN
        FOR r IN (SELECT emp_id FROM w16_emp
                  WHERE  UPPER(emp_name) LIKE '%' || UPPER(p_emp_name) || '%'
                  ORDER  BY emp_id)
        LOOP
            find_emp(r.emp_id);             -- সংখ্যা দিয়ে ডাকা, তাই প্রথমটা চলে
            v_cnt := v_cnt + 1;
        END LOOP;
        IF v_cnt = 0 THEN
            DBMS_OUTPUT.PUT_LINE('No employee matching ' || p_emp_name);
        END IF;
    END find_emp;
```

```sql
EXEC w19_hr_pkg.find_emp(3);          -- 3: Salma, Sewing, 11000
EXEC w19_hr_pkg.find_emp('ha');       -- Habib (আর নামে "ha" থাকা যে কেউ)
EXEC w19_hr_pkg.find_emp('Salma');    -- 3: Salma, ...
```

কলকারীকে দুইটা নাম মনে রাখতে হয় না (`find_emp_by_id`, `find_emp_by_name`)। একটা নাম, যা আছে তাই দাও।

### সংখ্যার Parameter আলাদা

```sql
-- মাসের নাম: তারিখ দিয়ে বা 'YYYY-MM' দিয়ে
FUNCTION month_label (p_date  IN DATE)     RETURN VARCHAR2;
FUNCTION month_label (p_month IN VARCHAR2) RETURN VARCHAR2;

-- স্যালারি: শুধু Basic, বা Basic + অনুপস্থিতি
FUNCTION net (p_basic IN NUMBER) RETURN NUMBER;
FUNCTION net (p_basic IN NUMBER, p_days IN NUMBER) RETURN NUMBER;
```

দ্বিতীয় জোড়া সংখ্যায় আলাদা। অবশ্য এখানে Default (`p_days DEFAULT 0`) দিয়েই একটা Function-এ হয়ে যেত। Default দিয়ে হলে Default ভালো, Overloading তখন যখন কাজের ধরনই আলাদা (যেমন ID দিয়ে খোঁজা বনাম নাম দিয়ে খোঁজা)।

## ৪. Overloading-এর নিয়ম (১৫ মিনিট)

| ভালো Overload | এড়িয়ে চলো |
|---|---|
| Parameter-এর **ধরন** আলাদা পরিবারের (`NUMBER` বনাম `VARCHAR2` বনাম `DATE`) | শুধু Parameter-এর **নাম** আলাদা |
| Parameter-এর **সংখ্যা** আলাদা (Default ছাড়া) | শুধু **Mode** আলাদা (`IN` বনাম `OUT`) |
| | শুধু **RETURN ধরন** আলাদা |
| | একই পরিবারের ধরন (`NUMBER` বনাম `INTEGER`) |

ডান দিকেরগুলো অনেক সময় Compile হয়ে যায়, কিন্তু ডাকার সময় Oracle ঠিক করতে পারে না কোনটা। শুধু নাম আলাদা হলে Named Notation (`find_emp(p_a => 1)`) দিয়ে ডাকা যায়, Positional দিলে এরর। এমন Package বিভ্রান্তিকর, বানিও না।

দ্বিধা হলে ডাকার সময়:

```
PLS-00307: too many declarations of 'X' match this call
```

### Default দিয়ে দ্বিধা

```sql
PROCEDURE show (p_id IN NUMBER);
PROCEDURE show (p_id IN NUMBER, p_detail IN VARCHAR2 DEFAULT 'N');

show(5);      -- PLS-00307: দুইটাই মেলে
```

### শুধু Package-এ (আর Local)

```sql
CREATE OR REPLACE PROCEDURE w19_x (p IN NUMBER) IS BEGIN NULL; END;
/
CREATE OR REPLACE PROCEDURE w19_x (p IN VARCHAR2) IS BEGIN NULL; END;
/
```

এরর আসে না! দ্বিতীয়টা প্রথমটাকে **বদলে দেয়** (`OR REPLACE`)। Standalone Procedure-এ Overloading হয় না, একটা নামে একটাই অবজেক্ট। Package-এর ভেতরে, বা কোনো ব্লকের ভেতরের Local Procedure-এ হয়।

```sql
        payslip(v_id, p_month);
    EXCEPTION
        WHEN NO_DATA_FOUND THEN
            RAISE_APPLICATION_ERROR(-20201, 'No employee named ' || p_emp_name);
        WHEN TOO_MANY_ROWS THEN
            RAISE_APPLICATION_ERROR(-20206, 'Several employees named ' || p_emp_name || ', use ID');
    END payslip;
```

`payslip(v_id, p_month)`-এর `v_id` সংখ্যা, তাই Oracle প্রথম `payslip` বেছে নেয়।

`emp_name` আর `month_label` একই Package-এ, তাই নাম ছাড়াই ডাকা যায়। তবে Body-তে এগুলো `payslip`-এর আগে লেখা থাকুক, অথবা Spec-এ থাকুক (তাহলে ক্রম যেকোনো)। এখানে দুইটাই Public, তাই সমস্যা নেই।

**উত্তর:**

- **৩:** `ORA-04068`, দ্বিতীয়বার ঠিক চলে, মান শুরু থেকে
- **৪:** `ROLLBACK` টেবিলের বদল ফেরায়, Package Variable-কে না। সারাংশ বলে ৩টা ইস্যু, অথচ টেবিলে কিছুই নেই
- **৫:** Package Variable আর টেবিল আলাদা হয়ে যেতে পারে, তাই গুরুত্বপূর্ণ হিসাব (স্টক, টাকা) সবসময় টেবিল থেকে, Package Variable শুধু সুবিধার জন্য
- **৯:** `PLS-00307` (ডাকার সময়)
- **১০:** Spec সম্ভবত Compile হবে, কিন্তু `find_emp(5)` দিলে `PLS-00307`। `find_emp(p_a => 5)` চলে। কাজের না, শুধু বিভ্রান্তি
- **১১:** একটাই, শেষেরটা (`VARCHAR2`)

</details>

## সারাংশ

- Body-র Procedure-এর বাইরে ঘোষণা করা Variable Session জুড়ে থাকে, প্রতিটা Session-এর আলাদা
- Variable Private রাখো, Getter/Setter দিয়ে পড়ো-বদলাও
- Package Variable `ROLLBACK`-এ ফেরে না, Compile-এ হারায় (`ORA-04068`), APEX-এ রিকোয়েস্ট পেরিয়ে ভরসা নেই
- Overloading: একই নাম, Parameter-এর ধরন বা সংখ্যা আলাদা
- শুধু নাম, Mode বা RETURN আলাদা হলে চলে না; দ্বিধা হলে `PLS-00307`
- Default দিয়ে হলে Default, কাজই আলাদা হলে Overloading

**পরের ক্লাস (মঙ্গলবার):** Package Initialization: Session-এর শুরুতে একবার সেটিং লোড করা।
