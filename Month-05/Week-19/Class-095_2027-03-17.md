# ক্লাস ৯৫: ভালো Package ডিজাইন

**তারিখ:** ১৭ মার্চ ২০২৭, বুধবার
**সময়:** সন্ধ্যা ৭:০০ থেকে রাত ১০:০০
**সপ্তাহ:** ১৯ | **ধাপ:** ৩ (PL/SQL)

---

## আজকে কী শিখব

- এক Package এক মডিউল
- Spec স্থির, Body স্বাধীন: Body বদলালে কিছু ভাঙে না
- Utility Package: সবার কাজে লাগা জিনিস এক জায়গায়
- Package-দের স্তর, আর বৃত্তাকার নির্ভরতা এড়ানো
- ভালো Package-এর চেকলিস্ট

---

## ১. এক Package এক মডিউল (৩০ মিনিট)

### খারাপ: সব এক Package-এ

```
w19_erp_pkg
    stock_issue, stock_receive, gross, payslip, issue_book,
    return_book, log_error, month_label, process_payroll, ...
```

৫০০০ লাইনের এক Package:
- কেউ স্টকে একটা ছোট বদল করল, Compile হলো, আর সবার Session-এ `ORA-04068`, Payroll আর Library-র ব্যবহারকারীদেরও
- একসাথে দুইজন ডেভেলপার কাজ করতে পারে না, দুইজনই একই Body বদলাচ্ছে
- `GRANT EXECUTE` দিলে স্টোরকিপার Payroll-ও চালাতে পারে

### খারাপ: অসংখ্য ছোট Package

```
w19_stock_issue_pkg (১টা Procedure)
w19_stock_receive_pkg (১টা Procedure)
w19_stock_balance_pkg (১টা Function)
```

Package-এর কোনো লাভ নেই, আগের ছড়ানো Procedure-এর মতোই।

### ভালো: মডিউল ধরে

| Package | কী থাকে | কে ব্যবহার করে |
|---|---|---|
| `w19_util_pkg` | লগ, যাচাই, তারিখের সাহায্য | সব Package |
| `w19_setting_pkg` | সেটিং পড়া | Payroll |
| `w19_stock_pkg` | স্টক Receive, Issue, Transfer, Balance | Store, APEX-এর স্টক পেজ |
| `w19_hr_pkg` | কর্মচারীর তথ্য খোঁজা | HR, Payroll |
| `w19_payroll_pkg` | স্যালারি হিসাব, প্রসেস, Payslip | Payroll (কাল) |

**প্রশ্ন করো:** "এই Procedure কোন বিভাগের লোক চাইবে?" সেই বিভাগের Package-এ।

## ২. Spec স্থির, Body স্বাধীন (৩৫ মিনিট)

এটাই Package-এর সবচেয়ে বড় সুবিধা, আজ নিজে দেখো।

একটা Standalone Procedure যা Package ব্যবহার করে:

```sql
CREATE OR REPLACE PROCEDURE w19_low_stock_alert
IS
BEGIN
    FOR r IN (SELECT item_id, item_name FROM w14_stock ORDER BY item_id) LOOP
        IF w19_stock_pkg.is_low_stock(r.item_id) = 'Y' THEN
            DBMS_OUTPUT.PUT_LINE('LOW: ' || r.item_name || ' (' || w19_stock_pkg.stock_balance(r.item_id) || ')');
        END IF;
    END LOOP;
END w19_low_stock_alert;
/

SELECT object_name, object_type, status FROM user_objects
WHERE  object_name IN ('W19_STOCK_PKG', 'W19_LOW_STOCK_ALERT');
-- সব VALID
```

### পরীক্ষা ১: শুধু Body বদলাও

Body-তে `stock_balance`-এর ভেতরে একটা কমেন্ট যোগ করো, বা Error-এর বার্তা বদলাও। `CREATE OR REPLACE PACKAGE BODY ...` চালাও।

```sql
SELECT object_name, object_type, status FROM user_objects
WHERE  object_name IN ('W19_STOCK_PKG', 'W19_LOW_STOCK_ALERT');
-- W19_LOW_STOCK_ALERT  VALID   ← কিছুই হয়নি!
```

কলকারী নির্ভর করে **Spec**-এর উপর, Body-র উপর না। Body-তে যা খুশি বদলাও (ভুল ঠিক করা, দ্রুত করা, নতুন Private Procedure), যতক্ষণ Spec একই, বাইরের কেউ টের পায় না।

ছড়ানো Standalone Function (`w18_stock_balance`) বদলালে তার সব কলকারী INVALID হতো (ক্লাস ৮৯)।

### পরীক্ষা ২: Spec-এর ব্যবহৃত অংশ বদলাও

Spec-এ `is_low_stock`-এর `p_min`-এর ধরন `NUMBER` থেকে `PLS_INTEGER` করো (আর Body-তেও), দুইটা Compile করো।

```sql
-- W19_LOW_STOCK_ALERT  INVALID
```

কলকারী যে জিনিস ব্যবহার করে, সেটা বদলেছে। পরের বার ডাকলে Oracle নিজে Compile করার চেষ্টা করবে (ক্লাস ৮৯)। ফিরিয়ে দাও।

### পরীক্ষা ৩: Spec-এ নতুন কিছু যোগ করো

Spec-এর শেষে একটা নতুন Function `item_name(p_item_id) RETURN VARCHAR2` যোগ করো (Body-তেও)।

```sql
-- W19_LOW_STOCK_ALERT  VALID (Oracle 11g থেকে)
```

Oracle দেখে কলকারী নতুন জিনিসটা ব্যবহার করে না, তাই INVALID করে না।

### ফলাফল

| বদল | কলকারী |
|---|---|
| শুধু Body | **VALID** |
| Spec-এ নতুন কিছু যোগ | সাধারণত VALID |
| Spec-এ কলকারী যা ব্যবহার করে তা বদল | INVALID |

**নিয়ম:** Spec একটা চুক্তি। যোগ করো, কিন্তু যা আছে তা বদলিও না (ক্লাস ৯০-এর নিয়ম Package-এও)। Body যত খুশি বদলাও।

## ৩. Utility Package আর স্তর (৩৫ মিনিট)

সপ্তাহ ১৭ থেকে প্রতিটা Procedure-এ এই কোড:

```sql
EXCEPTION
    WHEN OTHERS THEN
        v_code := SQLCODE;
        v_msg  := SQLERRM;
        v_bt   := DBMS_UTILITY.FORMAT_ERROR_BACKTRACE;
        ...
```

আর এই:

```sql
IF p_qty IS NULL OR p_qty <= 0 THEN
    RAISE_APPLICATION_ERROR(-20002, '...');
END IF;
```

সব মডিউলে কাজে লাগা জিনিস এক Package-এ।

```sql
CREATE OR REPLACE PACKAGE w19_util_pkg
IS
    -- অপ্রত্যাশিত এরর w17_error_log-এ লেখে। Handler-এর ভেতর থেকে ডাকো।
    -- COMMIT করে না (ক্লাস ১০৭-এ Autonomous হবে)।
    PROCEDURE log_error (
        p_module  IN VARCHAR2,
        p_code    IN NUMBER,
        p_msg     IN VARCHAR2,
        p_bt      IN VARCHAR2 DEFAULT NULL,
        p_context IN VARCHAR2 DEFAULT NULL
    );

    -- শর্ত মিথ্যা বা NULL হলে RAISE_APPLICATION_ERROR(p_code, p_msg)
    PROCEDURE assert (
        p_condition IN BOOLEAN,
        p_code      IN PLS_INTEGER,
        p_msg       IN VARCHAR2
    );

    -- ব্যবসার নিয়মের এরর (-20000 থেকে -20999)?
    FUNCTION is_business_error (p_code IN NUMBER) RETURN BOOLEAN;

    -- 'YYYY-MM' → 'January 2027'
    FUNCTION month_label (p_month IN VARCHAR2) RETURN VARCHAR2;
END w19_util_pkg;
/

CREATE OR REPLACE PACKAGE BODY w19_util_pkg
IS
    PROCEDURE log_error (
        p_module  IN VARCHAR2,
        p_code    IN NUMBER,
        p_msg     IN VARCHAR2,
        p_bt      IN VARCHAR2 DEFAULT NULL,
        p_context IN VARCHAR2 DEFAULT NULL
    )
    IS
    BEGIN
        INSERT INTO w17_error_log (module_name, error_code, error_msg, backtrace, context_info)
        VALUES (SUBSTR(p_module, 1, 50), p_code, SUBSTR(p_msg, 1, 4000),
                SUBSTR(p_bt, 1, 4000), SUBSTR(p_context, 1, 400));
    END log_error;

    PROCEDURE assert (
        p_condition IN BOOLEAN,
        p_code      IN PLS_INTEGER,
        p_msg       IN VARCHAR2
    )
    IS
    BEGIN
        IF p_condition IS NULL OR NOT p_condition THEN
            RAISE_APPLICATION_ERROR(p_code, p_msg);
        END IF;
    END assert;

    FUNCTION is_business_error (p_code IN NUMBER) RETURN BOOLEAN
    IS
    BEGIN
        RETURN p_code BETWEEN -20999 AND -20000;
    END is_business_error;

    FUNCTION month_label (p_month IN VARCHAR2) RETURN VARCHAR2
    IS
    BEGIN
        RETURN TO_CHAR(TO_DATE(p_month || '-01', 'YYYY-MM-DD'), 'fmMonth YYYY', 'NLS_DATE_LANGUAGE=ENGLISH');
    END month_label;
END w19_util_pkg;
/
```

### assert দিয়ে যাচাই এক লাইনে

```sql
w19_util_pkg.assert(p_qty > 0, c_err_bad_qty, 'Quantity must be more than zero');
w19_util_pkg.assert(p_qty <= p_max_issue, c_err_need_approval, 'Issue of ' || p_qty || ' needs approval');
```

`p_qty` NULL হলে `p_qty > 0` NULL, আর `assert` NULL-কেও ব্যর্থ ধরে। তাই আলাদা `IS NULL` লাগে না।

`assert`-এর `BOOLEAN` Parameter থাকায় এটা শুধু PL/SQL থেকে ডাকা যায়, SQL থেকে না। ঠিক আছে, যাচাই PL/SQL-এরই কাজ।

### স্তর

```
          APEX পেজ, রাতের Job
                 │
   ┌─────────────┼──────────────┐
w19_stock_pkg  w19_payroll_pkg  w19_library_pkg      ← ব্যবসার Package
   │             │      │
   │        w19_hr_pkg  w19_setting_pkg              ← সাহায্যকারী
   │             │      │
   └─────── w19_util_pkg ┘                           ← সবার নিচে
```

**নিয়ম:** উপরের স্তর নিচের স্তরকে ডাকে, উল্টো না। `w19_util_pkg` কখনো `w19_stock_pkg` ডাকবে না।

### বৃত্তাকার নির্ভরতা

`w19_stock_pkg`-এর Spec যদি `w19_hr_pkg`-এর Spec-এর কোনো ধরন ব্যবহার করে, আর `w19_hr_pkg`-এর Spec আবার `w19_stock_pkg`-এর, তাহলে কোনটা আগে Compile হবে? কোনোটাই না।

Body থেকে Body ডাকা Oracle মেনে নেয় (Body নির্ভর করে শুধু অন্যের Spec-এর উপর)। কিন্তু ডিজাইনে বৃত্ত মানে দুইটা Package আসলে একটাই কাজ করছে, বা ভুল জায়গায় কিছু আছে। স্তর মানলে বৃত্ত হয় না।

## ৪. চেকলিস্ট (২০ মিনিট)

নতুন Package বানানোর পরে নিজেকে জিজ্ঞেস করো:

**Spec:**
- [ ] নাম মডিউল বোঝায় (`stock`, `payroll`), শেষে `_pkg`
- [ ] প্রতিটা Public Procedure/Function-এর উপরে এক লাইনের কমেন্ট: কী করে, কোন এরর দেয়
- [ ] শুধু যা বাইরের কারো লাগে, বাকি সব Private
- [ ] কোনো Public Variable নেই (Constant ঠিক আছে)
- [ ] এরর নম্বরের Constant আর Exception (`PRAGMA` সহ) Spec-এর শুরুতে
- [ ] Parameter `%TYPE`, `p_` নাম, ঐচ্ছিক Default সহ শেষে

**Body:**
- [ ] Private Procedure শুরুতে, Public পরে
- [ ] কোনো `COMMIT`/`ROLLBACK` নেই (শুধু সবচেয়ে উপরের Job ছাড়া)
- [ ] কোনো `WHEN OTHERS THEN NULL` নেই
- [ ] ব্যবসার নিয়মে `RAISE_APPLICATION_ERROR` + Spec-এর Constant
- [ ] অপ্রত্যাশিত এরর `w19_util_pkg.log_error` দিয়ে লগ, তারপর `RAISE`
- [ ] Hard-coded সংখ্যা নেই, Constant বা সেটিং টেবিল

**ব্যবহার:**
- [ ] অন্য Package কে কে এটা ডাকে, `USER_DEPENDENCIES` দেখে নিয়েছি
- [ ] Spec-এর পুরনো কিছু বদলাইনি, শুধু যোগ করেছি
- [ ] APEX/ব্যবহারকারীকে শুধু এই Package-এর `EXECUTE`, টেবিলের না

এই চেকলিস্ট `week19.sql`-এর শুরুতে কপি করে রাখো। কালকের Payroll Package এটা দিয়ে মিলাবে।

## ৫. হাতে-কলমে প্র্যাকটিস (৬০ মিনিট)

সব `learn_freepdb1`-এ।

1. `w19_low_stock_alert` বানাও। ক্লাসের তিনটা পরীক্ষা করো, প্রতিবার `status` লেখো।
2. একই পরীক্ষা Standalone দিয়ে: `w18_stock_balance` (সপ্তাহ ১৮) শুধু ভেতরের কমেন্ট বদলে আবার `CREATE OR REPLACE`। তার কলকারী (`w18_is_low_stock`) কী হলো? Package-এর সাথে পার্থক্য লেখো।
3. `w19_util_pkg` বানাও। `assert(1 > 2, -20999, 'Test')`, `assert(NULL, -20999, 'Null')`, `assert(2 > 1, ...)` চালাও।
4. `w19_stock_pkg`-এর `check_qty`, সীমার যাচাই সব `w19_util_pkg.assert` দিয়ে লেখো। পরীক্ষা ঘ, চ (`issue(1, 0)`, `issue(1, 600)`) আবার চালাও, একই এরর?
5. `w19_stock_pkg.stock_issue`-এ `WHEN OTHERS` Handler: `is_business_error` হলে শুধু `RAISE`, না হলে `log_error` তারপর `RAISE`। (`ROLLBACK`/`COMMIT` কলকারীর হাতে, ক্লাস ৮৯।) ইচ্ছা করে ভাগে ০ দিয়ে পরীক্ষা করো, তারপর কলকারী ব্লকে `ROLLBACK` আর লগ `COMMIT` কীভাবে করবে ভাবো।
6. `w19_hr_pkg`-এর `month_label` সরিয়ে `w19_util_pkg.month_label` ব্যবহার করো। `w19_hr_pkg`-এর কলকারী কেউ `month_label` ব্যবহার করছিল? `USER_DEPENDENCIES` দিয়ে দেখো আগে।
7. স্তরের ছবিটা তোমার এই সপ্তাহের সব Package দিয়ে আঁকো। কোনো তীর কি উপরের দিকে যাচ্ছে?
8. `USER_DEPENDENCIES` থেকে এই সপ্তাহের Package-দের পরস্পর নির্ভরতা: কে কাকে ডাকে।
9. `w19_stock_pkg`-কে চেকলিস্ট দিয়ে মিলাও। কয়টা টিক পড়ল? বাকিগুলো ঠিক করো।
10. **কালকের প্রস্তুতি:** `w19_payroll_pkg`-এর **শুধু Spec** লেখো, Body না: Constant (এরর `-20201` থেকে `-20206`), Exception, আর এই Public গুলোর মাথা: `gross`, `deduction`, `net`, `check_emp`, `process_emp`, `process_month (p_month, p_dept DEFAULT NULL)`, `payslip` (দুইটা Overload), `dept_report`, `month_total`। প্রতিটার উপরে কমেন্ট। কাল Body।

Handler-এর ভেতরে ছোট `DECLARE ... BEGIN ... END`: Handler-এ ঢুকেই মান তুলে রাখার একটা পরিষ্কার উপায়, আলাদা Variable উপরে ঘোষণা করতে হয় না।

**সাবধান:** এখানে লগ `ROLLBACK` ছাড়া লেখা হয়েছে। এরর কলকারী পর্যন্ত গিয়ে না ধরা হলে Oracle পুরো Statement বাতিল করবে, **লগসহ**। লগ রাখতে কলকারী নিজে ধরবে, `ROLLBACK` করবে, আবার লগ লিখবে... জটিল। এই সমস্যার পরিষ্কার সমাধান ক্লাস ১০৭-এর Autonomous Transaction। ততদিন এই সীমাবদ্ধতা মেনে নাও।

**উত্তর:**

- **২:** `w18_stock_balance` বদলালে `w18_is_low_stock` INVALID (পরে ডাকলে নিজে Compile হয়)। Package-এ Body বদলালে কলকারী VALID-ই থাকে
- **৭:** `w19_util_pkg`-এর কোনো তীর উপরে যাওয়া উচিত না

</details>

## সারাংশ

- এক Package এক মডিউল, না খুব বড়, না খুব ছোট
- কলকারী Spec-এর উপর নির্ভর করে, Body বদলালে কিছু ভাঙে না
- Spec-এ শুধু যোগ, পুরনো বদল না
- সবার কাজের জিনিস (লগ, `assert`, তারিখ) Utility Package-এ, সবার নিচে
- স্তর মানো: উপর থেকে নিচে ডাকো, বৃত্ত বানাবে না
- চেকলিস্ট দিয়ে প্রতিটা Package মিলাও
