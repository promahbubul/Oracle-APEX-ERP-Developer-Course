# ক্লাস ৮৭: Parameter: IN, OUT, IN OUT

**তারিখ:** ৭ মার্চ ২০২৭, রবিবার
**সময়:** সন্ধ্যা ৭:০০ থেকে রাত ১০:০০
**সপ্তাহ:** ১৮ | **ধাপ:** ৩ (PL/SQL)

---

## আজকে কী শিখব

- `IN`: Procedure-এ মান পাঠানো
- `OUT`: Procedure থেকে মান ফেরত আনা
- `IN OUT`: পাঠানো, বদলানো, ফেরত
- Bind Variable দিয়ে পরীক্ষা: `VARIABLE`, `PRINT`
- Parameter-এর নিয়ম আর এরর

---

## ১. IN (৩০ মিনিট)

কালকের `w18_dept_staff (p_dept IN VARCHAR2)`-এ `IN` লিখেছিলে। মানে: **কলকারী মান দেয়, Procedure শুধু পড়ে।**

```sql
SET SERVEROUTPUT ON

CREATE OR REPLACE PROCEDURE w18_show_emp (
    p_emp_id IN w16_emp.emp_id%TYPE
)
IS
    v_name  w16_emp.emp_name%TYPE;
    v_dept  w16_emp.dept_name%TYPE;
BEGIN
    SELECT emp_name, dept_name INTO v_name, v_dept
    FROM   w16_emp
    WHERE  emp_id = p_emp_id;

    DBMS_OUTPUT.PUT_LINE(p_emp_id || ': ' || v_name || ' (' || v_dept || ')');
EXCEPTION
    WHEN NO_DATA_FOUND THEN
        RAISE_APPLICATION_ERROR(-20201, 'Employee ' || p_emp_id || ' not found');
END w18_show_emp;
/

EXEC w18_show_emp(3);       -- 3: Salma (Sewing)
EXEC w18_show_emp(99);      -- ORA-20201
```

- `IN` লেখা ঐচ্ছিক, না লিখলে Default `IN`। তবু লিখে রাখো, পড়তে সুবিধা
- ধরনে `%TYPE` দাও (ক্লাস ৬৮): কলাম বদলালে Parameter নিজে মানিয়ে নেয়
- সপ্তাহ ১৭-এর সব শেখা এখানে চলে: Handler, `RAISE_APPLICATION_ERROR`

### যেকোনো Expression দেওয়া যায়

```sql
DECLARE
    v_id NUMBER := 1;
BEGIN
    w18_show_emp(v_id);          -- Variable
    w18_show_emp(v_id + 4);      -- Expression: 5
    w18_show_emp(8);             -- সরাসরি মান
END;
/
```

### IN-এ মান বসানো যায় না

```sql
CREATE OR REPLACE PROCEDURE w18_bad_in (p_qty IN NUMBER)
IS
BEGIN
    p_qty := p_qty + 1;
END;
/
-- PLS-00363: expression 'P_QTY' cannot be used as an assignment target
```

বদলাতে চাইলে Local Variable-এ কপি করো:

```sql
IS
    v_qty NUMBER := p_qty;
BEGIN
    v_qty := v_qty + 1;
```

## ২. OUT (৪০ মিনিট)

`DBMS_OUTPUT` শুধু তুমি দেখো (ক্লাস ৮৪)। কলকারী, যেমন APEX পেজ, **মান** চায়: Salma-র নাম, Basic, বিভাগ। সেজন্য `OUT`।

```sql
CREATE OR REPLACE PROCEDURE w18_get_emp (
    p_emp_id  IN  w16_emp.emp_id%TYPE,
    p_name    OUT w16_emp.emp_name%TYPE,
    p_dept    OUT w16_emp.dept_name%TYPE,
    p_basic   OUT w16_emp.basic_salary%TYPE
)
IS
BEGIN
    SELECT emp_name, dept_name, basic_salary
    INTO   p_name, p_dept, p_basic
    FROM   w16_emp
    WHERE  emp_id = p_emp_id;
EXCEPTION
    WHEN NO_DATA_FOUND THEN
        RAISE_APPLICATION_ERROR(-20201, 'Employee ' || p_emp_id || ' not found');
END w18_get_emp;
/
```

Procedure নিজে কিছু ছাপায় না। মান ভরে দেয়, কলকারী যা খুশি করে।

### কল করা: Variable লাগবেই

```sql
DECLARE
    v_name  w16_emp.emp_name%TYPE;
    v_dept  w16_emp.dept_name%TYPE;
    v_basic w16_emp.basic_salary%TYPE;
BEGIN
    w18_get_emp(3, v_name, v_dept, v_basic);
    DBMS_OUTPUT.PUT_LINE(v_name || ', ' || v_dept || ', ' || v_basic);     -- Salma, Sewing, 11000
END;
/
```

`OUT`-এর জায়গায় সরাসরি মান দিলে কোথায় রাখবে? তাই:

```sql
w18_get_emp(3, 'X', v_dept, v_basic);
-- PLS-00363: expression 'X' cannot be used as an assignment target
```

### Bind Variable দিয়ে তাড়াতাড়ি পরীক্ষা

Block না লিখে SQL Developer-এ:

```sql
VARIABLE g_name  VARCHAR2(50)
VARIABLE g_dept  VARCHAR2(30)
VARIABLE g_basic NUMBER

EXEC w18_get_emp(9, :g_name, :g_dept, :g_basic);

PRINT g_name g_dept g_basic
```

পুরোটা সিলেক্ট করে `F5`। `:` দিয়ে Bind Variable। APEX-এর `:P10_EMP_NAME` এর আত্মীয়, সপ্তাহ ২৮-এ দেখবে।

### হিসাবের Procedure

সপ্তাহ ১৬-এর স্যালারির নিয়ম এক জায়গায়:

```sql
CREATE OR REPLACE PROCEDURE w18_calc_salary (
    p_basic       IN  NUMBER,
    p_absent_days IN  NUMBER,
    p_gross       OUT NUMBER,
    p_deduction   OUT NUMBER,
    p_net         OUT NUMBER
)
IS
    c_house_pct  CONSTANT NUMBER := 0.5;
    c_medical    CONSTANT NUMBER := 750;
    c_transport  CONSTANT NUMBER := 450;
    c_month_days CONSTANT NUMBER := 30;
BEGIN
    p_gross     := p_basic + p_basic * c_house_pct + c_medical + c_transport;
    p_deduction := ROUND(p_basic / c_month_days * NVL(p_absent_days, 0));
    p_net       := p_gross - p_deduction;
END w18_calc_salary;
/

DECLARE
    v_g NUMBER;
    v_d NUMBER;
    v_n NUMBER;
BEGIN
    w18_calc_salary(11000, 2, v_g, v_d, v_n);
    DBMS_OUTPUT.PUT_LINE(v_g || ' - ' || v_d || ' = ' || v_n);       -- 17700 - 733 = 16967
END;
/
```

এখন স্যালারি শিট, Payslip, বা "চাকরি ছাড়লে কত পাবে" সবাই একই নিয়ম ব্যবহার করবে। নিয়ম বদলালে (যেমন চিকিৎসা ভাতা ৭৫০ থেকে ১০০০) এক জায়গায় বদলাও।

### OUT ভেতরে শুরু হয় NULL দিয়ে

```sql
CREATE OR REPLACE PROCEDURE w18_out_test (p_val OUT NUMBER)
IS
BEGIN
    DBMS_OUTPUT.PUT_LINE('Inside: [' || p_val || ']');       -- [] মানে NULL
    p_val := 10;
END;
/

DECLARE
    v NUMBER := 99;
BEGIN
    w18_out_test(v);
    DBMS_OUTPUT.PUT_LINE('After: ' || v);                    -- 10
END;
/
```

কলকারীর ৯৯ Procedure দেখে না। `OUT` শুধু ফেরত দেওয়ার জন্য, নেওয়ার জন্য না। কোনো `OUT`-এ মান না বসালে কলকারী NULL পায়।

## ৩. IN OUT (২৫ মিনিট)

মান নিয়ে আসো, বদলাও, ফেরত দাও।

### কার্টনের হিসাবে পরিমাণ বাড়ানো

বায়ার ৫০ পিস চায়, কিন্তু কার্টনে ১২টা করে যায়। পুরো কার্টন পাঠাতে হবে।

```sql
CREATE OR REPLACE PROCEDURE w18_round_to_carton (
    p_qty      IN OUT NUMBER,
    p_per_ctn  IN     NUMBER
)
IS
BEGIN
    IF p_per_ctn IS NULL OR p_per_ctn <= 0 THEN
        RAISE_APPLICATION_ERROR(-20901, 'Pieces per carton must be more than zero');
    END IF;
    p_qty := CEIL(p_qty / p_per_ctn) * p_per_ctn;
END w18_round_to_carton;
/

DECLARE
    v_qty NUMBER := 50;
BEGIN
    w18_round_to_carton(v_qty, 12);
    DBMS_OUTPUT.PUT_LINE('Ship: ' || v_qty);          -- 60 (5 cartons)
END;
/
```

### মোবাইল নম্বর পরিষ্কার করা

```sql
CREATE OR REPLACE PROCEDURE w18_clean_mobile (p_mobile IN OUT VARCHAR2)
IS
BEGIN
    p_mobile := REPLACE(REPLACE(TRIM(p_mobile), '-', ''), ' ', '');
    IF p_mobile LIKE '+88%' THEN
        p_mobile := SUBSTR(p_mobile, 4);
    END IF;
END w18_clean_mobile;
/

DECLARE
    v_m VARCHAR2(20) := ' +88 01711-123456 ';
BEGIN
    w18_clean_mobile(v_m);
    DBMS_OUTPUT.PUT_LINE('[' || v_m || ']');          -- [01711123456]
END;
/
```

### তিনটার তুলনা

| | `IN` | `OUT` | `IN OUT` |
|---|---|---|---|
| কলকারীর মান ভেতরে আসে | হ্যাঁ | **না** (NULL) | হ্যাঁ |
| ভেতরে বদলানো যায় | **না** | হ্যাঁ | হ্যাঁ |
| বদল কলকারী পায় | — | হ্যাঁ | হ্যাঁ |
| কল করার সময় দিতে পারো | মান, Variable, Expression | শুধু Variable | শুধু Variable |
| Default মান দেওয়া যায় (ক্লাস ৯০) | হ্যাঁ | না | না |

## ৪. নিয়ম আর এরর (২৫ মিনিট)

| ভুল | এরর |
|---|---|
| Parameter-এর ধরনে সাইজ: `VARCHAR2(30)` | `PLS-00103` |
| `IN`-এ মান বসানো | `PLS-00363` |
| `OUT`/`IN OUT`-এ সরাসরি মান পাঠানো | `PLS-00363` |
| Parameter-এর সংখ্যা কম-বেশি | `PLS-00306: wrong number or types of arguments` |
| ধরন মেলে না (সংখ্যার জায়গায় লেখা) | চালানোর সময় `VALUE_ERROR`, বা `PLS-00306` |

### এরর হলে OUT-এর কী হয়

```sql
CREATE OR REPLACE PROCEDURE w18_out_fail (p_val OUT NUMBER)
IS
BEGIN
    p_val := 10;
    p_val := p_val / 0;           -- না ধরা এরর
END;
/

DECLARE
    v NUMBER := 99;
BEGIN
    BEGIN
        w18_out_fail(v);
    EXCEPTION
        WHEN ZERO_DIVIDE THEN NULL;     -- শুধু পরীক্ষার জন্য চুপ করানো
    END;
    DBMS_OUTPUT.PUT_LINE(v);            -- 99, 10 না
END;
/
```

Procedure ব্যর্থ হলে `OUT`-এর মান কলকারীর কাছে **ফেরত যায় না**, আগের মান থাকে। কারণ Oracle ভেতরে একটা কপিতে কাজ করে, সফল হলে তবে কপি ফেরত দেয়।

**নিয়ম:** Procedure ব্যর্থ হলে `OUT`-এর মান বিশ্বাস করো না। এরর দেখো, মান না।

### নামের নিয়ম

| ধরন | আগে | উদাহরণ |
|---|---|---|
| Parameter | `p_` | `p_emp_id` |
| Local Variable | `v_` | `v_cnt` |
| Constant | `c_` | `c_min_wage` |
| Cursor | `c_` বা `cur_` | `c_emp` |
| Exception | `e_` | `e_low_stock` |

Parameter আর কলামের নাম একই রাখলে (`emp_id`) `WHERE emp_id = emp_id` সব রো মেলায়! `p_` দিলে এই ফাঁদ থাকে না।

CREATE OR REPLACE PROCEDURE w18_split_name (
    p_full  IN  VARCHAR2,
    p_first OUT VARCHAR2,
    p_last  OUT VARCHAR2
)
IS
    v_full VARCHAR2(200) := TRIM(p_full);
    v_pos  PLS_INTEGER;
BEGIN
    v_pos := INSTR(v_full, ' ');
    IF v_pos = 0 THEN
        p_first := v_full;
        p_last  := NULL;
    ELSE
        p_first := SUBSTR(v_full, 1, v_pos - 1);
        p_last  := TRIM(SUBSTR(v_full, v_pos + 1));
    END IF;
END w18_split_name;

CREATE OR REPLACE PROCEDURE w18_salary_dept_report (p_month IN VARCHAR2)
IS
    v_prev  w16_emp.dept_name%TYPE;
    v_sub   NUMBER := 0;
    v_grand NUMBER := 0;
    v_rows  NUMBER := 0;
BEGIN
    FOR r IN (SELECT e.dept_name, e.emp_name, s.net_salary
              FROM   w16_salary s JOIN w16_emp e ON e.emp_id = s.emp_id
              WHERE  s.salary_month = p_month
              ORDER  BY e.dept_name, s.emp_id)
    LOOP
        IF v_prev IS NOT NULL AND r.dept_name <> v_prev THEN
            DBMS_OUTPUT.PUT_LINE('  Subtotal ' || v_prev || ': ' || v_sub);
            v_sub := 0;
        END IF;
        DBMS_OUTPUT.PUT_LINE('  ' || RPAD(r.emp_name, 10) || LPAD(r.net_salary, 8));
        v_sub   := v_sub + r.net_salary;
        v_grand := v_grand + r.net_salary;
        v_prev  := r.dept_name;
        v_rows  := v_rows + 1;
    END LOOP;

    IF v_rows = 0 THEN
        RAISE_APPLICATION_ERROR(-20204, 'Salary for ' || p_month || ' not processed');
    END IF;

    DBMS_OUTPUT.PUT_LINE('  Subtotal ' || v_prev || ': ' || v_sub);
    DBMS_OUTPUT.PUT_LINE('Grand total: ' || v_grand);        -- 176090
END w18_salary_dept_report;
/

2. `IN`-এ মান বসালে কোন এরর?
3. `OUT` Parameter ভেতরে কী মান দিয়ে শুরু হয়?
4. `OUT`-এর জায়গায় সংখ্যা `5` পাঠানো যায়?
5. Procedure ব্যর্থ হলে `OUT`-এর মান কলকারী পায়?

<details>
<summary>উত্তর দেখো</summary>

1. `IN`
2. `PLS-00363`
3. NULL
4. না, Variable লাগে
5. না, আগের মান থাকে

</details>

## সারাংশ

- `IN`: শুধু পড়া, যেকোনো Expression পাঠানো যায়, Default Mode
- `OUT`: ভেতরে NULL দিয়ে শুরু, বসানো মান কলকারী পায়, Variable লাগবে
- `IN OUT`: নিয়ে আসো, বদলাও, ফেরত দাও
- Bind Variable (`VARIABLE`, `:g_x`, `PRINT`) দিয়ে তাড়াতাড়ি পরীক্ষা
- ব্যর্থ হলে `OUT` ফেরত আসে না
- Parameter-এর নাম `p_` দিয়ে, কলামের নামের সাথে গুলিয়ে ফেলার ফাঁদ এড়াতে

**পরের ক্লাস (সোমবার):** Function: একটা মান ফেরত দেয়, আর SQL-এর ভেতরেও ব্যবহার করা যায়।
