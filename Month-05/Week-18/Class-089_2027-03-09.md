# ক্লাস ৮৯: Procedure বনাম Function

**তারিখ:** ৯ মার্চ ২০২৭, মঙ্গলবার
**সময়:** সন্ধ্যা ৭:০০ থেকে রাত ১০:০০
**সপ্তাহ:** ১৮ | **ধাপ:** ৩ (PL/SQL)

---

## আজকে কী শিখব

- কখন Procedure, কখন Function: সিদ্ধান্তের নিয়ম
- স্তরে স্তরে সাজানো: Procedure Procedure-কে, Function-কে ডাকে
- `COMMIT` কার দায়িত্ব, এরর কোথায় ধরা
- Dependency: টেবিল বদলালে Procedure INVALID
- `GRANT EXECUTE`: টেবিল না দিয়ে শুধু কাজের অনুমতি

---

## ১. কোনটা কখন (৩০ মিনিট)

| প্রশ্ন | উত্তর হ্যাঁ হলে |
|---|---|
| টেবিলে কিছু বদলাবে (`INSERT`/`UPDATE`/`DELETE`)? | **Procedure** |
| SQL-এর `SELECT`/`WHERE`-এ লাগবে? | **Function** |
| একটা মান হিসাব করে দেবে? | **Function** |
| কোনো মান ফেরত দেবে না, শুধু কাজ করবে? | **Procedure** |
| দুই বা তার বেশি মান ফেরত দেবে? | **Procedure** (`OUT`), অথবা পরে Record (সপ্তাহ ২১) |
| হ্যাঁ/না যাচাই (মেম্বার Active?) | **Function** (`'Y'`/`'N'`) |
| যাচাই ব্যর্থ হলে থামাতে হবে | **Procedure** যা `RAISE_APPLICATION_ERROR` দেয় |

### ERP-র উদাহরণ

| কাজ | ধরন | নাম |
|---|---|---|
| স্টক ইস্যু | Procedure | `stock_issue(p_item, p_qty)` |
| এখনকার স্টক | Function | `stock_balance(p_item)` |
| স্যালারি প্রসেস | Procedure | `process_payroll(p_month)` |
| একজনের Gross | Function | `gross(p_basic)` |
| বই ইস্যুর আগে যাচাই | Procedure | `check_can_issue(p_member, p_copy)` |
| মেম্বার Active কি না | Function | `is_member_active(p_member)` |
| ইনভয়েস নম্বর পরের টা | Function? | **Procedure**, কারণ Counter টেবিল বদলায় (ক্লাস ৮০) |

শেষেরটা ফাঁদ। "নম্বর দাও" শুনে Function মনে হয়, কিন্তু Counter বাড়ায়, মানে বদল। বদল = Procedure।

### একটা মোটা দাগের নিয়ম

**Function পড়ে, Procedure লেখে।**

## ২. স্তরে স্তরে সাজানো (৩৫ মিনিট)

বড় একটা Procedure-এর বদলে ছোট ছোট টুকরা, প্রতিটার একটাই কাজ।

```
w18_process_payroll(p_month)              ← কলকারী: প্রতিজনের জন্য
    └── w18_process_one_emp(p_month, p_emp_id)
            ├── w18_check_emp(p_emp_id)          ← যাচাই, এরর দিলে থামে
            ├── w18_gross(basic)                  ← হিসাব (ক্লাস ৮৮)
            ├── w18_deduction(basic, days)        ← হিসাব
            └── INSERT INTO w16_salary
```

### যাচাইয়ের Procedure

```sql
CREATE OR REPLACE PROCEDURE w18_check_emp (
    p_emp_id IN w16_emp.emp_id%TYPE
)
IS
    c_min_wage CONSTANT NUMBER := 8000;
    v_status   w16_emp.status%TYPE;
    v_basic    w16_emp.basic_salary%TYPE;
BEGIN
    SELECT status, basic_salary INTO v_status, v_basic
    FROM   w16_emp WHERE emp_id = p_emp_id;

    IF v_status = 'LEFT' THEN
        RAISE_APPLICATION_ERROR(-20203, 'Employee ' || p_emp_id || ' has left, no salary');
    END IF;
    IF v_basic < c_min_wage THEN
        RAISE_APPLICATION_ERROR(-20202, 'Employee ' || p_emp_id || ': basic below minimum wage');
    END IF;
EXCEPTION
    WHEN NO_DATA_FOUND THEN
        RAISE_APPLICATION_ERROR(-20201, 'Employee ' || p_emp_id || ' not found');
END w18_check_emp;
/
```

সফল হলে চুপচাপ শেষ। ব্যর্থ হলে এরর। কলকারীকে কিছু যাচাই করতে হয় না।

### একজনের স্যালারি

```sql
CREATE OR REPLACE PROCEDURE w18_process_one_emp (
    p_month  IN VARCHAR2,
    p_emp_id IN w16_emp.emp_id%TYPE
)
IS
    v_basic  w16_emp.basic_salary%TYPE;
    v_days   NUMBER;
    v_gross  NUMBER;
    v_ded    NUMBER;
BEGIN
    w18_check_emp(p_emp_id);

    SELECT basic_salary INTO v_basic FROM w16_emp WHERE emp_id = p_emp_id;

    SELECT NVL(MAX(absent_days), 0) INTO v_days
    FROM   w16_absent
    WHERE  emp_id = p_emp_id AND absent_month = p_month;

    v_gross := w18_gross(v_basic);
    v_ded   := w18_deduction(v_basic, v_days);

    DELETE FROM w16_salary WHERE salary_month = p_month AND emp_id = p_emp_id;

    INSERT INTO w16_salary
           (salary_month, emp_id, basic_salary, house_rent, medical, transport,
            gross_salary, absent_days, deduction, net_salary)
    VALUES (p_month, p_emp_id, v_basic, v_basic * 0.5, 750, 450,
            v_gross, v_days, v_ded, v_gross - v_ded);
END w18_process_one_emp;
/
```

`NVL(MAX(...), 0)`: অনুপস্থিতির রো না থাকলেও `NO_DATA_FOUND` হয় না (ক্লাস ৮১-র Aggregate কৌশল)।

### সবার

```sql
CREATE OR REPLACE PROCEDURE w18_process_payroll (
    p_month IN VARCHAR2
)
IS
    e_skip_left EXCEPTION;
    e_skip_wage EXCEPTION;
    PRAGMA EXCEPTION_INIT(e_skip_left, -20203);
    PRAGMA EXCEPTION_INIT(e_skip_wage, -20202);
    v_ok   NUMBER := 0;
    v_skip NUMBER := 0;
BEGIN
    FOR r IN (SELECT emp_id FROM w16_emp ORDER BY emp_id) LOOP
        BEGIN
            w18_process_one_emp(p_month, r.emp_id);
            v_ok := v_ok + 1;
        EXCEPTION
            WHEN e_skip_left OR e_skip_wage THEN
                DBMS_OUTPUT.PUT_LINE('Skipped: ' || SQLERRM);
                v_skip := v_skip + 1;
        END;
    END LOOP;
    DBMS_OUTPUT.PUT_LINE(p_month || ': ' || v_ok || ' processed, ' || v_skip || ' skipped');
END w18_process_payroll;
/

SET SERVEROUTPUT ON
EXEC w18_process_payroll('2027-01');
-- Skipped: ORA-20203: Employee 10 has left, no salary
-- 2027-01: 9 processed, 1 skipped
COMMIT;
```

সপ্তাহ ১৭-এর ১০০ লাইনের ব্লক এখন তিনটা ছোট টুকরা, প্রতিটা আলাদা পরীক্ষা করা যায়: `EXEC w18_check_emp(10);`।

**খেয়াল করো:** ভেতরের কোনো Procedure-এ `COMMIT` নেই। কেন? পরের অংশে।

## ৩. COMMIT কার দায়িত্ব (৩০ মিনিট)

ধরো `w18_process_one_emp`-এর শেষে `COMMIT` ছিল। এখন APEX-এর একটা পেজ:

1. বোনাস টেবিলে রো ঢোকাল
2. `w18_process_one_emp` ডাকল → **`COMMIT`**
3. অন্য একটা যাচাই ব্যর্থ হলো → `ROLLBACK`

ফল: ধাপ ১-এর বোনাস সেভ হয়ে গেছে (ধাপ ২-এর `COMMIT` সেটাও সেভ করেছে), অথচ পুরো কাজ ব্যর্থ। ডাটা অর্ধেক।

**নিয়ম: যে Transaction শুরু করে, সে-ই শেষ করে।**

| কে | `COMMIT`? |
|---|---|
| ছোট কাজের Procedure (`process_one_emp`, `stock_issue`) | **না** |
| Function | **কখনো না** |
| APEX পেজ | APEX নিজে পেজ প্রসেস শেষে `COMMIT` করে |
| SQL Developer-এ পরীক্ষা | তুমি হাতে |
| রাতের Job-এর সবচেয়ে উপরের Procedure (সপ্তাহ ২২) | হ্যাঁ, শেষে একবার |

`w18_process_payroll`-ও `COMMIT` করেনি, উপরে `EXEC`-এর পরে তুমি করেছ। চাইলে এটাকে "সবচেয়ে উপরের" ধরে শেষে `COMMIT` দিতে পারো, কিন্তু তখন অন্য কেউ একে ভেতর থেকে ডাকতে পারবে না।

### এরর কোথায় ধরবে

| স্তর | কাজ |
|---|---|
| নিচের Procedure (`check_emp`) | ব্যবসার নিয়ম ভাঙলে `RAISE_APPLICATION_ERROR`, আর কিছু ধরে না |
| মাঝের (`process_one_emp`) | সাধারণত কিছুই ধরে না, এরর উপরে যেতে দেয় |
| উপরের (`process_payroll`) | যে এরর জানে কী করতে হবে (Skip), শুধু সেটা ধরে |
| সবার উপরে (APEX, Job) | বাকি সব দেখায় বা লগ করে |

ভুল: প্রতিটা স্তরে `WHEN OTHERS THEN DBMS_OUTPUT...`। এরর হারায়, লগ চারবার, কেউ জানে না আসলে কী হয়েছে।

### ব্যর্থ Procedure-এর অর্ধেক কাজ

```sql
BEGIN
    UPDATE w14_stock SET balance_qty = balance_qty + 1 WHERE item_id = 1;   -- কলকারীর কাজ
    w18_check_emp(10);                                                       -- ব্যর্থ
END;
/
SELECT balance_qty FROM w14_stock WHERE item_id = 1;     -- 600
```

এরর একদম উপরে (SQL Developer পর্যন্ত) না ধরা গেলে পুরো ব্লক বাতিল, কলকারীর কাজসহ (ক্লাস ৮১)। কিন্তু ভেতরে ধরলে:

```sql
BEGIN
    UPDATE w14_stock SET balance_qty = balance_qty + 1 WHERE item_id = 1;
    BEGIN
        w18_check_emp(10);
    EXCEPTION
        WHEN OTHERS THEN NULL;
    END;
END;
/
SELECT balance_qty FROM w14_stock WHERE item_id = 1;     -- 601
ROLLBACK;
```

এরর ধরা হলে Oracle **কিছুই** বাতিল করে না। কলকারীর আগের কাজ থাকে, আর সাবধান: Procedure ব্যর্থ হওয়ার আগে ভেতরে যা `UPDATE`/`INSERT` করেছিল, সেটাও থেকে যায়! (`w18_check_emp` কোনো বদল করে না, তাই এখানে সমস্যা নেই।)

সমাধান ক্লাস ৮৫-এর `SAVEPOINT`: ডাকার আগে `SAVEPOINT`, ধরলে `ROLLBACK TO`। অথবা ধরো-ই না, উপরে যেতে দাও।

## ৪. Dependency: টেবিল বদলালে কী হয় (২৫ মিনিট)

`w18_gross` কোনো টেবিল ছোঁয় না। কিন্তু `w18_check_emp` নির্ভর করে `w16_emp`-এর উপর।

```sql
SELECT name, type, referenced_name, referenced_type
FROM   user_dependencies
WHERE  name LIKE 'W18%'
AND    referenced_type IN ('TABLE', 'VIEW', 'PROCEDURE', 'FUNCTION')
ORDER  BY name;
```

| NAME | REFERENCED_NAME |
|---|---|
| W18_CHECK_EMP | W16_EMP |
| W18_PROCESS_ONE_EMP | W16_EMP, W16_ABSENT, W16_SALARY, W18_CHECK_EMP, W18_GROSS, W18_DEDUCTION |
| W18_PROCESS_PAYROLL | W16_EMP, W18_PROCESS_ONE_EMP |

### পরীক্ষা

```sql
CREATE TABLE w18_dep_test (a NUMBER, b NUMBER);

CREATE OR REPLACE FUNCTION w18_dep_fn RETURN NUMBER
IS
    v NUMBER;
BEGIN
    SELECT COUNT(b) INTO v FROM w18_dep_test;
    RETURN v;
END;
/

SELECT object_name, status FROM user_objects WHERE object_name = 'W18_DEP_FN';   -- VALID

ALTER TABLE w18_dep_test DROP COLUMN b;

SELECT object_name, status FROM user_objects WHERE object_name = 'W18_DEP_FN';   -- INVALID

SELECT w18_dep_fn FROM dual;     -- ORA-06575 / ORA-04063: has errors
```

কলাম ফেরত দিলে:

```sql
ALTER TABLE w18_dep_test ADD (b NUMBER);
SELECT w18_dep_fn FROM dual;     -- 0, Oracle নিজে আবার Compile করে নিয়েছে
SELECT object_name, status FROM user_objects WHERE object_name = 'W18_DEP_FN';   -- VALID
```

- নির্ভর করা জিনিস বদলালে Oracle Procedure-কে INVALID দাগায়
- পরের বার ডাকলে নিজে Compile করার চেষ্টা করে। পারলে VALID, না পারলে এরর
- হাতে Compile: `ALTER FUNCTION w18_dep_fn COMPILE;` (Procedure-এর জন্য `ALTER PROCEDURE ... COMPILE`)

**ERP-তে:** টেবিলে কলাম বাদ দেওয়া বা নাম বদলানোর আগে `USER_DEPENDENCIES` দেখো, কোন কোন Procedure ভাঙবে।

## ৫. GRANT EXECUTE (১৫ মিনিট)

ক্লাস ৯-এ `store_user` বানিয়েছিলে। সে যদি কর্মচারীর তথ্য দেখতে চায়, দুই উপায়:

| উপায় | `store_user` পায় |
|---|---|
| `GRANT SELECT ON w16_emp TO store_user;` | পুরো টেবিল, Basic-সহ সবার সব কলাম |
| `GRANT EXECUTE ON w18_show_emp TO store_user;` | শুধু Procedure চালানোর অনুমতি, যা নাম আর বিভাগ দেখায় |

```sql
-- learn_freepdb1-এ
GRANT EXECUTE ON w18_show_emp TO store_user;
```

`store_user` কানেকশনে:

```sql
SET SERVEROUTPUT ON
EXEC learn.w18_show_emp(3);                 -- 3: Salma (Sewing)
SELECT * FROM learn.w16_emp;                -- ORA-00942: table or view does not exist
```

Procedure চলে **তৈরিকারীর (`learn`) অনুমতিতে**, কলকারীর না। একে বলে **Definer's Rights**। তাই `store_user` টেবিল না দেখেও Procedure চালাতে পারে।

ERP-তে এটাই নিরাপত্তার মূল: ব্যবহারকারীকে টেবিল না দিয়ে শুধু Procedure দাও। কোন কাজ করা যাবে, সেটা Procedure ঠিক করে। APEX-এর নিরাপত্তা (সপ্তাহ ৩৩) এর উপর দাঁড়ায়।

```sql
REVOKE EXECUTE ON w18_show_emp FROM store_user;
```

> `store_user` না থাকলে বা পাসওয়ার্ড মনে না থাকলে এই অংশ পড়ে যাও, প্র্যাকটিস ১৩ বাদ দাও।

## ৬. হাতে-কলমে প্র্যাকটিস (৪৫ মিনিট)

সব `learn_freepdb1`-এ।

1. ক্লাসের সিদ্ধান্তের টেবিল দেখে ঠিক করো (Procedure না Function, কেন): ক. বায়ারের মোট অর্ডার পরিমাণ; খ. অর্ডার বাতিল করা; গ. শিপমেন্টের তারিখ পার কি না; ঘ. নতুন GRN নম্বর; ঙ. এক অর্ডারের মোট পিস আর মোট দাম দুইটাই।
2. `w18_check_emp` বানাও, ১, ১০, ৯৯ দিয়ে `EXEC`।
3. `w18_process_one_emp` বানাও। `EXEC w18_process_one_emp('2027-01', 3);`, তারপর `w16_salary`-তে Salma-র রো দেখো। (Net ১৬৯৬৭) `ROLLBACK`।
4. `w18_process_payroll` বানাও আর চালাও। মোট Net সপ্তাহ ১৬-এর সাথে মেলে? (১৭৬০৯০) `COMMIT`।
5. ৪ নম্বর আবার চালাও। ডুপ্লিকেট এরর আসে না কেন?
6. Nasima-র Basic ৭৫০০ করে ৪ নম্বর চালাও (`COMMIT` ছাড়া)। কয়জন Skip? তারপর `ROLLBACK`।
7. `w18_process_one_emp`-এর শেষে `COMMIT` যোগ করে ক্লাসের "COMMIT কার দায়িত্ব"-এর বিপদটা নিজে দেখাও: আগে `w14_stock`-এ ১ যোগ, তারপর Procedure, তারপর `ROLLBACK`। স্টক কত? (৬০১!) ঠিক করো: `COMMIT` মোছো, স্টক ৬০০ করে `COMMIT`।
8. `USER_DEPENDENCIES` থেকে `W18_PROCESS_ONE_EMP` কোন কোন জিনিসের উপর নির্ভর করে?
9. `w18_dep_test` পরীক্ষাটা করো, প্রতিটা ধাপে `status` লেখো। শেষে টেবিল আর Function মুছে দাও।
10. `w18_gross`-এ ইচ্ছা করে একটা Compile Error দাও। `w18_net` (ক্লাস ৮৮) আর `w18_process_one_emp`-এর `status` কী হলো? `w18_gross` ঠিক করো, তারপর `ALTER PROCEDURE w18_process_one_emp COMPILE;`।

**১:**

- ক. Function: পড়ে, একটা মান, SQL-এ কাজে লাগবে
- খ. Procedure: বদলায়

```sql
-- ১১
CREATE OR REPLACE FUNCTION w18_is_member_active (
    p_member_id IN lib_member.member_id%TYPE
) RETURN VARCHAR2
IS
    v_active lib_member.is_active%TYPE;
BEGIN
    SELECT is_active INTO v_active FROM lib_member WHERE member_id = p_member_id;
    RETURN v_active;
EXCEPTION
    WHEN NO_DATA_FOUND THEN
        RETURN 'N';
END w18_is_member_active;
/

CREATE OR REPLACE PROCEDURE w18_check_member (
    p_member_id IN lib_member.member_id%TYPE
)
IS
    v_active lib_member.is_active%TYPE;
BEGIN
    SELECT is_active INTO v_active FROM lib_member WHERE member_id = p_member_id;
    IF v_active <> 'Y' THEN
        RAISE_APPLICATION_ERROR(-20102, 'Member ' || p_member_id || ' is inactive');
    END IF;
EXCEPTION
    WHEN NO_DATA_FOUND THEN
        RAISE_APPLICATION_ERROR(-20101, 'Member ' || p_member_id || ' not found');
END w18_check_member;
/

-- ১২
SELECT member_id, member_name, w18_is_member_active(member_id) AS active
FROM   lib_member ORDER BY member_id;
```

Function প্রশ্নের উত্তর দেয় (রিপোর্ট, `CASE`, `IF`), Procedure কাজ আটকায় (ইস্যুর আগে)। ১২-র মতো রিপোর্টে আসলে `is_active` কলাম সরাসরিই পড়া যেত। Function-টা লাভের হয় যখন "Active" মানে আরো জটিল শর্ত (যেমন মেম্বারশিপের মেয়াদ)।

**১০:** দুইটাই INVALID। ঠিক করার পরে `COMPILE` (বা শুধু চালালেই) আবার VALID।

## সারাংশ

- Function পড়ে আর একটা মান দেয়, Procedure লেখে বা কাজ করে
- বড় কাজ ছোট টুকরায়: যাচাই, হিসাব, সেভ আলাদা, উপরের Procedure সাজায়
- `COMMIT` সবচেয়ে উপরের কলকারীর, ভেতরের Procedure আর Function-এর কখনো না
- এরর যে স্তর সামলাতে জানে সেখানেই ধরো, বাকিরা উপরে যেতে দেয়
- টেবিল বদলালে নির্ভরশীল Procedure INVALID, `USER_DEPENDENCIES` দেখো
- `GRANT EXECUTE`: টেবিল না দিয়ে কাজের অনুমতি (Definer's Rights)
