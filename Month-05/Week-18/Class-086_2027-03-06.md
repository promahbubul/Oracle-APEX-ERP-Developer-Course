## ১. Anonymous Block থেকে Stored Procedure (২০ মিনিট)

গত চার সপ্তাহ যা লিখেছ সব **Anonymous Block**: নাম নেই, `DECLARE`/`BEGIN` দিয়ে শুরু।

| সমস্যা | উদাহরণ |
|---|---|
| ডাটাবেসে থাকে না | `week17.sql` ফাইল হারালে কোড শেষ |
| প্রতিবার Compile | চালানোর আগে Oracle প্রতিবার নতুন করে পড়ে |
| মান বদলাতে কোড বদলাও | `v_item_id := 2` হাতে বদলাতে হয় |
| অন্যরা ব্যবহার করতে পারে না | APEX পেজ তোমার ফাইল দেখে না |

**Stored Procedure:** নাম দেওয়া PL/SQL ব্লক, ডাটাবেসের ভেতরে সেভ থাকে, একবার Compile হয়, যে কেউ নাম ধরে ডাকতে পারে, মান Parameter দিয়ে দেওয়া যায়।

| | Anonymous Block | Stored Procedure |
|---|---|---|
| নাম | নেই | আছে |
| কোথায় থাকে | তোমার ফাইলে | ডাটাবেসে |
| Compile | প্রতিবার | একবার (`CREATE`-এর সময়) |
| ইনপুট | কোডের ভেতরে মান | Parameter |
| কে চালাতে পারে | যার কাছে ফাইল | অনুমতি থাকলে সবাই, APEX-ও |

ERP-তে প্রায় সব ব্যবসার লজিক Procedure, Function আর Package-এ থাকে। APEX পেজ শুধু সেগুলো ডাকে। এই সপ্তাহ থেকে আসল ERP ডেভেলপারের কাজ শুরু।

## ২. বানানো আর কল করা (৪০ মিনিট)

### সবচেয়ে ছোট Procedure

```sql
CREATE OR REPLACE PROCEDURE w18_hello
IS
BEGIN
    DBMS_OUTPUT.PUT_LINE('Hello from a stored procedure');
END w18_hello;
/
```

`F5` চাপলে: `Procedure W18_HELLO compiled`। এখনো কিছু ছাপায়নি, শুধু সেভ হয়েছে।

| অংশ | মানে |
|---|---|
| `CREATE OR REPLACE` | না থাকলে বানাও, থাকলে বদলে দাও |
| `PROCEDURE w18_hello` | নাম |
| `IS` (বা `AS`) | এখান থেকে ঘোষণার অংশ, `DECLARE` শব্দটা লেখা হয় না |
| `BEGIN ... END w18_hello;` | কাজ, শেষে নাম দিলে পড়া সহজ (ঐচ্ছিক) |
| `/` | SQL Developer-কে বলা: এখানে শেষ, Compile করো |

`IS` আর `AS` হুবহু এক। এই কোর্সে `IS`।

### কল করা

```sql
SET SERVEROUTPUT ON

-- ১. EXEC (SQL Developer / SQL*Plus-এর শর্টকাট)
EXEC w18_hello;

-- ২. Anonymous Block থেকে
BEGIN
    w18_hello;
END;
/

-- ৩. CALL (SQL Statement, বন্ধনী লাগবেই)
CALL w18_hello();
```

| উপায় | কোথায় | মনে রাখো |
|---|---|---|
| `EXEC` | শুধু SQL Developer / SQL*Plus | এক লাইনে পরীক্ষার জন্য সবচেয়ে সহজ |
| `BEGIN ... END` | সব জায়গায়: অন্য Procedure, APEX, Trigger | আসল কাজে এটাই |
| `CALL` | SQL Statement যেখানে চলে | `CALL w18_hello;` (বন্ধনী ছাড়া) এরর দেয় |

APEX-এর Page Process-এ তুমি লিখবে শুধু `w18_hello;`, APEX নিজে `BEGIN ... END` জুড়ে দেয়।

### Variable আর Cursor-সহ

`IS`-এর পরে যা লেখো, সেটাই আগের `DECLARE`-এর অংশ:

```sql
CREATE OR REPLACE PROCEDURE w18_active_staff
IS
    v_cnt NUMBER := 0;

    CURSOR c_emp IS
        SELECT emp_name, dept_name
        FROM   w16_emp
        WHERE  status = 'ACTIVE'
        ORDER  BY dept_name, emp_name;
BEGIN
    FOR r IN c_emp LOOP
        v_cnt := v_cnt + 1;
        DBMS_OUTPUT.PUT_LINE(RPAD(r.dept_name, 12) || r.emp_name);
    END LOOP;
    DBMS_OUTPUT.PUT_LINE('Active staff: ' || v_cnt);       -- 9
END w18_active_staff;
/

EXEC w18_active_staff;
```

### প্রথম Parameter

কাল বিস্তারিত, আজ একটা স্বাদ:

```sql
CREATE OR REPLACE PROCEDURE w18_dept_staff (p_dept IN VARCHAR2)
IS
BEGIN
    FOR r IN (SELECT emp_name, basic_salary
              FROM   w16_emp
              WHERE  dept_name = p_dept AND status = 'ACTIVE'
              ORDER  BY emp_id)
    LOOP
        DBMS_OUTPUT.PUT_LINE(r.emp_name || ' ' || r.basic_salary);
    END LOOP;
END w18_dept_staff;
/

EXEC w18_dept_staff('Sewing');
EXEC w18_dept_staff('Quality');
```

এক Procedure, অনেক মান। ক্লাস ৮০-এর Parameterized Cursor-এর মতো, কিন্তু এবার পুরো প্রোগ্রাম।

Parameter-এর ধরনে সাইজ দেওয়া যায় না (`VARCHAR2(30)` না), Cursor Parameter-এর মতোই।

### বদলানো

কোড বদলে আবার `CREATE OR REPLACE` চালালেই পুরনোটা যায়, নতুনটা বসে। আলাদা `ALTER` লাগে না। অনুমতি (`GRANT`) থাকলে সেটাও থেকে যায়।

## ৩. Compile Error (৩০ মিনিট)

Anonymous Block-এ এরর হলে সাথে সাথে লাল বার্তা। Procedure আলাদা।

```sql
CREATE OR REPLACE PROCEDURE w18_broken
IS
    v_cnt NUMBER;
BEGIN
    SELECT COUNT(*) INTO v_cnt FROM w16_emp
    DBMS_OUTPUT.PUT_LINE(v_cnt);              -- আগের লাইনে ; নেই
END;
/
```

```
Procedure W18_BROKEN compiled
Errors: check compiler log
```

**"compiled" লেখা দেখে ভেবো না ঠিক আছে।** Procedure ডাটাবেসে সেভ হয়েছে, কিন্তু **INVALID** অবস্থায়। চালাতে গেলে:

```sql
EXEC w18_broken;
-- PLS-00905: object LEARN.W18_BROKEN is invalid
```

### এরর দেখা

নিচের মতো কিছু দেখাবে (লাইন নম্বর আর বার্তা ভার্সনভেদে সামান্য আলাদা হতে পারে):

```sql
SHOW ERRORS
```

```
Errors for PROCEDURE LEARN.W18_BROKEN:
LINE/COL  ERROR
--------  ----------------------------------------------------
6/5       PL/SQL: ORA-00933: SQL command not properly ended
5/5       PL/SQL: SQL Statement ignored
```

অথবা যেকোনো সময়, যেকোনো Procedure-এর:

```sql
SELECT line, position, text
FROM   user_errors
WHERE  name = 'W18_BROKEN'
ORDER  BY sequence;
```

SQL Developer-এ নিচে **Compiler Log** ট্যাবেও দেখায়, এরর-এ ডাবল ক্লিক করলে লাইনে নিয়ে যায়।

- লাইন নম্বর গোনা হয় `CREATE` থেকে, ১ নম্বর লাইন `CREATE OR REPLACE ...`
- প্রথম এরর ঠিক করো, তারপর আবার Compile। পরেরগুলো প্রায়ই প্রথমটার ফল

### নাম বড় হাতের

Oracle সব নাম বড় হাতের অক্ষরে রাখে। `WHERE name = 'w18_broken'` কিছু পাবে না, `'W18_BROKEN'` লাগবে।

### কোন এরর কখন ধরা পড়ে

| এরর | কখন |
|---|---|
| সেমিকোলন নেই, বানান ভুল | Compile-এ |
| টেবিল বা কলাম নেই | **Compile-এ** (Anonymous Block-এর মতো চালানোর সময় না) |
| `NO_DATA_FOUND`, `ZERO_DIVIDE` | চালানোর সময় |

দ্বিতীয়টা বড় সুবিধা: ভুল কলামের নাম কোড সেভ করার মুহূর্তেই ধরা পড়ে।

## ৪. Data Dictionary আর মোছা (২৫ মিনিট)

### আমার সব Procedure

```sql
SELECT object_name, object_type, status, last_ddl_time
FROM   user_objects
WHERE  object_type IN ('PROCEDURE', 'FUNCTION')
ORDER  BY object_name;
```

| `status` | মানে |
|---|---|
| `VALID` | চালানো যায় |
| `INVALID` | Compile Error আছে, বা যে টেবিলের উপর নির্ভর করে সেটা বদলেছে (ক্লাস ৮৯) |

SQL Developer-এর বাঁ দিকে Connection-এর ভেতরে **Procedures** ফোল্ডারেও দেখা যায়। লাল ক্রস মানে INVALID।

### কোড দেখা

```sql
SELECT line, text
FROM   user_source
WHERE  name = 'W18_ACTIVE_STAFF'
ORDER  BY line;
```

তোমার `.sql` ফাইল হারালেও কোড ডাটাবেসে থাকে। তবু ফাইলে রাখো, আর পরে Git-এ (ক্লাস ১৭৩)। ডাটাবেসে কেউ `CREATE OR REPLACE` দিলে পুরনো কোড আর ফেরত আসে না।

### মোছা

```sql
DROP PROCEDURE w18_broken;
```

`CREATE OR REPLACE` আর `DROP` দুইটাই DDL, তাই চালানোর আগে চলমান Transaction নিজে থেকে `COMMIT` হয়ে যায় (ক্লাস ২৫)। আগে `UPDATE` করে `ROLLBACK`-এর অপেক্ষায় থাকলে সাবধান।

1. Procedure-এ `DECLARE`-এর জায়গায় কী লেখা হয়?
2. `IS` আর `AS`-এর পার্থক্য কী?
3. `CALL`-এ কী লাগবেই?
4. "Compiled" দেখালেও Procedure কি সবসময় চালানো যায়?
5. Compile Error কোথায় দেখবে? দুইটা উপায়।

<details>
<summary>উত্তর দেখো</summary>

1. কিছু না, `IS`-এর পরেই ঘোষণা
2. কোনো পার্থক্য নেই
3. বন্ধনী `()`
4. না, এরর থাকলে INVALID, চালালে `PLS-00905`
5. `SHOW ERRORS`, `USER_ERRORS` (আর SQL Developer-এর Compiler Log)

## সারাংশ

- Stored Procedure = নাম দেওয়া ব্লক, ডাটাবেসে সেভ, একবার Compile, Parameter নেয়
- `CREATE OR REPLACE PROCEDURE name (params) IS ... BEGIN ... END name; /`
- কল: `EXEC` (পরীক্ষা), `BEGIN ... END` (আসল কাজ), `CALL name()` (SQL)
- "Compiled" মানে সেভ, ঠিক না-ও হতে পারে: `SHOW ERRORS`, `USER_ERRORS`, `status`
- `USER_OBJECTS`, `USER_SOURCE` দিয়ে খোঁজা, `DROP PROCEDURE` দিয়ে মোছা

**পরের ক্লাস (রবিবার):** Parameter: `IN`, `OUT`, `IN OUT`, Procedure থেকে মান ফেরত আনা।
