# ক্লাস ৯০: Default Parameter, Named Notation

**তারিখ:** ১০ মার্চ ২০২৭, বুধবার
**সময়:** সন্ধ্যা ৭:০০ থেকে রাত ১০:০০
**সপ্তাহ:** ১৮ | **ধাপ:** ৩ (PL/SQL)

---

## আজকে কী শিখব

- `DEFAULT` দিয়ে ঐচ্ছিক Parameter
- তিনভাবে মান পাঠানো: Positional, Named, Mixed
- SQL-এর ভেতরে Named Notation
- পুরনো কলকারী না ভেঙে নতুন Parameter যোগ করা
- Parameter-এর ক্রম আর নামের ভালো নিয়ম

## ১. DEFAULT (৪০ মিনিট)

কর্মচারীর তালিকার Procedure। কখনো চাই সব বিভাগ, কখনো একটা; সাধারণত শুধু `ACTIVE`, কখনো `LEFT`। প্রতিবার সব মান লেখা ঝামেলা।

```sql
SET SERVEROUTPUT ON

CREATE OR REPLACE PROCEDURE w18_emp_list (
    p_dept      IN VARCHAR2 DEFAULT NULL,           -- NULL মানে সব বিভাগ
    p_status    IN VARCHAR2 DEFAULT 'ACTIVE',
    p_min_basic IN NUMBER   DEFAULT 0
)
IS
    v_cnt NUMBER := 0;
BEGIN
    FOR r IN (SELECT emp_id, emp_name, dept_name, basic_salary
              FROM   w16_emp
              WHERE  (dept_name = p_dept OR p_dept IS NULL)
              AND    status = p_status
              AND    basic_salary >= p_min_basic
              ORDER  BY emp_id)
    LOOP
        DBMS_OUTPUT.PUT_LINE(r.emp_id || '. ' || RPAD(r.emp_name, 8) || RPAD(r.dept_name, 11) || r.basic_salary);
        v_cnt := v_cnt + 1;
    END LOOP;
    DBMS_OUTPUT.PUT_LINE('-- ' || v_cnt || ' employee(s)');
END w18_emp_list;
/
```

```sql
EXEC w18_emp_list;                         -- সব ACTIVE: 9
EXEC w18_emp_list('Sewing');               -- Sewing ACTIVE: 3
EXEC w18_emp_list('Store', 'LEFT');        -- Tania: 1
EXEC w18_emp_list('Sewing', 'ACTIVE', 11000);   -- Salma, Jamal: 2
```

- `DEFAULT` থাকলে কলকারী মানটা না দিলে সেটা বসে
- `DEFAULT`-এর বদলে `:=` লিখলেও একই (`p_status IN VARCHAR2 := 'ACTIVE'`)। এই কোর্সে `DEFAULT`, পড়তে পরিষ্কার
- ক্লাস ৮০-তে Cursor Parameter-এ একই জিনিস দেখেছিলে

### Default মান হিসেবে যা চলে

```sql
p_as_of   IN DATE     DEFAULT TRUNC(SYSDATE),
p_month   IN VARCHAR2 DEFAULT TO_CHAR(SYSDATE, 'YYYY-MM'),
p_min_qty IN NUMBER   DEFAULT 0
```

প্রতিবার ডাকার সময় হিসাব হয়, তাই `SYSDATE` সবসময় আজকের।

### Function-এ

```sql
CREATE OR REPLACE FUNCTION w18_gross (
    p_basic     IN NUMBER,
    p_medical   IN NUMBER DEFAULT 750,
    p_transport IN NUMBER DEFAULT 450
) RETURN NUMBER
IS
    c_house_pct CONSTANT NUMBER := 0.5;
BEGIN
    RETURN p_basic + p_basic * c_house_pct + p_medical + p_transport;
END w18_gross;
/

SELECT w18_gross(11000)            FROM dual;      -- 17700
SELECT w18_gross(11000, 1000)      FROM dual;      -- 17950
SELECT w18_gross(11000, 1000, 600) FROM dual;      -- 18100
```

ক্লাস ৮৮-এর সব জায়গা (`w18_net`, View, Query) আগের মতোই চলবে, কারণ তারা শুধু Basic দিত, আর বাকি দুইটার Default আছে।

### OUT-এ Default চলে না

```sql
CREATE OR REPLACE PROCEDURE w18_bad_default (p_x OUT NUMBER DEFAULT 0)
IS BEGIN NULL; END;
/
-- PLS-00230: OUT and IN OUT formal parameters may not have default expressions
```

যুক্তি সহজ: `OUT` কলকারীর Variable-এ মান **রাখে**। কোন Variable-এ রাখবে, সেটা না দিলে চলে না।

## ২. তিনভাবে মান পাঠানো (৪০ মিনিট)

### Positional: ক্রম ধরে

```sql
EXEC w18_emp_list('Sewing', 'ACTIVE', 11000);
```

প্রথম মান প্রথম Parameter-এ, দ্বিতীয় দ্বিতীয়তে। এ পর্যন্ত সব এভাবেই।

**সমস্যা:** শুধু `p_min_basic` দিতে চাই, বিভাগ আর অবস্থা Default থাকুক:

```sql
EXEC w18_emp_list(14000);     -- ভুল! 14000 যায় p_dept-এ
```

কোনো এরর নেই (সংখ্যা লেখায় রূপান্তর হয়), শুধু `dept_name = '14000'`, তাই ০ জন। নীরব ভুল।

### Named: নাম ধরে

```sql
EXEC w18_emp_list(p_min_basic => 14000);
-- Rahim, Farida, Habib: 3
```

`=>` (সমান আর বড়-চিহ্ন) মানে "এই Parameter-এ এই মান"। ক্রম যেকোনো:

```sql
EXEC w18_emp_list(p_status => 'LEFT', p_dept => 'Store');
```

### Mixed: আগে ক্রম, পরে নাম

```sql
EXEC w18_emp_list('Quality', p_min_basic => 15000);     -- Habib
```

নিয়ম: **Positional সবসময় আগে।** Named-এর পরে Positional চলে না:

```sql
EXEC w18_emp_list(p_dept => 'Quality', 'ACTIVE');
-- PLS-00312: a positional parameter association may not follow a named association
```

### কোনটা কখন

| পরিস্থিতি | ভালো |
|---|---|
| ১–২টা Parameter, অর্থ স্পষ্ট (`w18_show_emp(3)`) | Positional |
| অনেক Parameter, বেশিরভাগ Default | Named |
| `TRUE`/`FALSE`, `'Y'`/`'N'`, সংখ্যা যার অর্থ বোঝা যায় না | Named |
| অন্য কেউ কোড পড়বে | Named |

তুলনা করো:

```sql
w18_post_voucher(1001, 'Y', 'N', 0, NULL, 'Y');

w18_post_voucher(p_voucher_no  => 1001,
                 p_auto_post   => 'Y',
                 p_send_email  => 'N');
```

দ্বিতীয়টা ৬ মাস পরেও বোঝা যায়।

### SQL-এর ভেতরেও

```sql
SELECT emp_name,
       w18_gross(basic_salary)                    AS gross_now,
       w18_gross(basic_salary, p_medical => 1000) AS gross_new_medical
FROM   w16_emp
WHERE  status = 'ACTIVE'
ORDER  BY emp_id;
```

চিকিৎসা ভাতা ১০০০ হলে কত বাড়বে, এক Query-তে। (প্রতিজনের ২৫০, মোট ২২৫০)

## ৩. পুরনো কলকারী না ভেঙে বদলানো (২৫ মিনিট)

৩ মাস পরে HR বলল: Payroll-এ "শুধু একটা বিভাগ" প্রসেস করার সুবিধা চাই। `w18_process_payroll(p_month)` ইতিমধ্যে ৫ জায়গা থেকে ডাকা হয়।

### ভুল উপায়

```sql
CREATE OR REPLACE PROCEDURE w18_process_payroll (
    p_month IN VARCHAR2,
    p_dept  IN VARCHAR2          -- Default নেই
)
```

পুরনো ৫টা কল `w18_process_payroll('2027-01')` এখন `PLS-00306: wrong number or types of arguments`। যারা ডাকে, তারা INVALID।

### ঠিক উপায়: শেষে, Default দিয়ে

```sql
CREATE OR REPLACE PROCEDURE w18_process_payroll (
    p_month IN VARCHAR2,
    p_dept  IN VARCHAR2 DEFAULT NULL       -- NULL মানে সব, আগের মতো
)
IS
    e_skip_left EXCEPTION;
    e_skip_wage EXCEPTION;
    PRAGMA EXCEPTION_INIT(e_skip_left, -20203);
    PRAGMA EXCEPTION_INIT(e_skip_wage, -20202);
    v_ok   NUMBER := 0;
    v_skip NUMBER := 0;
BEGIN
    FOR r IN (SELECT emp_id FROM w16_emp
              WHERE  (dept_name = p_dept OR p_dept IS NULL)
              ORDER  BY emp_id)
    LOOP
        BEGIN
            w18_process_one_emp(p_month, r.emp_id);
            v_ok := v_ok + 1;
        EXCEPTION
            WHEN e_skip_left OR e_skip_wage THEN
                DBMS_OUTPUT.PUT_LINE('Skipped: ' || SQLERRM);
                v_skip := v_skip + 1;
        END;
    END LOOP;
    DBMS_OUTPUT.PUT_LINE(p_month || NVL2(p_dept, ' (' || p_dept || ')', '')
                         || ': ' || v_ok || ' processed, ' || v_skip || ' skipped');
END w18_process_payroll;
/

EXEC w18_process_payroll('2027-01');                 -- আগের মতো: 9 processed, 1 skipped
EXEC w18_process_payroll('2027-01', 'Sewing');       -- 3 processed, 0 skipped
ROLLBACK;
```

**নিয়ম:**
1. নতুন Parameter সবসময় **শেষে**
2. সবসময় **Default** দিয়ে, যাতে Default-এ আগের আচরণ থাকে
3. পুরনো Parameter-এর নাম বা ক্রম বদলাবে না: Named Notation-এ যারা নাম লিখেছে, তারা ভাঙবে

APEX অ্যাপে কয়েকশো পেজ একই Procedure ডাকে। এই তিন নিয়ম না মানলে একটা বদলে পুরো অ্যাপ ভাঙে।

## ৪. ক্রম আর নামের নিয়ম (১৫ মিনিট)

**Parameter-এর ক্রম:**

1. প্রয়োজনীয় `IN` (Default ছাড়া), সবচেয়ে জরুরিটা আগে: `p_month`, `p_emp_id`
2. ঐচ্ছিক `IN` (Default সহ)
3. `OUT` আর `IN OUT` শেষে

```sql
PROCEDURE w18_get_salary (
    p_emp_id     IN  NUMBER,                     -- ১
    p_month      IN  VARCHAR2 DEFAULT NULL,      -- ২
    p_net        OUT NUMBER                      -- ৩
)
```

`OUT` Default নিতে পারে না, তাই `OUT` থাকলে তার আগের ঐচ্ছিক Parameter বাদ দিতে Named লাগবে: `w18_get_salary(3, p_net => v_net)`।

**নামের নিয়ম (এই কোর্সে):**

| | নিয়ম | উদাহরণ |
|---|---|---|
| Procedure | ক্রিয়া দিয়ে | `process_payroll`, `issue_stock`, `check_emp` |
| Function | যা ফেরত দেয় | `gross`, `stock_balance`, `is_member_active` |
| হ্যাঁ/না Function | `is_`, `has_` | `is_low_stock`, `has_overdue_books` |
| Parameter | `p_` + কলামের নাম | `p_emp_id`, `p_item_id` |

নামেই বোঝা যাবে কী করে, ভেতর না খুলেই।

```sql
CREATE OR REPLACE PROCEDURE w18_issue_book_check (
    p_member_id IN lib_member.member_id%TYPE,
    p_copy_id   IN lib_book_copy.copy_id%TYPE,
    p_as_of     IN DATE DEFAULT TRUNC(SYSDATE)
)
IS
    v_active    lib_member.is_active%TYPE;
    v_max_books lib_member_type.max_books%TYPE;
    v_open_cnt  NUMBER;
    v_overdue   NUMBER;
    v_status    lib_book_copy.copy_status%TYPE;
BEGIN
    BEGIN
        SELECT m.is_active, t.max_books INTO v_active, v_max_books
        FROM   lib_member m
               JOIN lib_member_type t ON t.member_type_id = m.member_type_id
        WHERE  m.member_id = p_member_id;
    EXCEPTION
        WHEN NO_DATA_FOUND THEN
            RAISE_APPLICATION_ERROR(-20101, 'Member ' || p_member_id || ' not found');
    END;

    IF v_active <> 'Y' THEN
        RAISE_APPLICATION_ERROR(-20102, 'Member ' || p_member_id || ' is inactive');
    END IF;

    SELECT COUNT(*),
           COUNT(CASE WHEN due_date < p_as_of THEN 1 END)
    INTO   v_open_cnt, v_overdue
    FROM   lib_book_issue
    WHERE  member_id = p_member_id AND return_date IS NULL;

    IF v_open_cnt >= v_max_books THEN
        RAISE_APPLICATION_ERROR(-20103, 'Member has ' || v_open_cnt || ' of ' || v_max_books || ' books');
    END IF;
    IF v_overdue > 0 THEN
        RAISE_APPLICATION_ERROR(-20106, 'Member has ' || v_overdue || ' overdue book(s)');
    END IF;

    BEGIN
        SELECT copy_status INTO v_status FROM lib_book_copy WHERE copy_id = p_copy_id;
    EXCEPTION
        WHEN NO_DATA_FOUND THEN
            RAISE_APPLICATION_ERROR(-20104, 'Copy ' || p_copy_id || ' not found');
    END;

    IF v_status <> 'AVAILABLE' THEN
        RAISE_APPLICATION_ERROR(-20105, 'Copy ' || p_copy_id || ' is ' || v_status);
    END IF;
END w18_issue_book_check;
/

EXEC w18_issue_book_check(1, 1);
EXEC w18_issue_book_check(1, 1, p_as_of => DATE '2027-03-04');
```

## ৬. হোমওয়ার্ক

1. কাল স্টক IN/OUT-এর দিন। ক্লাস ৮৬–৯০-এর সারাংশ পড়ে আসো, আর ক্লাস ৮৯-এর হোমওয়ার্কের গাছটা সাথে রাখো।
2. তোমার ৫টা Procedure-এর Parameter তালিকা আজকের ক্রমের নিয়মে আবার সাজাও।

## সারাংশ

- `DEFAULT` দিলে Parameter ঐচ্ছিক, কলকারী না দিলে Default বসে
- Positional (ক্রম), Named (`p_x => মান`), Mixed (আগে ক্রম, পরে নাম)
- অনেক বা অস্পষ্ট Parameter-এ Named, SQL-এর ভেতরেও চলে
- `OUT`/`IN OUT`-এ Default চলে না
- নতুন Parameter শেষে আর Default দিয়ে, পুরনো নাম-ক্রম অপরিবর্তিত
- ক্রম: প্রয়োজনীয় `IN`, ঐচ্ছিক `IN`, তারপর `OUT`
