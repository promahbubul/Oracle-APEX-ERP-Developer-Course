## ১. রিভিশন (২০ মিনিট)

খাতা না দেখে উত্তর দাও। না পারলে সেই ক্লাসের ফাইল আবার পড়ো।

**ক্লাস ৮৬:** Anonymous Block আর Stored Procedure-এর ৩টা পার্থক্য কী? "Compiled with errors" হলে কোথায় এরর দেখবে? `CALL`-এ কী লাগে?

**ক্লাস ৮৭:** `OUT` Parameter ভেতরে কী মান দিয়ে শুরু হয়? `IN`-এ মান বসালে কী হয়? Procedure ব্যর্থ হলে `OUT`-এর কী হয়?

**ক্লাস ৮৮:** Function SQL থেকে ডাকার ৩টা নিয়ম কী? SQL-এ NO_DATA_FOUND-এর কী হয়? `RETURN` ছাড়া শেষ হলে কোন এরর?

**ক্লাস ৮৯:** "Function পড়ে, Procedure লেখে" মানে কী? ছোট Procedure-এ `COMMIT` কেন না? টেবিল বদলালে Procedure-এর কী হয়?

**ক্লাস ৯০:** Named Notation কখন? নতুন Parameter কীভাবে যোগ করবে? `OUT`-এ Default কেন চলে না?

## ২. মূল কাজ (১১৫ মিনিট)

`learn_freepdb1`-এ করো। প্রতিটা Procedure আর Function `week18.sql`-এ, প্রতিটার উপরে কমেন্টে এক লাইনে কী করে।

**আজকের গল্প:** স্টোর বিভাগের জন্য স্টকের Back-end বানাবে। পরে APEX-এর "Goods Receive" আর "Goods Issue" পেজ শুধু এগুলো ডাকবে। কোনো পেজ সরাসরি `w14_stock`-এ `UPDATE` করবে না।

```
w18_stock_receive ─┐
w18_stock_issue  ──┼── w18_stock_balance (Function)
w18_stock_transfer ┘      w18_item_exists (Function)
     │
     └── w18_log_error (অপ্রত্যাশিত এরর লগ)

রিপোর্ট: w18_txn_total (Function), w18_stock_card (Procedure), w18_is_low_stock (Function)
```

**নিয়ম:**

1. কোনো Procedure বা Function `COMMIT` করবে না (শুধু `w18_log_error`, কারণ নিচে দেখো)
2. ব্যবসার নিয়মে `RAISE_APPLICATION_ERROR`, সপ্তাহ ১৭-এর নম্বরের তালিকা
3. Parameter `%TYPE` দিয়ে, নাম `p_`, ঐচ্ছিকগুলো Default সহ শেষে
4. পরীক্ষা `EXEC` দিয়ে, শেষে `ROLLBACK`

শুরুর আগে: `w14_stock` ৬০০ / ৬০ / ১৮০।

### অংশ ক: Function (৪টা)

1. **`w18_item_exists(p_item_id) RETURN VARCHAR2`**: আইটেম থাকলে `'Y'`, না থাকলে `'N'`। `COUNT(*)` দিয়ে, যাতে NO_DATA_FOUND না আসে।
2. **`w18_stock_balance(p_item_id) RETURN NUMBER`**: ক্লাস ৮৮-এর মতো, না পেলে `-20003`। SQL থেকে আইটেম ১ আর ৯৯ দিয়ে।
3. **`w18_txn_total(p_item_id, p_txn_type, p_from DATE DEFAULT NULL, p_to DATE DEFAULT NULL) RETURN NUMBER`**: আইটেমের একটা ধরনের (`RECEIVE`/`ISSUE`) মোট পরিমাণ, তারিখের সীমা দিলে সেই সীমায়। কিছু না থাকলে ০। `p_txn_type` ভুল হলে `-20006: Type must be RECEIVE or ISSUE`।
4. **`w18_is_low_stock(p_item_id, p_min IN NUMBER DEFAULT 100) RETURN VARCHAR2`**: ক্লাস ৮৮-এর সাথে Default সীমা। SQL-এ Default দিয়ে আর `p_min => 200` দিয়ে। (১টা; ২টা)

### অংশ খ: লগ (১টা)

5. **`w18_log_error(p_module, p_code, p_msg, p_backtrace DEFAULT NULL, p_context DEFAULT NULL)`**: `w17_error_log`-এ একটা রো।
   - এটা নিজে `COMMIT` করে না। কলকারী আগে `ROLLBACK`, তারপর এটা, তারপর `COMMIT` (ক্লাস ৮৫-এর ক্রম)
   - `SQLCODE`/`SQLERRM` Parameter হিসেবে নেয়, কারণ Handler-এর ভেতরেই মান তুলে রাখা নিরাপদ
   - ক্লাস ১০৭-এ এটা Autonomous Transaction হবে, তখন নিজেই `COMMIT` করবে আর কলকারীর কাজে হাত দেবে না

### অংশ গ: স্টক IN/OUT (৩টা)

6. **`w18_stock_receive(p_item_id, p_qty, p_max_receive IN NUMBER DEFAULT 5000, p_txn_id OUT NUMBER)`**:
   - পরিমাণ NULL বা ≤ ০: `-20002`
   - `p_max_receive`-এর বেশি: `-20005: Receive of n looks wrong, check unit`
   - আইটেম নেই: `-20003` (`UPDATE`-এর পরে `SQL%NOTFOUND`)
   - স্টক বাড়াও, `w14_txn`-এ `RECEIVE`, নতুন `txn_id` `p_txn_id`-এ (`RETURNING txn_id INTO p_txn_id`)

7. **`w18_stock_issue(p_item_id, p_qty, p_min_stock DEFAULT 20, p_max_issue DEFAULT 500, p_txn_id OUT NUMBER)`**:
   - সপ্তাহ ১৭-এর স্টক ইস্যুর সব নিয়ম (`-20002`, `-20004`, `-20003`, `-20001`), সীমা এবার Parameter
   - ব্যালেন্স পড়ো `FOR UPDATE` দিয়ে
   - অপ্রত্যাশিত এরর হলে: তথ্য তোলো, `ROLLBACK`, `w18_log_error`, `COMMIT`, `RAISE`। ব্যবসার নিয়ম (`-20xxx`) লগ হবে না, শুধু `RAISE`

8. **`w18_stock_transfer(p_from_item, p_to_item, p_qty)`**: `w18_stock_issue` আর `w18_stock_receive` ডেকে। দুই আইটেম একই হলে `-20007: Cannot transfer to the same item`। একটা ব্যর্থ হলে দুইটাই বাতিল, এজন্য কিছু ধরবে না।

```sql
CREATE OR REPLACE FUNCTION w18_item_exists (

CREATE OR REPLACE FUNCTION w18_stock_balance (
    p_item_id IN w14_stock.item_id%TYPE
) RETURN NUMBER
IS
    v_bal w14_stock.balance_qty%TYPE;
BEGIN
    SELECT balance_qty INTO v_bal FROM w14_stock WHERE item_id = p_item_id;
    RETURN v_bal;
EXCEPTION
    WHEN NO_DATA_FOUND THEN
        RAISE_APPLICATION_ERROR(-20003, 'Item ' || p_item_id || ' not found');
END w18_stock_balance;
/

-- ৩
CREATE OR REPLACE FUNCTION w18_txn_total (
    p_item_id  IN w14_txn.item_id%TYPE,
    p_txn_type IN w14_txn.txn_type%TYPE,
    p_from     IN DATE DEFAULT NULL,
    p_to       IN DATE DEFAULT NULL
) RETURN NUMBER
IS
    v_total NUMBER;
BEGIN
    IF p_txn_type NOT IN ('RECEIVE', 'ISSUE') OR p_txn_type IS NULL THEN
        RAISE_APPLICATION_ERROR(-20006, 'Type must be RECEIVE or ISSUE');
    END IF;

    SELECT NVL(SUM(qty), 0) INTO v_total
    FROM   w14_txn
    WHERE  item_id  = p_item_id
    AND    txn_type = p_txn_type
    AND    (txn_date >= p_from OR p_from IS NULL)
    AND    (txn_date <  p_to + 1 OR p_to IS NULL);
    RETURN v_total;
END w18_txn_total;
/
```

`txn_date < p_to + 1`: `txn_date`-এ সময়ও থাকে (`DEFAULT SYSDATE`)। `<= p_to` দিলে শেষ দিনের দুপুরের লেনদেন বাদ পড়ত (ক্লাস ৩৪-এর তারিখের ফাঁদ)।

```sql
SET SERVEROUTPUT ON

-- ৬
CREATE OR REPLACE PROCEDURE w18_stock_receive (
    p_item_id     IN  w14_stock.item_id%TYPE,
    p_qty         IN  NUMBER,
    p_max_receive IN  NUMBER DEFAULT 5000,
    p_txn_id      OUT w14_txn.txn_id%TYPE
)
IS
BEGIN
    IF p_qty IS NULL OR p_qty <= 0 THEN
        RAISE_APPLICATION_ERROR(-20002, 'Quantity must be more than zero');
    END IF;
    IF p_qty > p_max_receive THEN
        RAISE_APPLICATION_ERROR(-20005, 'Receive of ' || p_qty || ' looks wrong, check unit');
    END IF;

    UPDATE w14_stock SET balance_qty = balance_qty + p_qty WHERE item_id = p_item_id;
    IF SQL%NOTFOUND THEN
        RAISE_APPLICATION_ERROR(-20003, 'Item ' || p_item_id || ' not found');
    END IF;

    INSERT INTO w14_txn (item_id, txn_type, qty)
    VALUES (p_item_id, 'RECEIVE', p_qty)
    RETURNING txn_id INTO p_txn_id;
END w18_stock_receive;
/
```

`RETURNING ... INTO`: `INSERT` যে Identity মান বানাল সেটা সাথে সাথে ফেরত আনে, আলাদা `SELECT` লাগে না। `UPDATE` আর `DELETE`-এও চলে।

`OUT` থাকায় `p_max_receive` Default হলেও `EXEC`-এ সরাসরি বাদ দেওয়া যায় না, Named লাগে (ক্লাস ৯০):

```sql
VARIABLE g_txn NUMBER
EXEC w18_stock_receive(3, 200, p_txn_id => :g_txn);
PRINT g_txn
```

```sql
-- ৭
CREATE OR REPLACE PROCEDURE w18_stock_issue (
    p_item_id   IN  w14_stock.item_id%TYPE,
    p_qty       IN  NUMBER,
    p_min_stock IN  NUMBER DEFAULT 20,
    p_max_issue IN  NUMBER DEFAULT 500,
    p_txn_id    OUT w14_txn.txn_id%TYPE
)
IS
    v_balance w14_stock.balance_qty%TYPE;
    v_code    NUMBER;
    v_msg     VARCHAR2(4000);
    v_bt      VARCHAR2(4000);
BEGIN
    IF p_qty IS NULL OR p_qty <= 0 THEN
        RAISE_APPLICATION_ERROR(-20002, 'Quantity must be more than zero');
    END IF;
    IF p_qty > p_max_issue THEN
        RAISE_APPLICATION_ERROR(-20004, 'Issue of ' || p_qty || ' needs manager approval (limit ' || p_max_issue || ')');
    END IF;

    BEGIN
        SELECT balance_qty INTO v_balance
        FROM   w14_stock
        WHERE  item_id = p_item_id
        FOR UPDATE;
    EXCEPTION
        WHEN NO_DATA_FOUND THEN
            RAISE_APPLICATION_ERROR(-20003, 'Item ' || p_item_id || ' not found');
    END;

    IF v_balance - p_qty < p_min_stock THEN
        RAISE_APPLICATION_ERROR(-20001,
            'Cannot issue ' || p_qty || ': only ' || v_balance || ' in stock, minimum ' || p_min_stock);
    END IF;

    UPDATE w14_stock SET balance_qty = balance_qty - p_qty WHERE item_id = p_item_id;

    INSERT INTO w14_txn (item_id, txn_type, qty)
    VALUES (p_item_id, 'ISSUE', p_qty)
    RETURNING txn_id INTO p_txn_id;
EXCEPTION
    WHEN OTHERS THEN
        v_code := SQLCODE;
        v_msg  := SQLERRM;
        v_bt   := DBMS_UTILITY.FORMAT_ERROR_BACKTRACE;
        IF v_code NOT BETWEEN -20999 AND -20000 THEN
            ROLLBACK;
            w18_log_error('STOCK_ISSUE', v_code, v_msg, v_bt,
                          'item=' || p_item_id || ', qty=' || p_qty);
            COMMIT;
        END IF;
        RAISE;
END w18_stock_issue;
/
```

**সতর্কতা:** অপ্রত্যাশিত এররে এখানে `ROLLBACK` আর `COMMIT` আছে, যা "ছোট Procedure-এ `COMMIT` না" নিয়মের ব্যতিক্রম। এটাই ক্লাস ৮৫-এর দুর্বলতা: কলকারীর আগের কাজও বাতিল হয়। ক্লাস ১০৭-এ `w18_log_error` Autonomous হলে এখানের `ROLLBACK`/`COMMIT` মুছে শুধু `w18_log_error(...)`; `RAISE;` থাকবে।

- **১০:** স্টক কার্ডে Opening-এ সপ্তাহ ১৪-এর আগের ব্যালেন্স আসবে, তারপর প্রতিটা লেনদেন। সবকিছু Procedure দিয়ে হলে শেষে সবসময় `OK`। কেউ সরাসরি `UPDATE w14_stock` করলে (যেমন সপ্তাহ ১৬-এর অনুশীলনে `COMMIT` করে ফেললে) `MISMATCH`, তখন Opening ভুল দেখায়। এজন্যই নিয়ম: স্টক শুধু Procedure দিয়ে বদলাবে
- **১৪:** `%TYPE`-এর জন্য টেবিলও তালিকায় আসতে পারে
- **১৫:** Function চলে (Definer's Rights), টেবিল `ORA-00942`
- **১৬:** লগে `STOCK_ISSUE`, `ORA-01476`, স্টক অপরিবর্তিত (লগের আগের `ROLLBACK`)
