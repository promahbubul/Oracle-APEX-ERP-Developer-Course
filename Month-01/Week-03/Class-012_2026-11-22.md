# ক্লাস ১২: Foreign Key, Not Null, Check ও Default

**তারিখ:** ২২ নভেম্বর ২০২৬, রবিবার
**সময়:** সন্ধ্যা ৭:০০ থেকে রাত ১০:০০
**সপ্তাহ:** ৩ | **ধাপ:** ১ (কম্পিউটার ও ডাটাবেসের বেসিক)

---

## আজকে কী শিখব

- Foreign Key কী, Parent আর Child টেবিল কী
- `ON DELETE CASCADE` আর `ON DELETE SET NULL`
- Not Null দিয়ে মান বাধ্যতামূলক করা
- Check দিয়ে শর্ত বসানো
- Default দিয়ে স্বয়ংক্রিয় মান দেওয়া
- সব Constraint একসাথে একটা টেবিলে ব্যবহার

> আজকের কোড ক্লাস ১১-এর `buyer` আর `style` টেবিল ব্যবহার করে। এগুলো না থাকলে আগে ক্লাস ১১-এর কোড চালাও।

---

## ১. Foreign Key (৬০ মিনিট)

`style` টেবিলে `buyer_id` আছে। কিন্তু এখনো `buyer_id = 99` দেওয়া যায়, যদিও এমন কোনো Buyer নেই। এই ধরনের রো-কে বলে **Orphan (এতিম) রো**।

**Foreign Key (FK)** নিশ্চিত করে: Child টেবিলের মান অবশ্যই Parent টেবিলে থাকতে হবে।

| শব্দ | মানে | উদাহরণ |
|---|---|---|
| **Parent টেবিল** | যার মান ব্যবহার হচ্ছে | `buyer` |
| **Child টেবিল** | যে মান ব্যবহার করছে, FK এখানে থাকে | `style` |

```
buyer (Parent)                    style (Child)
┌──────────┬────────────┐         ┌──────────┬───────────┬──────────┐
│ BUYER_ID │ BUYER_NAME │         │ STYLE_ID │ STYLE_NO  │ BUYER_ID │
├──────────┼────────────┤         ├──────────┼───────────┼──────────┤
│ 1        │ H&M        │ ◄────── │ 1        │ HM-TS-001 │ 1        │
│ 2        │ Zara       │ ◄────── │ 3        │ ZR-HD-001 │ 2        │
└──────────┴────────────┘         └──────────┴───────────┴──────────┘
```

### FK যোগ করা

```sql
ALTER TABLE style ADD CONSTRAINT style_buyer_fk
    FOREIGN KEY (buyer_id) REFERENCES buyer (buyer_id);
```

নাম রাখার নিয়ম: `child_parent_fk`, যেমন `style_buyer_fk`।

### FK দুই দিক থেকে কাজ করে

`Ctrl + Enter` দিয়ে একটা একটা করে চালাও:

```sql
-- ১. Child-এ এমন buyer_id, যা Parent-এ নেই
INSERT INTO style VALUES (4, 'XX-TS-001', 'Test Style', 99);

-- ২. যে Buyer-এর স্টাইল আছে, তাকে মোছা
DELETE FROM buyer WHERE buyer_id = 1;
```

```
ORA-02291: integrity constraint (LEARN.STYLE_BUYER_FK) violated - parent key not found
ORA-02292: integrity constraint (LEARN.STYLE_BUYER_FK) violated - child record found
```

যে Buyer-এর কোনো স্টাইল নেই, তাকে মোছা যায়:

```sql
SET DEFINE OFF

INSERT INTO buyer VALUES (3, 'Walmart', 'USA');
COMMIT;

DELETE FROM buyer WHERE buyer_id = 3;     -- চলবে
ROLLBACK;                                 -- মোছাটা বাতিল, Walmart ফিরে এলো
```

### FK-এর নিয়ম

- FK সবসময় Parent-এর **Primary Key বা Unique** কলামের দিকে যাবে
- দুই কলামের Data Type একই হওয়া উচিত
- আগে Parent-এ ডাটা ঢোকাও, তারপর Child-এ
- মোছার সময় উল্টো: আগে Child, তারপর Parent
- FK কলাম NULL হতে পারে, যদি না Not Null দেওয়া থাকে

Parent-এর সাধারণ কলামের দিকে FK দিলে কী হয়:

```sql
ALTER TABLE style ADD CONSTRAINT style_country_fk
    FOREIGN KEY (style_name) REFERENCES buyer (country);
```

```
ORA-02270: no matching unique or primary key for this column-list
```

### Parent মুছলে Child-এর কী হবে?

| অপশন | Parent মুছলে | কখন |
|---|---|---|
| (কিছু না লিখলে) | মোছা যাবে না, এরর | **ERP-তে প্রায় সবসময়** |
| `ON DELETE CASCADE` | Child রো-ও মুছে যাবে | অর্ডার মুছলে তার লাইন আইটেম |
| `ON DELETE SET NULL` | Child-এর FK কলাম NULL হবে | সুপারভাইজার চলে গেলে লাইনের সুপারভাইজার খালি |

```sql
CREATE TABLE test_po (
    po_id  NUMBER(10) CONSTRAINT test_po_pk PRIMARY KEY,
    po_no  VARCHAR2(20)
);

CREATE TABLE test_po_line (
    line_id  NUMBER(10) CONSTRAINT test_po_line_pk PRIMARY KEY,
    po_id    NUMBER(10),
    qty      NUMBER(10),
    CONSTRAINT test_po_line_po_fk FOREIGN KEY (po_id)
        REFERENCES test_po (po_id) ON DELETE CASCADE
);

INSERT INTO test_po VALUES (1, 'PO-001');
INSERT INTO test_po_line VALUES (1, 1, 100);
INSERT INTO test_po_line VALUES (2, 1, 200);
COMMIT;

DELETE FROM test_po WHERE po_id = 1;

SELECT * FROM test_po_line;     -- কোনো রো নেই, সব মুছে গেছে
```

> **সাবধান:** `CASCADE` ভুল জায়গায় দিলে একটা Buyer মুছতেই তার সব স্টাইল আর অর্ডার মুছে যেতে পারে। ERP-তে সাধারণত রেকর্ড না মুছে `is_active = 'N'` করা হয়।

### Parent টেবিল DROP করা

```sql
DROP TABLE buyer;
```

```
ORA-02449: unique/primary keys in table referenced by foreign keys
```

`DROP TABLE buyer CASCADE CONSTRAINTS;` দিলে টেবিল মুছে যায়, আর Child-এর FK-ও বাদ যায়। এখন এটা চালাবে না, শুধু জেনে রাখো।

## ২. Not Null (১৫ মিনিট)

**Not Null** মানে কলাম খালি রাখা যাবে না।

```sql
CREATE TABLE test_unit (
    unit_id    NUMBER(5)    CONSTRAINT test_unit_pk PRIMARY KEY,
    unit_name  VARCHAR2(20) CONSTRAINT test_unit_name_nn NOT NULL
);

INSERT INTO test_unit VALUES (1, 'Kg');      -- চলবে
INSERT INTO test_unit VALUES (2, NULL);      -- এরর ORA-01400
INSERT INTO test_unit VALUES (3, '');        -- এরর ORA-01400, '' মানে NULL
```

আগের টেবিলের কলামে যোগ করতে:

```sql
ALTER TABLE buyer MODIFY buyer_name NOT NULL;
```

পুরনো ডাটায় NULL থাকলে `ORA-02296` আসে। আগে সেই ডাটা ঠিক করতে হয়।

**কোন কলামে দেবে?** যেটা ছাড়া রেকর্ডের মানে থাকে না: নাম, তারিখ, পরিমাণ, প্রয়োজনীয় FK। মন্তব্য বা ঐচ্ছিক ফোন নম্বরে না।

> **Unique + Not Null:** এই দুইটা একসাথে দিলে কলামে মান থাকতেই হবে, আর একই মান দুইবার হবে না। যেমন: `style_no`।

## ৩. Check (৩০ মিনিট)

**Check** হলো নিজের লেখা শর্ত। শর্ত না মানলে ডাটা ঢোকে না।

```sql
CREATE TABLE test_check (
    item_id     NUMBER(10) CONSTRAINT test_check_pk PRIMARY KEY,
    qty         NUMBER(10),
    is_active   CHAR(1),
    start_date  DATE,
    end_date    DATE,
    CONSTRAINT test_check_qty_ck    CHECK (qty > 0),
    CONSTRAINT test_check_active_ck CHECK (is_active IN ('Y', 'N')),
    CONSTRAINT test_check_date_ck   CHECK (end_date >= start_date)
);

INSERT INTO test_check VALUES (1, 100, 'Y', DATE '2026-11-01', DATE '2026-11-30');   -- চলবে
INSERT INTO test_check VALUES (2, -5, 'Y', NULL, NULL);                              -- এরর
INSERT INTO test_check VALUES (3, 100, 'X', NULL, NULL);                             -- এরর
INSERT INTO test_check VALUES (4, 100, 'N', DATE '2026-11-30', DATE '2026-11-01');   -- এরর
```

```
ORA-02290: check constraint (LEARN.TEST_CHECK_QTY_CK) violated
```

### ERP-তে সাধারণ Check

| কাজ | শর্ত |
|---|---|
| পরিমাণ ধনাত্মক | `CHECK (qty > 0)` |
| Y/N | `CHECK (is_active IN ('Y', 'N'))` |
| নির্দিষ্ট স্ট্যাটাস | `CHECK (status IN ('OPEN', 'SHIPPED', 'CANCELLED'))` |
| সীমার মধ্যে | `CHECK (efficiency_pct BETWEEN 0 AND 150)` |
| দুই কলাম তুলনা | `CHECK (ship_date >= order_date)` |

### দুইটা ফাঁদ

**ফাঁদ ১: NULL শর্ত পার হয়ে যায়।**

```sql
INSERT INTO test_check (item_id, qty) VALUES (5, NULL);   -- চলবে!
```

`NULL > 0` সত্যও না, মিথ্যাও না। Check শুধু **মিথ্যা** হলে আটকায়। খালি রাখতে না চাইলে Not Null-ও দাও।

**ফাঁদ ২: Check-এ `SYSDATE` ব্যবহার করা যায় না।**

```sql
ALTER TABLE test_check ADD CONSTRAINT test_check_past_ck
    CHECK (start_date >= SYSDATE);
```

```
ORA-02436: date or system variable wrongly specified in CHECK constraint
```

"তারিখ আজকের আগে হবে না" এই ধরনের নিয়ম পরে APEX Validation বা Trigger দিয়ে করব।

## ৪. Default (১৫ মিনিট)

**Default** হলো সেই মান, যা `INSERT`-এ কলামটা না লিখলে নিজে থেকে বসে।

```sql
CREATE TABLE test_default (
    id          NUMBER(10)  CONSTRAINT test_default_pk PRIMARY KEY,
    is_active   CHAR(1)     DEFAULT 'Y',
    created_on  DATE        DEFAULT SYSDATE
);

INSERT INTO test_default (id) VALUES (1);                            -- Y আর আজকের তারিখ বসবে
INSERT INTO test_default (id, is_active) VALUES (2, 'N');            -- নিজের দেওয়া মান
INSERT INTO test_default (id, is_active) VALUES (3, NULL);           -- NULL-ই বসবে!
COMMIT;

SELECT * FROM test_default;
```

**মনে রাখো:** Default কাজ করে শুধু কলামটা **না লিখলে**। `NULL` নিজে লিখে দিলে NULL-ই বসে। আর Default আসলে Constraint না, তাই এটা কোনো ডাটা আটকায় না।

লেখার ক্রম: আগে `DEFAULT`, তারপর Constraint:

```sql
status VARCHAR2(20) DEFAULT 'OPEN' NOT NULL
```

## ৫. সব একসাথে (২০ মিনিট)

```sql
CREATE TABLE orders (
    order_id    NUMBER(10),
    order_no    VARCHAR2(20)  NOT NULL,
    style_id    NUMBER(10)    NOT NULL,
    order_qty   NUMBER(10)    NOT NULL,
    order_date  DATE          DEFAULT TRUNC(SYSDATE) NOT NULL,
    ship_date   DATE,
    status      VARCHAR2(20)  DEFAULT 'OPEN' NOT NULL,
    CONSTRAINT orders_pk           PRIMARY KEY (order_id),
    CONSTRAINT orders_order_no_uk  UNIQUE (order_no),
    CONSTRAINT orders_style_fk     FOREIGN KEY (style_id) REFERENCES style (style_id),
    CONSTRAINT orders_qty_ck       CHECK (order_qty > 0),
    CONSTRAINT orders_status_ck    CHECK (status IN ('OPEN', 'SHIPPED', 'CANCELLED')),
    CONSTRAINT orders_ship_date_ck CHECK (ship_date >= order_date)
);

INSERT INTO orders (order_id, order_no, style_id, order_qty, ship_date)
VALUES (1, 'ORD-001', 1, 5000, TRUNC(SYSDATE) + 60);

INSERT INTO orders (order_id, order_no, style_id, order_qty)
VALUES (2, 'ORD-002', 3, 3000);
COMMIT;

SELECT * FROM orders;
```

`order_date` আর `status` আমরা দিইনি, নিজে থেকে বসেছে। `ORD-002`-এর `ship_date` খালি থাকা সত্ত্বেও Check আটকায়নি।

**প্রতিটা নিয়ম ভেঙে দেখো:**

| ভুল | INSERT-এর মান | এরর |
|---|---|---|
| একই order_no | `(3, 'ORD-001', 1, 100)` | ORA-00001 |
| Style নেই | `(3, 'ORD-003', 99, 100)` | ORA-02291 |
| পরিমাণ ০ | `(3, 'ORD-003', 1, 0)` | ORA-02290 |
| order_no খালি | `(3, NULL, 1, 100)` | ORA-01400 |

এগুলো চালাবে এভাবে: `INSERT INTO orders (order_id, order_no, style_id, order_qty) VALUES (...);`

### Data Dictionary থেকে দেখা

```sql
SELECT constraint_name, constraint_type, search_condition, r_constraint_name
FROM   user_constraints
WHERE  table_name = 'ORDERS';
```

- `search_condition`: Check-এর শর্ত
- `r_constraint_name`: FK কোন Parent Key-এর দিকে গেছে
- নাম না দেওয়া Not Null-গুলো `SYS_C...` নামে দেখাবে, এগুলো `C` টাইপ

### এই ক্লাসের এরর

| এরর | কারণ |
|---|---|
| `ORA-02291` | Child-এ এমন মান, যা Parent-এ নেই |
| `ORA-02292` | Child রো আছে, তাই Parent মোছা যাচ্ছে না |
| `ORA-02270` | FK যে কলামের দিকে, সেটা PK বা Unique না |
| `ORA-02298` | পুরনো Child ডাটায় Orphan আছে, তাই FK বসছে না |
| `ORA-02449` | Child আছে, তাই Parent টেবিল DROP হচ্ছে না |
| `ORA-02290` | Check-এর শর্ত মানেনি |
| `ORA-02296` | পুরনো ডাটায় NULL আছে, তাই Not Null বসছে না |
| `ORA-01400` | Not Null কলামে NULL দিয়েছ |

## ৬. হাতে-কলমে প্র্যাকটিস (৪০ মিনিট)

**কাজ ১:** সপ্তাহ ২-এর Store টেবিলগুলো শক্ত করো (ক্লাস ১১-এ এগুলোতে PK দিয়েছ):

1. FK: `item.category_id` → `item_category`, `goods_receive.item_id` → `item`, `goods_receive.supplier_id` → `supplier`, `goods_issue.item_id` → `item`
2. Not Null: `item.item_name`, `supplier.supplier_name`, `goods_receive`-এর `receive_date` আর `qty`
3. Check: `goods_receive.qty > 0`, `goods_issue.qty > 0`, `supplier.is_active` শুধু Y বা N

**কাজ ২:** ক্লাস ১১-এর `style_item` টেবিলে `style` আর `item`-এর দিকে দুইটা FK দাও।

**কাজ ৩:** চালানোর আগে আন্দাজ করো কোনটা চলবে আর কোনটা এরর দেবে।

```sql
CREATE TABLE test_dept (
    dept_id    NUMBER(5)    CONSTRAINT test_dept_pk PRIMARY KEY,
    dept_name  VARCHAR2(50) CONSTRAINT test_dept_name_nn NOT NULL
);

CREATE TABLE test_emp (
    emp_id   NUMBER(5) CONSTRAINT test_emp_pk PRIMARY KEY,
    dept_id  NUMBER(5),
    salary   NUMBER(10,2),
    CONSTRAINT test_emp_dept_fk FOREIGN KEY (dept_id) REFERENCES test_dept (dept_id),
    CONSTRAINT test_emp_salary_ck CHECK (salary > 0)
);

INSERT INTO test_dept VALUES (10, 'Cutting');
INSERT INTO test_dept VALUES (20, 'Sewing');

INSERT INTO test_emp VALUES (1, 10, 15000);       -- ১
INSERT INTO test_emp VALUES (2, 30, 15000);       -- ২
INSERT INTO test_emp VALUES (3, NULL, 15000);     -- ৩
INSERT INTO test_emp VALUES (4, 10, -5);          -- ৪
INSERT INTO test_emp VALUES (5, 10, NULL);        -- ৫
DELETE FROM test_dept WHERE dept_id = 10;         -- ৬
DELETE FROM test_dept WHERE dept_id = 20;         -- ৭
COMMIT;
```

## ৭. হোমওয়ার্ক

1. `purchase_order` টেবিল বানাও: po_id (PK), po_no (Unique, Not Null), supplier_id (FK, Not Null), po_date (Default আজকের তারিখ), total_amount (০-এর বেশি), status (`DRAFT`, `APPROVED`, `CLOSED`, Default `DRAFT`)। ২টা ডাটা ঢোকাও।
2. ওই টেবিলের প্রতিটা Constraint ভেঙে একটা করে এরর দেখো, আর এরর কোডগুলো খাতায় লেখো।
3. ভাবো আর লেখো: `ON DELETE CASCADE` গার্মেন্টস ERP-র কোন টেবিলে দেওয়া ঠিক হবে না? ২টা উদাহরণ, কারণসহ।

<details>
<summary>হোমওয়ার্কের সমাধান</summary>

**১:**

```sql
CREATE TABLE purchase_order (
    po_id         NUMBER(10),
    po_no         VARCHAR2(20)  NOT NULL,
    supplier_id   NUMBER(10)    NOT NULL,
    po_date       DATE          DEFAULT TRUNC(SYSDATE) NOT NULL,
    total_amount  NUMBER(12,2),
    status        VARCHAR2(20)  DEFAULT 'DRAFT' NOT NULL,
    CONSTRAINT purchase_order_pk          PRIMARY KEY (po_id),
    CONSTRAINT purchase_order_po_no_uk    UNIQUE (po_no),
    CONSTRAINT purchase_order_supplier_fk FOREIGN KEY (supplier_id) REFERENCES supplier (supplier_id),
    CONSTRAINT purchase_order_amount_ck   CHECK (total_amount > 0),
    CONSTRAINT purchase_order_status_ck   CHECK (status IN ('DRAFT', 'APPROVED', 'CLOSED'))
);

INSERT INTO purchase_order (po_id, po_no, supplier_id, total_amount) VALUES (1, 'PO-001', 1, 5040.00);
INSERT INTO purchase_order (po_id, po_no, supplier_id, total_amount, status) VALUES (2, 'PO-002', 2, 7750.00, 'APPROVED');
COMMIT;
```

**৩:** যেমন `supplier` → `goods_receive`, কারণ সাপ্লায়ার মুছলে মাল গ্রহণের পুরনো হিসাব হারিয়ে যাবে। `buyer` → `style`, কারণ Buyer মুছলে তার সব স্টাইলের রেকর্ড হারাবে। হিসাবের রেকর্ড মোছা ঠিক না।

</details>

## ৮. কুইজ

1. Foreign Key কোন টেবিলে থাকে, Parent না Child?
2. `ORA-02291` আর `ORA-02292`-এর পার্থক্য কী?
3. `ON DELETE CASCADE` কী করে?
4. Check-এর কলামে NULL দিলে কী হয়?
5. `INSERT`-এ Default কলামে নিজে `NULL` লিখলে কী বসবে?

<details>
<summary>উত্তর দেখো</summary>

1. Child টেবিলে
2. `ORA-02291`: Child-এ দেওয়া মান Parent-এ নেই। `ORA-02292`: Child রো থাকায় Parent মোছা যাচ্ছে না
3. Parent রো মুছলে তার সব Child রো-ও মুছে দেয়
4. ডাটা ঢুকে যায়, কারণ শর্ত মিথ্যা হয়নি। আটকাতে Not Null লাগে
5. NULL বসবে, Default কাজ করবে না

</details>

## সারাংশ

- Foreign Key: Child-এর মান Parent-এ থাকতে হবে, Parent-এর PK বা Unique-এর দিকে যায়
- ERP-তে সাধারণত `CASCADE` না দিয়ে মোছা আটকানো হয়
- Not Null: মান বাধ্যতামূলক
- Check: নিজের শর্ত, তবে NULL আটকায় না, আর `SYSDATE` চলে না
- Default: কলাম না লিখলে নিজে থেকে বসা মান

**পরের ক্লাস:** Relationship: One-to-One, One-to-Many।
