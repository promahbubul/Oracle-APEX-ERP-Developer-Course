# ক্লাস ১১: Primary Key ও Unique Key

**তারিখ:** ২১ নভেম্বর ২০২৬, শনিবার
**সময়:** সন্ধ্যা ৭:০০ থেকে রাত ১০:০০
**সপ্তাহ:** ৩ | **ধাপ:** ১ (কম্পিউটার ও ডাটাবেসের বেসিক)

---

## আজকে কী শিখব

- Constraint কী, কেন লাগে
- Primary Key কী, কীভাবে বানায়
- একাধিক কলাম মিলে Primary Key (Composite Key)
- Unique Key কী
- Primary Key আর Unique Key-এর পার্থক্য
- Constraint-এর নাম দেওয়া আর Data Dictionary থেকে দেখা
- সপ্তাহ ২-এর টেবিলগুলোতে Key যোগ করা

---

## ১. Constraint কেন লাগে (২০ মিনিট)

সপ্তাহ ২-এর প্র্যাকটিসে দেখেছিলাম, আমাদের টেবিলে একই ID দুইবার দেওয়া যায়। নিজে দেখো:

| BUYER_ID | BUYER_NAME |
|---|---|
| 1 | H&M |
| 1 | Zara |

`BUYER_ID = 1` বললে কোন Buyer বোঝাবে? H&M, নাকি Zara? এই ডাটা দিয়ে অর্ডার, ইনভয়েস, সবকিছুতে ভুল হবে।

**Constraint** হলো টেবিলের উপর বসানো নিয়ম। নিয়ম ভাঙে এমন ডাটা Oracle ঢুকতেই দেয় না।

| Constraint | কাজ | কবে শিখব |
|---|---|---|
| **Primary Key** | প্রতিটা রো আলাদাভাবে চেনা | আজ |
| **Unique** | একই মান দুইবার না | আজ |
| Foreign Key | অন্য টেবিলের সাথে সম্পর্ক | কাল |
| Not Null | মান খালি রাখা যাবে না | কাল |
| Check | নির্দিষ্ট শর্ত মানতে হবে | কাল |

**কেন Excel বা APEX ফর্মের উপর ভরসা না করে ডাটাবেসে নিয়ম রাখব?** ডাটা অনেক পথে ঢুকতে পারে: ফর্ম, Excel ইমপোর্ট, API, সরাসরি SQL। ডাটাবেসের নিয়ম সব পথেই কাজ করে।

---

## ২. Primary Key (৪০ মিনিট)

**Primary Key (PK)** হলো সেই কলাম, যা দিয়ে টেবিলের প্রতিটা রো আলাদাভাবে চেনা যায়।

PK-এর নিয়ম:
- মান **ইউনিক** হতে হবে, একই মান দুইবার না
- মান **খালি (NULL)** হতে পারবে না
- একটা টেবিলে PK থাকবে **মাত্র একটা**

### PK বানানো

`learn_freepdb1` কানেকশনে চালাও:

```sql
SET DEFINE OFF

CREATE TABLE buyer (
    buyer_id    NUMBER(10)    CONSTRAINT buyer_pk PRIMARY KEY,
    buyer_name  VARCHAR2(100),
    country     VARCHAR2(50)
);

INSERT INTO buyer VALUES (1, 'H&M', 'Sweden');
INSERT INTO buyer VALUES (2, 'Zara', 'Spain');
COMMIT;
```

- `CONSTRAINT buyer_pk`: Constraint-এর নাম
- `PRIMARY KEY`: Constraint-এর ধরন

> `buyer` টেবিল আগে থেকে থাকলে `ORA-00955` আসবে। তখন `DROP TABLE buyer;` চালিয়ে আবার বানাও।

### এবার নিয়ম ভাঙার চেষ্টা করো

`Ctrl + Enter` দিয়ে একটা একটা করে চালাও:

```sql
-- একই ID আবার
INSERT INTO buyer VALUES (1, 'Primark', 'Ireland');

-- ID খালি
INSERT INTO buyer VALUES (NULL, 'Walmart', 'USA');
```

এরর আসবে (নতুন ভার্সনে লেখা আরেকটু লম্বা হতে পারে):

```
ORA-00001: unique constraint (LEARN.BUYER_PK) violated
ORA-01400: cannot insert NULL into ("LEARN"."BUYER"."BUYER_ID")
```

খেয়াল করো, এররে Constraint-এর নাম `BUYER_PK` দেখাচ্ছে। তাই নাম দেখেই বোঝা যায় কোন নিয়ম ভেঙেছে।

### নাম না দিলে কী হয়?

```sql
CREATE TABLE test_noname (
    id NUMBER PRIMARY KEY
);
```

এটাও চলে, কিন্তু Oracle নিজে `SYS_C008123`-এর মতো নাম দেয়। এরর এলে এই নাম দেখে কিছু বোঝা যায় না। **তাই সবসময় নিজে নাম দেবে।**

### নাম রাখার নিয়ম

| Constraint | নিয়ম | উদাহরণ |
|---|---|---|
| Primary Key | `টেবিল_pk` | `buyer_pk` |
| Unique | `টেবিল_কলাম_uk` | `style_style_no_uk` |

### PK লেখার দুই উপায়

**উপায় ১: কলামের পাশে (Column Level)**, যেটা উপরে করেছি।

**উপায় ২: সব কলামের শেষে (Table Level)**

```sql
CREATE TABLE fabric_type (
    fabric_type_id  NUMBER(10),
    type_name       VARCHAR2(50),
    CONSTRAINT fabric_type_pk PRIMARY KEY (fabric_type_id)
);
```

দুইটার ফল একই। তবে একাধিক কলাম মিলে Key হলে উপায় ২-ই লাগবে।

### একটা টেবিলে দুইটা PK?

```sql
CREATE TABLE test_two_pk (
    a NUMBER PRIMARY KEY,
    b NUMBER PRIMARY KEY
);
```

```
ORA-02260: table can have only one primary key
```

> **ID কোথা থেকে আসবে?** এখন হাতে লিখছি। বাস্তবে Oracle নিজেই নম্বর দেয়, সেটা শিখব সপ্তাহ ১১-তে (Sequence, Identity Column)।

## ৩. Composite Primary Key (২০ মিনিট)

কখনো একটা কলাম দিয়ে রো চেনা যায় না, কয়েকটা কলাম মিলে চিনতে হয়। একে বলে **Composite Key**।

উদাহরণ: একটা অর্ডারের Color-Size ব্রেকডাউন।

| ORDER_NO | COLOR_NAME | SIZE_CODE | ORDER_QTY |
|---|---|---|---|
| ORD-001 | Black | S | 500 |
| ORD-001 | Black | M | 800 |
| ORD-001 | White | S | 300 |

এখানে `ORD-001` বারবার আসছে, `Black` আর `S`-ও। কিন্তু **তিনটা মিলে** একবারই আসে।

```sql
CREATE TABLE order_size_qty (
    order_no    VARCHAR2(20),
    color_name  VARCHAR2(30),
    size_code   VARCHAR2(10),
    order_qty   NUMBER(10),
    CONSTRAINT order_size_qty_pk PRIMARY KEY (order_no, color_name, size_code)
);

INSERT INTO order_size_qty VALUES ('ORD-001', 'Black', 'S', 500);
INSERT INTO order_size_qty VALUES ('ORD-001', 'Black', 'M', 800);
INSERT INTO order_size_qty VALUES ('ORD-001', 'White', 'S', 300);
COMMIT;

-- তিনটা মিলে আগেই আছে, তাই এরর
INSERT INTO order_size_qty VALUES ('ORD-001', 'Black', 'S', 100);
```

**মনে রাখো:** এটা এখনো **একটাই** PK, শুধু তিনটা কলাম নিয়ে। আর তিনটা কলামের কোনোটাই খালি রাখা যাবে না।

> কলামের নাম `size` দিইনি, কারণ `SIZE` Oracle-এর Reserved word।

## ৪. Unique Key (৩০ মিনিট)

**Unique Key (UK)** নিশ্চিত করে একই মান দুইবার ঢুকবে না। PK ছাড়াও অন্য যেসব কলামের মান ইউনিক হওয়া দরকার, সেখানে এটা বসে।

উদাহরণ: `style_id` হলো PK, কিন্তু `style_no`-ও দুইবার হওয়া চলবে না।

```sql
CREATE TABLE style (
    style_id    NUMBER(10),
    style_no    VARCHAR2(30),
    style_name  VARCHAR2(100),
    buyer_id    NUMBER(10),
    CONSTRAINT style_pk PRIMARY KEY (style_id),
    CONSTRAINT style_style_no_uk UNIQUE (style_no)
);

INSERT INTO style VALUES (1, 'HM-TS-001', 'Basic T-Shirt', 1);
INSERT INTO style VALUES (2, 'HM-PL-002', 'Pique Polo', 1);
INSERT INTO style VALUES (3, 'ZR-HD-001', 'Fleece Hoodie', 2);
COMMIT;

-- ID নতুন, কিন্তু style_no পুরনো, তাই এরর
INSERT INTO style VALUES (4, 'HM-TS-001', 'Another Shirt', 1);
```

```
ORA-00001: unique constraint (LEARN.STYLE_STYLE_NO_UK) violated
```

### একটা টেবিলে অনেক Unique Key, আর NULL চলে

```sql
CREATE TABLE worker (
    worker_id  NUMBER(10),
    emp_code   VARCHAR2(20),
    nid_no     VARCHAR2(20),
    mobile_no  VARCHAR2(20),
    CONSTRAINT worker_pk PRIMARY KEY (worker_id),
    CONSTRAINT worker_emp_code_uk UNIQUE (emp_code),
    CONSTRAINT worker_nid_no_uk UNIQUE (nid_no),
    CONSTRAINT worker_mobile_no_uk UNIQUE (mobile_no)
);

INSERT INTO worker VALUES (1, 'EMP-0001', '1990123456', '01711000001');
INSERT INTO worker VALUES (2, 'EMP-0002', NULL, '01811000002');
INSERT INTO worker VALUES (3, 'EMP-0003', NULL, '01911000003');
COMMIT;

-- মোবাইল নম্বর আগেই আছে, তাই এরর
INSERT INTO worker VALUES (4, 'EMP-0004', NULL, '01711000001');
```

দুইজনের `nid_no` খালি, তবু কোনো এরর আসেনি। **NULL মানে "মান জানা নেই", তাই দুইটা NULL-কে Oracle একই মান ধরে না।** কলামটা খালিও রাখা যাবে না চাইলে Unique-এর সাথে Not Null লাগবে, সেটা কাল শিখব।

### দুইটা ফাঁদ

**ফাঁদ ১: খালি লেখা `''` Oracle-এ NULL।** তাই `''` দুইবার ঢোকালেও Unique Key আটকায় না।

**ফাঁদ ২: Unique Key ছোট-বড় হাতের অক্ষর আলাদা ধরে।**

```sql
-- 'HM-TS-001' আছে, কিন্তু এটা ঢুকে যাবে
INSERT INTO style VALUES (5, 'hm-ts-001', 'Lowercase Style', 1);

SELECT * FROM style;

-- COMMIT দিইনি, তাই এটা বাতিল করা যাবে
ROLLBACK;
```

বাস্তবে এই সমস্যা আটকানো হয় ডাটা ঢোকানোর সময় `UPPER` করে, অথবা Function-based Index দিয়ে (সপ্তাহ ১১)।

## ৫. Primary Key বনাম Unique Key (১৫ মিনিট)

| | Primary Key | Unique Key |
|---|---|---|
| একই মান দুইবার | না | না |
| NULL | **না** | **হ্যাঁ** |
| টেবিলে কয়টা | **মাত্র ১টা** | **যতগুলো দরকার** |
| কাজ | রো চেনা | ব্যবসার নিয়ম রক্ষা |
| উদাহরণ | `style_id` | `style_no`, `mobile_no` |

দুইটার জন্যই Oracle নিজে থেকে একটা **Index** বানায়, তাই এই কলামে খোঁজা দ্রুত হয়। Index বিস্তারিত সপ্তাহ ১১-তে।

### PK-র জন্য কোন কলাম নেব?

| ধরন | মানে | উদাহরণ |
|---|---|---|
| **Natural Key** | বাস্তব জীবনের মান | `style_no`, `nid_no` |
| **Surrogate Key** | শুধু চেনার জন্য বানানো নম্বর | `style_id` |

**ERP-তে সাধারণত Surrogate Key-কে PK করা হয়, আর Natural Key-তে Unique বসানো হয়।** কারণ:
- PK-র মান কখনো বদলানো উচিত না, অন্য টেবিল এটার উপর নির্ভর করে
- Buyer স্টাইল নম্বর বদলে দিলে শুধু `style_no` বদলালেই হয়
- সংখ্যার ID ছোট, সম্পর্ক তৈরি করা সহজ

## ৬. Data Dictionary থেকে Constraint দেখা (১৫ মিনিট)

```sql
-- আমার টেবিলের Constraint
SELECT constraint_name, constraint_type, table_name
FROM   user_constraints
WHERE  table_name IN ('BUYER', 'STYLE', 'WORKER')
ORDER  BY table_name;

-- কোন Constraint কোন কলামে
SELECT constraint_name, column_name, position
FROM   user_cons_columns
WHERE  table_name = 'ORDER_SIZE_QTY'
ORDER  BY position;

-- Oracle নিজে যেসব Index বানিয়েছে
SELECT index_name, table_name, uniqueness
FROM   user_indexes
WHERE  table_name = 'WORKER';
```

| `constraint_type` | মানে |
|---|---|
| `P` | Primary Key |
| `U` | Unique |
| `R` | Foreign Key (Reference) |
| `C` | Check, Not Null-ও এখানে দেখায় |

`DESC buyer` চালিয়ে দেখো: `BUYER_ID`-এর পাশে `NOT NULL` লেখা। PK দিলে কলামটা নিজে থেকেই Not Null হয়ে যায়।

### এই ক্লাসের এরর

| এরর | কারণ |
|---|---|
| `ORA-00001` | PK বা Unique-এর মান আগে থেকেই আছে |
| `ORA-01400` | NULL দেওয়া যাবে না এমন কলামে NULL দিয়েছ |
| `ORA-02260` | একটা টেবিলে দুইটা PK দিতে চেয়েছ |
| `ORA-02437` | পুরনো ডাটায় ডুপ্লিকেট আছে, তাই PK বসানো যাচ্ছে না |
| `ORA-02299` | পুরনো ডাটায় ডুপ্লিকেট আছে, তাই Unique বসানো যাচ্ছে না |
| `ORA-01449` | পুরনো ডাটায় NULL আছে, তাই PK বসানো যাচ্ছে না |

## ৭. হাতে-কলমে প্র্যাকটিস (৪০ মিনিট)

**কাজ ১:** সপ্তাহ ২-এর প্র্যাকটিসের ৫টা টেবিলে PK যোগ করো। আগে থেকে থাকা টেবিলে Constraint যোগ করতে লেখা হয় এভাবে (`ALTER TABLE` বিস্তারিত সপ্তাহ ৫-এ):

```sql
ALTER TABLE item_category ADD CONSTRAINT item_category_pk PRIMARY KEY (category_id);
```

বাকি ৪টা নিজে লেখো। তারপর এই দুই জায়গায় Unique যোগ করো: `item_category.category_name` আর `supplier.mobile_no`।

**কাজ ২:** চালানোর আগে আন্দাজ করো কোনটা চলবে আর কোনটা এরর দেবে। তারপর চালিয়ে মিলাও।

```sql
CREATE TABLE test_key (
    id    NUMBER        CONSTRAINT test_key_pk PRIMARY KEY,
    code  VARCHAR2(10)  CONSTRAINT test_key_code_uk UNIQUE
);

INSERT INTO test_key VALUES (1, 'A');
INSERT INTO test_key VALUES (2, 'A');
INSERT INTO test_key VALUES (3, NULL);
INSERT INTO test_key VALUES (4, NULL);
INSERT INTO test_key VALUES (4, 'B');
INSERT INTO test_key VALUES (NULL, 'C');
INSERT INTO test_key VALUES (5, 'a');
INSERT INTO test_key VALUES (6, '');
```

**কাজ ৩:** `style_item` টেবিল বানাও: কোন স্টাইলে কোন আইটেম কতটা লাগে। কলাম: `style_id`, `item_id`, `qty_per_pc`। একটা স্টাইলে একটা আইটেম একবারই থাকবে, তাই কোন PK দেবে ভাবো। ৩টা ডাটা ঢুকিয়ে একটা ডুপ্লিকেট দিয়ে এরর দেখো।

নিজের টেবিলে কলামের নাম আলাদা হলে সেই নাম দাও। ডুপ্লিকেট বা NULL-এর এরর এলে আগে সেই ডাটা ঠিক করো।

## ৮. হোমওয়ার্ক

1. ক্লাস ৬-এর `accessories` টেবিলে `acc_id`-তে PK আর `acc_name`-এ Unique যোগ করো। `sewing_line` টেবিলে `line_id`-তে PK আর `line_name`-এ Unique যোগ করো।
2. নিচের প্রতিটা টেবিলে কোন কলাম PK হবে আর কোনটায় Unique লাগবে, কারণসহ খাতায় লেখো:
   - `customer`: customer_id, customer_name, email, mobile_no
   - `invoice`: invoice_id, invoice_no, invoice_date, amount
   - `line_target`: line_id, target_date, target_qty (প্রতিদিন প্রতি লাইনে একটাই টার্গেট)
3. `user_constraints` থেকে তোমার সব টেবিলের Constraint-এর তালিকা দেখো। কোনো নাম `SYS_C` দিয়ে শুরু হলে সেটা কোন টেবিলের, খুঁজে বের করো।

## ৯. কুইজ

1. Constraint কী?
2. Primary Key-র ২টা নিয়ম বলো।
3. একটা টেবিলে কয়টা Primary Key আর কয়টা Unique Key থাকতে পারে?
4. Unique কলামে দুইটা রো-তে NULL রাখা যায় কি?
5. `ORA-00001` কখন আসে?

<details>
<summary>উত্তর দেখো</summary>

1. টেবিলের উপর বসানো নিয়ম, যা ভুল ডাটা ঢুকতে দেয় না
2. মান ইউনিক হতে হবে, আর NULL হতে পারবে না
3. Primary Key ১টা, Unique Key যতগুলো দরকার
4. হ্যাঁ, রাখা যায়
5. Primary Key বা Unique কলামে আগে থেকে থাকা মান আবার দিলে

</details>

## সারাংশ

- Constraint হলো ডাটাবেসের নিয়ম, যা সব পথে আসা ডাটায় কাজ করে
- Primary Key: ইউনিক, NULL না, টেবিলে একটাই (কয়েকটা কলাম মিলেও হতে পারে)
- Unique Key: ইউনিক, NULL চলে, যতগুলো দরকার
- ERP-তে সাধারণত `style_id` PK, আর `style_no` Unique
- Constraint-এর নাম সবসময় নিজে দেবে: `buyer_pk`, `style_style_no_uk`

**পরের ক্লাস:** Foreign Key, Not Null, Check, Default।
