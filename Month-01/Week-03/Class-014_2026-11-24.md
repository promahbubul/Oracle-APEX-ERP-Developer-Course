# ক্লাস ১৪: Many-to-Many ও Junction Table

**তারিখ:** ২৪ নভেম্বর ২০২৬, মঙ্গলবার
**সময়:** সন্ধ্যা ৭:০০ থেকে রাত ১০:০০
**সপ্তাহ:** ৩ | **ধাপ:** ১ (কম্পিউটার ও ডাটাবেসের বেসিক)

---

## আজকে কী শিখব

- Many-to-Many সম্পর্ক কী
- কেন দুই টেবিলে FK দিয়ে এটা বানানো যায় না
- Junction Table কী, কীভাবে বানায়
- Junction Table-এ বাড়তি তথ্য রাখা
- Composite PK নাকি আলাদা ID

---

## ১. Many-to-Many-র সমস্যা (৩০ মিনিট)

উদাহরণ: Supplier আর Item।
- একটা Supplier **অনেক** Item দেয়: ABC Textile দেয় Single Jersey, Pique
- একটা Item **অনেক** Supplier দেয়: Cotton Yarn দেয় ABC Textile, XYZ Spinning

দুই দিকেই "অনেক", তাই এটা **Many-to-Many (M:N)**।

### ভুল উপায়গুলো

**ভুল ১: `item` টেবিলে `supplier_id`**

| ITEM_ID | ITEM_NAME | SUPPLIER_ID |
|---|---|---|
| 3 | Cotton Yarn 30/1 | 1 |

একটা Item-এর জন্য একটাই Supplier রাখা গেল। দ্বিতীয় Supplier-এর জন্য একই আইটেমের আরেকটা রো লাগবে, তখন `item_id` আর Unique থাকে না।

**ভুল ২: এক সেলে অনেক মান**

| ITEM_ID | ITEM_NAME | SUPPLIER_IDS |
|---|---|---|
| 3 | Cotton Yarn 30/1 | 1,2 |

FK দেওয়া যায় না, ভুল ID আটকানো যায় না, খোঁজা কঠিন।

**ভুল ৩: অনেকগুলো কলাম**

| ITEM_ID | ITEM_NAME | SUPPLIER_1 | SUPPLIER_2 | SUPPLIER_3 |
|---|---|---|---|---|
| 3 | Cotton Yarn 30/1 | 1 | 2 | NULL |

৪ জন Supplier হলে টেবিল বদলাতে হবে, আর বেশিরভাগ ঘর খালি পড়ে থাকবে।

## ২. সমাধান: Junction Table (৩৫ মিনিট)

**Junction Table** হলো মাঝখানের একটা টেবিল, যা M:N সম্পর্ককে **দুইটা ১:N সম্পর্কে** ভেঙে দেয়। একে Bridge Table বা Associative Table-ও বলে।

```
SUPPLIER ──< SUPPLIER_ITEM >── ITEM
```

| SUPPLIER |  | SUPPLIER_ITEM |  | ITEM |
|---|---|---|---|---|
| 1 ABC Textile | ◄ | 1, 1 | ► | 1 Single Jersey |
| 1 ABC Textile | ◄ | 1, 2 | ► | 2 Pique |
| 1 ABC Textile | ◄ | 1, 3 | ► | 3 Cotton Yarn |
| 2 XYZ Spinning | ◄ | 2, 3 | ► | 3 Cotton Yarn |

Junction Table-এর প্রতিটা রো মানে একটা জোড়া: "এই Supplier এই Item দেয়।"

**নিয়ম:**
- দুই Parent-এর দিকে দুইটা FK থাকবে
- একই জোড়া দুইবার থাকবে না

নাম রাখার নিয়ম: দুই টেবিলের নাম জুড়ে (`supplier_item`), অথবা কাজের নাম (`enrollment`)।

> ক্লাস ১১-এ তুমি `style_item` বানিয়েছ, আর ক্লাস ১২-এ তাতে দুইটা FK দিয়েছ। **ওটাই একটা Junction Table।** একটা স্টাইলে অনেক আইটেম, একটা আইটেম অনেক স্টাইলে।

## ৩. Junction Table বানানো (৩৫ মিনিট)

```sql
CREATE TABLE supplier_item (
    supplier_id  NUMBER(10),
    item_id      NUMBER(10),
    CONSTRAINT supplier_item_pk PRIMARY KEY (supplier_id, item_id),
    CONSTRAINT supplier_item_supplier_fk FOREIGN KEY (supplier_id) REFERENCES supplier (supplier_id),
    CONSTRAINT supplier_item_item_fk FOREIGN KEY (item_id) REFERENCES item (item_id)
);

INSERT INTO supplier_item VALUES (1, 1);
INSERT INTO supplier_item VALUES (1, 2);
INSERT INTO supplier_item VALUES (1, 3);
INSERT INTO supplier_item VALUES (2, 3);
INSERT INTO supplier_item VALUES (2, 4);
COMMIT;
```

### দুই দিক থেকে প্রশ্ন

```sql
-- Supplier 1 কী কী আইটেম দেয়?
SELECT item_id FROM supplier_item WHERE supplier_id = 1;

-- Item 3 কে কে দেয়?
SELECT supplier_id FROM supplier_item WHERE item_id = 3;
```

নামসহ দেখতে তিনটা টেবিল JOIN করতে হয় (সপ্তাহ ৯-এ শিখব, এখন শুধু চালিয়ে দেখো):

```sql
SELECT s.supplier_name, i.item_name
FROM   supplier_item si
JOIN   supplier s ON s.supplier_id = si.supplier_id
JOIN   item     i ON i.item_id     = si.item_id
ORDER  BY s.supplier_name, i.item_name;
```

### নিয়ম ভেঙে দেখো

`Ctrl + Enter` দিয়ে একটা একটা করে চালাও:

```sql
INSERT INTO supplier_item VALUES (1, 1);     -- এরর ORA-00001, জোড়াটা আগেই আছে
INSERT INTO supplier_item VALUES (99, 1);    -- এরর ORA-02291, Supplier 99 নেই
INSERT INTO supplier_item VALUES (1, 99);    -- এরর ORA-02291, Item 99 নেই
DELETE FROM item WHERE item_id = 3;          -- এরর ORA-02292, জোড়া আছে
```

চারটাই এরর দেবে, তাই কোনো ডাটা বদলাবে না।

## ৪. Junction Table-এ বাড়তি তথ্য (২০ মিনিট)

কিছু তথ্য Supplier-এরও না, Item-এরও না, **জোড়াটার**। যেমন: "ABC Textile থেকে Cotton Yarn-এর দাম"। একই আইটেম ভিন্ন Supplier-এর কাছে ভিন্ন দামে পাওয়া যায়।

| তথ্য | কোথায় রাখবে | কেন |
|---|---|---|
| সাপ্লায়ারের ঠিকানা | `supplier` | শুধু Supplier-এর |
| আইটেমের ইউনিট | `item` | শুধু Item-এর |
| এই Supplier-এর কাছে এই Item-এর দাম | `supplier_item` | জোড়ার |

```sql
ALTER TABLE supplier_item ADD (
    unit_price  NUMBER(10,2),
    lead_days   NUMBER(4)
);

UPDATE supplier_item SET unit_price = 3.25, lead_days = 15
WHERE  supplier_id = 1 AND item_id = 3;

UPDATE supplier_item SET unit_price = 3.10, lead_days = 10
WHERE  supplier_id = 2 AND item_id = 3;
COMMIT;

-- Cotton Yarn-এর দাম কার কাছে কত?
SELECT supplier_id, unit_price, lead_days
FROM   supplier_item
WHERE  item_id = 3;
```

> **Lead Time / Lead Days:** অর্ডার দেওয়ার পর মাল আসতে কত দিন লাগে। `ALTER` আর `UPDATE` বিস্তারিত সপ্তাহ ৫-এ।

গার্মেন্টসে আরো Junction Table:

| সম্পর্ক | Junction Table | বাড়তি তথ্য |
|---|---|---|
| Style, Item | `style_item` | প্রতি পিসে কত লাগে |
| Worker, Operation | `worker_operation` | দক্ষতার মাত্রা |
| PO, Item | `po_item` | পরিমাণ, দাম |
| App User, Role | `user_role` | কবে থেকে এই রোল |

## ৫. Composite PK নাকি আলাদা ID (২০ মিনিট)

Junction Table দুইভাবে বানানো যায়:

**উপায় ১: Composite PK** (উপরে যেটা করেছি)

```sql
CONSTRAINT supplier_item_pk PRIMARY KEY (supplier_id, item_id)
```

**উপায় ২: আলাদা ID, আর জোড়ায় Unique**

```sql
CREATE TABLE po_item (
    po_item_id  NUMBER(10),
    po_id       NUMBER(10) NOT NULL,
    item_id     NUMBER(10) NOT NULL,
    qty         NUMBER(12,3),
    CONSTRAINT po_item_pk PRIMARY KEY (po_item_id),
    CONSTRAINT po_item_po_item_uk UNIQUE (po_id, item_id),
    CONSTRAINT po_item_po_fk FOREIGN KEY (po_id) REFERENCES purchase_order (po_id),
    CONSTRAINT po_item_item_fk FOREIGN KEY (item_id) REFERENCES item (item_id)
);
```

> এই টেবিলের জন্য ক্লাস ১২-এর হোমওয়ার্কের `purchase_order` টেবিল লাগবে।

| | Composite PK | আলাদা ID + Unique |
|---|---|---|
| কলাম | কম | একটা বেশি |
| অন্য টেবিল এর দিকে FK দিলে | দুইটা কলাম লাগে | একটা কলামেই হয় |
| APEX-এ ফর্ম বা গ্রিড | একটু ঝামেলা | সহজ |
| কখন | ছোট, শুধু জোড়া রাখা টেবিল | বড়, লেনদেনের টেবিল |

**সুপারিশ:** শুধু জোড়া রাখলে Composite PK। লেনদেনের টেবিল, বা অন্য টেবিল এর দিকে FK দেবে এমন হলে আলাদা ID। উপায় ২-এ **Unique ভুলে গেলে** একই জোড়া দুইবার ঢুকে যাবে।

## ৬. হাতে-কলমে প্র্যাকটিস (৪০ মিনিট)

**কাজ ১:** Worker আর Operation-এর সম্পর্ক বানাও। একজন কর্মী অনেক কাজ জানে (Collar Join, Sleeve Attach), একটা কাজ অনেক কর্মী জানে।
- `operation` টেবিল: operation_id, operation_name (Unique, Not Null), smv
- `worker_operation` Junction Table: worker_id, operation_id, skill_grade (`A`, `B`, `C` ছাড়া আর কিছু না)
- ৪টা Operation, আর ৫টা জোড়া ঢোকাও (ক্লাস ১১-এর `worker` টেবিলের ১, ২, ৩ নম্বর কর্মী)

> **SMV (Standard Minute Value):** একটা কাজ করতে আদর্শ কত মিনিট লাগে। ধাপ ৮-এ বিস্তারিত।

**কাজ ২:** এই টেবিলের ডিজাইন ঠিক করো। নতুন টেবিল কী কী হবে, কোন কলাম কোথায় যাবে লেখো।

| ORDER_NO | SHIP_DATE | FACTORY_UNITS |
|---|---|---|
| ORD-001 | 2027-01-15 | Unit-A: 3000, Unit-B: 2000 |
| ORD-002 | 2027-02-20 | Unit-A: 3000 |

**কাজ ৩:** প্রতিটা জোড়ার সম্পর্কের ধরন লেখো। M:N হলে Junction Table-এর নাম দাও, আর তাতে কোন বাড়তি তথ্য থাকতে পারে বলো।
1. Buyer আর Supplier (Buyer নির্দিষ্ট করে দেয় কোন Supplier থেকে কিনতে হবে)
2. Order আর Sewing Line (একটা অর্ডার কয়েক লাইনে চলে, একটা লাইনে সময়ভেদে কয়েকটা অর্ডার)
3. Style আর Style Costing Sheet

## ৭. হোমওয়ার্ক

1. একটা স্কুলের কথা ভাবো: Student আর Subject। টেবিল ৩টা খাতায় ডিজাইন করো, ৩ জন Student আর ৩টা Subject-এর ডাটা দাও। নম্বর (marks) কোন টেবিলে রাখবে, কেন?
2. `po_item` টেবিলটা বানাও (ক্লাস ১২-এর `purchase_order` দরকার)। ৩টা ডাটা ঢোকাও। একই PO-তে একই Item দ্বিতীয়বার দিয়ে এরর দেখো।
3. কাল ER Diagram শিখব। আজকের `SUPPLIER ──< SUPPLIER_ITEM >── ITEM` ছবিটা খাতায় আঁকো, প্রতিটা টেবিলের কলাম লিখে।

## ৮. কুইজ

1. Many-to-Many সম্পর্ক সরাসরি FK দিয়ে বানানো যায় না কেন?
2. Junction Table কী করে?
3. Junction Table-এ কয়টা FK থাকে?
4. "এই Supplier-এর কাছে এই Item-এর দাম" কোন টেবিলে রাখবে?
5. আলাদা ID দিলে Junction Table-এ আর কী দিতে ভোলা যাবে না?

<details>
<summary>উত্তর দেখো</summary>

1. এক ঘরে একটাই মান রাখা যায়, তাই কোনো একটা টেবিলে অনেকগুলো ID রাখা যায় না
2. M:N সম্পর্ককে দুইটা ১:N সম্পর্কে ভেঙে দেয়
3. দুইটা, দুই Parent-এর দিকে
4. Junction Table-এ (`supplier_item`), কারণ এটা জোড়ার তথ্য
5. দুই FK কলামের উপর Unique, নাহলে একই জোড়া দুইবার ঢুকবে

## সারাংশ

- M:N সম্পর্ক মাঝখানের Junction Table দিয়ে দুইটা ১:N-এ ভাঙা হয়
- Junction Table-এ দুইটা FK, আর জোড়ার উপর PK বা Unique
- যে তথ্য জোড়ার, সেটা Junction Table-এ
- ছোট টেবিলে Composite PK, লেনদেনের টেবিলে আলাদা ID + Unique
