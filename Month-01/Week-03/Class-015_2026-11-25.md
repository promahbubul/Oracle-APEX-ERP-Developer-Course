## ১. ER Diagram কী (১৫ মিনিট)

**ER Diagram (Entity Relationship Diagram)** হলো ডাটাবেসের ছবি: কোন কোন টেবিল থাকবে, প্রতিটায় কী কলাম, আর কোনটা কোনটার সাথে যুক্ত।

বাড়ি বানানোর আগে যেমন নকশা লাগে, টেবিল বানানোর আগে তেমনি ER Diagram লাগে।

**কেন লাগে:**
- কোড লেখার আগেই ডিজাইনের ভুল ধরা পড়ে
- ব্যবহারকারী আর টিমের সাথে আলোচনা করা সহজ হয়
- নতুন ডেভেলপার ছবি দেখেই ডাটাবেস বুঝতে পারে
- ইন্টারভিউ আর পোর্টফোলিওতে দেখানো যায়

### তিনটা মূল শব্দ

| শব্দ | মানে | ডাটাবেসে কী হয় | উদাহরণ |
|---|---|---|---|
| **Entity** | যে জিনিসের তথ্য রাখব | টেবিল | Buyer, Style |
| **Attribute** | সেই জিনিসের বৈশিষ্ট্য | কলাম | buyer_name, country |
| **Relationship** | Entity-গুলোর সম্পর্ক | Foreign Key | Buyer-এর অনেক Style |

## ২. Crow's Foot চিহ্ন (২৫ মিনিট)

সম্পর্ক দেখানোর সবচেয়ে প্রচলিত পদ্ধতি হলো **Crow's Foot** (কাকের পা)। Many দিকের চিহ্নটা দেখতে কাকের পায়ের মতো।

লাইনের প্রতিটা প্রান্তে দুইটা তথ্য থাকে: **সর্বনিম্ন** আর **সর্বোচ্চ** কয়টা।

| চিহ্ন | মানে | কথায় |
|---|---|---|
| `──┼┼` | ঠিক একটা | একটাই, অবশ্যই থাকবে |
| `──o┼` | শূন্য অথবা একটা | থাকতেও পারে, না-ও পারে |
| `──┼<` | এক বা অনেক | অন্তত একটা |
| `──o<` | শূন্য বা অনেক | না-ও থাকতে পারে, অনেকও হতে পারে |

- `┼` বা `|` = এক
- `o` = শূন্য
- `<` = অনেক (কাকের পা)

### উদাহরণ পড়া

```
BUYER ┼┼────────o< STYLE
```

দুই দিক থেকে পড়ো:
- **বাম থেকে:** একটা Buyer-এর **শূন্য বা অনেক** Style (নতুন Buyer-এর হয়তো এখনো স্টাইল নেই)
- **ডান থেকে:** একটা Style-এর **ঠিক একটা** Buyer

```
WORKER ┼┼────────o┼ WORKER_BANK
```

- একজন Worker-এর **শূন্য বা একটা** ব্যাংক রেকর্ড
- একটা ব্যাংক রেকর্ড **ঠিক একজন** Worker-এর

### কলামের পাশের চিহ্ন

| চিহ্ন | মানে |
|---|---|
| **PK** | Primary Key |
| **FK** | Foreign Key |
| **UK** | Unique Key |

সাধারণত PK সবার উপরে লেখা হয়।

```
┌──────────────────────┐            ┌──────────────────────┐
│ BUYER                │            │ STYLE                │
├──────────────────────┤            ├──────────────────────┤
│ PK buyer_id          │┼┼────────o<│ PK style_id          │
│    buyer_name        │            │ UK style_no          │
│    country           │            │    style_name        │
└──────────────────────┘            │ FK buyer_id          │
                                    └──────────────────────┘
```

## ৩. বর্ণনা থেকে ER Diagram (২৫ মিনিট)

**বর্ণনা:** "ফ্যাক্টরিতে কয়েকটা ফ্লোর আছে, প্রতিটা ফ্লোরে কয়েকটা লাইন। প্রতিটা লাইনে কর্মীরা কাজ করেন, একজন কর্মী একটা লাইনেই থাকেন। প্রতিদিন প্রতি লাইনে ঘণ্টাভিত্তিক প্রোডাকশন এন্ট্রি হয়। একজন কর্মী কয়েকটা Operation জানেন।"

### ৭টা ধাপ

**১. বিশেষ্য খুঁজে Entity বের করো:** Floor, Line, Worker, Production Entry, Operation

**২. প্রতিটার Attribute লেখো:**
- Floor: floor_name
- Line: line_name, daily_target
- Worker: emp_code, worker_name, mobile_no
- Production Entry: entry_date, hour_no, produced_qty
- Operation: operation_name, smv

**৩. কোনটার সাথে কোনটা যুক্ত খুঁজো:** Floor-Line, Line-Worker, Line-Production Entry, Worker-Operation

**৪. দুই দিক থেকে প্রশ্ন করে ধরন ঠিক করো:**

| জোড়া | ধরন |
|---|---|
| Floor, Line | ১:N |
| Line, Worker | ১:N |
| Line, Production Entry | ১:N |
| Worker, Operation | M:N |

**৫. M:N ভাঙো:** `worker_operation` Junction Table

**৬. PK আর FK বসাও:** Many দিকের টেবিলে FK

**৭. আবার পড়ে মিলিয়ে দেখো:** ছবি থেকে কথায় বলো, মূল বর্ণনার সাথে মেলে কি না।

```
FLOOR ┼┼──o< LINE ┼┼──o< PRODUCTION_ENTRY
              ┼
              ┼
              o
              ^
            WORKER ┼┼──o< WORKER_OPERATION >o──┼┼ OPERATION
```

## ৪. draw.io দিয়ে আঁকা (৪০ মিনিট)

**draw.io** ফ্রি অনলাইন ডায়াগ্রাম টুল। ইনস্টল বা অ্যাকাউন্ট ছাড়াই চলে।

> মেনুর নাম আর জায়গা ভার্সনভেদে একটু আলাদা হতে পারে। ঠিক এই নাম না পেলে কাছাকাছি নামটা খোঁজো।

### ধাপ ১: নতুন ডায়াগ্রাম

1. যাও: **https://app.diagrams.net**
2. কোথায় সেভ করবে জিজ্ঞেস করলে **Device** বেছে নাও
3. **Create New Diagram** → **Blank Diagram**
4. নাম দাও: `garments_er.drawio`, তারপর **Create**

### ধাপ ২: টেবিল বানানো

1. বাম পাশে **Search Shapes**-এ লেখো `table`, অথবা **Entity Relation** অংশটা খোলো
2. টেবিলের Shape টেনে ক্যানভাসে আনো
3. উপরের ঘরে ডাবল-ক্লিক করে টেবিলের নাম লেখো: `BUYER`
4. প্রতিটা রো-তে ডাবল-ক্লিক করে কলাম লেখো: `PK buyer_id`, `buyer_name`, `country`
5. রো বাড়াতে একটা রো সিলেক্ট করে `Ctrl + D` চাপো (ডুপ্লিকেট হবে), তারপর লেখা বদলাও

`Entity Relation` অংশ না দেখালে বাম পাশের নিচে **+ More Shapes** থেকে চালু করো।

### ধাপ ৩: সম্পর্কের লাইন

1. একটা টেবিলের উপর মাউস রাখলে চারপাশে নীল বিন্দু বা তীর দেখাবে
2. সেখান থেকে টেনে অন্য টেবিলে ছাড়ো
3. লাইনটা সিলেক্ট করো
4. ডান পাশে **Format** প্যানেলের **Style** ট্যাবে লাইনের শুরু আর শেষের প্রান্ত বদলাও
5. তালিকায় Crow's Foot চিহ্নগুলো থাকে (নাম ER দিয়ে শুরু, যেমন `ERone`, `ERmany`, `ERzeroToMany`)

### ধাপ ৪: সাজানো

| শর্টকাট বা কাজ | ফল |
|---|---|
| `Ctrl + D` | সিলেক্ট করা জিনিসের কপি |
| `Ctrl + Z` | আগের অবস্থায় ফেরা |
| `Ctrl + S` | সেভ |
| `Ctrl` + মাউসের চাকা | জুম |
| **Arrange → Layout** | অটো সাজানো |

**সাজানোর ভালো অভ্যাস:**
- Parent বাম বা উপরে, Child ডান বা নিচে
- লাইন যতটা সম্ভব একে অন্যকে না কাটা
- সব টেবিলে এক রকম কলাম ক্রম: PK, UK, সাধারণ কলাম, FK

### ধাপ ৫: সেভ ও এক্সপোর্ট

1. **File → Save** দিয়ে `.drawio` ফাইল সেভ করো। এটা পরে আবার এডিট করা যায়
2. **File → Export as → PNG** দিয়ে ছবি বানাও। এটা CV, ডকুমেন্ট বা রিপোর্টে দেওয়ার জন্য

## ৫. ER Diagram থেকে SQL (১৫ মিনিট)

ছবি থেকে কোড লেখার নিয়ম:

| ER Diagram-এ | SQL-এ |
|---|---|
| Entity | `CREATE TABLE` |
| Attribute | কলাম, সঠিক Data Type সহ |
| PK | `PRIMARY KEY` |
| UK | `UNIQUE` |
| FK | `FOREIGN KEY ... REFERENCES` |
| `┼` (অবশ্যই আছে) | FK কলামে `NOT NULL` |
| `o` (না-ও থাকতে পারে) | FK কলামে NULL চলবে |

**টেবিল বানানোর ক্রম:** আগে Parent, তারপর Child।

```
১. factory_floor       (কারো উপর নির্ভর করে না)
২. prod_line           (factory_floor লাগে)
৩. production_hourly   (prod_line লাগে)
```

উল্টো ক্রমে বানালে Parent না পেয়ে `ORA-00942` আসে।

## ৬. হাতে-কলমে প্র্যাকটিস (৬০ মিনিট)

**কাজ ১:** এই সপ্তাহে বানানো Store টেবিলগুলোর ER Diagram draw.io-তে আঁকো: `item_category`, `item`, `supplier`, `supplier_item`, `goods_receive`, `goods_issue`। প্রতিটা কলাম, PK, FK দেখাও, আর লাইনে ঠিক Crow's Foot চিহ্ন দাও। PNG এক্সপোর্ট করো।

**কাজ ২:** Oracle-এর দিক থেকে মিলিয়ে দেখো। ক্লাস ১৩-এর FK তালিকার কোয়েরি চালাও, আর তোমার ছবির সব লাইন সেই তালিকায় আছে কি না দেখো।

**কাজ ৩:** নিচের বর্ণনা থেকে ER Diagram বানাও:

> "একটা Buyer অনেক Order দেয়। প্রতিটা Order-এ এক বা একাধিক Item থাকে (একটা Item অনেক Order-এ থাকতে পারে), আর প্রতিটা Item-এর পরিমাণ আর দাম লিখতে হয়। প্রতিটা Order কয়েকটা Shipment-এ যেতে পারে, প্রতিটা Shipment একটা Order-এর।"

## সারাংশ

- ER Diagram ডাটাবেসের নকশা: Entity, Attribute, Relationship
- Crow's Foot: `┼` এক, `o` শূন্য, `<` অনেক
- বর্ণনা থেকে: Entity → Attribute → সম্পর্ক → ধরন → M:N ভাঙা → PK/FK → মিলিয়ে দেখা
- draw.io-তে `.drawio` ফাইল এডিটের জন্য, PNG দেখানোর জন্য
- SQL লেখার সময় আগে Parent, পরে Child
