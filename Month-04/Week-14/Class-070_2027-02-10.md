## ১. INSERT (৩০ মিনিট)

```sql
CREATE TABLE w14_note (
    note_id     NUMBER(10) CONSTRAINT w14_note_pk PRIMARY KEY,
    note_text   VARCHAR2(200) NOT NULL,
    created_on  DATE DEFAULT SYSDATE NOT NULL
);

CREATE SEQUENCE w14_note_seq;
```

```sql
DECLARE
    v_text w14_note.note_text%TYPE := 'First note';
BEGIN
    INSERT INTO w14_note (note_id, note_text)
    VALUES (w14_note_seq.NEXTVAL, v_text);

    COMMIT;

    DBMS_OUTPUT.PUT_LINE('Saved');
END;
/

SELECT * FROM w14_note;
```

SQL আগের মতোই, শুধু মানের জায়গায় Variable। `INTO` লাগে না, কারণ কিছু ফেরত আসে না।

### Sequence

```sql
DECLARE
    v_id w14_note.note_id%TYPE;
BEGIN
    v_id := w14_note_seq.NEXTVAL;          -- 11g থেকে সরাসরি চলে

    INSERT INTO w14_note (note_id, note_text) VALUES (v_id, 'Second note');
    COMMIT;

    DBMS_OUTPUT.PUT_LINE('New ID: ' || v_id);
END;
/
```

### RETURNING INTO: ঢোকানোর পরে মান জানা

ক্লাস ৫৩-এ বলেছিলাম: Identity-তে `CURRVAL` নেই, এখানে শিখবে।

```sql
CREATE TABLE w14_grn (
    grn_id    NUMBER(10) GENERATED ALWAYS AS IDENTITY CONSTRAINT w14_grn_pk PRIMARY KEY,
    grn_no    VARCHAR2(30) NOT NULL,
    grn_date  DATE DEFAULT TRUNC(SYSDATE) NOT NULL
);

CREATE TABLE w14_grn_item (
    grn_item_id  NUMBER(10) GENERATED ALWAYS AS IDENTITY CONSTRAINT w14_grn_item_pk PRIMARY KEY,
    grn_id       NUMBER(10) NOT NULL,
    item_name    VARCHAR2(50) NOT NULL,
    qty          NUMBER(12,3) NOT NULL,
    CONSTRAINT w14_grn_item_grn_fk FOREIGN KEY (grn_id) REFERENCES w14_grn (grn_id)
);
```

```sql
-- Master-Detail
DECLARE
    v_grn_id w14_grn.grn_id%TYPE;
BEGIN
    INSERT INTO w14_grn (grn_no)
    VALUES ('GRN-0001')
    RETURNING grn_id INTO v_grn_id;

    INSERT INTO w14_grn_item (grn_id, item_name, qty) VALUES (v_grn_id, 'Button', 1000);
    INSERT INTO w14_grn_item (grn_id, item_name, qty) VALUES (v_grn_id, 'Zipper', 500);

    COMMIT;

    DBMS_OUTPUT.PUT_LINE('GRN ID: ' || v_grn_id);
END;
/

SELECT g.grn_no, i.item_name, i.qty
FROM   w14_grn g
JOIN   w14_grn_item i ON i.grn_id = g.grn_id;
```

## ২. UPDATE ও DELETE (৩০ মিনিট)

```sql
DECLARE
    v_note_id w14_note.note_id%TYPE := 1;
    v_text    w14_note.note_text%TYPE := 'Changed note';
BEGIN
    UPDATE w14_note
    SET    note_text = v_text
    WHERE  note_id = v_note_id;

    COMMIT;
END;
/
```

### RETURNING

```sql
DECLARE
    v_new_balance NUMBER;
BEGIN
    UPDATE w5_stock
    SET    balance_qty = balance_qty + 10
    WHERE  item_id = 2
    RETURNING balance_qty INTO v_new_balance;

    DBMS_OUTPUT.PUT_LINE('New balance: ' || v_new_balance);

    ROLLBACK;
END;
/
```

আবার `SELECT` চালাতে হয় না। `DELETE`-এও `RETURNING` চলে।

### DELETE

```sql
DECLARE
    v_note_id w14_note.note_id%TYPE := 2;
BEGIN
    DELETE FROM w14_note WHERE note_id = v_note_id;
    ROLLBACK;
END;
/
```

### MERGE

ক্লাস ৬৪-এর `dual`-এর ছাঁচে Variable:

```sql
DECLARE
    v_item_id    w13_item_master.item_id%TYPE := 20;
    v_item_name  w13_item_master.item_name%TYPE := 'Hook';
    v_unit_price w13_item_master.unit_price%TYPE := 0.25;
BEGIN
    MERGE INTO w13_item_master t
    USING (SELECT v_item_id AS item_id, v_item_name AS item_name, v_unit_price AS unit_price FROM dual) s
    ON (t.item_id = s.item_id)
    WHEN MATCHED THEN
        UPDATE SET t.unit_price = s.unit_price
    WHEN NOT MATCHED THEN
        INSERT (item_id, item_name, unit_price)
        VALUES (s.item_id, s.item_name, s.unit_price);

    ROLLBACK;
END;
/
```

## ৩. SQL%ROWCOUNT (২০ মিনিট)

`UPDATE`, `DELETE` যদি কোনো রো না পায়, **এরর হয় না।** `SELECT INTO`-র উল্টো। তাহলে কীভাবে জানবে?

Oracle শেষ SQL-এর হিসাব রাখে (**Implicit Cursor**, সপ্তাহ ১৬)।

| Attribute | মানে |
|---|---|
| `SQL%ROWCOUNT` | কয়টা রো বদলেছে |
| `SQL%FOUND` | অন্তত একটা রো বদলেছে? `TRUE` |
| `SQL%NOTFOUND` | কোনো রো বদলায়নি? `TRUE` |

```sql
BEGIN
    UPDATE lib_book SET publish_year = publish_year WHERE category_id = 1;
    DBMS_OUTPUT.PUT_LINE('Rows: ' || SQL%ROWCOUNT);      -- 4

    UPDATE lib_book SET publish_year = publish_year WHERE book_id = 9999;
    DBMS_OUTPUT.PUT_LINE('Rows: ' || SQL%ROWCOUNT);      -- 0, এরর নেই

    ROLLBACK;
END;
/
```

### সবচেয়ে সাধারণ বাগ

```sql
-- ID ভুল, কোনো রো বদলায়নি, কিন্তু "Saved" দেখাচ্ছে!
BEGIN
    UPDATE w14_note SET note_text = 'X' WHERE note_id = 9999;
    COMMIT;
    DBMS_OUTPUT.PUT_LINE('Saved');
END;
/
```

**ইউজার ভাবছে হয়েছে, আসলে হয়নি।** `SQL%ROWCOUNT` দেখে যাচাই করতে হয়। `IF` আগামী সপ্তাহে, এখন শুধু ছাপো:

```sql
BEGIN
    UPDATE w14_note SET note_text = 'X' WHERE note_id = 9999;
    DBMS_OUTPUT.PUT_LINE(SQL%ROWCOUNT || ' row(s) updated');
    ROLLBACK;
END;
/
```

### এক জায়গায় রাখো

`SQL%ROWCOUNT` **পরের SQL চলার পরে বদলে যায়।** দরকার হলে সাথে সাথে Variable-এ রাখো। এমনকি `COMMIT`-এর পরে `SQL%ROWCOUNT` আর নির্ভরযোগ্য না। তাই `COMMIT`-এর আগে দেখো।

## ৪. Transaction ও ব্লক (৩৫ মিনিট)

ক্লাস ২৫-এর নিয়মগুলো একই। তবে ব্লক আর এররের মিলন আলাদা জিনিস।

### নিজে থেকে COMMIT হয় না

```sql
BEGIN
    INSERT INTO w14_note (note_id, note_text) VALUES (w14_note_seq.NEXTVAL, 'Test A');
END;
/

SELECT note_text FROM w14_note;      -- এই সেশনে দেখা যায়

ROLLBACK;

SELECT note_text FROM w14_note;      -- Test A নেই
```

ব্লক শেষ মানে `COMMIT` না।

### এরর, Handler ছাড়া: পুরো ব্লক বাতিল

```sql
DECLARE
    v_zero NUMBER := 0;
    v_x    NUMBER;
BEGIN
    INSERT INTO w14_note (note_id, note_text) VALUES (w14_note_seq.NEXTVAL, 'Test B');
    v_x := 1 / v_zero;
    INSERT INTO w14_note (note_id, note_text) VALUES (w14_note_seq.NEXTVAL, 'Test C');
END;
/

SELECT note_text FROM w14_note;      -- Test B নেই
```

Oracle-এর কাছে পুরো Anonymous Block একটা স্টেটমেন্ট। ধরা না পড়া এরর হলে **এই ব্লকের সব কাজ** বাতিল।

### এরর, Handler সহ: বিপদ

```sql
DECLARE
    v_zero NUMBER := 0;
    v_x    NUMBER;
BEGIN
    INSERT INTO w14_note (note_id, note_text) VALUES (w14_note_seq.NEXTVAL, 'Test D');
    v_x := 1 / v_zero;
EXCEPTION
    WHEN ZERO_DIVIDE THEN
        DBMS_OUTPUT.PUT_LINE('Error caught');
END;
/

SELECT note_text FROM w14_note;      -- Test D আছে!
```

**এরর ধরলে `Test D` থেকে গেল,** আর `COMMIT` দিলে স্থায়ী হবে। মাঝপথের কাজ অর্ধেক হয়ে থাকতে পারে। তাই Handler-এ `ROLLBACK` দিতে হয়:

```sql
ROLLBACK;
```

```sql
EXCEPTION
    WHEN OTHERS THEN
        ROLLBACK;
        RAISE;
```

`RAISE` এরর আবার ছুড়ে দেয়, যাতে ডাকা জায়গা জানতে পারে। `WHEN OTHERS` আর `RAISE` সপ্তাহ ১৭-এ।

| অবস্থা | কাজ |
|---|---|
| এরর নেই, `COMMIT` আছে | স্থায়ী |
| এরর নেই, `COMMIT` নেই | ঝুলে থাকে |
| এরর, Handler নেই | এই ব্লকের কাজ বাতিল |
| এরর, Handler আছে, `ROLLBACK` নেই | **কাজ ঝুলে থাকে, পরের `COMMIT`-এ স্থায়ী** |

### SAVEPOINT

```sql
BEGIN
    INSERT INTO w14_note (note_id, note_text) VALUES (w14_note_seq.NEXTVAL, 'Keep this');
    SAVEPOINT sp1;

    INSERT INTO w14_note (note_id, note_text) VALUES (w14_note_seq.NEXTVAL, 'Drop this');
    ROLLBACK TO sp1;

    COMMIT;
END;
/
```

### COMMIT কোথায়

**নতুনদের ভুল:** প্রতিটা `INSERT`-এর পরে `COMMIT`। তাহলে মাঝপথে এরর হলে আগের অংশ ফেরানো যায় না।

**নিয়ম:** পুরো কাজ শেষে একবার।

**আরেকটা নিয়ম:** Procedure-এর ভেতরে `COMMIT` সাধারণত না। যে ডাকে, সে ঠিক করবে (সপ্তাহ ১৮)। **APEX Process-এ `COMMIT` লাগে না** (ক্লাস ২৫)।

### মাল গ্রহণের Transaction

ক্লাস ২৫-এ `w5_receive` আর `w5_stock` হাতে করেছিলে। এবার ব্লকে:

```sql
CREATE TABLE w14_stock (
    item_id      NUMBER(10) CONSTRAINT w14_stock_pk PRIMARY KEY,
    item_name    VARCHAR2(50) NOT NULL,
    balance_qty  NUMBER(12,3) DEFAULT 0 NOT NULL,
    CONSTRAINT w14_stock_balance_ck CHECK (balance_qty >= 0)
);

CREATE TABLE w14_txn (
    txn_id    NUMBER(10) GENERATED ALWAYS AS IDENTITY CONSTRAINT w14_txn_pk PRIMARY KEY,
    item_id   NUMBER(10) NOT NULL,
    txn_type  VARCHAR2(10) NOT NULL,
    qty       NUMBER(12,3) NOT NULL,
    txn_date  DATE DEFAULT SYSDATE NOT NULL,
    CONSTRAINT w14_txn_item_fk FOREIGN KEY (item_id) REFERENCES w14_stock (item_id),
    CONSTRAINT w14_txn_type_ck CHECK (txn_type IN ('RECEIVE', 'ISSUE')),
    CONSTRAINT w14_txn_qty_ck CHECK (qty > 0)
);

INSERT INTO w14_stock (item_id, item_name, balance_qty) VALUES (1, 'Single Jersey', 500);
INSERT INTO w14_stock (item_id, item_name, balance_qty) VALUES (2, 'Button 18L', 100);
COMMIT;
```

```sql
-- মাল গ্রহণ: Single Jersey, 100 কেজি
DECLARE
    v_item_id w14_stock.item_id%TYPE := 1;
    v_qty     w14_txn.qty%TYPE := 100;
    v_balance w14_stock.balance_qty%TYPE;
BEGIN
    INSERT INTO w14_txn (item_id, txn_type, qty)
    VALUES (v_item_id, 'RECEIVE', v_qty);

    UPDATE w14_stock
    SET    balance_qty = balance_qty + v_qty
    WHERE  item_id = v_item_id
    RETURNING balance_qty INTO v_balance;

    COMMIT;

    DBMS_OUTPUT.PUT_LINE('Stock now: ' || v_balance);       -- 600
EXCEPTION
    WHEN OTHERS THEN
        ROLLBACK;
        RAISE;
END;
/
```

```sql
-- মাল ইস্যু: স্টকের চেয়ে বেশি, Button 18L, 500 পিস
DECLARE
    v_item_id w14_stock.item_id%TYPE := 2;
    v_qty     w14_txn.qty%TYPE := 500;
BEGIN
    INSERT INTO w14_txn (item_id, txn_type, qty)
    VALUES (v_item_id, 'ISSUE', v_qty);

    UPDATE w14_stock
    SET    balance_qty = balance_qty - v_qty
    WHERE  item_id = v_item_id;

    COMMIT;
EXCEPTION
    WHEN OTHERS THEN
        ROLLBACK;
        RAISE;
END;
/
```

`ORA-02290` আসবে। `w14_txn`-এ কোনো রো থাকবে না, আর স্টক একই। **এটাই ঠিক আচরণ।** নিজে পরীক্ষা করো:

```sql
SELECT * FROM w14_stock;     -- Single Jersey 600, Button 18L 100
SELECT * FROM w14_txn;       -- শুধু RECEIVE
```

> ইউজারকে সুন্দর বার্তা দিতে `IF` আর `RAISE_APPLICATION_ERROR` লাগবে। সপ্তাহ ১৫ আর ১৭-এ। সপ্তাহ ১৮-এ এটাই Procedure হবে, আর ২০-এ Trigger।

## ৫. হাতে-কলমে প্র্যাকটিস (৬৫ মিনিট)

1. `w14_note`-এ Variable দিয়ে একটা রো ঢোকাও। `RETURNING` দিয়ে `note_id` দেখাও। `COMMIT`।
2. `w14_note`-এর `note_text` বড় হাতে করো। `SQL%ROWCOUNT` দেখাও। `ROLLBACK`।
3. `w14_grn`-এ নতুন GRN `GRN-0002` আর ৩টা আইটেম, `RETURNING` দিয়ে।
4. `w14_stock`-এ `Pique` (আইটেম ৩, ব্যালেন্স ২০০) ঢোকাও।
5. Pique ৫০ কেজি রিসিভের Transaction, `RETURNING` দিয়ে নতুন ব্যালেন্স। (২৫০)
6. Pique ৭০ কেজি ইস্যুর Transaction। (১৮০)
7. Pique ৯৯৯ কেজি ইস্যুর চেষ্টা। `ORA-02290`-এর পরে `w14_txn` আর `w14_stock` যাচাই করো।
8. নেই এমন আইটেম ৯৯ ইস্যুর চেষ্টা। `INSERT`-এ FK `ORA-02291`।
9. `w14_stock`-এ `item_id = 99` `UPDATE` করো। `SQL%ROWCOUNT` দেখো। এরর এলো?
10. `w5_buyer`-এ Variable দিয়ে `Uniqlo`, `Japan` ঢোকাও। `ROLLBACK`।
11. Handler সহ আর ছাড়া ক্লাসের দুই পরীক্ষা নিজে করো, ফল লেখো।
12. `SAVEPOINT` দিয়ে ৩টা নোটের মধ্যে ২টা রাখো।

```sql
    INSERT INTO w14_note (note_id, note_text) VALUES (w14_note_seq.NEXTVAL, 'Drop');
    ROLLBACK TO sp1;
    COMMIT;
END;
/
```

</details>

## ৬. হোমওয়ার্ক

1. কাল ১০টা ব্লকের দিন। ক্লাস ৬৬–৭০-এর সারাংশ পড়ে আসো।
2. "UPDATE কোনো রো না পেলে এরর দেয় না" কেন বিপজ্জনক? একটা গার্মেন্টসের উদাহরণ লেখো।
3. Handler-এ `ROLLBACK` না দিলে কী ঘটতে পারে, ধাপে ধাপে লেখো।

## ৭. কুইজ

1. `RETURNING INTO` কী করে?
2. `UPDATE` কোনো রো না পেলে কী হয়?
3. `SQL%ROWCOUNT` কী দেখায়?
4. ধরা না পড়া এরর হলে ব্লকের আগের `INSERT`-এর কী হয়?
5. Handler দিয়ে এরর ধরলে আগের `INSERT`-এর কী হয়?

<details>
<summary>উত্তর দেখো</summary>

1. DML-এর পরে মান Variable-এ দেয়, আবার `SELECT` লাগে না
2. এরর হয় না, `SQL%ROWCOUNT` 0
3. শেষ DML-এ কয়টা রো বদলেছে
4. বাতিল হয়
5. থেকে যায়, `ROLLBACK` দিতে হয়

## সারাংশ

- ব্লকে DML SQL-এর মতোই, মানের জায়গায় Variable
- `RETURNING ... INTO`: Master-Detail-এর জন্য নতুন ID
- `UPDATE`, `DELETE` শূন্য রো-তে এরর দেয় না, `SQL%ROWCOUNT` দেখো
- ব্লক শেষ মানে `COMMIT` না
- এরর ধরলে নিজে `ROLLBACK` দাও: `WHEN OTHERS THEN ROLLBACK; RAISE;`
- `COMMIT` পুরো কাজ শেষে একবার
