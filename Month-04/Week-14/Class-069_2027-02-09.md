## আজকে কী শিখব

- `SELECT INTO`: ঠিক একটা রো
- `NO_DATA_FOUND`, `TOO_MANY_ROWS`

## ১. SELECT INTO (৪০ মিনিট)

```sql
SELECT কলাম১, কলাম২
INTO   v_একটা, v_দুইটা
FROM   টেবিল
WHERE  শর্ত;
```

**নিয়ম: ঠিক একটা রো আসতে হবে।** শূন্য না, দুইটাও না।

```sql
DECLARE
    v_title lib_book.book_title%TYPE;
    v_year  lib_book.publish_year%TYPE;
BEGIN
    SELECT book_title, publish_year
    INTO   v_title, v_year
    FROM   lib_book
    WHERE  book_id = 1;

    DBMS_OUTPUT.PUT_LINE(v_title || ' (' || v_year || ')');      -- Oracle SQL for Beginners (2021)
END;
/
```

- `SELECT`-এর কলাম আর `INTO`-এর Variable: **সংখ্যা আর ক্রম মিলতে হবে**
- ক্রমে মিলানো হয়, নামে না

### Variable দিয়ে শর্ত

```sql
DECLARE
    v_book_id lib_book.book_id%TYPE := 4;
    v_title   lib_book.book_title%TYPE;
BEGIN
    SELECT book_title INTO v_title FROM lib_book WHERE book_id = v_book_id;
    DBMS_OUTPUT.PUT_LINE(v_title);       -- Oracle APEX in Practice
END;
/
```

শর্তের মান বদলাতে শুধু `v_book_id` বদলাও। **APEX-এ এটাই `:P5_BOOK_ID`।**

### JOIN সহ

```sql
DECLARE
    v_order_no w5_order.order_no%TYPE := 'ORD-501';
    v_buyer    w5_buyer.buyer_name%TYPE;
    v_qty      w5_order.order_qty%TYPE;
    v_value    NUMBER;
BEGIN
    SELECT b.buyer_name, o.order_qty, o.order_qty * s.fob_price
    INTO   v_buyer, v_qty, v_value
    FROM   w5_order o
    JOIN   w5_style s ON o.style_id = s.style_id
    JOIN   w5_buyer b ON s.buyer_id = b.buyer_id
    WHERE  o.order_no = v_order_no;

    DBMS_OUTPUT.PUT_LINE(v_buyer || ': ' || v_qty || ' pcs, $' || v_value);     -- H&M: 5000 pcs, $11750
END;
/
```

### Aggregate

```sql
DECLARE
    v_count NUMBER;
    v_total NUMBER;
    v_avg   NUMBER;
BEGIN
    SELECT COUNT(*), SUM(fine_amount), AVG(fine_amount)
    INTO   v_count, v_total, v_avg
    FROM   lib_fine;

    DBMS_OUTPUT.PUT_LINE('Count: ' || v_count);    -- 5
    DBMS_OUTPUT.PUT_LINE('Total: ' || v_total);    -- 165
    DBMS_OUTPUT.PUT_LINE('Avg  : ' || v_avg);      -- 33
END;
/
```

### Record-এ

```sql
DECLARE
    rec_member lib_member%ROWTYPE;
BEGIN
    SELECT * INTO rec_member FROM lib_member WHERE member_id = 1;
    DBMS_OUTPUT.PUT_LINE(rec_member.member_name);
END;
/
```

### এক ব্লকে কয়েকটা, আগের ফল পরে

```sql
DECLARE
    v_member_id lib_book_issue.member_id%TYPE;
    v_name      lib_member.member_name%TYPE;
BEGIN
    SELECT member_id INTO v_member_id FROM lib_book_issue WHERE issue_id = 5;
    SELECT member_name INTO v_name FROM lib_member WHERE member_id = v_member_id;

    DBMS_OUTPUT.PUT_LINE('Issue 5 went to: ' || v_name);       -- Kamal Uddin
END;
/
```

## ২. দুইটা সবচেয়ে সাধারণ এরর (৪০ মিনিট)

### NO_DATA_FOUND: কোনো রো নেই

```sql
DECLARE
    v_title lib_book.book_title%TYPE;
BEGIN
    SELECT book_title INTO v_title FROM lib_book WHERE book_id = 9999;
    DBMS_OUTPUT.PUT_LINE(v_title);
END;
/
```

```
ORA-01403: no data found
```

**সাধারণ `SELECT`-এ শূন্য রো কোনো এরর না। `SELECT INTO`-তে এটা এরর।** ব্লক থেমে যায়।

### TOO_MANY_ROWS: একাধিক রো

```sql
DECLARE
    v_title lib_book.book_title%TYPE;
BEGIN
    SELECT book_title INTO v_title FROM lib_book WHERE category_id = 1;
    DBMS_OUTPUT.PUT_LINE(v_title);
END;
/
```

```
ORA-01422: exact fetch returns more than requested number of rows
```

একটা Variable-এ ৪টা বই আঁটে না। অনেক রো-র জন্য Cursor লাগে (সপ্তাহ ১৬)।

### ধরে ফেলা

```sql
DECLARE
    v_title lib_book.book_title%TYPE;
BEGIN
    SELECT book_title INTO v_title FROM lib_book WHERE book_id = 9999;
    DBMS_OUTPUT.PUT_LINE(v_title);
EXCEPTION
    WHEN NO_DATA_FOUND THEN
        DBMS_OUTPUT.PUT_LINE('এই বই নেই');
    WHEN TOO_MANY_ROWS THEN
        DBMS_OUTPUT.PUT_LINE('একাধিক বই পাওয়া গেছে');
END;
/
```

বিস্তারিত সপ্তাহ ১৭-এ। **`SELECT INTO`-র সাথে এই দুইটা প্রায় সবসময় ভাবতে হয়।**

### আরো কিছু এরর

| এরর | কারণ |
|---|---|
| `ORA-01403` | কোনো রো নেই |
| `ORA-01422` | একাধিক রো |
| `ORA-00947` | কলামের চেয়ে Variable বেশি |
| `ORA-00913` | Variable-এর চেয়ে কলাম বেশি |
| `ORA-06502` | মান Variable-এ আঁটে না, বা ধরন মেলে না |
| `PLS-00428` | `INTO` নেই |

## ৩. নিরাপদে আনা (২৫ মিনিট)

### Aggregate এরর দেয় না

`COUNT`, `SUM`, `MAX` সবসময় **একটা রো** দেয়, মিল না থাকলেও (ক্লাস ৩৮)।

```sql
DECLARE
    v_count NUMBER;
    v_total NUMBER;
BEGIN
    SELECT COUNT(*), SUM(fine_amount)
    INTO   v_count, v_total
    FROM   lib_fine
    WHERE  issue_id = 9999;

    DBMS_OUTPUT.PUT_LINE('Count: ' || v_count);     -- 0
    DBMS_OUTPUT.PUT_LINE('Total: ' || NVL(v_total, 0));   -- NULL থেকে 0
END;
/
```

### রো আছে কি না জানা

```sql
DECLARE
    v_count NUMBER;
BEGIN
    SELECT COUNT(*) INTO v_count FROM lib_book WHERE book_id = 1;
    DBMS_OUTPUT.PUT_LINE('Found: ' || v_count);     -- 1
END;
/
```

`IF v_count > 0` দিয়ে পরের ধাপ, আগামী সপ্তাহে।

বড় টেবিলে শুধু "আছে কি না" জানতে `COUNT(*)` পুরো টেবিল গুনতে পারে। `FETCH FIRST 1 ROW ONLY`-এর মতো কৌশলে থেমে যাওয়া ভালো:

```sql
DECLARE
    v_exists NUMBER;
BEGIN
    SELECT COUNT(*) INTO v_exists
    FROM  (SELECT 1 FROM lib_book_issue WHERE member_id = 3 FETCH FIRST 1 ROW ONLY);

    DBMS_OUTPUT.PUT_LINE('Exists: ' || v_exists);     -- 1
END;
/
```

### শুধু প্রথমটা নেওয়া

```sql
DECLARE
    v_issue_id lib_book_issue.issue_id%TYPE;
BEGIN
    SELECT issue_id INTO v_issue_id
    FROM   lib_book_issue
    WHERE  copy_id = 1
    ORDER  BY issue_date DESC
    FETCH  FIRST 1 ROW ONLY;

    DBMS_OUTPUT.PUT_LINE('Last issue of copy 1: ' || v_issue_id);     -- 11
END;
/
```

ক্লাস ৩০-এর `FETCH FIRST` এখানে কাজে লাগল। একাধিক রো-র ঝুঁকি থাকলে এই উপায়, তবে **`ORDER BY` না দিলে কোন রো আসবে, ঠিক নেই।**

### SQL-এর ভেতরে Subquery দিয়ে

PL/SQL-এ `IN (SELECT...)` সরাসরি `:=`-এর ডানে চলে না। দুই ধাপে বা `SELECT ... FROM dual` দিয়ে:

```sql
DECLARE
    v_avg NUMBER;
    v_max NUMBER;
BEGIN
    SELECT (SELECT AVG(fine_amount) FROM lib_fine),
           (SELECT MAX(fine_amount) FROM lib_fine)
    INTO   v_avg, v_max
    FROM   dual;

    DBMS_OUTPUT.PUT_LINE(v_avg || ' | ' || v_max);     -- 33 | 40
END;
/
```

## ৪. একই নামের ফাঁদ (১৫ মিনিট)

```sql
DECLARE
    member_id lib_member.member_id%TYPE := 1;      -- কলামের নামে Variable!
    v_name    lib_member.member_name%TYPE;
BEGIN
    SELECT member_name INTO v_name
    FROM   lib_member
    WHERE  member_id = member_id;

    DBMS_OUTPUT.PUT_LINE(v_name);
END;
/
```

```
ORA-01422: exact fetch returns more than requested number of rows
```

ভুল বোঝা যায় না: এক জন চেয়েছিলাম! **Oracle SQL-এর ভেতরে নাম আগে কলাম হিসেবে দেখে।** তাই `member_id = member_id` মানে কলাম = কলাম, যা প্রতিটা রো-তে সত্য।

`UPDATE`-এ আরো ভয়ঙ্কর: `UPDATE t SET x = 1 WHERE id = id` **সব রো** বদলে দেয়, এরর ছাড়া!

**সমাধান:** `v_` উপসর্গ। এটাই নিয়মটার কারণ।

```sql
v_member_id lib_member.member_id%TYPE := 1;
...
WHERE member_id = v_member_id;
```

## সারাংশ

- `SELECT ... INTO ...`: ঠিক একটা রো, Variable আর কলাম ক্রমে মেলে
- শূন্য রো: `NO_DATA_FOUND`। একাধিক: `TOO_MANY_ROWS`
- Aggregate সবসময় একটা রো দেয়, তাই নিরাপদ
- অনেক রো-র জন্য Cursor, সপ্তাহ ১৬-এ
- Variable-এর নাম কলামের নামে রাখবে না। সবসময় `v_`

**পরের ক্লাস:** PL/SQL-এর ভেতরে INSERT, UPDATE, DELETE।
