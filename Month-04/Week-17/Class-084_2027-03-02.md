# ক্লাস ৮৪: RAISE_APPLICATION_ERROR

**তারিখ:** ২ মার্চ ২০২৭, মঙ্গলবার
**সময়:** সন্ধ্যা ৭:০০ থেকে রাত ১০:০০
**সপ্তাহ:** ১৭ | **ধাপ:** ৩ (PL/SQL)

---

## আজকে কী শিখব

- `DBMS_OUTPUT`-এর বার্তা কেন আসল প্রোগ্রামে কাজ করে না
- `RAISE_APPLICATION_ERROR`: নিজের নম্বর, নিজের বার্তা
- এরর নম্বরের পরিকল্পনা
- আগের সব যাচাই এবার আসল এরর দিয়ে
- নিজের এরর আবার ধরা, তৃতীয় Parameter

---

## ১. সমস্যা: কেউ DBMS_OUTPUT দেখে না (২০ মিনিট)

গতকালের স্টক ইস্যুর কোডে Handler ছিল:

```sql
WHEN e_low_stock THEN
    DBMS_OUTPUT.PUT_LINE('Stock too low');
```

SQL Developer-এ তুমি বার্তা দেখো। কিন্তু ৪ মাস পরে এই কোড APEX-এর একটা বাটনের পেছনে চলবে।

| কে চালায় | `DBMS_OUTPUT` দেখে? |
|---|---|
| তুমি, SQL Developer-এ | হ্যাঁ (`SERVEROUTPUT ON` থাকলে) |
| APEX পেজ | **না** |
| অন্য Procedure যে তোমার কোড ডাকে | **না** |
| রাতের অটো Job (সপ্তাহ ২২) | **না** |

আরো খারাপ: Handler এরর ধরে ফেলেছে, তাই ব্লক **সফল**। APEX ভাবে স্টক ইস্যু হয়ে গেছে, সবুজ "Saved" দেখায়। স্টোরকিপার জানেই না কিছু হয়নি।

আর গতকালের না ধরা User-defined Exception দেখাত `ORA-06510: unhandled user-defined exception`। কোন নিয়ম ভাঙল, কিছুই বলে না।

**দরকার:** এমন একটা এরর যা

1. ব্লককে **ব্যর্থ** করে (যাতে কলকারী জানে),
2. **নিজের বার্তা** বহন করে, আর
3. **নিজের নম্বর** দেয় (যাতে প্রোগ্রাম চিনতে পারে)।

## ২. RAISE_APPLICATION_ERROR (৩৫ মিনিট)

```sql
RAISE_APPLICATION_ERROR(error_number, message);
```

| Parameter | নিয়ম |
|---|---|
| `error_number` | **-20000 থেকে -20999**, এই ১০০০টা নম্বর তোমার জন্য রাখা |
| `message` | যেকোনো লেখা, ২০৪৮ বাইট পর্যন্ত |

```sql
SET SERVEROUTPUT ON

DECLARE
    c_min_stock CONSTANT NUMBER := 20;
    v_item_id   w14_stock.item_id%TYPE := 2;
    v_qty       NUMBER := 50;
    v_balance   w14_stock.balance_qty%TYPE;
BEGIN
    SELECT balance_qty INTO v_balance FROM w14_stock WHERE item_id = v_item_id;

    IF v_balance - v_qty < c_min_stock THEN
        RAISE_APPLICATION_ERROR(-20001,
            'Cannot issue ' || v_qty || ': only ' || v_balance || ' in stock, minimum ' || c_min_stock);
    END IF;

    UPDATE w14_stock SET balance_qty = balance_qty - v_qty WHERE item_id = v_item_id;
END;
/
```

```
ORA-20001: Cannot issue 50: only 60 in stock, minimum 20
ORA-06512: at line 10
```

ঠিক Oracle-এর নিজের এররের মতো দেখতে। APEX এই বার্তাটাই ব্যবহারকারীকে দেখাবে (সপ্তাহ ২৯-এ নিজে দেখবে)।

### Exception ঘোষণা লাগল না

`RAISE_APPLICATION_ERROR` একসাথে Exception বানায় আর ছোঁড়ে। `DECLARE`-এ কিছু লাগে না।

### ডাটার কী হয়

এটা না ধরা Exception, তাই ক্লাস ৮১-র নিয়ম: **ব্লকের সব বদল বাতিল।** স্টক কমবে না, লেনদেনের রো থাকবে না। ঠিক যা চাই।

### নম্বর সীমার বাইরে

```sql
BEGIN
    RAISE_APPLICATION_ERROR(-30001, 'Test');
END;
/
-- ORA-21000: error number argument to raise_application_error of -30001 is out of range
```

`-20000`-এর চেয়ে বড় (যেমন `-1`, `20001`) দিলেও একই এরর।

### গতকালের কাঠামোর সাথে মিলিয়ে

দুইভাবে লেখা যায়:

**ক. সরাসরি**, যাচাইয়ের জায়গাতেই:

```sql
IF v_qty <= 0 THEN
    RAISE_APPLICATION_ERROR(-20002, 'Quantity must be more than zero');
END IF;
```

**খ. নিজের Exception দিয়ে, শেষে এক জায়গায় রূপান্তর:**

```sql
EXCEPTION
    WHEN e_bad_qty THEN
        RAISE_APPLICATION_ERROR(-20002, 'Quantity must be more than zero');
    WHEN e_low_stock THEN
        RAISE_APPLICATION_ERROR(-20001, 'Stock too low');
```

ছোট প্রোগ্রামে ক সহজ। বড় প্রোগ্রামে খ-তে সব বার্তা এক জায়গায় থাকে। দুইটাই চলে।

## ৪. আগের যাচাই, এবার আসল এরর দিয়ে (৪০ মিনিট)

### স্টক ইস্যু

```sql
DECLARE
    c_min_stock CONSTANT NUMBER := 20;
    c_max_issue CONSTANT NUMBER := 500;

    v_item_id  w14_stock.item_id%TYPE := 1;
    v_qty      NUMBER := 100;
    v_balance  w14_stock.balance_qty%TYPE;
BEGIN
    IF v_qty IS NULL OR v_qty <= 0 THEN
        RAISE_APPLICATION_ERROR(-20002, 'Quantity must be more than zero');
    END IF;

    IF v_qty > c_max_issue THEN
        RAISE_APPLICATION_ERROR(-20004, 'Issue of ' || v_qty || ' needs manager approval (limit ' || c_max_issue || ')');
    END IF;

    BEGIN
        SELECT balance_qty INTO v_balance
        FROM   w14_stock
        WHERE  item_id = v_item_id
        FOR UPDATE;
    EXCEPTION
        WHEN NO_DATA_FOUND THEN
            RAISE_APPLICATION_ERROR(-20003, 'Item ' || v_item_id || ' not found');
    END;

    IF v_balance - v_qty < c_min_stock THEN
        RAISE_APPLICATION_ERROR(-20001,
            'Cannot issue ' || v_qty || ': only ' || v_balance || ' in stock, minimum ' || c_min_stock);
    END IF;

    UPDATE w14_stock SET balance_qty = balance_qty - v_qty WHERE item_id = v_item_id;
    INSERT INTO w14_txn (item_id, txn_type, qty) VALUES (v_item_id, 'ISSUE', v_qty);

    DBMS_OUTPUT.PUT_LINE('Issued ' || v_qty || ', new balance ' || (v_balance - v_qty));
    ROLLBACK;     -- পরীক্ষার জন্য, আসল প্রোগ্রামে COMMIT কলকারীর কাজ
END;
/
```

`EXCEPTION` অংশই নেই, বাইরের ব্লকে! প্রতিটা ভুল সোজা ব্যর্থ হয় আর নিজের বার্তা বহন করে। শুধু `NO_DATA_FOUND`-কে নিজের নম্বরে বদলাতে ছোট Nested Block।

`FOR UPDATE`-এর Lock? ব্যর্থ হলে Oracle ব্লকের কাজ বাতিল করে, কিন্তু Lock ছাড়ে Transaction শেষ হলে (`ROLLBACK`/`COMMIT`)। SQL Developer-এ এরর দেখার পরে `ROLLBACK;` দাও। APEX নিজে Page Process শেষে এটা সামলায়।

### স্যালারি প্রসেসের আগে কর্মচারী যাচাই

```sql
DECLARE
    c_min_wage CONSTANT NUMBER := 8000;
    v_emp_id   w16_emp.emp_id%TYPE := 10;
    v_status   w16_emp.status%TYPE;
    v_basic    w16_emp.basic_salary%TYPE;
BEGIN
    BEGIN
        SELECT status, basic_salary INTO v_status, v_basic
        FROM   w16_emp WHERE emp_id = v_emp_id;
    EXCEPTION
        WHEN NO_DATA_FOUND THEN
            RAISE_APPLICATION_ERROR(-20201, 'Employee ' || v_emp_id || ' not found');
    END;

    IF v_status = 'LEFT' THEN
        RAISE_APPLICATION_ERROR(-20203, 'Employee ' || v_emp_id || ' has left, no salary');
    END IF;

    IF v_basic < c_min_wage THEN
        RAISE_APPLICATION_ERROR(-20202, 'Basic ' || v_basic || ' is below minimum wage ' || c_min_wage);
    END IF;

    DBMS_OUTPUT.PUT_LINE('Employee ' || v_emp_id || ' OK for payroll');
END;
/
```

| `v_emp_id` | ফল |
|---|---|
| ১ | `Employee 1 OK for payroll` |
| ১০ | `ORA-20203: Employee 10 has left, no salary` |
| ৯৯ | `ORA-20201: Employee 99 not found` |

## ৫. নিজের এরর ধরা, তৃতীয় Parameter (২০ মিনিট)

### উপরের ব্লকে ধরা

কখনো বাইরের কোড এরর ধরে নিজে সিদ্ধান্ত নেয়। যেমন ৯ জনের স্যালারি যাচাই, কেউ ব্যর্থ হলে তার নাম লিখে পরের জনে যাও।

```sql
DECLARE
    e_left EXCEPTION;
    PRAGMA EXCEPTION_INIT(e_left, -20203);
BEGIN
    BEGIN
        RAISE_APPLICATION_ERROR(-20203, 'Employee 10 has left, no salary');
    EXCEPTION
        WHEN e_left THEN
            DBMS_OUTPUT.PUT_LINE('Skipped: ' || SQLERRM);
    END;
    DBMS_OUTPUT.PUT_LINE('Continue with next employee');
END;
/
-- Skipped: ORA-20203: Employee 10 has left, no salary
-- Continue with next employee
```

- ক্লাস ৮৩-এর `PRAGMA EXCEPTION_INIT` এখানেও কাজ করে
- `SQLERRM` দেয় এররের পুরো বার্তা (কাল বিস্তারিত)

### তৃতীয় Parameter: keeperrorstack

```sql
RAISE_APPLICATION_ERROR(-20001, 'message', TRUE);
```

| মান | এররের তালিকা (Error Stack) |
|---|---|
| `FALSE` (Default) | আগের এরর মুছে শুধু তোমারটা |
| `TRUE` | আগের এররের উপরে তোমারটা যোগ |

```sql
BEGIN
    DELETE FROM w16_emp WHERE emp_id = 3;
EXCEPTION
    WHEN OTHERS THEN
        RAISE_APPLICATION_ERROR(-20201, 'Could not delete employee 3', TRUE);
END;
/
-- ORA-20201: Could not delete employee 3
-- ORA-02292: integrity constraint (LEARN.W16_SALARY_EMP_FK) violated - child record found
```

`TRUE` দিলে আসল কারণ (`ORA-02292`) হারায় না। ব্যবহারকারী তোমার বার্তা দেখে, ডেভেলপার দেখে আসল কারণ।

## ৬. হাতে-কলমে প্র্যাকটিস (৪৫ মিনিট)

সব `learn_freepdb1`-এ। এরর দেখার পরে `ROLLBACK;` দিও।

1. ক্লাসের প্রথম কোড (`-20001`) চালাও। আইটেম ২-এর স্টক কি কমেছে? (না, ৬০)
2. `-30001` আর `-19999` দিয়ে চালাও, এরর লেখো।
3. স্টক ইস্যুর কোড ৬ রকম মানে: (১, ১০০), (১, ০), (১, ৬০০), (৯, ১০), (২, ৫০), (৩, ১৬০)। প্রতিটার নম্বর আর বার্তা। (শেষটা: ১৮০ − ১৬০ = ২০, Minimum-এর নিচে না, তাই Issued)
4. স্যালারি যাচাইয়ের কোড: ১, ১০, ৯৯। তারপর Nasima-র Basic ৭৫০০ করে ৬ দিয়ে। `ROLLBACK`।
5. লাইব্রেরি যাচাই (ক্লাস ৮৩ প্র্যাকটিস ৫) `RAISE_APPLICATION_ERROR` দিয়ে আবার লেখো, `-20101` থেকে `-20105`। বাইরে কোনো `EXCEPTION` থাকবে না।
6. ৫ নম্বর ৪ রকম মানে চালাও।
7. স্যালারি যাচাই সব `ACTIVE` আর `LEFT` কর্মচারীর জন্য Loop-এ: ভেতরের Nested Block `-20203` আর `-20202` `PRAGMA EXCEPTION_INIT` দিয়ে ধরে `Skipped: ...` ছাপাবে, অন্যদের `OK`। (এখানে `ACTIVE` শর্ত ছাড়া সব ১০ জন)
8. তৃতীয় Parameter `TRUE` আর `FALSE` দুইভাবে Salma মোছার কোড চালাও। পার্থক্য খাতায় লেখো।
9. **বায়ারের অর্ডার:** নিজের Variable-এ শিপমেন্টের তারিখ আর আজকের তারিখ। শিপমেন্ট পার হলে `-20301: Shipment date dd-Mon-yyyy has passed, order is locked`। `DATE '2027-02-15'` আর `DATE '2027-04-15'` দিয়ে পরীক্ষা করো, আজকের তারিখ ধরো `DATE '2027-03-02'`।
10. খারাপ বার্তা ঠিক করো: `RAISE_APPLICATION_ERROR(-20105, 'Error');` কপি ১২-এর জন্য।

            END IF;
            IF r.basic_salary < c_min_wage THEN
                RAISE_APPLICATION_ERROR(-20202, r.emp_name || ': basic below minimum wage');
            END IF;
            DBMS_OUTPUT.PUT_LINE(r.emp_name || ': OK');
        EXCEPTION
            WHEN e_left OR e_wage THEN
                DBMS_OUTPUT.PUT_LINE('Skipped: ' || SQLERRM);
        END;
    END LOOP;
END;
/
-- ৯ জন OK, শেষে: Skipped: ORA-20203: Tania has left, no salary

## সারাংশ

- `DBMS_OUTPUT` শুধু তুমি দেখো, APEX বা অন্য প্রোগ্রাম না
- `RAISE_APPLICATION_ERROR(-20xxx, 'বার্তা')`: ব্লক ব্যর্থ, নিজের নম্বর, নিজের বার্তা, সব বদল বাতিল
- নম্বর মডিউল ধরে ভাগ করো, বার্তায় কী হয়েছে, কোন মান, কী করতে হবে
- `PRAGMA EXCEPTION_INIT(e, -20xxx)` দিয়ে নিজের এরর আবার ধরা যায়
- `TRUE` দিলে আসল Oracle এরর হারায় না

**পরের ক্লাস (বুধবার):** `SQLCODE`, `SQLERRM`, আর Error Log টেবিলে এরর সেভ করা।
