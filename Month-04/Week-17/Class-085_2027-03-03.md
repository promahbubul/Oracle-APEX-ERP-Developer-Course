# ক্লাস ৮৫: SQLCODE, SQLERRM, Error Log টেবিলে এরর সেভ করা

**তারিখ:** ৩ মার্চ ২০২৭, বুধবার
**সময়:** সন্ধ্যা ৭:০০ থেকে রাত ১০:০০
**সপ্তাহ:** ১৭ | **ধাপ:** ৩ (PL/SQL)

## আজকে কী শিখব

- `SQLCODE`: কোন এরর, নম্বরে
- `SQLERRM`: এররের বার্তা
- `DBMS_UTILITY.FORMAT_ERROR_BACKTRACE`: কোন লাইনে
- Error Log টেবিল বানানো আর তাতে এরর লেখা
- Loop-এ খারাপ রো লগ করে বাকিগুলো সেভ করা (`SAVEPOINT`)

## ১. SQLCODE (২৫ মিনিট)

`WHEN OTHERS` সব ধরে, কিন্তু **কী** ধরল? `SQLCODE` বলে দেয়।

```sql
SET SERVEROUTPUT ON

DECLARE
    v_name w16_emp.emp_name%TYPE;
BEGIN
    SELECT emp_name INTO v_name FROM w16_emp WHERE dept_name = 'Sewing';
EXCEPTION
    WHEN OTHERS THEN
        DBMS_OUTPUT.PUT_LINE('Code: ' || SQLCODE);       -- -1422
END;
/
```

### কোন এররে কোন মান

| পরিস্থিতি | `SQLCODE` |
|---|---|
| `TOO_MANY_ROWS` | -1422 |
| `ZERO_DIVIDE` | -1476 |
| `DUP_VAL_ON_INDEX` | -1 |
| `NO_DATA_FOUND` | **+100** (ব্যতিক্রম!) |
| `RAISE_APPLICATION_ERROR(-20001, ...)` | -20001 |
| নিজের Exception, `PRAGMA` ছাড়া | **+1** |
| Handler-এর বাইরে, কোনো এরর নেই | 0 |

`NO_DATA_FOUND`-এর +১০০ এসেছে SQL-এর আন্তর্জাতিক মান (ANSI) থেকে। ORA নম্বর -১৪০৩ হলেও `SQLCODE` ১০০।

### নম্বর দেখে সিদ্ধান্ত

```sql
EXCEPTION
    WHEN OTHERS THEN
        IF SQLCODE BETWEEN -20999 AND -20000 THEN
            DBMS_OUTPUT.PUT_LINE('Business rule failed');
        ELSE
            DBMS_OUTPUT.PUT_LINE('System error');
        END IF;
        RAISE;
```

নিজের নিয়ম ভাঙা (ব্যবহারকারীর ভুল) আর সিস্টেমের এরর (প্রোগ্রামারের সমস্যা) আলাদা করা যায়।

## ২. SQLERRM (২৫ মিনিট)

**এররের পুরো বার্তা, নম্বরসহ।**

```sql
BEGIN
    DBMS_OUTPUT.PUT_LINE(10 / 0);
EXCEPTION
    WHEN OTHERS THEN
        DBMS_OUTPUT.PUT_LINE(SQLERRM);       -- ORA-01476: divisor is equal to zero
END;
/
```

| পরিস্থিতি | `SQLERRM` |
|---|---|
| Oracle এরর | `ORA-01476: divisor is equal to zero` |
| `RAISE_APPLICATION_ERROR` | `ORA-20001: Cannot issue 50: ...` |
| নিজের Exception, `PRAGMA` ছাড়া | `User-Defined Exception` |
| Handler-এর বাইরে | `ORA-0000: normal, successful completion` |

### কোন Constraint ভাঙল

ক্লাস ৮২-তে বলেছিলাম `DUP_VAL_ON_INDEX` বলে না কোন Constraint। `SQLERRM` বলে:

```sql
BEGIN
    INSERT INTO lib_member (member_id, member_name, mobile_no, member_type_id)
    SELECT 999, 'Test', mobile_no, member_type_id FROM lib_member WHERE member_id = 1;
EXCEPTION
    WHEN DUP_VAL_ON_INDEX THEN
        DBMS_OUTPUT.PUT_LINE(SQLERRM);
        -- ORA-00001: unique constraint (LEARN.LIB_MEMBER_MOBILE_UK) violated
        IF INSTR(SQLERRM, 'LIB_MEMBER_MOBILE_UK') > 0 THEN
            DBMS_OUTPUT.PUT_LINE('This mobile number is already registered');
        END IF;
END;
/
```

এজন্যই Constraint-এর নাম অর্থবোধক রাখতে বলেছিলাম (সপ্তাহ ৩)। `SYS_C008123` থাকলে কিছুই বোঝা যেত না।

Oracle-এর নতুন ভার্সনে বার্তার শেষে আরো কিছু তথ্য থাকতে পারে, তাই পুরো বার্তা মেলানোর বদলে `INSTR` দিয়ে নাম খোঁজো।

### নম্বর দিয়ে বার্তা

```sql
DBMS_OUTPUT.PUT_LINE(SQLERRM(-1476));     -- ORA-01476: divisor is equal to zero
```

### SQL-এর ভেতরে সরাসরি না

```sql
INSERT INTO some_log VALUES (SQLCODE, SQLERRM);     -- PLS-00231: function may not be used in SQL
```

আগে Variable-এ নাও, তারপর Variable দিয়ে `INSERT`:

```sql
v_code := SQLCODE;
v_msg  := SQLERRM;
INSERT INTO some_log VALUES (v_code, v_msg);
```

## ৩. কোন লাইনে: FORMAT_ERROR_BACKTRACE (২০ মিনিট)

`SQLERRM` বলে **কী**, কিন্তু **কোথায়** না। ২০০ লাইনের প্রোগ্রামে এটা জানা জরুরি।

```sql
DECLARE
    v_a NUMBER := 10;
    v_b NUMBER := 0;
BEGIN
    v_a := v_a + 1;
    v_a := v_a / v_b;                  -- লাইন ৬
    v_a := v_a - 1;
EXCEPTION
    WHEN OTHERS THEN
        DBMS_OUTPUT.PUT_LINE('Error : ' || SQLERRM);
        DBMS_OUTPUT.PUT_LINE('Where : ' || DBMS_UTILITY.FORMAT_ERROR_BACKTRACE);
END;
/
-- Error : ORA-01476: divisor is equal to zero
-- Where : ORA-06512: at line 6
```

| Function | কী দেয় |
|---|---|
| `SQLCODE` | নম্বর |
| `SQLERRM` | বার্তা (৫১২ অক্ষর পর্যন্ত) |
| `DBMS_UTILITY.FORMAT_ERROR_STACK` | পুরো এররের তালিকা (লম্বা বার্তাও) |
| `DBMS_UTILITY.FORMAT_ERROR_BACKTRACE` | কোন লাইনে, কোন Procedure-এ |

পরের সপ্তাহ থেকে Procedure-এর ভেতরে Procedure ডাকবে। তখন Backtrace পুরো পথ দেখাবে: কে কাকে ডেকেছিল, কোথায় ভাঙল।

**সতর্কতা:** Handler-এ ঢোকার পরে প্রথম কাজ এই মানগুলো Variable-এ তুলে রাখা। Handler-এর ভেতরে অন্য SQL বা এরর হলে মান বদলে যেতে পারে।

## ৪. Error Log টেবিল (৪৫ মিনিট)

`DBMS_OUTPUT` তুমিই দেখো, আর স্ক্রিন বন্ধ করলে হারিয়ে যায়। আসল ERP-তে প্রতিটা অপ্রত্যাশিত এরর একটা টেবিলে লেখা হয়। সকালে সাপোর্ট টিম দেখে রাতে কী ভেঙেছিল।

```sql
CREATE TABLE w17_error_log (
    log_id        NUMBER GENERATED ALWAYS AS IDENTITY CONSTRAINT w17_error_log_pk PRIMARY KEY,
    log_time      TIMESTAMP      DEFAULT SYSTIMESTAMP NOT NULL,
    module_name   VARCHAR2(50)   NOT NULL,
    error_code    NUMBER,
    error_msg     VARCHAR2(4000),
    backtrace     VARCHAR2(4000),
    context_info  VARCHAR2(400),
    db_user       VARCHAR2(128)  DEFAULT USER NOT NULL
);
```

| কলাম | কেন |
|---|---|
| `module_name` | কোন প্রোগ্রাম (`STOCK_ISSUE`, `PAYROLL`) |
| `error_code`, `error_msg` | `SQLCODE`, `SQLERRM` |
| `backtrace` | কোন লাইনে |
| `context_info` | তখন কোন মান ছিল (`item=2, qty=50`), পুনরায় ঘটাতে লাগে |
| `db_user`, `log_time` | কে, কখন |

### লগ করার প্যাটার্ন

```sql
DECLARE
    v_item_id NUMBER := 2;
    v_qty     NUMBER := 50;
    v_pack    NUMBER := 0;

    v_code    NUMBER;
    v_msg     VARCHAR2(4000);
    v_bt      VARCHAR2(4000);
BEGIN
    UPDATE w14_stock SET balance_qty = balance_qty - v_qty WHERE item_id = v_item_id;
    DBMS_OUTPUT.PUT_LINE('Packs: ' || v_qty / v_pack);          -- ভুল: ০ দিয়ে ভাগ
    COMMIT;
EXCEPTION
    WHEN OTHERS THEN
        -- ১. সবার আগে এররের তথ্য তুলে রাখো
        v_code := SQLCODE;
        v_msg  := SQLERRM;
        v_bt   := DBMS_UTILITY.FORMAT_ERROR_BACKTRACE;

        -- ২. অর্ধেক করা কাজ বাতিল
        ROLLBACK;

        -- ৩. লগ লেখো আর সেভ করো
        INSERT INTO w17_error_log (module_name, error_code, error_msg, backtrace, context_info)
        VALUES ('STOCK_ISSUE', v_code, v_msg, v_bt,
                'item=' || v_item_id || ', qty=' || v_qty);
        COMMIT;

        -- ৪. কলকারীকে জানাও
        RAISE;
END;
/
```

```sql
SELECT log_id, log_time, module_name, error_code, error_msg, context_info
FROM   w17_error_log
ORDER  BY log_id DESC;
```

ক্রম গুরুত্বপূর্ণ:

| ধাপ | না করলে |
|---|---|
| ১. তথ্য তুলে রাখা | `ROLLBACK`/`INSERT`-এর পরে `SQLERRM` বদলাতে পারে |
| ২. `ROLLBACK` আগে | পরের `COMMIT` অর্ধেক কাজও (স্টক কমা) সেভ করে দিত! |
| ৩. `INSERT` + `COMMIT` | লগ থাকে, পরের `RAISE`-এ বাতিল হয় না |
| ৪. `RAISE` | ব্লক "সফল" দেখাত, কলকারী জানত না |

স্টক দেখো: আইটেম ২ এখনো ৬০। লগে একটা রো।

### এই পদ্ধতির দুর্বলতা

`ROLLBACK` পুরো Transaction বাতিল করে, এই ব্লকের আগের কাজও। আর `COMMIT` সবকিছু সেভ করে। বড় প্রোগ্রামে এটা বিপদ।

সমাধান **Autonomous Transaction** (ক্লাস ১০৭): লগের Procedure নিজের আলাদা Transaction-এ চলে, মূল কাজে হাত দেয় না। তখন এই প্যাটার্ন আরো পরিষ্কার হবে। আপাতত এভাবে।

### কোন এরর লগ করবে

| এরর | লগ? |
|---|---|
| ব্যবসার নিয়ম (`-20001` স্টক কম) | সাধারণত না, ব্যবহারকারীর ভুল, বার্তাই যথেষ্ট |
| অপ্রত্যাশিত (`ORA-01476`, `ORA-06502`) | **হ্যাঁ**, প্রোগ্রামের সমস্যা |

```sql
WHEN OTHERS THEN
    IF SQLCODE NOT BETWEEN -20999 AND -20000 THEN
        -- লগ লেখো
    END IF;
    RAISE;
```

## ৫. Loop-এ খারাপ রো লগ করে বাকিগুলো সেভ (২০ মিনিট)

সমস্যা: ১০টা রো প্রসেস করছ, ৩ নম্বরটা খারাপ। চাই ৯টা সেভ, খারাপটা লগে। কিন্তু খারাপ রো-র অর্ধেক কাজ বাতিল হতে হবে, বাকি ৯টার না।

`ROLLBACK` দিলে আগের ভালোগুলোও যায়। সমাধান ক্লাস ২৫-এর **`SAVEPOINT`**:

```sql
DECLARE
    v_code NUMBER;
    v_msg  VARCHAR2(4000);
    v_ok   NUMBER := 0;
    v_bad  NUMBER := 0;
BEGIN
    FOR r IN (SELECT item_id, item_name,
                     CASE item_id WHEN 2 THEN 0 ELSE 10 END AS pack_size
              FROM   w14_stock ORDER BY item_id)
    LOOP
        SAVEPOINT before_item;
        BEGIN
            UPDATE w14_stock
            SET    balance_qty = balance_qty + 100 / r.pack_size
            WHERE  item_id = r.item_id;
            v_ok := v_ok + 1;
        EXCEPTION
            WHEN OTHERS THEN
                v_code := SQLCODE;
                v_msg  := SQLERRM;
                ROLLBACK TO before_item;              -- শুধু এই রো-র কাজ বাতিল
                INSERT INTO w17_error_log (module_name, error_code, error_msg, context_info)
                VALUES ('STOCK_REFILL', v_code, v_msg, 'item=' || r.item_id);
                v_bad := v_bad + 1;
        END;
    END LOOP;

    DBMS_OUTPUT.PUT_LINE(v_ok || ' ok, ' || v_bad || ' logged');    -- 2 ok, 1 logged
    ROLLBACK;     -- পরীক্ষার জন্য। আসল কাজে COMMIT, তখন লগও সেভ হবে
END;
/
```

- প্রতিটা রো-র আগে `SAVEPOINT`
- এরর হলে শুধু সেখানে ফেরা
- লগের `INSERT` একই Transaction-এ, শেষের `COMMIT`-এ ভালো রো-র সাথে সেভ হবে

এখানে `ROLLBACK` দেওয়ায় লগও মুছে যাবে। প্র্যাকটিসে `COMMIT` দিয়ে দেখবে।

            INSERT INTO w17_error_log (module_name, error_code, error_msg, backtrace, context_info)
            VALUES ('STOCK_ISSUE', v_code, v_msg, v_bt, 'item=' || v_item_id || ', qty=' || v_qty);
            COMMIT;
        END IF;
        RAISE;
END;

-- ভাগে ০ পরীক্ষা: UPDATE-এর আগে v_balance := v_balance / 0; যোগ করো

    INSERT INTO lib_member (member_id, member_name, mobile_no, member_type_id)

    WHEN DUP_VAL_ON_INDEX THEN
        IF INSTR(SQLERRM, 'LIB_MEMBER_MOBILE_UK') > 0 THEN

## সারাংশ

- `SQLCODE`: নম্বর (ব্যতিক্রম: NO_DATA_FOUND +১০০, নিজের Exception +১)
- `SQLERRM`: বার্তা, Constraint-এর নামসহ, `INSTR` দিয়ে খোঁজো
- `FORMAT_ERROR_BACKTRACE`: কোন লাইনে
- Handler-এ প্রথমে তথ্য তোলো, `ROLLBACK`, লগ + `COMMIT`, তারপর `RAISE`
- ব্যবসার নিয়ম সাধারণত লগ হয় না, অপ্রত্যাশিত এরর সবসময়
- Loop-এ `SAVEPOINT` দিয়ে শুধু খারাপ রো বাতিল
