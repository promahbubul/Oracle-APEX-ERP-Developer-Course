## ১. ZERO_DIVIDE (২৫ মিনিট)

`ORA-01476: divisor is equal to zero`

সপ্তাহ ১৫-এর প্র্যাকটিস ১১-এর Efficiency মনে আছে? `পিস × SMV × ১০০ / (অপারেটর × ঘণ্টা × ৬০)`। কোনো লাইনে আজ কেউ আসেনি, অপারেটর ০।

```sql
SET SERVEROUTPUT ON

DECLARE
    v_pcs       NUMBER := 0;
    v_smv       NUMBER := 15;
    v_operators NUMBER := 0;
    v_hours     NUMBER := 8;
    v_eff       NUMBER;
BEGIN
    v_eff := v_pcs * v_smv * 100 / (v_operators * v_hours * 60);
    DBMS_OUTPUT.PUT_LINE('Efficiency: ' || ROUND(v_eff, 2) || '%');
EXCEPTION
    WHEN ZERO_DIVIDE THEN
        DBMS_OUTPUT.PUT_LINE('No operators on this line today');
END;
/
```

### আগে থেকে আটকানোই ভালো

```sql
IF v_operators = 0 OR v_hours = 0 THEN
    DBMS_OUTPUT.PUT_LINE('No operators on this line today');
ELSE
    v_eff := v_pcs * v_smv * 100 / (v_operators * v_hours * 60);
    DBMS_OUTPUT.PUT_LINE('Efficiency: ' || ROUND(v_eff, 2) || '%');
END IF;
```

**নিয়ম:** যে এরর তুমি আগেই জানো আসতে পারে, সেটা `IF` দিয়ে আটকাও। Exception রাখো **অপ্রত্যাশিত** জিনিসের জন্য। কারণ:

- `IF` পড়লেই বোঝা যায় কী হচ্ছে
- Exception-এ লাফ দিলে বাকি কাজ (যেমন অন্য লাইনের হিসাব) বাদ পড়ে

### SQL-এর ভেতরে

Query-তে ভাগ করলে `NULLIF` (ক্লাস ৩৬) দিয়ে ০-কে NULL বানাও। NULL দিয়ে ভাগে এরর নেই, ফল NULL।

```sql
SELECT 100 / NULLIF(0, 0) AS result FROM dual;     -- NULL, এরর না
```

## ২. DUP_VAL_ON_INDEX (২৫ মিনিট)

`ORA-00001: unique constraint violated`

Primary Key বা Unique Constraint-এ যে মান আগেই আছে, সেটা আবার ঢোকালে।

```sql
BEGIN
    INSERT INTO w16_emp (emp_id, emp_name, dept_name, basic_salary)
    VALUES (1, 'Rubel', 'Cutting', 11000);
    DBMS_OUTPUT.PUT_LINE('Inserted');
EXCEPTION
    WHEN DUP_VAL_ON_INDEX THEN
        DBMS_OUTPUT.PUT_LINE('Employee ID 1 already exists');
END;
/
```

সপ্তাহ ১৬-এর প্র্যাকটিস ৪-এ স্যালারি শিট দুইবার চালালে এটাই এসেছিল।

### "থাকলে আপডেট, না থাকলে ঢোকাও", আরেক উপায়

ক্লাস ৭৬-এ `UPDATE` আগে, `SQL%NOTFOUND` হলে `INSERT` করেছিলে। উল্টো দিক থেকে:

```sql
DECLARE
    v_id    NUMBER := 3;
    v_name  VARCHAR2(50) := 'Pique';
BEGIN
    INSERT INTO w14_stock (item_id, item_name, balance_qty) VALUES (v_id, v_name, 0);
    DBMS_OUTPUT.PUT_LINE('Inserted');
EXCEPTION
    WHEN DUP_VAL_ON_INDEX THEN
        UPDATE w14_stock SET item_name = v_name WHERE item_id = v_id;
        DBMS_OUTPUT.PUT_LINE('Already there, updated');
END;
/
ROLLBACK;
```

কোনটা কখন?

| বেশিরভাগ ক্ষেত্রে রো | আগে করো |
|---|---|
| আগে থেকেই আছে | `UPDATE`, তারপর `SQL%NOTFOUND`-এ `INSERT` |
| নতুন | `INSERT`, তারপর `DUP_VAL_ON_INDEX`-এ `UPDATE` |

দুইটার চেয়ে একটা `MERGE` (ক্লাস ৬৪) প্রায়ই ভালো।

### Unique Key-তেও

`lib_member`-এর মোবাইল Unique (`lib_member_mobile_uk`)। একই মোবাইলে নতুন মেম্বার ঢোকালেও `DUP_VAL_ON_INDEX`। তবে বার্তা দেখে বোঝা যায় না **কোন** Constraint। ক্লাস ৮৫-এ `SQLERRM` দিয়ে Constraint-এর নাম বের করবে।

## ৩. VALUE_ERROR আর INVALID_NUMBER (২০ মিনিট)

### VALUE_ERROR (ORA-06502)

PL/SQL-এ মান Variable-এ আঁটে না, বা রূপান্তর হয় না।

```sql
DECLARE
    v_code VARCHAR2(5);
    v_qty  NUMBER(3);
    v_num  NUMBER;
BEGIN
    v_code := 'STY-2027-001';       -- ১২ অক্ষর, জায়গা ৫: character string buffer too small
    -- v_qty := 1500;               -- NUMBER(3)-এ ৪ অঙ্ক: number precision too large
    -- v_num := '12a';              -- character to number conversion error
EXCEPTION
    WHEN VALUE_ERROR THEN
        DBMS_OUTPUT.PUT_LINE('Value does not fit or is not a number');
END;
/
```

তিনটা লাইন একটা একটা করে খুলে চালাও, তিনবারই `VALUE_ERROR`।

### INVALID_NUMBER (ORA-01722)

একই রূপান্তরের ভুল, কিন্তু **SQL Statement-এর ভেতরে**।

```sql
BEGIN
    INSERT INTO w14_stock (item_id, item_name, balance_qty)
    VALUES (4, 'Rib', TO_NUMBER('12a'));
EXCEPTION
    WHEN INVALID_NUMBER THEN
        DBMS_OUTPUT.PUT_LINE('Quantity is not a number');
END;
/
```

| কোথায় রূপান্তর | Exception |
|---|---|
| PL/SQL-এর `:=` বা Expression | `VALUE_ERROR` |
| SQL (`SELECT`, `INSERT`, `UPDATE`)-এর ভেতরে | `INVALID_NUMBER` |

মনে রাখা কঠিন। তাই অনেকে দুইটা একসাথে লেখে: `WHEN VALUE_ERROR OR INVALID_NUMBER THEN`।

APEX-এ ব্যবহারকারী Text Field-এ সংখ্যার জায়গায় লেখা দিলে এগুলোই আসবে।

## ৪. WHEN OTHERS (২৫ মিনিট)

উপরের কোনো `WHEN` না মিললে `OTHERS` সব ধরে।

```sql
DECLARE
    v_name w16_emp.emp_name%TYPE;
BEGIN
    SELECT emp_name INTO v_name FROM w16_emp WHERE emp_id = 99;
EXCEPTION
    WHEN TOO_MANY_ROWS THEN
        DBMS_OUTPUT.PUT_LINE('Many');
    WHEN OTHERS THEN
        DBMS_OUTPUT.PUT_LINE('Something went wrong');      -- NO_DATA_FOUND এখানে আসে
END;
/
```

### নিয়ম

| নিয়ম | না মানলে |
|---|---|
| `OTHERS` সবার শেষে | `PLS-00370: OTHERS handler must be last` |
| একটা ব্লকে একটাই `OTHERS` | Compile Error |
| `OTHERS`-এর সাথে `OR` চলে না | Compile Error |

### সবচেয়ে বিপজ্জনক লাইন

```sql
EXCEPTION
    WHEN OTHERS THEN
        NULL;
```

এর মানে: **"যা-ই হোক, চুপ থাকো।"** স্টক কমল কি না, স্যালারি ঢুকল কি না, কেউ জানবে না। প্রোগ্রাম "successfully completed" দেখায়, অথচ কাজ হয়নি। পরে খুঁজে পাওয়া প্রায় অসম্ভব।

Oracle-এর Compiler এর জন্য সতর্কও করে (`PLW-06009`, Warning চালু থাকলে)।

**নিয়ম:** `WHEN OTHERS`-এ অন্তত একটা কাজ করো:

1. বার্তা দেখাও বা লগে লেখো (ক্লাস ৮৫), **আর**
2. `RAISE;` দিয়ে এরর আবার উপরে পাঠাও (ক্লাস ৮৩)

```sql
EXCEPTION
    WHEN OTHERS THEN
        ROLLBACK;
        DBMS_OUTPUT.PUT_LINE('Unexpected error, nothing saved');
        RAISE;           -- এরর আবার ছোঁড়া, যাতে কলকারী জানে
```

### কোনটা ধরবে

যে এরর তুমি **চেনো আর সামলাতে জানো**, শুধু সেটা নাম ধরে ধরো। বাকি সব হয় উপরে যেতে দাও, নয়তো `OTHERS`-এ লগ করে `RAISE`।

## ৫. Nested Block: কোথায় ধরা পড়ে (২৫ মিনিট)

গতকাল দেখেছ, ভেতরের ব্লকে এরর ধরলে বাইরের ব্লক চলতে থাকে। এবার নিয়মগুলো।

### নিয়ম ১: ভেতরে ধরলে বাইরে চলতে থাকে

```sql
BEGIN
    DBMS_OUTPUT.PUT_LINE('Outer start');
    BEGIN
        DBMS_OUTPUT.PUT_LINE(10 / 0);
    EXCEPTION
        WHEN ZERO_DIVIDE THEN
            DBMS_OUTPUT.PUT_LINE('Inner caught');
    END;
    DBMS_OUTPUT.PUT_LINE('Outer continues');
END;
/
-- Outer start / Inner caught / Outer continues
```

### নিয়ম ২: ভেতরে না ধরলে বাইরে যায়

```sql
BEGIN
    DBMS_OUTPUT.PUT_LINE('Outer start');
    BEGIN
        DBMS_OUTPUT.PUT_LINE(10 / 0);
    EXCEPTION
        WHEN NO_DATA_FOUND THEN                         -- মেলে না
            DBMS_OUTPUT.PUT_LINE('Inner caught');
    END;
    DBMS_OUTPUT.PUT_LINE('Outer continues');            -- চলবে না
EXCEPTION
    WHEN ZERO_DIVIDE THEN
        DBMS_OUTPUT.PUT_LINE('Outer caught');
END;
/
-- Outer start / Outer caught
```

এটাকে বলে **Propagation**: Exception এক ধাপ এক ধাপ উপরে ওঠে, যতক্ষণ না কেউ ধরে। কেউ না ধরলে লাল এরর।

### নিয়ম ৩: DECLARE-এর এরর নিজের ব্লক ধরে না

```sql
BEGIN
    DECLARE
        v_code VARCHAR2(3) := 'ABCD';                   -- এখানেই VALUE_ERROR
    BEGIN
        NULL;
    EXCEPTION
        WHEN VALUE_ERROR THEN
            DBMS_OUTPUT.PUT_LINE('Inner caught');       -- চলবে না!
    END;
EXCEPTION
    WHEN VALUE_ERROR THEN
        DBMS_OUTPUT.PUT_LINE('Outer caught');           -- এটা চলে
END;
/
```

ব্লকের `EXCEPTION` শুধু তার `BEGIN`-এর এরর পাহারা দেয়। `DECLARE`-এ মান বসানোর ভুল সোজা উপরে যায়।

### নিয়ম ৪: Handler-এর ভেতরের এররও উপরে যায়

Handler-এর ভেতরে নতুন এরর হলে একই ব্লকের অন্য `WHEN` সেটা ধরে না, বাইরে চলে যায়।

### আসল কাজ: Loop-এ খারাপ রো বাদ দিয়ে চলা

৩টা আইটেমে ভাগ করতে হবে, একটার ভাগ ০:

```sql
DECLARE
    v_ok  NUMBER := 0;
    v_bad NUMBER := 0;
BEGIN
    FOR r IN (SELECT item_id, item_name, balance_qty,
                     CASE item_id WHEN 2 THEN 0 ELSE 10 END AS pack_size
              FROM   w14_stock ORDER BY item_id)
    LOOP
        BEGIN
            DBMS_OUTPUT.PUT_LINE(r.item_name || ': ' || r.balance_qty / r.pack_size || ' packs');
            v_ok := v_ok + 1;
        EXCEPTION
            WHEN ZERO_DIVIDE THEN
                DBMS_OUTPUT.PUT_LINE(r.item_name || ': pack size missing, skipped');
                v_bad := v_bad + 1;
        END;
    END LOOP;
    DBMS_OUTPUT.PUT_LINE(v_ok || ' ok, ' || v_bad || ' skipped');     -- 2 ok, 1 skipped
END;
/
```

Nested Block না থাকলে প্রথম খারাপ রো-তেই পুরো Loop থামত। ইমপোর্ট, মাস শেষের প্রসেস, বাল্ক আপডেট: সব জায়গায় এই প্যাটার্ন।

- **৭:** `NUMBER(4,2)`-এ দশমিকের আগে মাত্র ২ অঙ্ক (সর্বোচ্চ ৯৯.৯৯), তাই `VALUE_ERROR`
- **৮:** `'15'` চলে (লুকিয়ে রূপান্তর), `'15 pcs'` `VALUE_ERROR`
- **১০:** `PLS-00370`
- **১৩:** না। Rina (৪)-এ এরর হয়ে বাইরের Handler-এ চলে যায়, Loop শেষ, Jamal থেকে কেউ ছাপা হয় না

**ভুল:**

- **১৪:** ডুপ্লিকেট `emp_id` ২, কিন্তু `WHEN OTHERS THEN NULL` চুপ করে রাখে। ব্যবহারকারী ভাবে Karim সেভ হয়েছে। `DUP_VAL_ON_INDEX` নাম ধরে ধরো আর বার্তা দাও।
- **১৫:** এরর `DECLARE`-এ (২ অঙ্কের জায়গায় ১৫০), ভেতরের ব্লকের Handler ধরে না। বাইরেও Handler নেই, তাই লাল `ORA-06502`। মান `BEGIN`-এ বসাও, অথবা বাইরের ব্লকে Handler দাও।

## সারাংশ

- `ZERO_DIVIDE`: জানা ঝুঁকি, `IF` বা `NULLIF` দিয়ে আগেই আটকাও
- `DUP_VAL_ON_INDEX`: PK/Unique-এ ডুপ্লিকেট, "থাকলে আপডেট" প্যাটার্নেও কাজে লাগে
- `VALUE_ERROR` (PL/SQL) আর `INVALID_NUMBER` (SQL): মান আঁটে না বা সংখ্যা না
- `WHEN OTHERS` শেষে, কখনো `NULL` দিয়ে চুপ না, লগ করো আর `RAISE`
- Exception নিচ থেকে উপরে ওঠে, Nested Block দিয়ে Loop-এ খারাপ রো বাদ দিয়ে চলা যায়

**পরের ক্লাস (সোমবার):** User-defined Exception: নিজের ব্যবসার নিয়মের জন্য নিজের Exception।
