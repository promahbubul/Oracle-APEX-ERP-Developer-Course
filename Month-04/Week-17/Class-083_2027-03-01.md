## আজকে কী শিখব

- Oracle-এর চোখে ঠিক, ব্যবসার চোখে ভুল
- নিজের Exception: ঘোষণা, `RAISE`, ধরা
- স্টক আর লাইব্রেরির নিয়ম Exception দিয়ে
- `PRAGMA EXCEPTION_INIT`: নামহীন ORA এররকে নাম দেওয়া

## ১. কেন নিজের Exception (২০ মিনিট)

```sql
UPDATE w14_stock SET balance_qty = balance_qty - 50 WHERE item_id = 2;
```

Button 18L-এ ৬০ আছে, ৫০ ইস্যু হলো, থাকল ১০। Oracle-এর চোখে সব ঠিক।

কিন্তু ফ্যাক্টরির নিয়ম: **কোনো আইটেম ২০-এর নিচে নামলে ইস্যু বন্ধ, আগে Purchase Requisition।** Oracle এই নিয়ম জানে না। তোমাকে বলে দিতে হবে।

এমন নিয়ম ERP-তে শত শত:

| নিয়ম | Oracle নিজে ধরে? |
|---|---|
| ইস্যুর পরিমাণ ০ বা ঋণাত্মক হতে পারবে না | CHECK থাকলে হ্যাঁ, না থাকলে না |
| Minimum Stock-এর নিচে ইস্যু না | না |
| নিষ্ক্রিয় মেম্বার বই নিতে পারবে না | না |
| এক মেম্বার `max_books`-এর বেশি না | না |
| শিপমেন্টের তারিখ পার হলে অর্ডার বদলানো যাবে না | না |

এগুলোর জন্য **User-defined Exception**।

### IF দিয়েই তো পারি?

```sql
IF v_balance - v_qty < 20 THEN
    DBMS_OUTPUT.PUT_LINE('Below minimum');
ELSE
    UPDATE ...;
    INSERT ...;
    IF ... THEN ... ELSE ... END IF;     -- আরো যাচাই
END IF;
```

যাচাই ৫টা হলে `IF`-এর ভেতরে `IF`-এর ভেতরে `IF`। আসল কাজ খুঁজে পাওয়া যায় না।

Exception দিয়ে: যাচাই উপরে এক লাইন করে, ব্যর্থ হলেই লাফ। আসল কাজ সোজা নিচে। বার্তা সব এক জায়গায়।

## ২. ঘোষণা, RAISE, ধরা (৩৫ মিনিট)

তিন ধাপ:

| ধাপ | কোথায় | লেখা |
|---|---|---|
| ১. ঘোষণা | `DECLARE` | `e_low_stock EXCEPTION;` |
| ২. ছোঁড়া | `BEGIN` | `RAISE e_low_stock;` |
| ৩. ধরা | `EXCEPTION` | `WHEN e_low_stock THEN ...` |

```sql
SET SERVEROUTPUT ON

DECLARE
    c_min_stock CONSTANT NUMBER := 20;

    v_item_id   w14_stock.item_id%TYPE := 2;
    v_qty       NUMBER := 50;
    v_balance   w14_stock.balance_qty%TYPE;

    e_low_stock EXCEPTION;
BEGIN
    SELECT balance_qty INTO v_balance FROM w14_stock WHERE item_id = v_item_id;

    IF v_balance - v_qty < c_min_stock THEN
        RAISE e_low_stock;
    END IF;

    UPDATE w14_stock SET balance_qty = balance_qty - v_qty WHERE item_id = v_item_id;
    DBMS_OUTPUT.PUT_LINE('Issued ' || v_qty);
    ROLLBACK;
EXCEPTION
    WHEN e_low_stock THEN
        DBMS_OUTPUT.PUT_LINE('Cannot issue ' || v_qty || ', only ' || v_balance
                             || ' in stock (minimum ' || c_min_stock || ')');
    WHEN NO_DATA_FOUND THEN
        DBMS_OUTPUT.PUT_LINE('Item ' || v_item_id || ' not found');
END;
/
```

| `v_item_id`, `v_qty` | ফল |
|---|---|
| ২, ৫০ | `Cannot issue 50, only 60 in stock (minimum 20)` |
| ২, ৩০ | `Issued 30` (থাকে ৩০) |
| ৯, ১০ | `Item 9 not found` |

- Exception-এর নামের আগে `e_` দিলে চেনা সহজ
- `RAISE` হলে ঠিক Predefined Exception-এর মতো আচরণ: বাকি লাইন বাদ, Handler-এ লাফ
- একই Handler-এ নিজের আর Oracle-এর Exception পাশাপাশি

### না ধরলে

```sql
DECLARE
    e_low_stock EXCEPTION;
BEGIN
    RAISE e_low_stock;
END;
/
-- ORA-06510: PL/SQL: unhandled user-defined exception
```

Oracle তোমার Exception-এর নাম জানে না, তাই একটা সাধারণ এরর দেখায়। কলকারী বুঝতে পারে না **কী** হয়েছে। এর সমাধান কাল: `RAISE_APPLICATION_ERROR`।

### Predefined Exception-ও RAISE করা যায়

```sql
IF v_qty IS NULL THEN
    RAISE VALUE_ERROR;
END IF;
```

চলে, কিন্তু বিভ্রান্তিকর। নিজের নাম দেওয়াই ভালো।

## ৩. ব্যবসার নিয়ম, এক এক করে (৩০ মিনিট)

### স্টক ইস্যু, সব যাচাই

```sql
DECLARE
    c_min_stock CONSTANT NUMBER := 20;

    v_item_id  w14_stock.item_id%TYPE := 1;
    v_qty      NUMBER := 100;
    v_balance  w14_stock.balance_qty%TYPE;

    e_bad_qty     EXCEPTION;
    e_low_stock   EXCEPTION;
BEGIN
    -- যাচাই ১: পরিমাণ
    IF v_qty IS NULL OR v_qty <= 0 THEN
        RAISE e_bad_qty;
    END IF;

    -- যাচাই ২: আইটেম আছে কি না (NO_DATA_FOUND)
    SELECT balance_qty INTO v_balance
    FROM   w14_stock
    WHERE  item_id = v_item_id
    FOR UPDATE;                                       -- ক্লাস ৮০

    -- যাচাই ৩: Minimum Stock
    IF v_balance - v_qty < c_min_stock THEN
        RAISE e_low_stock;
    END IF;

    -- আসল কাজ
    UPDATE w14_stock SET balance_qty = balance_qty - v_qty WHERE item_id = v_item_id;
    INSERT INTO w14_txn (item_id, txn_type, qty) VALUES (v_item_id, 'ISSUE', v_qty);

    DBMS_OUTPUT.PUT_LINE('Issued ' || v_qty || ', new balance ' || (v_balance - v_qty));
    ROLLBACK;      -- পরীক্ষার জন্য
EXCEPTION
    WHEN e_bad_qty THEN
        DBMS_OUTPUT.PUT_LINE('Quantity must be more than zero');
    WHEN NO_DATA_FOUND THEN
        DBMS_OUTPUT.PUT_LINE('Item ' || v_item_id || ' not found');
    WHEN e_low_stock THEN
        ROLLBACK;                                     -- FOR UPDATE-এর Lock ছাড়া
        DBMS_OUTPUT.PUT_LINE('Stock too low: ' || v_balance || ' available, minimum ' || c_min_stock);
END;
/
```

পড়ে দেখো: **উপরে সব যাচাই, মাঝে আসল কাজ, নিচে সব বার্তা।** নতুন নিয়ম এলে একটা `IF ... RAISE` আর একটা `WHEN` যোগ করলেই হয়।

সপ্তাহ ১৫-এর প্র্যাকটিস ১৬-এর সাথে তুলনা করো, একই কাজ `IF`-এর সিঁড়ি দিয়ে করেছিলে।

### লাইব্রেরি: বই ইস্যুর আগে যাচাই

সপ্তাহ ১৫-এর প্র্যাকটিস ১৭ এবার Exception দিয়ে:

```sql
DECLARE
    v_member_id  lib_member.member_id%TYPE := 1;
    v_copy_id    lib_book_copy.copy_id%TYPE := 1;

    v_active     lib_member.is_active%TYPE;
    v_max_books  lib_member_type.max_books%TYPE;
    v_open_cnt   NUMBER;
    v_status     lib_book_copy.copy_status%TYPE;

    e_inactive      EXCEPTION;
    e_limit_reached EXCEPTION;
    e_not_available EXCEPTION;
BEGIN
    SELECT m.is_active, t.max_books
    INTO   v_active, v_max_books
    FROM   lib_member m
           JOIN lib_member_type t ON t.member_type_id = m.member_type_id
    WHERE  m.member_id = v_member_id;

    IF v_active <> 'Y' THEN
        RAISE e_inactive;
    END IF;

    SELECT COUNT(*) INTO v_open_cnt
    FROM   lib_book_issue
    WHERE  member_id = v_member_id AND return_date IS NULL;

    IF v_open_cnt >= v_max_books THEN
        RAISE e_limit_reached;
    END IF;

    SELECT copy_status INTO v_status FROM lib_book_copy WHERE copy_id = v_copy_id;

    IF v_status <> 'AVAILABLE' THEN
        RAISE e_not_available;
    END IF;

    DBMS_OUTPUT.PUT_LINE('Can issue');
EXCEPTION
    WHEN e_inactive THEN
        DBMS_OUTPUT.PUT_LINE('Member ' || v_member_id || ' is inactive');
    WHEN e_limit_reached THEN
        DBMS_OUTPUT.PUT_LINE('Member already has ' || v_open_cnt || ' of ' || v_max_books || ' books');
    WHEN e_not_available THEN
        DBMS_OUTPUT.PUT_LINE('Copy ' || v_copy_id || ' is ' || v_status);
    WHEN NO_DATA_FOUND THEN
        DBMS_OUTPUT.PUT_LINE('Member or copy not found');
END;
/
```

একটা সমস্যা: শেষের `NO_DATA_FOUND` বলতে পারে না মেম্বার নেই নাকি কপি নেই। প্র্যাকটিসে ঠিক করবে (Nested Block বা `COUNT(*)` দিয়ে)।

## ৪. PRAGMA EXCEPTION_INIT (৩০ মিনিট)

Oracle-এর হাজার হাজার এররের মধ্যে মাত্র ২০টার মতো নাম আছে। বাকিগুলো, যেমন:

| এরর | কখন |
|---|---|
| `ORA-02292` | Child রো আছে, Parent মুছতে চাইছ |
| `ORA-02291` | Parent নেই, এমন Foreign Key দিচ্ছ |
| `ORA-02290` | CHECK Constraint ভাঙছে |
| `ORA-01400` | NOT NULL কলামে NULL |

এগুলো `OTHERS` ছাড়া ধরার উপায় নেই, যদি না তুমি নাম দাও।

```sql
DECLARE
    e_child_exists EXCEPTION;
    PRAGMA EXCEPTION_INIT(e_child_exists, -2292);
BEGIN
    DELETE FROM w16_emp WHERE emp_id = 3;     -- Salma-র স্যালারি রো আছে w16_salary-তে
    DBMS_OUTPUT.PUT_LINE('Deleted');
EXCEPTION
    WHEN e_child_exists THEN
        DBMS_OUTPUT.PUT_LINE('Employee has salary records, mark as LEFT instead of deleting');
END;
/
```

- `PRAGMA` মানে Compiler-কে নির্দেশ। এটা চলার সময় কিছু করে না
- নম্বর **ঋণাত্মক**, শুরুর `0` বাদ: `ORA-02292` → `-2292`
- `PRAGMA` লাইন Exception ঘোষণার **পরে**, একই `DECLARE`-এ

### CHECK Constraint দিয়ে স্টক বাঁচানো

`w14_stock`-এ `w14_stock_balance_ck CHECK (balance_qty >= 0)` আছে (ক্লাস ৭০)।

```sql
DECLARE
    e_negative_stock EXCEPTION;
    PRAGMA EXCEPTION_INIT(e_negative_stock, -2290);
BEGIN
    UPDATE w14_stock SET balance_qty = balance_qty - 1000 WHERE item_id = 2;
EXCEPTION
    WHEN e_negative_stock THEN
        DBMS_OUTPUT.PUT_LINE('Not enough stock, balance cannot go below zero');
END;
/
```

**দুই স্তরের পাহারা:** টেবিলের Constraint শেষ রক্ষাকবচ, কেউ PL/SQL এড়িয়ে সরাসরি `UPDATE` দিলেও ধরে। আর PL/SQL-এর Exception সুন্দর বার্তা দেয়।

### সাধারণ ভুল

```sql
PRAGMA EXCEPTION_INIT(e_child_exists, 2292);     -- ধনাত্মক: PLS-00701, Compile হবে না
PRAGMA EXCEPTION_INIT(e_child_exists, -02292);   -- চলে, শুরুর 0 কোনো সমস্যা না
PRAGMA EXCEPTION_INIT(e_child_exists, -2291);    -- চলে, কিন্তু ভুল এরর! Handler কখনো চলবে না
```

ধনাত্মক নম্বর Oracle নিজেই আটকায় (`100` ছাড়া, যেটা NO_DATA_FOUND)। আসল বিপদ তৃতীয়টা: ভুল নম্বর দিলে কোনো সতর্কবার্তা নেই, শুধু Handler কখনো চলে না। নম্বর এররের বার্তা থেকে কপি করো, মুখস্থ থেকে না।

## ৫. RAISE; আর Scope (১৫ মিনিট)

### আবার ছোঁড়া

Handler-এ কিছু কাজ করে (যেমন বার্তা, `ROLLBACK`), তারপর এরর উপরে পাঠাতে শুধু `RAISE;`, নাম ছাড়া।

```sql
BEGIN
    BEGIN
        DELETE FROM w16_emp WHERE emp_id = 3;
    EXCEPTION
        WHEN OTHERS THEN
            DBMS_OUTPUT.PUT_LINE('Inner: delete failed, passing it up');
            RAISE;                        -- একই এরর
    END;
EXCEPTION
    WHEN OTHERS THEN
        DBMS_OUTPUT.PUT_LINE('Outer: got it');
END;
/
```

নাম ছাড়া `RAISE;` শুধু Handler-এর ভেতরে চলে। `BEGIN`-এ লিখলে Compile Error (`PLS-00367`)।

### Scope

- বাইরের ব্লকে ঘোষণা করা Exception ভেতরের ব্লকে দেখা যায়, `RAISE` আর ধরা দুইটাই চলে
- ভেতরে ঘোষণা করা Exception বাইরে **নাম ধরে** ধরা যায় না। বাইরে গেলে শুধু `OTHERS` ধরতে পারে

তাই যে Exception কয়েক ব্লকে লাগবে, সেটা সবচেয়ে বাইরের ব্লকে ঘোষণা করো। সপ্তাহ ১৯-এ Package-এ রাখলে পুরো অ্যাপ জুড়ে ব্যবহার করা যাবে।

```sql
    v_active     lib_member.is_active%TYPE;
    v_max_books  lib_member_type.max_books%TYPE;
    v_open_cnt   NUMBER;
    v_status     lib_book_copy.copy_status%TYPE;

    e_no_member     EXCEPTION;
    e_no_copy       EXCEPTION;
    e_inactive      EXCEPTION;
    e_limit_reached EXCEPTION;
    e_not_available EXCEPTION;
BEGIN
    BEGIN
        SELECT m.is_active, t.max_books INTO v_active, v_max_books
        FROM   lib_member m
               JOIN lib_member_type t ON t.member_type_id = m.member_type_id
        WHERE  m.member_id = v_member_id;
    EXCEPTION
        WHEN NO_DATA_FOUND THEN
            RAISE e_no_member;
    END;

    IF v_active <> 'Y' THEN
        RAISE e_inactive;
    END IF;

    SELECT COUNT(*) INTO v_open_cnt
    FROM   lib_book_issue
    WHERE  member_id = v_member_id AND return_date IS NULL;

    IF v_open_cnt >= v_max_books THEN
        RAISE e_limit_reached;
    END IF;

    BEGIN
        SELECT copy_status INTO v_status FROM lib_book_copy WHERE copy_id = v_copy_id;
    EXCEPTION
        WHEN NO_DATA_FOUND THEN
            RAISE e_no_copy;
    END;

    IF v_status <> 'AVAILABLE' THEN
        RAISE e_not_available;
    END IF;

    DBMS_OUTPUT.PUT_LINE('Can issue');
EXCEPTION
    WHEN e_no_member     THEN DBMS_OUTPUT.PUT_LINE('Member ' || v_member_id || ' not found');
    WHEN e_no_copy       THEN DBMS_OUTPUT.PUT_LINE('Copy ' || v_copy_id || ' not found');
    WHEN e_inactive      THEN DBMS_OUTPUT.PUT_LINE('Member ' || v_member_id || ' is inactive');
    WHEN e_limit_reached THEN DBMS_OUTPUT.PUT_LINE('Limit reached: ' || v_open_cnt || '/' || v_max_books);
    WHEN e_not_available THEN DBMS_OUTPUT.PUT_LINE('Copy ' || v_copy_id || ' is ' || v_status);
END;
/
```

ভেতরের ব্লক Oracle-এর এরর ধরে **নিজের** এরর ছোঁড়ে। এভাবে এক জাতের এরর (`NO_DATA_FOUND`) থেকে দুইটা আলাদা অর্থ পাওয়া যায়। বাইরের ব্লকে ঘোষণা করা Exception ভেতরে `RAISE` করা যাচ্ছে, Scope-এর নিয়ম মেনে।

```sql
DECLARE
    c_min_wage CONSTANT NUMBER := 8000;
    e_below_minimum EXCEPTION;
    v_bad NUMBER := 0;
BEGIN
    UPDATE w16_emp SET basic_salary = 7500 WHERE emp_id = 6;

    FOR r IN (SELECT emp_name, basic_salary FROM w16_emp WHERE status = 'ACTIVE' ORDER BY emp_id) LOOP
        BEGIN
            IF r.basic_salary < c_min_wage THEN
                RAISE e_below_minimum;
            END IF;
        EXCEPTION
            WHEN e_below_minimum THEN
                DBMS_OUTPUT.PUT_LINE(r.emp_name || ': basic ' || r.basic_salary || ' below minimum wage');
                v_bad := v_bad + 1;
        END;
    END LOOP;
    DBMS_OUTPUT.PUT_LINE(v_bad || ' employee(s) need correction');     -- 1
    ROLLBACK;
END;
```

## সারাংশ

- Oracle শুধু টেবিলের নিয়ম জানে, ব্যবসার নিয়ম তোমাকে বলতে হয়
- `e_x EXCEPTION;` → `RAISE e_x;` → `WHEN e_x THEN`
- কাঠামো: উপরে যাচাই আর `RAISE`, মাঝে আসল কাজ, নিচে সব বার্তা
- `PRAGMA EXCEPTION_INIT(e_x, -2292)`: নামহীন ORA এররকে নাম, নম্বর ঋণাত্মক
- `RAISE;` Handler থেকে একই এরর উপরে পাঠায়
- Constraint শেষ রক্ষাকবচ, PL/SQL Exception সুন্দর বার্তা

**পরের ক্লাস (মঙ্গলবার):** `RAISE_APPLICATION_ERROR`: নিজের এরর নম্বর আর বার্তা, যা APEX-ও দেখায়।
