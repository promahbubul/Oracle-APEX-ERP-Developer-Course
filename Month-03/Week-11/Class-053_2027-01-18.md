## ১. MAX + 1 কেন ভুল (১৫ মিনিট)

এতদিন ID হাতে লিখেছ। ক্লাস ৩৮-এ দেখেছিলে `MAX(id) + 1`। সমস্যা হয় যখন দুইজন একসাথে:

```
সময়    ইউজার A                        ইউজার B
১       MAX(id) = 100, নতুন = 101
২                                       MAX(id) = 100, নতুন = 101
৩       INSERT 101
৪                                       INSERT 101 → ORA-00001!
```

ERP-তে অনেকে একসাথে এন্ট্রি দেয়। **Sequence** এই সমস্যা মেটায়: Oracle নিজে ইউনিক নম্বর দেয়, দুইজন কখনো একই নম্বর পায় না।

## ২. Sequence বানানো (৩৫ মিনিট)

```sql
CREATE SEQUENCE w11_buyer_seq
START WITH 1
INCREMENT BY 1
NOCACHE;
```

| অপশন | মানে | ডিফল্ট |
|---|---|---|
| `START WITH` | শুরুর নম্বর | ১ |
| `INCREMENT BY` | কত করে বাড়বে | ১ |
| `MAXVALUE` / `NOMAXVALUE` | সর্বোচ্চ | প্রায় অসীম |
| `CYCLE` / `NOCYCLE` | শেষে আবার শুরু কি না | `NOCYCLE` |
| `CACHE n` / `NOCACHE` | কতটা আগে থেকে মেমোরিতে রাখবে | `CACHE 20` |

নাম রাখার নিয়ম `টেবিল_seq` (ক্লাস ২০)।

```sql
-- হাজার থেকে শুরু, ১০ করে বাড়ে
CREATE SEQUENCE w11_demo_seq START WITH 1000 INCREMENT BY 10;

SELECT w11_demo_seq.NEXTVAL FROM dual;     -- 1000
SELECT w11_demo_seq.NEXTVAL FROM dual;     -- 1010
```

### CACHE

`CACHE 20` মানে Oracle ২০টা নম্বর মেমোরিতে রাখে, ডিস্কে কম যায়, দ্রুত হয়। ডাটাবেস বন্ধ হলে বাকিগুলো হারিয়ে যায়, ফাঁকা থাকে।

**ব্যস্ত টেবিলে `CACHE` রাখো** (ডিফল্ট ২০ বা আরো বেশি)। `NOCACHE` সাধারণত দরকার নেই।

### CYCLE

```sql
CREATE SEQUENCE w11_cycle_seq START WITH 1 MAXVALUE 3 NOCACHE CYCLE;

SELECT w11_cycle_seq.NEXTVAL FROM dual;   -- 1
SELECT w11_cycle_seq.NEXTVAL FROM dual;   -- 2
SELECT w11_cycle_seq.NEXTVAL FROM dual;   -- 3
SELECT w11_cycle_seq.NEXTVAL FROM dual;   -- 1, আবার শুরু

DROP SEQUENCE w11_cycle_seq;
```

**PK-র জন্য কখনো `CYCLE` না,** একই নম্বর আবার আসবে।

## ৩. NEXTVAL ও CURRVAL (৩০ মিনিট)

| | কাজ |
|---|---|
| `seq.NEXTVAL` | পরের নম্বর নেয়, বাড়ায় |
| `seq.CURRVAL` | এই সেশনে শেষ যে নম্বর পেয়েছ |

```sql
-- নতুন সেশনে আগে CURRVAL চাইলে
SELECT w11_buyer_seq.CURRVAL FROM dual;
```

```
ORA-08002: sequence W11_BUYER_SEQ.CURRVAL is not yet defined in this session
```

### INSERT-এ

```sql
SET DEFINE OFF

CREATE TABLE w11_buyer (
    buyer_id    NUMBER(10) CONSTRAINT w11_buyer_pk PRIMARY KEY,
    buyer_name  VARCHAR2(100) NOT NULL
);

INSERT INTO w11_buyer VALUES (w11_buyer_seq.NEXTVAL, 'H&M');
INSERT INTO w11_buyer VALUES (w11_buyer_seq.NEXTVAL, 'Zara');
COMMIT;

SELECT * FROM w11_buyer;
```

### Master-Detail: CURRVAL-এর আসল কাজ

একটা PO আর তার আইটেমগুলো একসাথে ঢোকাতে হবে। Detail-এর FK-তে Master-এর ID লাগে।

```sql
CREATE SEQUENCE w11_po_seq;
CREATE SEQUENCE w11_po_item_seq;

CREATE TABLE w11_po (
    po_id  NUMBER(10) CONSTRAINT w11_po_pk PRIMARY KEY,
    po_no  VARCHAR2(20) NOT NULL
);

CREATE TABLE w11_po_item (
    po_item_id  NUMBER(10) CONSTRAINT w11_po_item_pk PRIMARY KEY,
    po_id       NUMBER(10) NOT NULL,
    item_name   VARCHAR2(50),
    qty         NUMBER(10),
    CONSTRAINT w11_po_item_po_fk FOREIGN KEY (po_id) REFERENCES w11_po (po_id)
);

-- Master
INSERT INTO w11_po VALUES (w11_po_seq.NEXTVAL, 'PO-0001');

-- Detail: CURRVAL আগের NEXTVAL-এর মানই দেয়
INSERT INTO w11_po_item VALUES (w11_po_item_seq.NEXTVAL, w11_po_seq.CURRVAL, 'Button', 1000);
INSERT INTO w11_po_item VALUES (w11_po_item_seq.NEXTVAL, w11_po_seq.CURRVAL, 'Zipper', 500);
COMMIT;

SELECT p.po_no, i.item_name, i.qty
FROM   w11_po p
JOIN   w11_po_item i ON i.po_id = p.po_id;
```

`CURRVAL` প্রতিটা সেশনের নিজের। তাই অন্য কেউ একই সময়ে আরেকটা PO করলেও তোমার `CURRVAL` বদলায় না।

### ব্যবসার নম্বর বানানো

```sql
-- ORD-2027-000001
SELECT 'ORD-' || TO_CHAR(SYSDATE, 'YYYY') || '-' || LPAD(w11_demo_seq.NEXTVAL, 6, '0') AS order_no
FROM   dual;
```

**`order_id`** (Sequence, PK) আর **`order_no`** (দেখানোর জন্য, Unique) আলাদা। ক্লাস ১১-এর Surrogate আর Natural Key মনে আছে?

### DEFAULT-এ Sequence (12c থেকে)

```sql
CREATE TABLE w11_note (
    note_id    NUMBER(10) DEFAULT w11_demo_seq.NEXTVAL
                          CONSTRAINT w11_note_pk PRIMARY KEY,
    note_text  VARCHAR2(100)
);

INSERT INTO w11_note (note_text) VALUES ('First');
COMMIT;

SELECT * FROM w11_note;
```

### Sequence বদলানো

```sql
ALTER SEQUENCE w11_demo_seq INCREMENT BY 1;
ALTER SEQUENCE w11_demo_seq MAXVALUE 9999999;

-- START WITH বদলানো যায় না
ALTER SEQUENCE w11_demo_seq START WITH 1;
```

```

```

নতুন ভার্সনে `ALTER SEQUENCE w11_demo_seq RESTART START WITH 1;` চলে। পুরনোয় `DROP` করে আবার বানাতে হয়।

## ৪. ফাঁকা নম্বর (Gap) (১৫ মিনিট)

**Sequence-এ ফাঁকা নম্বর স্বাভাবিক।**

```sql
SELECT w11_buyer_seq.NEXTVAL FROM dual;        -- ধরো 3

INSERT INTO w11_buyer VALUES (w11_buyer_seq.NEXTVAL, 'Temp');     -- 4
ROLLBACK;

INSERT INTO w11_buyer VALUES (w11_buyer_seq.NEXTVAL, 'Primark');  -- 5, 4 আর ফেরে না
COMMIT;

SELECT * FROM w11_buyer;
```

ফাঁকা হওয়ার কারণ:
- `ROLLBACK`: নম্বর ফেরত যায় না
- `CACHE`: ডাটাবেস বন্ধ হলে মেমোরির নম্বর হারায়
- `SELECT seq.NEXTVAL FROM dual`: শুধু দেখলেও নম্বর খরচ হয়

**এটাই ঠিক।** Sequence-এর কাজ **ইউনিক** নম্বর দেওয়া, **ধারাবাহিক** নয়। PK-তে ফাঁকা নম্বরে কিছু যায় আসে না।

> **ব্যতিক্রম: ইনভয়েস বা ভাউচার নম্বর।** Accounts-এ অনেক সময় ফাঁকা ছাড়া নম্বর আইনগতভাবে লাগে। তখন Sequence চলে না। আলাদা Counter টেবিল আর `FOR UPDATE` Lock লাগে, PL/SQL-এ শিখবে (সপ্তাহ ১৬)। এতে গতি কমে, তাই শুধু দরকারি জায়গায়।

## ৫. Identity Column (৩০ মিনিট)

Oracle 12c থেকে **Identity Column** আছে: Sequence নিজে থেকে বানানো থাকে, কলামেই বাঁধা।

```sql
CREATE TABLE w11_supplier (
    supplier_id    NUMBER(10) GENERATED ALWAYS AS IDENTITY
                              CONSTRAINT w11_supplier_pk PRIMARY KEY,
    supplier_name  VARCHAR2(100) NOT NULL
);

INSERT INTO w11_supplier (supplier_name) VALUES ('ABC Textile');
INSERT INTO w11_supplier (supplier_name) VALUES ('Delta Accessories');
COMMIT;

-- 1, 2
SELECT * FROM w11_supplier;
```

### তিন ধরন

| লেখা | হাতে মান দিলে | NULL দিলে |
|---|---|---|
| `GENERATED ALWAYS AS IDENTITY` | **এরর** | এরর |
| `GENERATED BY DEFAULT AS IDENTITY` | তোমার মান বসে | এরর |
| `GENERATED BY DEFAULT ON NULL AS IDENTITY` | তোমার মান বসে | নিজের নম্বর |

```sql
-- এরর
INSERT INTO w11_supplier (supplier_id, supplier_name) VALUES (99, 'Test');
```

```
ORA-32795: cannot insert into a generated always identity column
```

```sql
-- পুরনো ডাটা আনতে BY DEFAULT ভালো
CREATE TABLE w11_item (
    item_id    NUMBER(10) GENERATED BY DEFAULT ON NULL AS IDENTITY (START WITH 1000)
                          CONSTRAINT w11_item_pk PRIMARY KEY,
    item_name  VARCHAR2(100) NOT NULL
);

INSERT INTO w11_item (item_name) VALUES ('Button');            -- 1000
INSERT INTO w11_item (item_id, item_name) VALUES (5, 'Old');   -- 5
INSERT INTO w11_item (item_id, item_name) VALUES (NULL, 'New');-- 1001
COMMIT;

SELECT * FROM w11_item ORDER BY item_id;

SELECT table_name, column_name, generation_type, sequence_name
FROM   user_tab_identity_cols;
```

> **ফাঁদ:** `BY DEFAULT`-এ হাতে দেওয়া মান Sequence জানে না। হাতে ১০০০ দিলে, পরে Sequence ১০০০-এ পৌঁছালে `ORA-00001`। মাইগ্রেশনের পরে Sequence ঠিক করে নিতে হয়।

### Identity-র নম্বর জানা

Master-Detail-এ Identity-তে `CURRVAL` সরাসরি নেই। PL/SQL-এ `RETURNING id INTO` দিয়ে পাওয়া যায় (সপ্তাহ ১৪-এর পরে)। APEX-এর ফর্ম এটা নিজেই সামলায়।

### Sequence নাকি Identity

| | Sequence | Identity |
|---|---|---|
| কোথায় | আলাদা অবজেক্ট | কলামের অংশ |
| কয়েক টেবিলে একটা | হ্যাঁ | না |
| কোড | `seq.NEXTVAL` লিখতে হয় | কিছু লাগে না |
| ভুলে যাওয়ার ভয় | হ্যাঁ | না |
| পুরনো ভার্সন (11g) | চলে | **চলে না** |
| ডাটা ঢোকানো সহজ | হ্যাঁ | `ALWAYS`-এ না |

**সুপারিশ:** নতুন প্রজেক্টে সাধারণ PK-তে **Identity** (`BY DEFAULT ON NULL` অনেকে পছন্দ করে), আর APEX-এর উইজার্ডও এটা বানাতে পারে। পুরনো ERP-তে **Sequence + Trigger** প্রচুর দেখবে, সপ্তাহ ২০-এ শিখবে। **দুইটাই জানতে হবে।**

- Sequence: ইউনিক নম্বর, একসাথে অনেকজন কাজ করলেও নিরাপদ
- `NEXTVAL`, `CURRVAL`। Master-Detail-এ `CURRVAL`
- ফাঁকা নম্বর স্বাভাবিক, PK-তে সমস্যা নেই। ইনভয়েসে আলাদা ব্যবস্থা
- Identity: কলামেই বাঁধা Sequence। `ALWAYS`, `BY DEFAULT`, `BY DEFAULT ON NULL`
- নতুন প্রজেক্টে Identity, পুরনো ERP-তে Sequence + Trigger

**পরের ক্লাস:** Synonym।
