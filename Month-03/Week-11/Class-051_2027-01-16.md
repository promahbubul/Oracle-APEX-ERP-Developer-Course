## ১. View কী (২৫ মিনিট)

সপ্তাহ ৯-এ এই JOIN বারবার লিখেছ:

```sql
SELECT o.order_no, s.style_no, b.buyer_name, o.order_qty
FROM   w5_order o
JOIN   w5_style s ON o.style_id = s.style_id
JOIN   w5_buyer b ON s.buyer_id = b.buyer_id;
```

**View** হলো একটা **নাম দেওয়া কোয়েরি।** কোয়েরিটা ডাটাবেসে জমা থাকে, আর টেবিলের মতো ব্যবহার করা যায়।

```
View           = সংরক্ষিত কোয়েরি, ডাটা নেই
টেবিল          = ডাটা জমা থাকে
```

চালানোর সময় Oracle ভেতরের কোয়েরি চালায়, তাই **ফল সবসময় টেবিলের এখনকার ডাটা।**

### কেন লাগে

| কারণ | উদাহরণ |
|---|---|
| **সহজ করা** | ৫ টেবিলের JOIN একটা নামে |
| **নিয়ম এক জায়গায়** | "Late"-এর সংজ্ঞা বদলালে একটাই View বদলাও |
| **নিরাপত্তা** | বেতন ছাড়া কর্মীর তথ্য দেখানো |
| **বদল থেকে রক্ষা** | টেবিল ভাঙলেও View-র নাম আর কলাম একই রাখা যায় |

> APEX-এ রিপোর্ট প্রায়ই সরাসরি টেবিলে না, View-এর উপর বানানো হয়। সব হিসাব এক জায়গায় থাকে, পেজে শুধু `SELECT * FROM view`।

## ২. View বানানো (৪০ মিনিট)

```sql
SET DEFINE OFF

CREATE OR REPLACE VIEW w5_order_detail_v AS
SELECT o.order_id,
       o.order_no,
       o.order_date,
       o.ship_date,
       o.order_qty,
       o.status,
       s.style_no,
       s.style_name,
       s.fob_price,
       o.order_qty * s.fob_price AS order_value,
       b.buyer_name,
       b.country_name
FROM   w5_order o
JOIN   w5_style s ON o.style_id = s.style_id
JOIN   w5_buyer b ON s.buyer_id = b.buyer_id;
```

`OR REPLACE`: থাকলে নতুন করে বানায়, না থাকলে বানায়। অনুমতি ঠিক থাকে, তাই `DROP` করার চেয়ে এটা ভালো। নাম রাখার নিয়ম `_v` (ক্লাস ২০)।

### টেবিলের মতো ব্যবহার

```sql
-- ৪টা অর্ডার
SELECT order_no, buyer_name, order_qty FROM w5_order_detail_v;

-- H&M 8000, 24050; Primark 6000, 37200; Zara 4000, 31400
SELECT buyer_name, SUM(order_qty) AS total_qty, SUM(order_value) AS total_value
FROM   w5_order_detail_v
GROUP  BY buyer_name
ORDER  BY buyer_name;

-- WHERE, ORDER BY, JOIN সব চলে
SELECT order_no, order_value
FROM   w5_order_detail_v
WHERE  buyer_name = 'H&M'
ORDER  BY order_value DESC;
```

ক্লাস ৪৫-এর রিপোর্ট এখন তিন লাইনের।

### হিসাব করা কলামে Alias বাধ্যতামূলক

```sql
CREATE OR REPLACE VIEW w11_bad_v AS
SELECT order_no, order_qty * 2 FROM w5_order;
```

```
ORA-00998: must name this expression with a column alias
```

কলামের নাম আলাদা করেও লেখা যায়:

```sql
CREATE OR REPLACE VIEW w11_order_short_v (order_ref, qty_doubled) AS
SELECT order_no, order_qty * 2 FROM w5_order;

SELECT * FROM w11_order_short_v;

DROP VIEW w11_order_short_v;
```

### লাইব্রেরিতে

```sql
-- ৫টা রো
CREATE OR REPLACE VIEW lib_open_issue_v AS
SELECT i.issue_id,
       m.member_name,
       b.book_title,
       c.barcode,
       i.issue_date,
       i.due_date,
       TRUNC(SYSDATE) - i.due_date AS days_overdue
FROM   lib_book_issue i
JOIN   lib_member m    ON i.member_id = m.member_id
JOIN   lib_book_copy c ON i.copy_id = c.copy_id
JOIN   lib_book b      ON c.book_id = b.book_id
WHERE  i.return_date IS NULL;

SELECT member_name, book_title, days_overdue
FROM   lib_open_issue_v
WHERE  days_overdue > 0
ORDER  BY days_overdue DESC;
```

`days_overdue` প্রতিবার আজকের তারিখ ধরে নতুন করে হিসাব হয়। টেবিলে জমা থাকলে প্রতিদিন আপডেট করতে হতো। ক্লাস ১৯-এর "হিসাব করা কলাম না রাখা"-র এটাই সমাধান।

### নিরাপত্তা: কলাম লুকানো

```sql
-- মোবাইল আর ইমেইল ছাড়া মেম্বার
CREATE OR REPLACE VIEW lib_member_public_v AS
SELECT member_id, member_name, join_date, is_active
FROM   lib_member;

GRANT SELECT ON lib_member_public_v TO store_user;
```

`store_user` (ক্লাস ৯) এখন View দেখতে পারবে, আসল টেবিল না। পরীক্ষা করো:

```sql
-- store_user কানেকশনে
SELECT * FROM learn.lib_member_public_v;     -- চলবে
SELECT * FROM learn.lib_member;              -- ORA-00942
```

## ৩. Simple আর Complex View, DML (৩৫ মিনিট)

| | Simple View | Complex View |
|---|---|---|
| টেবিল | ১টা | একাধিক হতে পারে |
| ফাংশন, `GROUP BY`, `DISTINCT` | নেই | থাকতে পারে |
| DML | সাধারণত চলে | সীমিত |

### Simple View দিয়ে DML

```sql
CREATE OR REPLACE VIEW lib_active_member_v AS
SELECT member_id, member_name, mobile_no, member_type_id, is_active
FROM   lib_member
WHERE  is_active = 'Y';

-- ১৯ জন
SELECT COUNT(*) FROM lib_active_member_v;

-- আসল টেবিল বদলায়
UPDATE lib_active_member_v
SET    member_name = 'Sumon Mia Changed'
WHERE  member_id = 1;

SELECT member_name FROM lib_member WHERE member_id = 1;

ROLLBACK;
```

**View-তে ডাটা নেই,** তাই DML আসল টেবিলে যায়। `INSERT`-এর সময় View-তে নেই এমন `NOT NULL` কলামে `DEFAULT` না থাকলে এরর আসবে।

### যা চলে না

```sql
CREATE OR REPLACE VIEW lib_category_count_v AS
SELECT category_id, COUNT(*) AS book_count
FROM   lib_book
GROUP  BY category_id;

UPDATE lib_category_count_v SET book_count = 10 WHERE category_id = 1;
```

```
ORA-01732: data manipulation operation not legal on this view
```

`GROUP BY`, `DISTINCT`, Aggregate থাকলে Oracle জানে না কোন রো বদলাবে।

### JOIN View দিয়ে DML

```sql
-- চলে: w5_order-এর প্রতিটা রো View-তে একবারই আসে
UPDATE w5_order_detail_v SET order_qty = 5100 WHERE order_no = 'ORD-501';
ROLLBACK;

-- চলে না: একই Buyer অনেক রো-তে আসে
UPDATE w5_order_detail_v SET buyer_name = 'X' WHERE order_no = 'ORD-501';
```

```
ORA-01779: cannot modify a column which maps to a non key-preserved table
```

**Key-preserved** মানে: সেই টেবিলের PK View-তেও ইউনিক থাকে। `w5_order`-এর তা আছে, `w5_buyer`-এর নেই। Parent টেবিলের রো অনেকবার আসে।

জটিল View-তে DML করার উপায় `INSTEAD OF` Trigger, সপ্তাহ ২০-এ শিখবে।

## ৪. CHECK OPTION ও READ ONLY (২০ মিনিট)

### WITH CHECK OPTION

```sql
CREATE OR REPLACE VIEW w5_open_order_v AS
SELECT order_id, order_no, order_qty, status
FROM   w5_order
WHERE  status = 'OPEN'
WITH CHECK OPTION;

-- চলবে
UPDATE w5_open_order_v SET order_qty = 5100 WHERE order_no = 'ORD-501';
ROLLBACK;

-- চলবে না: এই রো View-র বাইরে চলে যেত
UPDATE w5_open_order_v SET status = 'SHIPPED' WHERE order_no = 'ORD-501';
```

```
ORA-01402: view WITH CHECK OPTION where-clause violation
```

`CHECK OPTION` ছাড়া এটা চলত, আর রো-টা View থেকে "হারিয়ে যেত"।

### WITH READ ONLY

```sql
CREATE OR REPLACE VIEW lib_book_readonly_v AS
SELECT book_id, book_title, publish_year
FROM   lib_book
WITH READ ONLY;

UPDATE lib_book_readonly_v SET publish_year = 2000;
```

```
ORA-42399: cannot perform a DML operation on a read-only view
```

রিপোর্টের জন্য বানানো View-তে `WITH READ ONLY` দাও।

## ৫. View ম্যানেজ করা (১৫ মিনিট)

```sql
-- আমার সব View আর কোড
SELECT view_name, text FROM user_views;

-- অবস্থা
SELECT object_name, status FROM user_objects WHERE object_type = 'VIEW';

-- মুছে ফেলা: শুধু View যায়, টেবিল বা ডাটা না
DROP VIEW lib_book_readonly_v;
```

### INVALID অবস্থা

View টেবিলের উপর নির্ভরশীল।

```sql
CREATE TABLE w11_demo (id NUMBER, name VARCHAR2(20));
CREATE OR REPLACE VIEW w11_demo_v AS SELECT id, name FROM w11_demo;

ALTER TABLE w11_demo DROP COLUMN name;

SELECT object_name, status FROM user_objects WHERE object_name = 'W11_DEMO_V';   -- INVALID

SELECT * FROM w11_demo_v;     -- ORA-04063: view has errors

DROP VIEW w11_demo_v;
DROP TABLE w11_demo;
```

**ERP-তে কলাম মোছার আগে দেখে নাও কে কে সেটা ব্যবহার করে:** `user_dependencies`।

### SELECT * দিয়ে View: সাবধান

```sql
CREATE TABLE w11_demo2 (id NUMBER);
CREATE OR REPLACE VIEW w11_demo2_v AS SELECT * FROM w11_demo2;

ALTER TABLE w11_demo2 ADD (name VARCHAR2(20));

DESC w11_demo2_v      -- name নেই!

DROP VIEW w11_demo2_v;
DROP TABLE w11_demo2;
```

Oracle `*`-কে View বানানোর সময়ের কলামে বদলে রাখে। View-তে কলামের নাম লেখাই ভালো। আর View-র ভেতরে `ORDER BY` না দিয়ে, যে ব্যবহার করবে তাকে দিতে দাও।

## ৬. হাতে-কলমে প্র্যাকটিস (৪৫ মিনিট)

1. `lib_book_detail_v`: বই, ক্যাটাগরির নাম, প্রকাশকের নাম, প্রকাশের বছর। (২০)
2. ওই View থেকে ক্যাটাগরিভিত্তিক বই সংখ্যা। (প্রতিটায় ৪টা)
3. `lib_issue_detail_v`: ইস্যু আইডি, মেম্বার, বই, স্টাফ, ইস্যুর তারিখ, ফেরতের তারিখ, অবস্থা (`Not returned`, `Late`, `On time`)। (২১)
4. ওই View থেকে অবস্থাভিত্তিক সংখ্যা। (`Not returned` ৫, `Late` ৫, `On time` ১১)
5. `lib_fine_detail_v`: মেম্বার, বই, জরিমানা, পরিশোধ। (৫)
6. `item_balance_v`: আইটেম আইডি, নাম, মোট In, মোট Out, ব্যালেন্স (ক্লাস ৪৯-এর কোয়েরি)। (৮)
7. ব্যালেন্স ১০০০-এর কম এমন আইটেম, View থেকে।
8. `lib_active_member_v`-তে `WITH CHECK OPTION` যোগ করে, একজনকে `is_active = 'N'` করার চেষ্টা করো।
9. `store_user`-কে শুধু `lib_book_detail_v` দেখার অনুমতি দাও, আর `store_user` থেকে পরীক্ষা করো।

       i.item_name,

LEFT   JOIN (SELECT item_id, SUM(in_qty) AS total_in, SUM(out_qty) AS total_out
             FROM  (SELECT item_id, qty AS in_qty, 0 AS out_qty FROM goods_receive
                    UNION ALL
                    SELECT item_id, 0, qty FROM goods_issue) x
             GROUP  BY item_id) l
       ON l.item_id = i.item_id;

- Simple View-তে DML চলে, `GROUP BY` থাকলে না, JOIN-এ শুধু Key-preserved টেবিলে
- `WITH CHECK OPTION`, `WITH READ ONLY` দিয়ে সুরক্ষা
- View-তে `*` না, কলামের নাম লেখো
