## ১. Synonym কী (২০ মিনিট)

**Synonym** হলো একটা অবজেক্টের **অন্য নাম**। টেবিল, View, Sequence, Procedure, Package যেকোনোটার।

```sql
-- প্রতিবার
SELECT * FROM hr.employees;

-- Synonym বানালে
SELECT * FROM emp;
```

### কেন লাগে

| কারণ | উদাহরণ |
|---|---|
| **ছোট নাম** | `hr.employees` → `emp` |
| **Schema লুকানো** | কোডে `ERP_STORE.` লিখতে হয় না |
| **বদল সহজ** | টেবিল অন্য Schema-তে গেলে শুধু Synonym বদলাও |
| **অন্য ডাটাবেসের টেবিল** | `item@erp_link` → `item` (সপ্তাহ ৩৯) |

### তুমি আগেই ব্যবহার করেছ

`DUAL`, `USER_TABLES` আসলে **Public Synonym**।

```sql
SELECT owner, synonym_name, table_owner, table_name
FROM   all_synonyms
WHERE  synonym_name IN ('DUAL', 'USER_TABLES');
```

`DUAL` আসলে `SYS.DUAL`। তুমি `SYS.` লেখোনি, Synonym সেটা করে দিয়েছে।

### মনে রাখো

- **Synonym অনুমতি দেয় না।** আসল অবজেক্টে অনুমতি লাগবেই
- Synonym-এ ডাটা নেই, শুধু একটা নাম
- `learn` ইউজারকে `CREATE SYNONYM` অনুমতি ক্লাস ৫-এ দেওয়া হয়েছে

## ২. Private Synonym (৩৫ মিনিট)

শুধু যে বানায়, তার Schema-তে থাকে।

```sql
-- learn_freepdb1
CREATE SYNONYM emp FOR hr.employees;
CREATE SYNONYM dept FOR hr.departments;

-- ১০৭
SELECT COUNT(*) FROM emp;

-- JOIN-ও চলে
SELECT e.last_name, d.department_name
FROM   emp e
JOIN   dept d ON e.department_id = d.department_id
WHERE  d.department_name = 'IT';
```

> ক্লাস ৯-এ `hr` ইউজার `learn`-কে `employees` আর `departments`-এ `SELECT` দিয়েছিল। না থাকলে `hr_freepdb1`-এ আগে `GRANT` চালাও।

### OR REPLACE

```sql
CREATE OR REPLACE SYNONYM emp FOR hr.employees;
```

### Synonym অনুমতি দেয় না

```sql
-- hr.locations-এ learn-এর অনুমতি নেই
CREATE SYNONYM loc FOR hr.locations;

SELECT * FROM loc;
```

```
ORA-00942: table or view does not exist
```

Synonym বানাতে পেরেছ, ব্যবহার করতে পারোনি। অনুমতি দাও:

```sql
-- hr_freepdb1
GRANT SELECT ON locations TO learn;

-- learn_freepdb1: এবার চলবে
SELECT city FROM loc;
```

### নিজের টেবিলের Synonym

```sql
CREATE SYNONYM member FOR lib_member;

SELECT COUNT(*) FROM member;     -- ২০

DROP SYNONYM member;
```

### অন্য অবজেক্টের

```sql
CREATE SYNONYM po_seq FOR w11_po_seq;
SELECT po_seq.NEXTVAL FROM dual;
DROP SYNONYM po_seq;

CREATE SYNONYM order_view FOR w5_order_detail_v;
SELECT COUNT(*) FROM order_view;
DROP SYNONYM order_view;
```

### দেখা ও মোছা

```sql
SELECT synonym_name, table_owner, table_name FROM user_synonyms;

DROP SYNONYM loc;
```

Synonym মুছলে আসল টেবিলের কিছু হয় না।

## ৩. Public Synonym (২৫ মিনিট)

**সব ইউজারের জন্য।** কোনো Schema-তে থাকে না, মালিক `PUBLIC`। বানাতে `CREATE PUBLIC SYNONYM` অনুমতি লাগে, সাধারণত অ্যাডমিনের।

```sql
-- system_freepdb1
CREATE PUBLIC SYNONYM lib_book_detail FOR learn.lib_book_detail_v;
```

```sql
-- learn_freepdb1: নিজের অনুমতি দাও
GRANT SELECT ON lib_book_detail_v TO store_user;
```

```sql
-- store_user কানেকশনে: Schema না লিখেই
SELECT book_title FROM lib_book_detail;
```

**Public Synonym অনুমতি দেয় না।** অনুমতি না থাকলে এখানেও `ORA-00942`। অনেকে ভাবে Public মানে সবাই দেখতে পাবে। না, শুধু নামটা সবার।

```sql
-- system_freepdb1: মোছা
DROP PUBLIC SYNONYM lib_book_detail;
```

### Private নাকি Public

| | Private | Public |
|---|---|---|
| কে ব্যবহার করতে পারে | যে বানিয়েছে (বা Schema দিয়ে অন্যরা) | সবাই |
| কে বানাতে পারে | `CREATE SYNONYM` | `CREATE PUBLIC SYNONYM` |
| ঝুঁকি | কম | নাম সংঘর্ষ, নিরাপত্তা |
| বাস্তবে | বেশি ব্যবহার | কম ব্যবহার |

**সুপারিশ:** Private ব্যবহার করো। Public Synonym একটা ডাটাবেসে একই নামে একটাই হয়, আর ভিন্ন অ্যাপে নাম মিলে গেলে ঝামেলা হয়। কিছু সিকিউরিটি স্ট্যান্ডার্ডে এটা এড়িয়ে চলতে বলা হয়।

## ৪. নাম খোঁজার ক্রম ও এরর (২০ মিনিট)

`SELECT * FROM emp` লিখলে Oracle এই ক্রমে খোঁজে:

```
১. আমার Schema-তে emp নামে টেবিল, View, ইত্যাদি
২. আমার Schema-তে emp নামে Private Synonym
৩. emp নামে Public Synonym
৪. না পেলে ORA-00942
```

তাই নিজের একটা `emp` টেবিল বানালে Synonym ঢেকে যায়। **একই Schema-তে একই নামে Synonym আর টেবিল থাকতে পারে না:**

```sql
CREATE TABLE emp (id NUMBER);
```

```
ORA-00955: name is already used by an existing object
```

### এরর

| এরর | কারণ |
|---|---|
| `ORA-00942` | আসল অবজেক্টে অনুমতি নেই, অথবা Synonym-ই নেই |
| `ORA-00955` | এই নামে অবজেক্ট আগেই আছে |
| `ORA-00980: synonym translation is no longer valid` | Synonym যার দিকে, সেটা মুছে গেছে |
| `ORA-01031` | Public Synonym বানানোর অনুমতি নেই |

```sql
-- ORA-00980 নিজে দেখো
CREATE TABLE w11_syn_demo (id NUMBER);
CREATE SYNONYM w11_syn FOR w11_syn_demo;
DROP TABLE w11_syn_demo;

SELECT * FROM w11_syn;

DROP SYNONYM w11_syn;
```

**আসল টেবিল মুছলে Synonym মোছে না।** বাতিল Synonym রয়ে যায়।

### বাস্তব ERP-তে

ক্লাস ৯-এ দেখেছিলে, বড় ERP-তে আলাদা Schema: `ERP_MERCH`, `ERP_STORE`।

```sql
-- APEX Workspace-এর Schema: ERP_APP। সব টেবিল ERP_STORE-এ
CREATE SYNONYM item FOR erp_store.item;
CREATE SYNONYM goods_receive FOR erp_store.goods_receive;
```

এতে APEX পেজের SQL-এ Schema লিখতে হয় না। পরে টেবিল সরালে পেজ না বদলিয়ে শুধু Synonym বদলাও।

**আরেকটা ব্যবহার: নতুন ভার্সনে যাওয়া।**

```sql
-- পুরনো টেবিল থেকে নতুন টেবিলে পাল্টানো, কোড বদলানো ছাড়া
CREATE OR REPLACE SYNONYM item FOR erp_store.item_new;
```

## সারাংশ

- Synonym: অন্য নাম, ডাটা নেই, অনুমতি দেয় না
- Private: `CREATE SYNONYM`। Public: অ্যাডমিনের, সবার জন্য নাম
- খোঁজার ক্রম: নিজের অবজেক্ট → Private → Public
- কাজ: ছোট নাম, Schema লুকানো, কোড না বদলে টেবিল পাল্টানো
- সাধারণত Private ব্যবহার করো

**পরের ক্লাস:** Index: B-Tree, Bitmap, Function-based Index।
