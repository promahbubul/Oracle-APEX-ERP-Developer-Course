## ১. Index কী (২৫ মিনিট)

১০০০ পৃষ্ঠার বইয়ে "Foreign Key" খুঁজতে হবে।

- **Index ছাড়া:** প্রথম পৃষ্ঠা থেকে সব পড়া। একে বলে **Full Table Scan**
- **Index দিয়ে:** বইয়ের শেষের সূচিতে দেখো: "Foreign Key: পৃষ্ঠা ৪৫৬"। সরাসরি সেখানে যাও

**Index** হলো কলামের মান আর সেই রো-র ঠিকানা (`ROWID`) রাখা একটা সাজানো কাঠামো।

```
INDEX (last_name)                TABLE
Abel      → ROWID ১৭৪            ১০০ King ...
Ande      → ROWID ১৬৬            ১০১ Kochhar ...
Grant     → ROWID ১৭৮            ...
King      → ROWID ১০০
King      → ROWID ১৫৬
```

### B-Tree: কীভাবে খোঁজে

```
              [ M ]                    ← Root
            /       \
       [ E ]         [ S ]             ← Branch
       /   \         /   \
    [A-D] [E-L]  [M-R] [S-Z]           ← Leaf: মান + ROWID
```

১০ লাখ রো-তেও ৩–৪ ধাপেই পাওয়া যায়, কারণ প্রতি ধাপে বাকি রো-র বেশিরভাগ বাদ পড়ে।

### দাম

Index ফ্রি না।

| লাভ | ক্ষতি |
|---|---|
| `SELECT` দ্রুত | `INSERT`, `UPDATE`, `DELETE` ধীর, কারণ Index-ও বদলায় |
| `ORDER BY`, JOIN-ও দ্রুত হতে পারে | জায়গা লাগে |

**PK আর Unique-এ Oracle নিজে থেকে Index বানায়** (ক্লাস ১১)। **FK-তে বানায় না,** নিজে দিতে হয়।

## ২. B-Tree Index (৪০ মিনিট)

### পরীক্ষার টেবিল

ছোট টেবিলে Index-এর প্রভাব দেখা যায় না, তাই ২ লাখ রো-র টেবিল বানাই (`CONNECT BY` সপ্তাহ ১৩-এ শিখবে):

```sql
CREATE TABLE w11_big AS
SELECT LEVEL AS order_id,
       'ORD-' || LPAD(LEVEL, 7, '0') AS order_no,
       MOD(LEVEL, 500) + 1 AS buyer_id,
       CASE MOD(LEVEL, 3) WHEN 0 THEN 'OPEN' WHEN 1 THEN 'SHIPPED' ELSE 'CANCELLED' END AS status,
       'buyer ' || MOD(LEVEL, 500) AS buyer_name,
       TRUNC(SYSDATE) - MOD(LEVEL, 1500) AS order_date,
       MOD(LEVEL, 10000) + 1 AS order_qty
FROM   dual
CONNECT BY LEVEL <= 200000;

SELECT COUNT(*) FROM w11_big;

-- Oracle-কে টেবিলের হিসাব দাও, যাতে সে ঠিক সিদ্ধান্ত নেয়
EXEC DBMS_STATS.GATHER_TABLE_STATS(USER, 'W11_BIG');
```

### Index ছাড়া: Execution Plan দেখো

```sql
EXPLAIN PLAN FOR
SELECT * FROM w11_big WHERE order_no = 'ORD-0100000';

SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY);
```

ফলে দেখবে: `TABLE ACCESS FULL`। ২ লাখ রো পড়ে ১টা রো খুঁজছে। `Cost` সংখ্যাটা মনে রাখো। (`Explain Plan` বিস্তারিত সপ্তাহ ৪০-এ।)

### Index বানাও

```sql
CREATE INDEX w11_big_order_no_idx ON w11_big (order_no);

EXPLAIN PLAN FOR
SELECT * FROM w11_big WHERE order_no = 'ORD-0100000';

SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY);
```

এবার: `INDEX RANGE SCAN` আর `TABLE ACCESS BY INDEX ROWID`। `Cost` অনেক কম।

### সময় মাপা

`F5` দিয়ে চালাও:

```sql
SET TIMING ON

SELECT * FROM w11_big WHERE buyer_name = 'buyer 100';

CREATE INDEX w11_big_buyer_name_idx ON w11_big (buyer_name);

SELECT * FROM w11_big WHERE buyer_name = 'buyer 100';

SET TIMING OFF
```

প্রথমবার, আর Index-এর পরে সময়ের তুলনা করো। দ্বিতীয়বার ক্যাশ থেকেও কিছু দ্রুত হতে পারে, তাই Plan-টাই বেশি নির্ভরযোগ্য প্রমাণ।

### দেখা ও মোছা

```sql
SELECT index_name, index_type, uniqueness, status
FROM   user_indexes
WHERE  table_name = 'W11_BIG';

SELECT index_name, column_name, column_position
FROM   user_ind_columns
WHERE  table_name = 'W11_BIG';

DROP INDEX w11_big_buyer_name_idx;
```

Index মুছলে ডাটা বা কোয়েরির ফল বদলায় না, শুধু গতি। **Index শুধু গতির বিষয়, ফলের না।**

### Unique Index

```sql
CREATE UNIQUE INDEX w11_big_order_id_uq ON w11_big (order_id);
```

নিয়ম রাখতে Unique Constraint ব্যবহার করো (ক্লাস ১১), তাতে Oracle নিজে Index বানায়।

## ৩. Composite Index (১৫ মিনিট)

একাধিক কলাম মিলে।

```sql
CREATE INDEX w11_big_buyer_date_idx ON w11_big (buyer_id, order_date);
```

**কলামের ক্রম জরুরি।** ফোনবুকের মতো: নাম আগে, ঠিকানা পরে। নাম জানলে খোঁজা সহজ, শুধু ঠিকানা দিয়ে কঠিন।

| শর্ত | Index ব্যবহার? |
|---|---|
| `buyer_id = 5` | হ্যাঁ, প্রথম কলাম |
| `buyer_id = 5 AND order_date = ...` | হ্যাঁ, সবচেয়ে ভালো |
| `order_date = ...` | সাধারণত না |

```sql
EXPLAIN PLAN FOR
SELECT * FROM w11_big WHERE buyer_id = 5 AND order_date >= TRUNC(SYSDATE) - 30;

SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY);
```

**নিয়ম:** যে কলাম সবচেয়ে বেশি `=` শর্তে আসে, সেটা আগে।

## ৪. Function-based Index (২০ মিনিট)

ক্লাস ৩১-এ বলেছিলাম: `WHERE UPPER(name) = ...` কলামের সাধারণ Index ব্যবহার করে না।

```sql
EXPLAIN PLAN FOR
SELECT * FROM w11_big WHERE UPPER(order_no) = 'ORD-0100000';

SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY);
```

`order_no`-তে Index থাকলেও `TABLE ACCESS FULL`।

```sql
CREATE INDEX w11_big_order_no_up_idx ON w11_big (UPPER(order_no));

EXPLAIN PLAN FOR
SELECT * FROM w11_big WHERE UPPER(order_no) = 'ORD-0100000';

SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY);
```

এবার Index ব্যবহার হচ্ছে। **কোয়েরির ফাংশন আর Index-এর ফাংশন হুবহু একই হতে হবে।**

### Unique Function-based Index

ক্লাস ১১-এ `'hm-ts-001'` আর `'HM-TS-001'` দুইটাই Unique পার হয়েছিল। সমাধান:

```sql
CREATE TABLE w11_style_code (style_no VARCHAR2(30));

CREATE UNIQUE INDEX w11_style_code_up_uq ON w11_style_code (UPPER(style_no));

INSERT INTO w11_style_code VALUES ('HM-TS-001');
INSERT INTO w11_style_code VALUES ('hm-ts-001');      -- ORA-00001!

ROLLBACK;
DROP TABLE w11_style_code;
```

### তারিখে

ক্লাস ২৭-এ `WHERE TRUNC(entry_date) = ...`-র কথা বলেছিলাম। এতেও Function-based Index দেওয়া যায়: `CREATE INDEX ... ON t (TRUNC(entry_date))`। তবে সাধারণ Index আর `>=`, `<` রেঞ্জই সহজ।

## ৫. Bitmap Index (১৫ মিনিট)

B-Tree ভালো যখন অনেক ভিন্ন মান। **অল্প ভিন্ন মান** (Y/N, স্ট্যাটাস) থাকলে **Bitmap** ছোট আর দ্রুত হতে পারে।

```
STATUS     রো: 1 2 3 4 5 6
OPEN           1 0 0 1 0 0
SHIPPED        0 1 0 0 1 0
CANCELLED      0 0 1 0 0 1
```

```sql
CREATE BITMAP INDEX w11_big_status_bx ON w11_big (status);

EXPLAIN PLAN FOR
SELECT COUNT(*) FROM w11_big WHERE status = 'OPEN';

SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY);
```

> Bitmap Index সব সংস্করণে থাকে না, যেমন Standard Edition-এ নেই। এরর এলে (`ORA-00439: feature not enabled`) এই অংশটা শুধু পড়ে যাও।

### Bitmap-এর ফাঁদ

**একটা `INSERT` বা `UPDATE` অনেক রো-কে Lock করে,** কারণ এক Bitmap-এ অনেক রো থাকে। ব্যবহারকারীরা আটকে যায়।

| | B-Tree | Bitmap |
|---|---|---|
| কত ভিন্ন মান | অনেক | অল্প |
| কাজের ধরন | ERP লেনদেন (OLTP) | রিপোর্ট, Data Warehouse |
| একসাথে `INSERT` | ঠিক আছে | **Lock সমস্যা** |

**ERP-র লেনদেনের টেবিলে Bitmap দেবে না।** শুধু বেশি পড়া আর কম লেখা হয় এমন টেবিলে। MV বা রিপোর্টের টেবিলে ঠিক আছে।

## ৬. কখন দেবে, কখন দেবে না (১৫ মিনিট)

### দেবে

- FK কলামে (`style.buyer_id`): JOIN দ্রুত হয়, আর Parent মোছার সময় Lock সমস্যা কমে
- বারবার `WHERE`, `ORDER BY`, JOIN-এ আসে এমন কলামে
- টেবিল বড়, আর কোয়েরি অল্প রো আনে

### দেবে না

- ছোট টেবিলে (শ-খানেক রো): Full Scan-ই দ্রুত
- কোয়েরি টেবিলের বেশিরভাগ রো আনে
- ঘন ঘন বদলায় এমন কলামে
- যা কখনো খোঁজা হয় না

### Index থাকলেও কাজ করে না যখন

| শর্ত | কেন | সমাধান |
|---|---|---|
| `UPPER(name) = 'X'` | কলামে ফাংশন | Function-based Index |
| `name LIKE '%X%'` | শুরুতে `%` | Oracle Text, বা নকশা বদলানো |
| `salary + 100 = 5000` | কলামে হিসাব | `salary = 4900` |
| `mobile_no = 1711000001` | Data Type আলাদা, নিজে বদল | `'01711000001'` |
| `col IS NULL` | সাধারণ Index-এ শুধু-NULL রো থাকে না | নকশা ভাবো |
| অনেক রো মেলে | Full Scan সস্তা | ঠিক আছে |

**Oracle নিজে ঠিক করে** Index নেবে কি না (Optimizer)। Index দিলেই ব্যবহার হবে, তা না। ক্লাসের `EXPLAIN PLAN` দেখে নিশ্চিত হও। বিস্তারিত সপ্তাহ ৪০-এ।

### এরর

| এরর | কারণ |
|---|---|
| `ORA-00955` | এই নামে অবজেক্ট আছে |
| `ORA-01408` | এই কলামে এমন Index আগেই আছে |
| `ORA-00439` | এই সংস্করণে ফিচার নেই |

### প্র্যাকটিসের পরে পরিষ্কার

নিচের প্র্যাকটিসে `w11_big` লাগবে। শেষ হলে মুছে দাও:

```sql
DROP TABLE w11_big PURGE;
```

টেবিল মুছলে তার সব Index মুছে যায়।

## ৭. হাতে-কলমে প্র্যাকটিস (৫০ মিনিট)

কালকের প্র্যাকটিসে লাইব্রেরিতে Index দেবে। আজ ভাবনাটা:

1. ক্লাসের `w11_big` টেবিলে `order_qty`-তে Index ছাড়া আর সহ `EXPLAIN PLAN` তুলনা করো, এই দুই কোয়েরিতে: ক. `order_qty = 5000`; খ. `order_qty > 10`। খ-তে Index ব্যবহার হলো কি? কেন?
2. `order_date >= TRUNC(SYSDATE) - 7`-এর জন্য Index দিয়ে Plan দেখো।
3. `TRUNC(order_date) = TRUNC(SYSDATE)` চালাও, Plan দেখো। Index ব্যবহার হলো কি? সমাধান দুইভাবে লেখো।
4. `(status, buyer_id)` আর `(buyer_id, status)`, কোন Composite Index ভালো, যদি প্রশ্ন হয় `buyer_id = 5 AND status = 'OPEN'`, আর শুধু `buyer_id = 5`?
5. প্রতিটা শর্তে Index কাজ করবে কি, `last_name`-এ সাধারণ Index ধরে:
   - ক. `last_name = 'King'`
   - খ. `last_name LIKE 'K%'`
   - গ. `last_name LIKE '%ing'`
   - ঘ. `UPPER(last_name) = 'KING'`
   - ঙ. `last_name || '' = 'King'`
6. গার্মেন্টসের `w5_order`-এর জন্য কোন কলামে কোন Index দেবে, আর কেন? (`style_id`, `order_date`, `status`, `order_no`)

## সারাংশ

- Index: সাজানো সূচি। পড়া দ্রুত, লেখা একটু ধীর, জায়গা লাগে
- B-Tree: ডিফল্ট, ERP-র প্রায় সব জায়গায়
- Composite: প্রথম কলাম জরুরি
- Function-based: কলামে ফাংশন থাকলে, হুবহু মিলিয়ে
- Bitmap: অল্প মান, রিপোর্টের টেবিলে, লেনদেনে না
- FK-তে Index দাও। `EXPLAIN PLAN` দিয়ে যাচাই করো
