# ক্লাস ৪২: Left Outer Join ও Right Outer Join

**তারিখ:** ৩ জানুয়ারি ২০২৭, রবিবার
**সময়:** সন্ধ্যা ৭:০০ থেকে রাত ১০:০০
**সপ্তাহ:** ৯ | **ধাপ:** ২ (Oracle SQL)

---

## আজকে কী শিখব

- Outer Join কেন লাগে
- `LEFT JOIN`, `RIGHT JOIN`
- মিল নেই এমন রো খোঁজা
- `ON` আর `WHERE`-এর পার্থক্য
- Outer Join-এর সাথে `COUNT`
- পুরনো `(+)` লেখা

## ১. Outer Join কেন (২০ মিনিট)

কাল দেখেছ: Inner Join-এ মিল না থাকা রো **চুপচাপ বাদ** পড়ে। ১০৭ জন কর্মী, রিপোর্টে ১০৬। কেউ এরর দেখে না।

বাস্তব ERP-তে এটা বিপজ্জনক:
- কোনো Buyer-এর কত অর্ডার? যার অর্ডার নেই, সে হারিয়ে যায়
- কোনো আইটেমের কত স্টক? যার রিসিভ নেই, সে তালিকায় নেই
- মোট বেতন? বিভাগ না থাকা কর্মীর বেতন বাদ

**Outer Join** মিল না থাকলেও এক পাশের সব রো রাখে, আর অন্য পাশ NULL দিয়ে ভরে।

```
employees LEFT JOIN departments

King   90  → Executive
Hunold 60  → IT
Grant  NULL → NULL          ← রো থাকল
```

## ২. LEFT JOIN (৪০ মিনিট)

**`LEFT JOIN`: বাম টেবিলের সব রো।** বাম মানে `FROM`-এর টেবিল। `LEFT OUTER JOIN` আর `LEFT JOIN` একই।

```sql
-- ১০৭টা রো, Grant-ও আছে
SELECT e.last_name, e.department_id, d.department_name
FROM   employees e
LEFT   JOIN departments d ON e.department_id = d.department_id;
```

### দিক উল্টালে

```sql
-- ১২২টা রো: ১০৬টা মিল, আর ১৬টা কর্মী ছাড়া বিভাগ
SELECT d.department_name, e.last_name
FROM   departments d
LEFT   JOIN employees e ON e.department_id = d.department_id
ORDER  BY d.department_name;
```

**কোন টেবিলটা বাম, সেটাই আসল।** নিজেকে জিজ্ঞেস করো: "কার সব রো চাই?" সেটাকে বামে রাখো।

### গার্মেন্টসের উদাহরণ (`learn_freepdb1`)

```sql
SET DEFINE OFF

-- ৪টা রো: H&M ২টা, Zara ১টা, Walmart-এর স্টাইল নেই
SELECT b.buyer_name, s.style_no
FROM   buyer b
LEFT   JOIN style s ON s.buyer_id = b.buyer_id
ORDER  BY b.buyer_name;
```

Walmart (ক্লাস ১২-এ ঢুকিয়েছিলে) আসছে, পাশে `style_no` ফাঁকা।

```sql
-- লাইব্রেরি: ২৫টা রো। ১৫টা বইয়ের ২০টা কপি, আর ৫টা বইয়ের কপি নেই
SELECT b.book_title, c.barcode
FROM   lib_book b
LEFT   JOIN lib_book_copy c ON c.book_id = b.book_id
ORDER  BY b.book_id;
```

### LEFT JOIN আর COUNT: সবচেয়ে সাধারণ ভুল

"প্রতিটা বিভাগে কতজন কর্মী?"

```sql
SELECT d.department_name,
       COUNT(*)             AS wrong_count,
       COUNT(e.employee_id) AS right_count
FROM   departments d
LEFT   JOIN employees e ON e.department_id = d.department_id
GROUP  BY d.department_name
ORDER  BY right_count, d.department_name;
```

কর্মী ছাড়া বিভাগে (যেমন `Benefits`) `wrong_count` দেখাবে **১**, `right_count` **০**।

`COUNT(*)` রো গোনে, আর কর্মী ছাড়া বিভাগেরও একটা রো আছে। **Outer Join-এ অন্য টেবিলের PK গোনো।** বিভাগ ২৭টা, তাই ২৭টা রো।

## ৩. RIGHT JOIN (১৫ মিনিট)

**`RIGHT JOIN`: ডান টেবিলের সব রো।**

```sql
-- ১২২টা রো: উপরের কোয়েরির মতোই
SELECT d.department_name, e.last_name
FROM   employees e
RIGHT  JOIN departments d ON e.department_id = d.department_id;
```

এই দুইটা একই ফল দেয়:

```sql
FROM employees e   RIGHT JOIN departments d ON ...
FROM departments d LEFT  JOIN employees e   ON ...
```

**বাস্তবে প্রায় সবাই `LEFT JOIN` লেখে।** টেবিলের ক্রম বদলালেই হয়, আর পড়া সহজ। `RIGHT JOIN` চিনে রাখো।

---

## ৪. মিল নেই এমন রো খোঁজা (২৫ মিনিট)

`LEFT JOIN` + `WHERE ডান_কলাম IS NULL` একটা খুব কাজের কৌশল।

```sql
-- কর্মী ছাড়া বিভাগ: ১৬টা
SELECT d.department_id, d.department_name
FROM   departments d
LEFT   JOIN employees e ON e.department_id = d.department_id
WHERE  e.employee_id IS NULL;

-- বিভাগ ছাড়া কর্মী: Grant
SELECT e.first_name, e.last_name
FROM   employees e
LEFT   JOIN departments d ON e.department_id = d.department_id
WHERE  d.department_id IS NULL;
```

**ডান টেবিলের কোন কলাম দিয়ে পরীক্ষা করবে?** PK বা Not Null কলাম। সেটা NULL হলে নিশ্চিত যে মিল নেই।

### ERP-র প্রশ্ন (`learn_freepdb1`)

```sql
-- কপি নেই এমন বই: ৫টা (১৬–২০)
SELECT b.book_id, b.book_title
FROM   lib_book b
LEFT   JOIN lib_book_copy c ON c.book_id = b.book_id
WHERE  c.copy_id IS NULL;

-- কখনো ইস্যু হয়নি এমন কপি: ৪টা (১৭–২০)
SELECT c.copy_id, c.barcode
FROM   lib_book_copy c
LEFT   JOIN lib_book_issue i ON i.copy_id = c.copy_id
WHERE  i.issue_id IS NULL;
```

বাস্তবে: "কোন আইটেম কখনো কেনা হয়নি?", "কোন Buyer-এর অর্ডার নেই?", "কোন অর্ডারের BOM নেই?"

## ৫. ON নাকি WHERE (২০ মিনিট)

Outer Join-এ শর্ত **কোথায়** লিখছ, তাতে ফল বদলে যায়।

```sql
-- ক: ২০টা রো। সব মেম্বার, যাদের বই বাইরে তাদের পাশে ইস্যু
SELECT m.member_name, i.issue_id
FROM   lib_member m
LEFT   JOIN lib_book_issue i ON i.member_id = m.member_id AND i.return_date IS NULL
ORDER  BY m.member_id;

-- খ: ৫টা রো। শুধু যাদের বই বাইরে
SELECT m.member_name, i.issue_id
FROM   lib_member m
LEFT   JOIN lib_book_issue i ON i.member_id = m.member_id
WHERE  i.return_date IS NULL
AND    i.issue_id IS NOT NULL
ORDER  BY m.member_id;
```

| শর্ত কোথায় | কী হয় |
|---|---|
| `ON`-এ | মেলানোর সময় ডান পাশ বাছে। **বামের সব রো থাকে** |
| `WHERE`-এ | মেলানোর পরে রো বাদ যায় |

### সাধারণ ভুল: Outer Join নষ্ট হয়ে যাওয়া

```sql
-- "সব বিভাগ, আর তাদের ১০০০০-এর বেশি বেতনের কর্মী"
SELECT d.department_name, e.last_name
FROM   departments d
LEFT   JOIN employees e ON e.department_id = d.department_id
WHERE  e.salary > 10000;
```

NULL-এর `salary > 10000` সত্য হয় না, তাই কর্মী ছাড়া বিভাগ সব বাদ। এটা কার্যত Inner Join হয়ে গেছে। ঠিক উপায়:

```sql
SELECT d.department_name, e.last_name
FROM   departments d
LEFT   JOIN employees e ON e.department_id = d.department_id AND e.salary > 10000;
```

**নিয়ম:** Outer Join-এ ডান টেবিলের শর্ত `ON`-এ, বাম টেবিলের শর্ত `WHERE`-এ।

## ৬. পুরনো লেখা: (+) (১০ মিনিট)

পুরনো Oracle কোডে এটা প্রচুর দেখবে:

```sql
-- পুরনো Inner Join
SELECT e.last_name, d.department_name
FROM   employees e, departments d
WHERE  e.department_id = d.department_id;

-- পুরনো Left Join: (+) যেদিকে মান না-ও থাকতে পারে
SELECT e.last_name, d.department_name
FROM   employees e, departments d
WHERE  e.department_id = d.department_id (+);
```

**পড়তে শেখো, নতুন কোডে লিখবে না।** শর্ত ভুলে গেলে পুরনো লেখায় সব রো গুণ হয়ে যায় (কাল দেখবে), আর `JOIN ... ON`-এ এরর আসে। পুরনো ERP-তে এই লেখা আসবেই।

## সারাংশ

- Outer Join মিল না থাকলেও এক পাশের সব রো রাখে, অন্য পাশ NULL
- `LEFT JOIN`: বামের সব। `RIGHT JOIN`: ডানের সব। `LEFT`-ই ব্যবহার করো
- মিল নেই খুঁজতে: `LEFT JOIN` + `WHERE ডান.PK IS NULL`
- ডান টেবিলের শর্ত `ON`-এ, `WHERE`-এ দিলে Outer Join নষ্ট হয়
- `COUNT(*)` না, `COUNT(ডান.PK)`
- পুরনো `(+)` পড়তে শেখো, লিখো না

**পরের ক্লাস:** Full Outer Join, Cross Join।
