## ১. Self Join (৪০ মিনিট)

**Self Join** মানে একটা টেবিলকে নিজের সাথেই JOIN করা। নতুন কোনো কীওয়ার্ড নেই, শুধু একই টেবিল দুইবার, দুইটা ভিন্ন Alias দিয়ে।

ক্লাস ১৩-এ দেখেছিলে: `employees.manager_id` আসলে `employees.employee_id`-র দিকে যায়। ম্যানেজারও একজন কর্মী।

| EMPLOYEE_ID | LAST_NAME | MANAGER_ID |
|---|---|---|
| 100 | King | NULL |
| 102 | De Haan | 100 |
| 103 | Hunold | 102 |
| 107 | Lorentz | 103 |

Lorentz-এর ম্যানেজার কে? `103`। ১০৩ কে? Hunold। এই দ্বিতীয় ধাপটার জন্যই JOIN লাগে।

**কল্পনা করো দুইটা কপি:** একটা "কর্মীর তালিকা" (`e`), আরেকটা "ম্যানেজারের তালিকা" (`m`)।

```
e (কর্মী)                       m (ম্যানেজার)
LAST_NAME  MANAGER_ID           EMPLOYEE_ID  LAST_NAME
Lorentz    103  ──────────────► 103          Hunold
Hunold     102  ──────────────► 102          De Haan
De Haan    100  ──────────────► 100          King
```

```sql
-- ১০৬টা রো
SELECT e.last_name AS employee_name,
       m.last_name AS manager_name
FROM   employees e
JOIN   employees m ON e.manager_id = m.employee_id
ORDER  BY e.employee_id;
```

**Alias এখানে বাধ্যতামূলক।** নাহলে Oracle জানবে না কোন কপি।

**সবচেয়ে সাধারণ ভুল: `ON`-এর দিক।**

| শর্ত | মানে |
|---|---|
| `e.manager_id = m.employee_id` | প্রতিটা `e`-এর পাশে তার **ম্যানেজার** |
| `e.employee_id = m.manager_id` | প্রতিটা `e`-এর পাশে তার **অধীনস্থ** |

### লেখা সাজিয়ে

```sql
SELECT e.last_name || ' reports to ' || m.last_name AS report_line
FROM   employees e
JOIN   employees m ON e.manager_id = m.employee_id;
```

### বিভাগের নামও

```sql
SELECT e.last_name AS employee_name,
       m.last_name AS manager_name,
       d.department_name
FROM   employees e
JOIN   employees m   ON e.manager_id = m.employee_id
JOIN   departments d ON e.department_id = d.department_id
WHERE  d.department_name = 'IT';
```

ফল ৫টা রো: Hunold-এর ম্যানেজার De Haan, বাকিদের Hunold। (`Ernst`, `Austin`, `Pataballa`, `Lorentz`)

## ২. Left Self Join (১৫ মিনিট)

King-এর ম্যানেজার নেই, তাই উপরের ১০৬টা রো-তে King বাদ।

```sql
-- ১০৭টা রো
SELECT e.last_name AS employee_name,
       NVL(m.last_name, 'No Manager') AS manager_name
FROM   employees e
LEFT   JOIN employees m ON e.manager_id = m.employee_id
ORDER  BY e.employee_id;
```

### গার্মেন্টসে: সুপারভাইজার

ক্লাস ১৩-এর `staff` টেবিল (`learn_freepdb1`):

```sql
-- ৩টা রো: Factory Manager → কেউ না, Floor In-charge → Factory Manager, Line Supervisor → Floor In-charge
SELECT s.staff_name,
       NVL(b.staff_name, 'Top Level') AS reports_to
FROM   staff s
LEFT   JOIN staff b ON s.supervisor_id = b.staff_id
ORDER  BY s.staff_id;
```

### কয়েক ধাপ উপরে

```sql
-- কর্মী → ম্যানেজার → ম্যানেজারের ম্যানেজার
SELECT e.last_name  AS employee_name,
       m.last_name  AS manager_name,
       mm.last_name AS senior_manager
FROM   employees e
LEFT   JOIN employees m  ON e.manager_id = m.employee_id
LEFT   JOIN employees mm ON m.manager_id = mm.employee_id
WHERE  e.last_name = 'Lorentz';
-- Lorentz → Hunold → De Haan
```

যত ধাপ, তত JOIN। কত ধাপ তা অজানা হলে Self Join কাজ করে না, তখন **Hierarchical Query** (`CONNECT BY`) লাগে, সপ্তাহ ১৩-এ শিখবে।

### ম্যানেজারের দলের আকার

```sql
-- নামসহ: King 14 জন আগে
SELECT m.last_name AS manager_name, COUNT(*) AS team_size
FROM   employees e
JOIN   employees m ON e.manager_id = m.employee_id
GROUP  BY m.employee_id, m.last_name
ORDER  BY team_size DESC;
```

`GROUP BY`-তে `m.employee_id`-ও দিয়েছি, কারণ দুইজন ম্যানেজারের পদবি একই হলে শুধু নাম দিয়ে দল করলে তাঁরা এক হয়ে যেতেন।

## ৩. একই টেবিলের রো তুলনা (২৫ মিনিট)

Self Join-এর আসল শক্তি: একই টেবিলের এক রো-কে আরেক রো-র সাথে তুলনা।

```sql
-- ম্যানেজারের চেয়ে বেশি বেতন (যেমন Abel, Ozer)
SELECT e.last_name AS employee_name, e.salary,
       m.last_name AS manager_name, m.salary AS manager_salary
FROM   employees e
JOIN   employees m ON e.manager_id = m.employee_id
WHERE  e.salary > m.salary;
```

```sql
-- ম্যানেজারের আগে যোগ দিয়েছেন
SELECT e.last_name, e.hire_date, m.last_name AS manager_name, m.hire_date AS manager_hired
FROM   employees e
JOIN   employees m ON e.manager_id = m.employee_id
WHERE  e.hire_date < m.hire_date;
```

```sql
-- ম্যানেজার যে বিভাগে, কর্মী অন্য বিভাগে
SELECT e.last_name, e.department_id, m.last_name AS manager_name, m.department_id AS manager_dept
FROM   employees e
JOIN   employees m ON e.manager_id = m.employee_id
WHERE  e.department_id <> m.department_id;
```

### গার্মেন্টসে

```sql
-- একই আইটেমের দাম দুই Supplier-এ আলাদা
-- (ক্লাস ১৪-এর supplier_item): আইটেম ৩: Supplier ১ → 3.25, Supplier ২ → 3.10
SELECT a.item_id,
       a.supplier_id AS supplier_a, a.unit_price AS price_a,
       b.supplier_id AS supplier_b, b.unit_price AS price_b
FROM   supplier_item a
JOIN   supplier_item b ON a.item_id = b.item_id
                      AND a.supplier_id < b.supplier_id
WHERE  a.unit_price <> b.unit_price;
```

## ৪. জোড়া বানানো (২০ মিনিট)

"বিভাগ ৬০-এর কর্মীদের জোড়া":

```sql
-- ২০টা রো: প্রতি জনের সাথে বাকি ৪ জন, আর একই জোড়া দুইবার
SELECT a.last_name, b.last_name
FROM   employees a
JOIN   employees b ON a.department_id = b.department_id
                  AND a.employee_id <> b.employee_id
WHERE  a.department_id = 60;
```

`Hunold-Ernst` আর `Ernst-Hunold` দুইবার এসেছে। শুধু একবার চাইলে `<>` না দিয়ে `<`:

```sql
-- ১০টা রো: ৫ জনের ১০টা জোড়া
SELECT a.last_name, b.last_name
FROM   employees a
JOIN   employees b ON a.department_id = b.department_id
                  AND a.employee_id < b.employee_id
WHERE  a.department_id = 60;
```

| শর্ত | ফল |
|---|---|
| শর্ত নেই | নিজের সাথেও জোড়া (`Hunold-Hunold`), মোট ২৫ |
| `<>` | নিজে বাদ, প্রতিটা জোড়া দুইবার, ২০ |
| `<` | প্রতিটা জোড়া একবার, ১০ |

### ডুপ্লিকেট খোঁজা

ক্লাস ৪০-এ `GROUP BY ... HAVING` দিয়ে ডুপ্লিকেট দেখেছিলে। Self Join-এ **কোন রো** দুইটা, তা-ও দেখা যায়:

```sql
-- একই last_name-এর কর্মীদের জোড়া (যেমন দুই King)
SELECT a.employee_id, a.first_name, b.employee_id AS other_id, b.first_name AS other_first, a.last_name
FROM   employees a
JOIN   employees b ON a.last_name = b.last_name
                  AND a.employee_id < b.employee_id;
```

## ৬. হোমওয়ার্ক

1. গার্মেন্টসের `line_output` টেবিল ভাবো (line_id, entry_date, produced_qty)। "আগের দিনের চেয়ে আজ বেশি বানিয়েছে এমন লাইন" Self Join দিয়ে কীভাবে লিখবে? টেবিল বানিয়ে ৫টা ডাটায় চালাও।
2. Self Join আর Hierarchical Query-র পার্থক্য কী হতে পারে, আন্দাজ করে লেখো। সপ্তাহ ১৩-এ মিলিয়ে নিও।
3. `<>` আর `<` দিয়ে জোড়া বানানোর পার্থক্য খাতায় ছবি এঁকে দেখাও।

## সারাংশ

- Self Join: একই টেবিল, দুইটা Alias
- `e.manager_id = m.employee_id`: কর্মীর পাশে ম্যানেজার। উল্টো দিলে অধীনস্থ
- `LEFT` দিলে যার উপরে কেউ নেই, সে-ও থাকে
- কত ধাপ অজানা হলে Hierarchical Query লাগে
- জোড়ায় `<` দিয়ে দুইবার আসা বন্ধ করো
