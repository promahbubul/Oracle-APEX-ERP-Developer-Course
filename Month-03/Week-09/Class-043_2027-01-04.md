- `FULL OUTER JOIN`
- `CROSS JOIN` ও Cartesian Product

## ১. FULL OUTER JOIN (৩০ মিনিট)

**দুই পাশের সব রো।** মিল না থাকলে অন্য পাশ NULL।

```sql
-- ১২৩টা রো: ১০৬টা মিল + ১টা বিভাগ ছাড়া কর্মী + ১৬টা কর্মী ছাড়া বিভাগ
SELECT e.last_name, d.department_name
FROM   employees e
FULL   OUTER JOIN departments d ON e.department_id = d.department_id
ORDER  BY d.department_name, e.last_name;
```

| JOIN | রো | কী কী আসে |
|---|---|---|
| Inner | ১০৬ | শুধু মিল |
| `employees` Left | ১০৭ | মিল + Grant |
| `departments` Left | ১২২ | মিল + ১৬টা বিভাগ |
| Full | ১২৩ | মিল + Grant + ১৬টা বিভাগ |

### মিল নেই এমন সব রো

```sql
-- ১৭টা রো: Grant আর ১৬টা বিভাগ
SELECT e.last_name, d.department_name
FROM   employees e
FULL   OUTER JOIN departments d ON e.department_id = d.department_id
WHERE  e.employee_id IS NULL
OR     d.department_id IS NULL;
```

### কোথায় কাজে লাগে

**দুই হিসাব মেলানো (Reconciliation):** পুরনো সিস্টেম আর নতুন সিস্টেমের ডাটা মেলানোর সময়।

```sql
-- লাইব্রেরিতে একটা খালি শেলফ যোগ করো (learn_freepdb1)
INSERT INTO lib_shelf VALUES (6, 'D-01');

-- ২১টা রো: ১৯টা মিল + শেলফ ছাড়া কপি (BC-0020) + কপি ছাড়া শেলফ (D-01)
SELECT c.barcode, s.shelf_code
FROM   lib_book_copy c
FULL   OUTER JOIN lib_shelf s ON c.shelf_id = s.shelf_id;

ROLLBACK;
```

ধরো একদিকে Store-এর হিসাব, অন্যদিকে Accounts-এর হিসাব। Full Join-এ `WHERE এক_পাশ IS NULL` দিলে **যা দুই হিসাবে মেলে না, শুধু সেগুলো** দেখা যায়।

## ২. CROSS JOIN (৩০ মিনিট)

**প্রতিটা রো-র সাথে অন্য টেবিলের প্রতিটা রো।** কোনো `ON` নেই। একে বলে **Cartesian Product**।

```
রং: Black, White     সাইজ: S, M, L

ফল (২ × ৩ = ৬):
Black S, Black M, Black L, White S, White M, White L
```

```sql
-- ১০৭ × ২৭ = ২৮৮৯টা রো
SELECT COUNT(*)
FROM   employees e
CROSS  JOIN departments d;
```

### কোথায় কাজে লাগে: Color-Size ছক

নতুন অর্ডারে সব রং আর সাইজের জন্য খালি ছক বানাতে হয়। Merchandiser শুধু পরিমাণ বসাবে। এটা গার্মেন্টস ERP-র বাস্তব কাজ।

```sql
CREATE TABLE w9_color (color_name VARCHAR2(30) CONSTRAINT w9_color_pk PRIMARY KEY);
CREATE TABLE w9_size  (size_code VARCHAR2(10) CONSTRAINT w9_size_pk PRIMARY KEY, sort_order NUMBER(2));

INSERT INTO w9_color VALUES ('Black');
INSERT INTO w9_color VALUES ('White');
INSERT INTO w9_color VALUES ('Navy');

INSERT INTO w9_size VALUES ('S', 1);
INSERT INTO w9_size VALUES ('M', 2);
INSERT INTO w9_size VALUES ('L', 3);
INSERT INTO w9_size VALUES ('XL', 4);
COMMIT;

-- ৩ × ৪ = ১২টা রো
SELECT c.color_name, s.size_code, 0 AS order_qty
FROM   w9_color c
CROSS  JOIN w9_size s
ORDER  BY c.color_name, s.sort_order;
```

এরপর `INSERT ... SELECT` দিয়ে এই ১২টা রো অর্ডারের ব্রেকডাউন টেবিলে ঢোকানো যায়।

### আরেকটা কাজ

প্রতিটা লাইনের প্রতিটা ঘণ্টার জন্য খালি এন্ট্রি (প্রজেক্ট ৩-এর Hourly Production), সব কর্মীর সব মাসের ফাঁকা হাজিরা ছক।

### ভুল করে Cartesian Product

পুরনো লেখায় শর্ত ভুলে গেলে এটা হয়:

```sql
SELECT e.last_name, d.department_name
FROM   employees e, departments d;       -- ২৮৮৯টা রো!
```

**কোনো এরর নেই।** বড় টেবিলে ডাটাবেস আটকে যেতে পারে: ১ লাখ × ১ লাখ = ১০০০ কোটি রো।

**ধরার উপায়:** রিপোর্টের ফল হঠাৎ অনেক গুণ বেড়ে গেলে, মোট টাকা অবিশ্বাস্য হলে, আগে JOIN-এর শর্ত দেখো।

```sql
-- ফাঁদ: ON-এ সবসময় সত্য শর্ত
SELECT COUNT(*) FROM employees e JOIN departments d ON 1 = 1;    -- ২৮৮৯
```

## ৩. Non-Equi Join (২০ মিনিট)

JOIN-এর শর্ত সবসময় `=` হতে হয় না।

```sql
CREATE TABLE w9_salary_grade (
    grade_name  VARCHAR2(10) CONSTRAINT w9_salary_grade_pk PRIMARY KEY,
    low_salary  NUMBER(8),
    high_salary NUMBER(8)
);

INSERT INTO w9_salary_grade VALUES ('Low', 0, 4999);
INSERT INTO w9_salary_grade VALUES ('Medium', 5000, 9999);
INSERT INTO w9_salary_grade VALUES ('High', 10000, 99999);
COMMIT;
```

`learn_freepdb1`-এ `hr.employees` দেখার অনুমতি লাগবে (ক্লাস ৯):

```sql
SELECT e.last_name, e.salary, g.grade_name
FROM   hr.employees e
JOIN   w9_salary_grade g ON e.salary BETWEEN g.low_salary AND g.high_salary;
```

ক্লাস ৩৯-এ এই কাজ `CASE` দিয়ে করেছিলে। টেবিল রাখলে সীমা বদলাতে কোড বদলাতে হয় না, শুধু ডাটা।

```sql
-- hr_freepdb1: পদের বেতন সীমার মধ্যে থাকা কর্মী (১০৭ বা কাছাকাছি)
SELECT e.last_name, e.salary, j.job_title, j.min_salary, j.max_salary
FROM   employees e
JOIN   jobs j ON e.job_id = j.job_id
          AND e.salary BETWEEN j.min_salary AND j.max_salary;
```

গার্মেন্টসে: **মূল্যের ধাপ** (১০০০ পিস পর্যন্ত এক দাম, ৫০০০ পর্যন্ত আরেক দাম), **Incentive-এর ধাপ** (Efficiency অনুযায়ী বোনাস)।

## ৪. সব JOIN একসাথে (২০ মিনিট)

```
A (বাম)            B (ডান)

INNER      : শুধু A ∩ B
LEFT       : সব A, আর মিল থাকলে B
RIGHT      : সব B, আর মিল থাকলে A
FULL       : সব A + সব B
CROSS      : A × B, প্রতিটা রো-র সাথে প্রতিটা
```

| JOIN | মিল না থাকলে | কখন | `ON` লাগে? |
|---|---|---|---|
| `INNER` | বাদ | দুই পাশে থাকতেই হবে | হ্যাঁ |
| `LEFT` | ডান পাশ NULL | বাম পাশের সব চাই | হ্যাঁ |
| `RIGHT` | বাম পাশ NULL | এড়িয়ে চলো, `LEFT` লেখো | হ্যাঁ |
| `FULL` | এক পাশ NULL | দুই হিসাব মেলানো | হ্যাঁ |
| `CROSS` | প্রযোজ্য না | সব জোড়া বানানো | **না** |

### কোনটা নেব: সিদ্ধান্তের ক্রম

1. দুই পাশেই মিল থাকতে হবে? → `INNER`
2. একটা টেবিলের সব রো চাই? → সেটাকে বামে রেখে `LEFT`
3. দুই পাশের সব রো চাই? → `FULL`
4. সব জোড়া চাই? → `CROSS`

## ৬. হোমওয়ার্ক

## সারাংশ

- `FULL OUTER JOIN`: দুই পাশের সব, হিসাব মেলাতে কাজের
- `CROSS JOIN`: প্রতিটা রো-র সাথে প্রতিটা, Color-Size ছক বানাতে কাজের
- ভুল করে Cartesian Product হলে কোনো এরর আসে না
- Non-Equi Join: `BETWEEN` বা `<`, `>` দিয়ে মেলানো
- আগে প্রশ্ন: "কার সব রো চাই?"

**পরের ক্লাস:** Self Join।
