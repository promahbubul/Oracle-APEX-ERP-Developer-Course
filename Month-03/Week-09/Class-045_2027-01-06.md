## ১. চেইন করে JOIN (৪০ মিনিট)

ERP-র আসল রিপোর্টে অনেক টেবিল লাগে। নিয়ম একটাই: **প্রতিটা নতুন টেবিলের জন্য একটা `JOIN ... ON`।**

```sql
SELECT ...
FROM   টেবিল১ a
JOIN   টেবিল২ b ON a.x = b.x
JOIN   টেবিল৩ c ON b.y = c.y
JOIN   টেবিল৪ d ON c.z = d.z;
```

Oracle আগের ধাপের ফলের সাথে পরের টেবিল মেলায়।

### পথ খোঁজো: ER Diagram

HR-এর পথ (ক্লাস ৯):

```
EMPLOYEES ──► DEPARTMENTS ──► LOCATIONS ──► COUNTRIES ──► REGIONS
       department_id    location_id    country_id    region_id
```

**কৌশল:** আগে কোন টেবিল থেকে কোন টেবিল লাগবে, খাতায় পথ আঁকো। পাশাপাশি নয় এমন টেবিল সরাসরি জোড়া লাগে না, মাঝের টেবিল লাগে।

### ধাপে ধাপে লেখো

```sql
-- ধাপ ১: কর্মী + বিভাগ (১০৬)
SELECT e.last_name, d.department_name
FROM   employees e
JOIN   departments d ON e.department_id = d.department_id;

-- ধাপ ২: + শহর (১০৬)
SELECT e.last_name, d.department_name, l.city
FROM   employees e
JOIN   departments d ON e.department_id = d.department_id
JOIN   locations l   ON d.location_id = l.location_id;

-- ধাপ ৩: + দেশ, অঞ্চল (১০৬)
SELECT e.last_name, d.department_name, l.city, c.country_name, r.region_name
FROM   employees e
JOIN   departments d ON e.department_id = d.department_id
JOIN   locations l   ON d.location_id = l.location_id
JOIN   countries c   ON l.country_id = c.country_id
JOIN   regions r     ON c.region_id = r.region_id;
```

**প্রতি ধাপে রো সংখ্যা দেখো।** হঠাৎ বেড়ে গেলে ফাঁদে পড়েছ (অংশ ৩)। হঠাৎ কমে গেলে Inner Join-এ মিল না থাকা রো বাদ পড়ছে।

### গার্মেন্টস: Buyer → Style → Order (`learn_freepdb1`)

```sql
SET DEFINE OFF

-- ৪টা অর্ডার: ORD-501, ORD-504 → H&M; ORD-502 → Zara; ORD-503 → Primark
```

### লাইব্রেরি: কে কোন বই নিয়েছেন

```
LIB_MEMBER ◄── LIB_BOOK_ISSUE ──► LIB_BOOK_COPY ──► LIB_BOOK
                     │
                     └──► LIB_STAFF
```

```sql

SELECT m.member_name,
```

## ২. JOIN + GROUP BY (৩৫ মিনিট)

```sql
-- শহরভিত্তিক কর্মী: South San Francisco 45, Oxford 34, Seattle 18, Southlake 5, Toronto 2, London 1, Munich 1
SELECT l.city, COUNT(*) AS headcount
FROM   employees e
JOIN   departments d ON e.department_id = d.department_id
JOIN   locations l   ON d.location_id = l.location_id
GROUP  BY l.city
ORDER  BY headcount DESC;

-- দেশভিত্তিক: US 68, UK 35, Canada 2, Germany 1
SELECT c.country_name, COUNT(*) AS headcount
FROM   employees e
JOIN   departments d ON e.department_id = d.department_id
JOIN   locations l   ON d.location_id = l.location_id
JOIN   countries c   ON l.country_id = c.country_id
GROUP  BY c.country_name
ORDER  BY headcount DESC;

-- অঞ্চলভিত্তিক: Americas 70, Europe 36
SELECT r.region_name, COUNT(*) AS headcount, SUM(e.salary) AS total_salary
FROM   employees e
JOIN   departments d ON e.department_id = d.department_id
JOIN   locations l   ON d.location_id = l.location_id
JOIN   countries c   ON l.country_id = c.country_id
JOIN   regions r     ON c.region_id = r.region_id
GROUP  BY r.region_name;
```

## ৩. দুইটা বড় ফাঁদ (৩৫ মিনিট)

### ফাঁদ ১: LEFT JOIN-এর পরে INNER JOIN

```sql
-- "সব বিভাগ, কর্মী থাকলে তার পদের নাম"। ফল ১০৬টা, ১২২ না!
SELECT d.department_name, e.last_name, j.job_title
FROM   departments d
LEFT   JOIN employees e ON e.department_id = d.department_id
JOIN   jobs j           ON e.job_id = j.job_id;
```

১৬টা কর্মী ছাড়া বিভাগে `e.job_id` NULL। Inner Join `j`-এ মেলে না, রো বাদ। **পরের Inner Join আগের Outer Join-কে নষ্ট করে দিল।**

```sql
-- ঠিক: ১২২টা রো
SELECT d.department_name, e.last_name, j.job_title
FROM   departments d
LEFT   JOIN employees e ON e.department_id = d.department_id
LEFT   JOIN jobs j      ON e.job_id = j.job_id;
```

**নিয়ম: একবার `LEFT` হলে সেই পথের বাকি সবগুলো `LEFT`।**

### ফাঁদ ২: Fan-out, হিসাব গুণ হওয়া

একটা বইয়ের ২টা কপি আর ২ জন লেখক। দুইটাই JOIN করলে কী হয়?

```sql
-- বই ১: ৪টা রো! ২ × ২
SELECT b.book_title, c.barcode, a.author_name
FROM   lib_book b
JOIN   lib_book_copy c    ON c.book_id = b.book_id
JOIN   lib_book_author ba ON ba.book_id = b.book_id
JOIN   lib_author a       ON ba.author_id = a.author_id
WHERE  b.book_id = 1;
```

প্রতিটা কপির সাথে প্রতিটা লেখক। দুইটা "Many" দিক একই টেবিল থেকে বের হলে এমন হয়।

```sql
-- বই ১-এর কপি কয়টা? ২ হওয়ার কথা, COUNT(*) দেবে ৪
SELECT b.book_title, COUNT(*) AS wrong_count, COUNT(DISTINCT c.copy_id) AS right_count
FROM   lib_book b
JOIN   lib_book_copy c    ON c.book_id = b.book_id
JOIN   lib_book_author ba ON ba.book_id = b.book_id
WHERE  b.book_id = 1
GROUP  BY b.book_title;
```

**গার্মেন্টসে এটা সবচেয়ে ক্ষতিকর ভুল।** একটা অর্ডারের সাথে তার PI আর শিপমেন্ট JOIN করে `SUM(order_qty)` নিলে অর্ডারের পরিমাণ কয়েকগুণ দেখায়। রিপোর্টে সংখ্যা দেখলেই বিশ্বাস করবে না, মিলিয়ে নেবে।

**এড়ানোর উপায়:**
1. প্রতি ধাপে রো সংখ্যা দেখো
2. ছোট ডাটায় হাতে হিসাব করে মিলাও
3. দুইটা হিসাব আলাদা করে, পরে জোড়া দাও (Subquery, সপ্তাহ ১০)
4. গোনার সময় `COUNT(DISTINCT id)`, তবে `SUM`-এ এটা কাজ করে না

```sql
FROM   order_size_qty q
JOIN   orders o ON q.order_no = o.order_no
JOIN   style s  ON o.style_id = s.style_id
JOIN   buyer b  ON s.buyer_id = b.buyer_id;

-- ১২
SELECT s.style_no, SUM(o.order_qty) AS total_qty, SUM(o.order_qty * s.fob_price) AS total_value
FROM   w5_order o
JOIN   w5_style s ON o.style_id = s.style_id
GROUP  BY s.style_no;

-- ১৩: COUNT(DISTINCT) কেন: এক স্টাইলের অনেক অর্ডার হলে স্টাইল গুণ হতো
SELECT b.buyer_name,
       COUNT(DISTINCT s.style_id) AS style_count,
       COUNT(DISTINCT o.order_id) AS order_count
FROM   w5_buyer b
LEFT   JOIN w5_style s ON s.buyer_id = b.buyer_id
LEFT   JOIN w5_order o ON o.style_id = s.style_id
GROUP  BY b.buyer_name;

-- ১৪
SELECT sup.supplier_name, i.item_name, c.category_name, si.unit_price
FROM   supplier_item si
JOIN   supplier sup      ON si.supplier_id = sup.supplier_id
JOIN   item i            ON si.item_id = i.item_id
JOIN   item_category c   ON i.category_id = c.category_id;

-- ১৫
SELECT g.receive_date, i.item_name, s.supplier_name, g.qty, g.qty * g.unit_price AS total_amount
FROM   goods_receive g
JOIN   item i     ON g.item_id = i.item_id
JOIN   supplier s ON g.supplier_id = s.supplier_id;

-- ১৬
SELECT s.supplier_name, SUM(g.qty * g.unit_price) AS total_amount
FROM   goods_receive g
JOIN   supplier s ON g.supplier_id = s.supplier_id
GROUP  BY s.supplier_name;

-- ১৭
SELECT m.member_name, b.book_title, st.staff_name,
       i.return_date - i.due_date AS days_late,
       f.fine_amount
FROM   lib_book_issue i
JOIN   lib_member m    ON i.member_id = m.member_id
JOIN   lib_book_copy c ON i.copy_id = c.copy_id
JOIN   lib_book b      ON c.book_id = b.book_id
JOIN   lib_staff st    ON i.staff_id = st.staff_id
LEFT   JOIN lib_fine f ON f.issue_id = i.issue_id
WHERE  i.return_date > i.due_date;

-- ১৮
SELECT cat.category_name, COUNT(*) AS copies
FROM   lib_book_copy c
JOIN   lib_book b       ON c.book_id = b.book_id
JOIN   lib_category cat ON b.category_id = cat.category_id
GROUP  BY cat.category_name;

-- ১৯
SELECT a.author_name, COUNT(*) AS books
FROM   lib_book_author ba
JOIN   lib_author a ON ba.author_id = a.author_id
GROUP  BY a.author_name
ORDER  BY books DESC;

-- ২০
SELECT b.book_title,
       LISTAGG(a.author_name, ', ') WITHIN GROUP (ORDER BY ba.author_order) AS authors
FROM   lib_book b
JOIN   lib_book_author ba ON ba.book_id = b.book_id
JOIN   lib_author a       ON ba.author_id = a.author_id
GROUP  BY b.book_title;

-- ২১: জরিমানা এক ইস্যুতে সর্বোচ্চ একটা, তাই গুণ হয় না
SELECT st.staff_name, COUNT(*) AS issues, NVL(SUM(f.fine_amount), 0) AS total_fine
FROM   lib_book_issue i
JOIN   lib_staff st    ON i.staff_id = st.staff_id
LEFT   JOIN lib_fine f ON f.issue_id = i.issue_id
GROUP  BY st.staff_name;
```

## ৫. হোমওয়ার্ক

1. কাল ২৫টা JOIN কোয়েরির দিন। ক্লাস ৪১–৪৫-এর সারাংশ পড়ে আসো।
2. ক্লাস ১৫-এর ER Diagram দেখে তিনটা রিপোর্টের পথ খাতায় লেখো: কোন টেবিল থেকে শুরু, কোন কোন টেবিল দিয়ে যাবে।
3. একটা Fan-out নিজে তৈরি করো: `w5_order`-এর সাথে একটা নতুন `w9_order_ship` (শিপমেন্ট) টেবিল বানাও, আর `w9_order_pi` (PI)। একই অর্ডারের ২টা শিপমেন্ট আর ২টা PI দাও। সব JOIN করে `SUM(order_qty)` দেখো কত আসে, কেন ভুল।

<details>
<summary>হোমওয়ার্ক ৩-এর সমাধান</summary>

```sql
CREATE TABLE w9_order_ship (ship_id NUMBER(5) CONSTRAINT w9_order_ship_pk PRIMARY KEY, order_id NUMBER(10), ship_qty NUMBER(10));
CREATE TABLE w9_order_pi   (pi_id NUMBER(5) CONSTRAINT w9_order_pi_pk PRIMARY KEY, order_id NUMBER(10), pi_value NUMBER(12,2));

INSERT INTO w9_order_ship VALUES (1, 1, 2000);
INSERT INTO w9_order_ship VALUES (2, 1, 3000);
INSERT INTO w9_order_pi VALUES (1, 1, 6000);
INSERT INTO w9_order_pi VALUES (2, 1, 5750);
COMMIT;

-- 20000 দেখাবে, আসল পরিমাণ 5000: রো হয়েছে ২ × ২ = ৪
SELECT o.order_no, SUM(o.order_qty) AS wrong_qty
FROM   w5_order o
JOIN   w9_order_ship s ON s.order_id = o.order_id
JOIN   w9_order_pi p   ON p.order_id = o.order_id
WHERE  o.order_id = 1
GROUP  BY o.order_no;
```

## সারাংশ

- প্রতিটা নতুন টেবিলের জন্য একটা `JOIN ... ON`। n টেবিলে n−1টা
- ER Diagram দেখে পথ বের করো, ধাপে ধাপে লেখো, প্রতি ধাপে রো গোনো
- একবার `LEFT` হলে সেই পথের বাকিগুলোও `LEFT`
- দুইটা Many দিক একসাথে হলে হিসাব গুণ হয়
- সংখ্যা দেখে বিশ্বাস নয়, মিলিয়ে দেখো
