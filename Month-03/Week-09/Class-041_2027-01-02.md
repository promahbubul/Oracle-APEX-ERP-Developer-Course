## ১. JOIN কেন দরকার (২০ মিনিট)

সপ্তাহ ৪-এ টেবিল ভেঙেছ, যাতে একটা তথ্য এক জায়গাতেই থাকে। এখন উল্টো সমস্যা: রিপোর্টে সেই তথ্য আবার একসাথে দরকার।

```sql
SELECT employee_id, last_name, department_id FROM employees;    -- বিভাগের নাম নেই
SELECT department_id, department_name FROM departments;         -- কর্মী নেই
```

ম্যানেজার জিজ্ঞেস করবে "King কোন বিভাগে?", `90` না, `Executive`।

**JOIN** দুই বা বেশি টেবিলের রো মিলিয়ে একটা ফলাফল দেয়। সাধারণত মেলানো হয় **FK = PK** দিয়ে।

```
EMPLOYEES                        DEPARTMENTS
LAST_NAME   DEPARTMENT_ID        DEPARTMENT_ID   DEPARTMENT_NAME
King        90  ───────────────► 90              Executive
Hunold      60  ───────────────► 60              IT
Grant       NULL                 (মিল নেই)
```

## ২. INNER JOIN (৪০ মিনিট)

```sql
SELECT কলাম
FROM   টেবিল১
JOIN   টেবিল২ ON টেবিল১.কলাম = টেবিল২.কলাম;
```

`INNER JOIN` আর `JOIN` একই। **শুধু দুই দিকে মিল থাকা রো** আসে।

```sql
-- ১০৬টা রো
SELECT employees.last_name,
       employees.department_id,
       departments.department_name
FROM   employees
JOIN   departments ON employees.department_id = departments.department_id;
```

**১০৭ জনের মধ্যে ১০৬টা রো কেন?** Kimberely Grant-এর `department_id` NULL, তাই মিল নেই, রো বাদ। বিভাগ না থাকা কর্মীকে দেখাতে Left Join লাগবে, কাল শিখব।

বিভাগ আছে ২৭টা, কিন্তু ফলে এসেছে ১১টা। বাকি ১৬টায় কোনো কর্মী নেই।

### গার্মেন্টসের উদাহরণ

সপ্তাহ ৩-এর টেবিল (`learn_freepdb1`):

```sql
SET DEFINE OFF

-- ৩টা রো: HM-TS-001, HM-PL-002 → H&M; ZR-HD-001 → Zara
SELECT style.style_no, style.style_name, buyer.buyer_name
FROM   style
```

নাম এক জায়গায় (`buyer`), অথচ প্রতিটা স্টাইলের পাশে দেখা যাচ্ছে। **Normalization আর JOIN একে অন্যের পরিপূরক।**

## ৩. Table Alias (২০ মিনিট)

টেবিলের নাম বারবার লেখা কঠিন। ছোট নাম দাও:

```sql
SELECT e.last_name,
       e.department_id,
       d.department_name
FROM   employees e
JOIN   departments d ON e.department_id = d.department_id;
```

| নিয়ম | উদাহরণ |
|---|---|
| Oracle-এ টেবিলের Alias-এ `AS` চলে না | `employees AS e` → `ORA-00933` |
| Alias দিলে পুরো নাম আর চলে না | `employees.last_name` → `ORA-00904` |
| অর্থবহ নাম দাও | `e`, `d`, না `a`, `b` |

### ORA-00918: কলাম কোন টেবিলের?

```sql
SELECT last_name, department_id, department_name
FROM   employees e
JOIN   departments d ON e.department_id = d.department_id;
```

```
ORA-00918: column ambiguously defined
```

`department_id` দুই টেবিলেই আছে। লিখতে হবে `e.department_id`।

**নিয়ম: JOIN-এ সব কলামে Alias দাও,** এক টেবিলে থাকলেও। পড়া সহজ হয়, আর পরে অন্য টেবিলে একই নামের কলাম এলে কোড ভাঙে না।

## ৪. USING ও NATURAL JOIN (২০ মিনিট)

### USING

দুই টেবিলে কলামের নাম একই হলে:

```sql
SELECT e.last_name, department_id, d.department_name
FROM   employees e
JOIN   departments d USING (department_id);
```

ফল ১০৬টা রো। কিন্তু `USING`-এর কলামে Alias দেওয়া যায় না:

```sql
SELECT e.department_id FROM employees e JOIN departments d USING (department_id);
```

```
ORA-25154: column part of USING clause cannot have qualifier
```

### NATURAL JOIN: এড়িয়ে চলো

একই নামের **সব** কলাম দিয়ে নিজে থেকে মেলায়।

```sql
SELECT last_name, department_name
FROM   employees NATURAL JOIN departments;
```

ফল **৩২টা রো**, ১০৬ না! দুই টেবিলেই `department_id` আর `manager_id` আছে, তাই দুইটাই মিলিয়েছে। অথচ একটা কর্মীর ম্যানেজার আর বিভাগের ম্যানেজার একই হওয়া আমরা চাইনি। **কোনো এরর আসে না, শুধু ফল ভুল।**

> বাস্তব কোডে `JOIN ... ON` লেখো। ইন্টারভিউয়ের জন্য বাকি দুইটা জেনে রাখো।

## ৫. JOIN-এর সাথে WHERE, GROUP BY (২৫ মিনিট)

চলার ক্রমে `FROM`-এর ভেতরে JOIN হয়, তারপর সব আগের মতো।

```sql
-- Sales বিভাগের কর্মী: ৩৪
SELECT e.last_name, e.salary, d.department_name
FROM   employees e
JOIN   departments d ON e.department_id = d.department_id
WHERE  d.department_name = 'Sales'
ORDER  BY e.salary DESC;
```

```sql
-- ক্লাস ৩৯-এর রিপোর্ট, এবার নামসহ। Shipping 45, Sales 34 আগে
SELECT d.department_name,
       COUNT(*)    AS headcount,
       SUM(e.salary) AS total_salary
FROM   employees e
JOIN   departments d ON e.department_id = d.department_id
GROUP  BY d.department_name
ORDER  BY headcount DESC;
```

### অন্য টেবিল


## সারাংশ

- JOIN আলাদা টেবিলের রো মেলায়, সাধারণত FK = PK দিয়ে
- Inner Join: শুধু মিল থাকা রো, মিল না থাকলে বাদ
- সবসময় `JOIN ... ON`, আর সব কলামে Alias
- `USING` চলে, `NATURAL JOIN` এড়িয়ে চলো
- JOIN-এর পরে `WHERE`, `GROUP BY`, `ORDER BY` আগের মতোই

**পরের ক্লাস:** Left Outer Join, Right Outer Join।
