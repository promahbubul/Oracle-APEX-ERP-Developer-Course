## ১. Set Operator কী (১৫ মিনিট)

**Set Operator** দুই কোয়েরির ফলকে **উপর-নিচে** জোড়ে।

```
JOIN: পাশাপাশি (কলাম বাড়ে)          UNION: উপর-নিচে (রো বাড়ে)

A  +  B                               A
┌───┬───┐                             ┌───┐
│ a │ x │                             │ a │
│ b │ y │                             │ b │
└───┴───┘                             ├───┤
                                      │ x │
                                      │ y │
                                      └───┘
```

| অপারেটর | কাজ | কবে |
|---|---|---|
| `UNION` | দুইটার সব, ডুপ্লিকেট বাদ | আজ |
| `UNION ALL` | দুইটার সব, ডুপ্লিকেটসহ | আজ |
| `INTERSECT` | দুইটাতেই আছে | কাল |
| `MINUS` | প্রথমটায় আছে, দ্বিতীয়টায় নেই | কাল |

## ২. UNION (৩০ মিনিট)

```sql
-- ২৮টা রো: ২৭টা বিভাগ আর কর্মীদের NULL। ডুপ্লিকেট বাদ, সাজানো
SELECT department_id FROM departments
UNION
SELECT department_id FROM employees;
```

- দুই ফলের একই রো একবারই আসে
- NULL-ও এক রকম ধরা হয়, একবার আসে
- Oracle সাধারণত ফল সাজিয়ে দেয়, তবে **ক্রমের ভরসা করবে না,** `ORDER BY` লেখো

### কোথায় লাগে: দুই টেবিল এক তালিকায়

```sql
-- learn_freepdb1: ২৩টা রো। মেম্বার আর স্টাফ এক তালিকায়
SELECT member_name AS person_name, 'Member' AS person_type FROM lib_member
UNION
SELECT staff_name, 'Staff' FROM lib_staff
ORDER  BY person_type, person_name;
```

`'Member'`, `'Staff'` লিটারাল দিয়ে কোন রো কোথা থেকে এলো বোঝা যায়। এটা খুব কাজের কৌশল।

```sql
SET DEFINE OFF

-- Buyer আর Supplier এক তালিকায়: "Party List"
SELECT buyer_name AS party_name, 'Buyer' AS party_type FROM w5_buyer
UNION
SELECT supplier_name, 'Supplier' FROM w5_supplier
ORDER  BY party_type, party_name;
```

### এক টেবিলে OR-এর বদলে

```sql
-- একই ফল
SELECT last_name FROM employees WHERE department_id = 60
UNION
SELECT last_name FROM employees WHERE department_id = 90;

SELECT DISTINCT last_name FROM employees WHERE department_id IN (60, 90);
```

এক টেবিলে `OR` বা `IN` সহজ। আলাদা টেবিলে `UNION` লাগে।

### কর্মীর বর্তমান ও আগের পদ

```sql
-- ১১৫টা রো: ১০৭ + ১০ − ২। Oracle-এর পরিচিত উদাহরণ
SELECT employee_id, job_id FROM employees
UNION
SELECT employee_id, job_id FROM job_history;
```

## ৩. UNION ALL (২৫ মিনিট)

```sql
-- ১৩৪টা রো: ১০৭ + ২৭। ডুপ্লিকেট বাদ যায় না
SELECT department_id FROM employees
UNION ALL
SELECT department_id FROM departments;

-- ১১৭টা রো: ১০৭ + ১০
SELECT employee_id, job_id FROM employees
UNION ALL
SELECT employee_id, job_id FROM job_history;
```

| | `UNION` | `UNION ALL` |
|---|---|---|
| ডুপ্লিকেট | বাদ দেয় | রাখে |
| সাজানো | ডুপ্লিকেট খুঁজতে অতিরিক্ত কাজ করে | করে না |
| গতি | ধীর | **দ্রুত** |

**নিয়ম: ডুপ্লিকেট হওয়ার সুযোগ নেই, অথবা রাখতে চাও? তাহলে সবসময় `UNION ALL`।** `UNION` বড় ডাটায় ধীর।

### সবচেয়ে বিপজ্জনক ভুল: টাকার হিসাবে UNION

```sql
-- ভুল: একই পরিমাণের দুইটা রিসিভ, একটা বাদ
SELECT qty FROM (SELECT 100 AS qty FROM dual)
UNION
SELECT qty FROM (SELECT 100 AS qty FROM dual);        -- ১টা রো!

-- ঠিক
SELECT qty FROM (SELECT 100 AS qty FROM dual)
UNION ALL
SELECT qty FROM (SELECT 100 AS qty FROM dual);        -- ২টা রো
```

**একই পরিমাণের দুইটা লেনদেন হলে `UNION` একটা ফেলে দেয়।** স্টক বা Ledger-এর হিসাবে `UNION` একটা গোপন ভুল। এরর আসে না, শুধু ব্যালেন্স কমে যায়। এই ধরনের কাজে সবসময় `UNION ALL`।

## ৪. নিয়ম (২০ মিনিট)

**১. কলামের সংখ্যা একই**

```sql
SELECT employee_id, last_name FROM employees
UNION
SELECT department_id FROM departments;
```

```
ORA-01789: query block has incorrect number of result columns
```

**২. কলামের Data Type মিলতে হবে, ক্রম অনুযায়ী**

```sql
SELECT employee_id FROM employees
UNION
SELECT department_name FROM departments;
```

```
ORA-01790: expression must have same datatype as corresponding expression
```

**৩. একটা টেবিলে কলাম না থাকলে NULL দাও, প্রয়োজনে রূপান্তর করে**

```sql
SELECT employee_id, last_name, NULL AS location_id FROM employees WHERE department_id = 10
UNION ALL
SELECT department_id, department_name, location_id FROM departments WHERE department_id = 10;
```

**৪. শিরোনাম প্রথম কোয়েরির কলাম থেকে আসে**

```sql
SELECT last_name AS person FROM employees WHERE employee_id = 100
UNION
SELECT department_name FROM departments WHERE department_id = 10;
```

**৫. `ORDER BY` শুধু শেষে, একবার। প্রথম কোয়েরির নাম বা Alias দিয়ে**

```sql
-- ভুল: মাঝে ORDER BY, এরর ORA-00933
SELECT last_name FROM employees WHERE department_id = 60 ORDER BY last_name
UNION
SELECT last_name FROM employees WHERE department_id = 90;

-- ঠিক
SELECT last_name AS person FROM employees WHERE department_id = 60
UNION
SELECT last_name FROM employees WHERE department_id = 90
ORDER  BY person;
```

## ৫. গার্মেন্টসের Item Ledger (২৫ মিনিট)

Store-এর সবচেয়ে জরুরি রিপোর্ট: **একটা আইটেমের সব আসা-যাওয়া এক তালিকায়।** ডাটা দুই টেবিলে: `goods_receive`, `goods_issue` (সপ্তাহ ২)। `UNION ALL` ঠিক এই কাজের জন্য।

```sql
-- learn_freepdb1: আইটেম ১: রিসিভ 1200.5, ইস্যু 400
SELECT receive_date AS txn_date, 'RECEIVE' AS txn_type, qty AS in_qty, 0 AS out_qty
FROM   goods_receive
WHERE  item_id = 1
UNION ALL
SELECT issue_date, 'ISSUE', 0, qty
FROM   goods_issue
WHERE  item_id = 1
ORDER  BY txn_date;
```

### সব আইটেমের স্টক ব্যালেন্স

`UNION ALL`-এর ফলকে Inline View বানিয়ে `GROUP BY`:

```sql
SELECT item_id,
       SUM(in_qty)                AS total_in,
       SUM(out_qty)               AS total_out,
       SUM(in_qty) - SUM(out_qty) AS balance_qty
FROM  (SELECT item_id, qty AS in_qty, 0 AS out_qty FROM goods_receive
       UNION ALL
       SELECT item_id, 0, qty FROM goods_issue) ledger
GROUP  BY item_id
ORDER  BY item_id;
```

সপ্তাহ ২-এর ডাটায়: 

| ITEM_ID | IN | OUT | BALANCE |
|---|---|---|---|
| 1 | 1200.5 | 400 | 800.5 |
| 2 | 450.25 | 150.25 | 300 |
| 3 | 2500 | 800 | 1700 |
| 5 | 20000 | 5000 | 15000 |
| 6 | 8000 | 0 | 8000 |
| 7 | 75 | 20 | 55 |

**Inline View-তে কেন?** JOIN করলে এক আইটেমের ২টা রিসিভ আর ৩টা ইস্যু মিলে ৬টা রো হতো (Fan-out)। `UNION ALL`-এ সমস্যা নেই।

নামসহ আর যে আইটেমের লেনদেন নেই সেটাসহ দেখাতে: `item` টেবিলের সাথে `LEFT JOIN`। প্র্যাকটিসে করবে। **প্রজেক্ট ১-এর Stock Balance রিপোর্ট এই কোয়েরির বড় রূপ।**

## ৭. হোমওয়ার্ক

1. কেন Item Ledger-এ `UNION` ব্যবহার করা বিপজ্জনক? উদাহরণ দিয়ে ৩ লাইনে লেখো।
2. আইটেম ১-এর জন্য Ledger বানাও: তারিখ, ধরন, In, Out, আর শুধু মোট ব্যালেন্স একটা আলাদা কোয়েরিতে। চলমান ব্যালেন্স কেন কঠিন? (সপ্তাহ ১২-এ `SUM() OVER` দিয়ে শিখবে।)
3. `w5_receive` আর `w5_issue` (ক্লাস ২৫) দিয়ে একই ব্যালেন্স রিপোর্ট লেখো, আর `w5_stock`-এর ব্যালেন্সের সাথে মিলিয়ে দেখো।

<details>
<summary>হোমওয়ার্ক ৩-এর সমাধান</summary>

```sql
SELECT s.item_id, s.item_name, s.balance_qty AS stock_balance,
       NVL(l.total_in, 0) AS total_in,
       NVL(l.total_out, 0) AS total_out
FROM   w5_stock s
LEFT   JOIN (SELECT item_id, SUM(in_qty) AS total_in, SUM(out_qty) AS total_out
             FROM  (SELECT item_id, qty AS in_qty, 0 AS out_qty FROM w5_receive
                    UNION ALL
                    SELECT item_id, 0, qty FROM w5_issue) x
             GROUP  BY item_id) l
       ON l.item_id = s.item_id;
```

`balance_qty`-তে শুরুর স্টকও আছে, তাই সরাসরি `total_in - total_out`-এর সমান না-ও হতে পারে।

## সারাংশ

- Set Operator উপর-নিচে জোড়ে। কলাম সংখ্যা আর Data Type মিলতে হয়
- `UNION` ডুপ্লিকেট বাদ, `UNION ALL` রাখে আর দ্রুত
- লেনদেন বা টাকায় `UNION ALL`, নাহলে একই মানের রো হারাবে
- শিরোনাম প্রথম কোয়েরি থেকে, `ORDER BY` শুধু শেষে
- Item Ledger: `UNION ALL` + Inline View + `GROUP BY`
