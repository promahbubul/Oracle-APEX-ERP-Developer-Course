## ১. Correlated Subquery (৪০ মিনিট)

এতদিনের Subquery একবার চলত, তারপর বাইরের কোয়েরি। **Correlated Subquery** বাইরের কোয়েরির **প্রতিটা রো-র জন্য একবার** চলে, কারণ ভেতরে বাইরের কলাম ব্যবহার হয়।

**কাজ:** "**নিজের বিভাগের** গড়ের চেয়ে বেশি বেতন কে পান?"

```sql
SELECT e.last_name, e.department_id, e.salary
FROM   employees e
WHERE  e.salary > (SELECT AVG(i.salary)
                   FROM   employees i
                   WHERE  i.department_id = e.department_id)
ORDER  BY e.department_id;
```

```
Oracle:
রো ১: Hunold, বিভাগ 60 → ভেতর: বিভাগ 60-র গড় = 5760 → 9000 > 5760? হ্যাঁ, রাখো
রো ২: Ernst,  বিভাগ 60 → ভেতর: বিভাগ 60-র গড় = 5760 → 6000 > 5760? হ্যাঁ, রাখো
রো ৩: Austin, বিভাগ 60 → ভেতর: 5760 → 4800 > 5760? না
...
```

বিভাগ ৬০-এ শুধু Hunold আর Ernst। ক্লাস ৪৬-এর সাধারণ Subquery দিয়ে এটা হতো না, কারণ গড়টা প্রতিটা রো-র জন্য আলাদা।

**চেনার উপায়:** ভেতরের কোয়েরিতে বাইরের Alias (`e.`) আছে কি না।

**Alias বাধ্যতামূলক,** কারণ দুই পাশে একই টেবিল।

### প্রতিটা বিভাগের সর্বোচ্চ বেতনের কর্মী

ক্লাস ৪৭-এ জোড়া দিয়ে করেছিলে:

```sql
-- ১১ জন
SELECT e.last_name, e.department_id, e.salary
FROM   employees e
WHERE  e.salary = (SELECT MAX(i.salary)
                   FROM   employees i
                   WHERE  i.department_id = e.department_id);
```

### SELECT-এ: প্রতি রো-তে একটা হিসাব

```sql
-- ২৭টা বিভাগ, কর্মী না থাকলে ০
SELECT d.department_name,
       (SELECT COUNT(*)
        FROM   employees e
        WHERE  e.department_id = d.department_id) AS headcount
FROM   departments d
ORDER  BY headcount DESC;
```

**Fan-out-এর ভালো সমাধান।** একই সাথে দুই হিসাব:

```sql
-- learn_freepdb1: Buyer, স্টাইল সংখ্যা, অর্ডার পরিমাণ, কোনো গুণ হয় না
SELECT b.buyer_name,
       (SELECT COUNT(*) FROM w5_style s WHERE s.buyer_id = b.buyer_id) AS style_count,
       (SELECT NVL(SUM(o.order_qty), 0)
        FROM   w5_order o
        JOIN   w5_style s ON o.style_id = s.style_id
        WHERE  s.buyer_id = b.buyer_id) AS total_qty
FROM   w5_buyer b;
```

### গতি

Correlated Subquery প্রতিটা রো-র জন্য চলে। ১ লাখ রো-তে ১ লাখ বার। Oracle অনেক সময় নিজে অপটিমাইজ করে, তবু বড় টেবিলে JOIN বা Inline View দ্রুত হতে পারে। সপ্তাহ ৪০-এ মিলিয়ে দেখবে।

## ২. EXISTS (৩৫ মিনিট)

**EXISTS** দেখে: ভেতরের কোয়েরি **অন্তত একটা রো** দেয় কি না। মানের দিকে তাকায় না।

```sql
-- যারা ম্যানেজার: ১৮ জন
SELECT m.employee_id, m.last_name
FROM   employees m
WHERE  EXISTS (SELECT 1
               FROM   employees e
               WHERE  e.manager_id = m.employee_id);
```

**`SELECT 1` কেন?** Oracle শুধু দেখে রো আছে কি না, কলাম দেখে না। তাই `1` লেখা প্রচলিত। `SELECT *` লিখলেও একই।

**প্রথম রো পেলেই থেমে যায়,** তাই অনেক সময় দ্রুত।

```sql
-- কর্মী আছে এমন বিভাগ: ১১টা
SELECT d.department_name
FROM   departments d
WHERE  EXISTS (SELECT 1 FROM employees e WHERE e.department_id = d.department_id);
```

JOIN দিলে প্রতি কর্মীর জন্য একটা রো হতো। `EXISTS`-এ প্রতিটা বিভাগ একবারই।

### ERP-তে (`learn_freepdb1`)

```sql
-- কপি আছে এমন বই: ১৫টা
SELECT b.book_title
FROM   lib_book b
WHERE  EXISTS (SELECT 1 FROM lib_book_copy c WHERE c.book_id = b.book_id);

-- জরিমানা পাওয়া মেম্বার: ৫ জন
SELECT m.member_name
FROM   lib_member m
WHERE  EXISTS (SELECT 1
               FROM   lib_book_issue i
               JOIN   lib_fine f ON f.issue_id = i.issue_id
               WHERE  i.member_id = m.member_id);

-- যে মেম্বার এখন বই রেখেছেন: ৫ জন
SELECT m.member_name
FROM   lib_member m
WHERE  EXISTS (SELECT 1
               FROM   lib_book_issue i
               WHERE  i.member_id = m.member_id
               AND    i.return_date IS NULL);
```

### শর্তসহ

```sql
-- ১০০০০-এর বেশি বেতনের কর্মী আছে এমন বিভাগ
SELECT d.department_name
FROM   departments d
WHERE  EXISTS (SELECT 1
               FROM   employees e
               WHERE  e.department_id = d.department_id
               AND    e.salary > 10000);
```

## ৩. NOT EXISTS (২৫ মিনিট)

```sql
-- কর্মী ছাড়া বিভাগ: ১৬টা
SELECT d.department_name
FROM   departments d
WHERE  NOT EXISTS (SELECT 1 FROM employees e WHERE e.department_id = d.department_id);

-- যারা ম্যানেজার নন: ৮৯ জন
SELECT m.last_name
FROM   employees m
WHERE  NOT EXISTS (SELECT 1 FROM employees e WHERE e.manager_id = m.employee_id);
```

**NULL-এর ফাঁদ নেই!** ক্লাস ৪৭-এর ঠিক যে কোয়েরি `NOT IN`-এ ০ রো দিয়েছিল, এখানে ঠিক ফল দিচ্ছে। `NULL` মিললে শুধু "রো নেই" ধরা হয়, পুরো ফল নষ্ট হয় না।

### তিন উপায়, একই প্রশ্ন

```sql
-- ক: NOT IN, NULL সামলাতে হয়
SELECT d.department_name FROM departments d
WHERE  d.department_id NOT IN (SELECT e.department_id FROM employees e WHERE e.department_id IS NOT NULL);

-- খ: NOT EXISTS, নিরাপদ
SELECT d.department_name FROM departments d
WHERE  NOT EXISTS (SELECT 1 FROM employees e WHERE e.department_id = d.department_id);

-- গ: LEFT JOIN + IS NULL (ক্লাস ৪২)
SELECT d.department_name FROM departments d
LEFT   JOIN employees e ON e.department_id = d.department_id
WHERE  e.employee_id IS NULL;
```

**সুপারিশ:** `NOT EXISTS`। পড়তে পরিষ্কার, NULL-এ নিরাপদ, আর সাধারণত দ্রুত।

### ERP-তে

```sql
-- কপি নেই এমন বই: ৫টা
SELECT b.book_title
FROM   lib_book b
WHERE  NOT EXISTS (SELECT 1 FROM lib_book_copy c WHERE c.book_id = b.book_id);

-- কখনো ইস্যু হয়নি এমন কপি: ৪টা
SELECT c.barcode
FROM   lib_book_copy c
WHERE  NOT EXISTS (SELECT 1 FROM lib_book_issue i WHERE i.copy_id = c.copy_id);

-- কখনো ইস্যু হয়নি এমন বই: ৯টা (১২–২০)
SELECT b.book_title
FROM   lib_book b
WHERE  NOT EXISTS (SELECT 1
                   FROM   lib_book_copy c
                   JOIN   lib_book_issue i ON i.copy_id = c.copy_id
                   WHERE  c.book_id = b.book_id);
```

বাস্তবের প্রশ্ন: "কোন আইটেম ৬ মাসে একবারও ইস্যু হয়নি?" (Dead Stock), "কোন Style-এর BOM নেই?", "কোন PO-র কোনো GRN হয়নি?"

## ৪. Correlated UPDATE ও DELETE (২০ মিনিট)

### UPDATE: অন্য টেবিলের হিসাব দিয়ে

ক্লাস ২৫-এর `w5_stock` আর `w5_receive`, `w5_issue`। স্টক ব্যালেন্স ঠিক আছে কি না যাচাই করে আবার হিসাব করা (Reconciliation)।

```sql
-- আগে দেখো
SELECT s.item_id, s.balance_qty,
       (SELECT NVL(SUM(r.qty), 0) FROM w5_receive r WHERE r.item_id = s.item_id) AS received
FROM   w5_stock s;

-- সব আইটেমের নতুন ব্যালেন্স = মোট রিসিভ। NVL না দিলে রিসিভ না থাকলে NULL বসবে
UPDATE w5_stock s
SET    s.balance_qty = NVL((SELECT SUM(r.qty) FROM w5_receive r WHERE r.item_id = s.item_id), 0);

SELECT * FROM w5_stock;

ROLLBACK;
```

### ফাঁদ: Subquery না মিললে NULL

```sql
-- সব রো বদলে যায়, মিল না পেলে NULL! Not Null Constraint থাকলে এরর, না থাকলে ডাটা নষ্ট
UPDATE lib_book b
SET    b.publish_year = (SELECT 2000 FROM lib_book_copy c WHERE c.book_id = b.book_id AND c.copy_id = 1);

SELECT book_id, publish_year FROM lib_book;

ROLLBACK;
```

১টা বই ছাড়া সবার `publish_year` NULL। **সাথে `WHERE EXISTS` দাও,** যাতে মিল থাকা রো-ই শুধু বদলায়:

```sql
UPDATE lib_book b
SET    b.publish_year = 2000
WHERE  EXISTS (SELECT 1 FROM lib_book_copy c WHERE c.book_id = b.book_id AND c.copy_id = 1);

ROLLBACK;
```

### DELETE

```sql
-- ইস্যু হয়নি এমন কপি মোছা: ৪টা
DELETE FROM lib_book_copy c
WHERE  NOT EXISTS (SELECT 1 FROM lib_book_issue i WHERE i.copy_id = c.copy_id);

ROLLBACK;
```

### কোনটা কখন

| প্রশ্ন | ব্যবহার |
|---|---|
| শুধু মান তুলনা, ভেতরে NULL নেই | `IN` |
| "নেই" খোঁজা | `NOT EXISTS` |
| "আছে" খোঁজা, বড় ডাটা | `EXISTS` |
| অন্য টেবিলের কলাম দেখানো | JOIN |
| প্রতিটা রো-র নিজের দলের সাথে তুলনা | Correlated Subquery বা Analytic Function (সপ্তাহ ১২) |

## ৬. হোমওয়ার্ক

1. "PO হয়েছে, কিন্তু GRN হয়নি" রিপোর্ট বানাতে কোন টেবিল লাগবে, আর `NOT EXISTS` কীভাবে লিখবে? ক্লাস ২২-এর `w5_po` আর নিজের বানানো `w5_po_grn` (grn_id, po_id) টেবিল দিয়ে চালাও।
2. `IN`, `EXISTS`, JOIN তিন উপায়ে "কর্মী আছে এমন বিভাগ" লেখো। তিনটার রো সংখ্যা তুলনা করো। কোনটা কেন আলাদা?
3. Correlated Subquery আর সাধারণ Subquery-র পার্থক্য খাতায় লেখো।

<details>
<summary>হোমওয়ার্ক ১ ও ২-এর সমাধান</summary>

```sql
-- ১
CREATE TABLE w5_po_grn (
    grn_id  NUMBER(10) CONSTRAINT w5_po_grn_pk PRIMARY KEY,
    po_id   NUMBER(10) NOT NULL,
    CONSTRAINT w5_po_grn_po_fk FOREIGN KEY (po_id) REFERENCES w5_po (po_id)
);

INSERT INTO w5_po_grn VALUES (1, 1);
COMMIT;

SELECT p.po_no, p.status
FROM   w5_po p
WHERE  NOT EXISTS (SELECT 1 FROM w5_po_grn g WHERE g.po_id = p.po_id);
```

**২:**

```sql
SELECT d.department_name FROM departments d
WHERE  d.department_id IN (SELECT e.department_id FROM employees e);                    -- ১১

SELECT d.department_name FROM departments d
WHERE  EXISTS (SELECT 1 FROM employees e WHERE e.department_id = d.department_id);      -- ১১

SELECT d.department_name FROM departments d
JOIN   employees e ON e.department_id = d.department_id;                                 -- ১০৬
```

JOIN প্রতি কর্মীর জন্য একটা রো দেয়। `DISTINCT` দিলে ১১ হবে।

## সারাংশ

- Correlated: ভেতরে বাইরের Alias, প্রতিটা রো-র জন্য চলে
- "নিজের দলের সাথে তুলনা"-র জন্য এটা লাগে
- `EXISTS`: অন্তত একটা রো আছে কি না, প্রথম রো পেলেই থামে
- `NOT EXISTS`: "নেই" খোঁজার সবচেয়ে নিরাপদ উপায়
- Correlated `UPDATE`-এ মিল না পেলে NULL বসে, তাই `WHERE EXISTS` দাও

**পরের ক্লাস:** Set Operator: UNION, UNION ALL।
