## ১. Running Total (৪০ মিনিট)

**`OVER`-এ `ORDER BY` দিলেই** `SUM` চলমান হয়ে যায়: শুরু থেকে এই রো পর্যন্ত।

ক্লাস ৫৯-এর `w12_monthly_ship`:

```sql
SELECT TO_CHAR(ship_month, 'Mon-YYYY') AS ship_mon,
       ship_qty,
       SUM(ship_qty) OVER (ORDER BY ship_month) AS running_total
FROM   w12_monthly_ship
ORDER  BY ship_month;
```

| SHIP_MON | SHIP_QTY | RUNNING_TOTAL |
|---|---|---|
| Jan-2026 | 10000 | 10000 |
| Feb-2026 | 12000 | 22000 |
| Mar-2026 | 9000 | 31000 |
| Apr-2026 | 15000 | 46000 |
| May-2026 | 11000 | 57000 |
| Jun-2026 | 13000 | 70000 |

তুলনা করো:

```sql
SUM(ship_qty) OVER ()                     -- সবগুলোর মোট: 70000, সব রো-তে একই
SUM(ship_qty) OVER (ORDER BY ship_month)  -- শুরু থেকে এই রো পর্যন্ত
```

### মোটের কত শতাংশ পর্যন্ত এলাম

```sql
SELECT TO_CHAR(ship_month, 'Mon-YYYY') AS ship_mon,
       ship_qty,
       SUM(ship_qty) OVER (ORDER BY ship_month) AS running_total,
       ROUND(SUM(ship_qty) OVER (ORDER BY ship_month)
             / SUM(ship_qty) OVER () * 100, 2) AS running_pct
FROM   w12_monthly_ship
ORDER  BY ship_month;
```

মার্চ পর্যন্ত ৪৪.২৯%। Target vs Achievement-এর চার্টে এটাই।

### PARTITION BY: বছরভিত্তিক বা লাইনভিত্তিক

```sql
-- প্রতি লাইনে আলাদা চলমান মোট। লাইন ১: 1000, 2150, 3290, 4490
SELECT line_id, entry_date, produced_qty,
       SUM(produced_qty) OVER (PARTITION BY line_id ORDER BY entry_date) AS running_total
FROM   w12_line_output
ORDER  BY line_id, entry_date;
```

### ERP-র আসল কাজ: Item Ledger

ক্লাস ৪৯-এ বলেছিলাম, চলমান ব্যালেন্স কঠিন। এখন সহজ: `UNION ALL` + `SUM() OVER`।

```sql
-- আইটেম ১: 1200.5, তারপর 800.5
SELECT txn_date, txn_type, in_qty, out_qty,
       SUM(in_qty - out_qty) OVER (ORDER BY txn_date
                                   ROWS UNBOUNDED PRECEDING) AS balance_qty
FROM  (SELECT receive_date AS txn_date, 'RECEIVE' AS txn_type, qty AS in_qty, 0 AS out_qty
       FROM   goods_receive
       WHERE  item_id = 1
       UNION ALL
       SELECT issue_date, 'ISSUE', 0, qty
       FROM   goods_issue
       WHERE  item_id = 1) ledger
ORDER  BY txn_date;
```

| TXN_TYPE | IN | OUT | BALANCE |
|---|---|---|---|
| RECEIVE | 1200.5 | 0 | 1200.5 |
| ISSUE | 0 | 400 | 800.5 |

**প্রজেক্ট ১-এর Item Ledger হুবহু এটা।** ব্যাংক স্টেটমেন্টের ব্যালেন্সও এভাবেই।

`ROWS UNBOUNDED PRECEDING` কেন লিখলাম? পরের অংশে।

## ২. Window Frame (৪০ মিনিট)

`OVER`-এর তৃতীয় অংশ: হিসাবে **কোন কোন রো** নেবে।

```sql
SUM(x) OVER (ORDER BY d ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)
                        └──────────── Frame ─────────────────┘
```

| লেখা | মানে |
|---|---|
| `UNBOUNDED PRECEDING` | দলের শুরু |
| `n PRECEDING` | n রো আগে |
| `CURRENT ROW` | এই রো |
| `n FOLLOWING` | n রো পরে |
| `UNBOUNDED FOLLOWING` | দলের শেষ |

### Moving Average: ৩ মাসের গড়

```sql
SELECT TO_CHAR(ship_month, 'Mon-YYYY') AS ship_mon,
       ship_qty,
       ROUND(AVG(ship_qty) OVER (ORDER BY ship_month
                                 ROWS BETWEEN 2 PRECEDING AND CURRENT ROW), 2) AS moving_avg_3m
FROM   w12_monthly_ship
ORDER  BY ship_month;
```

| SHIP_MON | SHIP_QTY | MOVING_AVG_3M |
|---|---|---|
| Jan-2026 | 10000 | 10000 |
| Feb-2026 | 12000 | 11000 |
| Mar-2026 | 9000 | 10333.33 |
| Apr-2026 | 15000 | 12000 |
| May-2026 | 11000 | 11666.67 |
| Jun-2026 | 13000 | 13000 |

মাসে মাসে ওঠানামা না দেখে প্রবণতা বোঝার জন্য।

### ডিফল্ট Frame: ফাঁদ

**`ORDER BY` দিলে, Frame না লিখলে ডিফল্ট হয়:**

```
RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
```

`RANGE` মানে **মান ধরে:** একই `ORDER BY` মানের সব রো একসাথে আসে।

```sql
-- বিভাগ ৬০, বেতনের ক্রমে
SELECT last_name, salary,
       SUM(salary) OVER (ORDER BY salary DESC) AS with_range,
       SUM(salary) OVER (ORDER BY salary DESC ROWS UNBOUNDED PRECEDING) AS with_rows
FROM   employees
WHERE  department_id = 60
ORDER  BY salary DESC;
```

| LAST_NAME | SALARY | WITH_RANGE | WITH_ROWS |
|---|---|---|---|
| Hunold | 9000 | 9000 | 9000 |
| Ernst | 6000 | 15000 | 15000 |
| Austin | 4800 | **24600** | 19800 |
| Pataballa | 4800 | **24600** | 24600 |
| Lorentz | 4200 | 28800 | 28800 |

Austin আর Pataballa-র মান সমান, তাই `RANGE`-এ দুইজনই একসাথে যোগ হয়েছে। **Item Ledger-এ একই দিনে দুইটা লেনদেন হলে ডিফল্টে দুই রো-তে একই ব্যালেন্স দেখাবে!** ভুল না হলেও ব্যবহারকারী বিভ্রান্ত হবে।

| | `ROWS` | `RANGE` (ডিফল্ট) |
|---|---|---|
| ধরে | রো সংখ্যা | মান |
| সমান মান | একটা একটা করে | একসাথে |
| গতি | সাধারণত দ্রুত | সাধারণত ধীর |

**নিয়ম:** চলমান মোটে `ROWS UNBOUNDED PRECEDING` লেখো, আর `ORDER BY`-তে এমন কলাম দাও যা ইউনিক (যেমন `txn_date, txn_id`)।

## ৩. FIRST_VALUE ও LAST_VALUE (৩০ মিনিট)

দলের প্রথম আর শেষ রো-র মান।

```sql
-- প্রতি বিভাগের সর্বোচ্চ বেতন যিনি পান, সবার পাশে
SELECT last_name, department_id, salary,
       FIRST_VALUE(last_name) OVER (PARTITION BY department_id ORDER BY salary DESC) AS top_earner,
       FIRST_VALUE(salary)    OVER (PARTITION BY department_id ORDER BY salary DESC) AS top_salary
FROM   employees
WHERE  department_id = 60;
```

সবার পাশে `Hunold`, `9000`। ফল থেকে `top_salary - salary` দিলে সর্বোচ্চের সাথে পার্থক্য: ০, ৩০০০, ৪২০০, ৪২০০, ৪৮০০।

`MAX(salary) OVER`-ও সর্বোচ্চ মান দেয়। কিন্তু `MAX(last_name)` সর্বোচ্চ **বেতনের** জনের নাম দেয় না, শুধু বর্ণক্রমের শেষ নাম। সেখানেই `FIRST_VALUE` লাগে।

### LAST_VALUE-এর বিখ্যাত ফাঁদ

```sql
-- ভুল: শেষ মান পেতে চাই
SELECT last_name, salary,
       LAST_VALUE(salary) OVER (ORDER BY salary DESC) AS wrong_last
FROM   employees
WHERE  department_id = 60;
```

ফল: ৯০০০, ৬০০০, ৪৮০০, ৪৮০০, ৪২০০। অর্থাৎ **নিজের মানই!** কারণ ডিফল্ট Frame শেষ হয় **এই রো-তে** (`CURRENT ROW`), দলের শেষে না।

```sql
-- ঠিক: সবার পাশে 4200
SELECT last_name, salary,
       LAST_VALUE(salary) OVER (ORDER BY salary DESC
                                ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING) AS real_last
FROM   employees
WHERE  department_id = 60;
```

**সহজ উপায়:** `LAST_VALUE`-এর বদলে উল্টো ক্রমে `FIRST_VALUE` লেখো। `FIRST_VALUE(salary) OVER (ORDER BY salary ASC)`। Frame ভাবতে হয় না।

### প্রথম আর শেষ তারিখ

```sql
-- প্রতি লাইনের প্রথম দিনের আউটপুট, আর এখন পর্যন্ত কত বেড়েছে
SELECT line_id, entry_date, produced_qty,
       FIRST_VALUE(produced_qty) OVER (PARTITION BY line_id ORDER BY entry_date) AS first_day_qty,
       produced_qty - FIRST_VALUE(produced_qty) OVER (PARTITION BY line_id ORDER BY entry_date) AS since_first
FROM   w12_line_output
ORDER  BY line_id, entry_date;
```

লাইন ১: প্রথম দিন ১০০০। শেষ দিনে +২০০।

### Analytic-এর পুরো ছবি

| ধরন | ফাংশন |
|---|---|
| Aggregate | `SUM`, `AVG`, `COUNT`, `MIN`, `MAX` + `OVER` |
| র‍্যাঙ্ক | `ROW_NUMBER`, `RANK`, `DENSE_RANK`, `NTILE` |
| অবস্থান | `LAG`, `LEAD`, `FIRST_VALUE`, `LAST_VALUE`, `NTH_VALUE` |

## ৫. হোমওয়ার্ক

1. কাল টপ ৩ আর রানিং টোটালের দিন। ক্লাস ৫৬–৬০-এর সারাংশ পড়ে আসো।
2. ব্যাংক স্টেটমেন্টের মতো `w12_bank_txn` টেবিল বানাও (txn_id, txn_date, debit, credit)। ৬টা রো দাও, একই দিনে ২টা। চলমান ব্যালেন্স `ROWS` আর `RANGE` দুই দিয়েই চালাও। পার্থক্য দেখো।
3. `LAST_VALUE`-এর ফাঁদ নিজের ভাষায় লেখো। কেন Frame বদলাতে হয়?

<details>
<summary>হোমওয়ার্ক ২-এর সমাধান</summary>

```sql
CREATE TABLE w12_bank_txn (
    txn_id    NUMBER(5) CONSTRAINT w12_bank_txn_pk PRIMARY KEY,
    txn_date  DATE,
    debit     NUMBER(10,2) DEFAULT 0,
    credit    NUMBER(10,2) DEFAULT 0
);

INSERT INTO w12_bank_txn VALUES (1, DATE '2027-01-01', 0, 10000);
INSERT INTO w12_bank_txn VALUES (2, DATE '2027-01-02', 2000, 0);
INSERT INTO w12_bank_txn VALUES (3, DATE '2027-01-02', 500, 0);
INSERT INTO w12_bank_txn VALUES (4, DATE '2027-01-03', 0, 3000);
INSERT INTO w12_bank_txn VALUES (5, DATE '2027-01-04', 1000, 0);
INSERT INTO w12_bank_txn VALUES (6, DATE '2027-01-05', 0, 800);
COMMIT;

SELECT txn_id, txn_date, debit, credit,
       SUM(credit - debit) OVER (ORDER BY txn_date) AS with_range,
       SUM(credit - debit) OVER (ORDER BY txn_date, txn_id ROWS UNBOUNDED PRECEDING) AS with_rows
FROM   w12_bank_txn
ORDER  BY txn_id;
```

`RANGE`-এ ২ জানুয়ারির দুই রো-তে একই ব্যালেন্স ৭৫০০। `ROWS`-এ ৮০০০, তারপর ৭৫০০।

## ৬. কুইজ

1. `SUM(x) OVER ()` আর `SUM(x) OVER (ORDER BY d)`-এর পার্থক্য কী?
2. `ORDER BY` দিলে Frame না লিখলে ডিফল্ট কী?
3. `ROWS` আর `RANGE`-এর পার্থক্য কী?
4. `LAST_VALUE` ডিফল্টে কেন নিজের মান দেয়?
5. ৩ মাসের Moving Average-এর Frame লেখো।

<details>
<summary>উত্তর দেখো</summary>

1. প্রথমটা সবগুলোর মোট, দ্বিতীয়টা শুরু থেকে এই রো পর্যন্ত চলমান মোট
2. `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`
3. `ROWS` রো ধরে, `RANGE` মান ধরে, তাই সমান মান একসাথে আসে
4. ডিফল্ট Frame `CURRENT ROW`-তে শেষ হয়, দলের শেষে না
5. `ROWS BETWEEN 2 PRECEDING AND CURRENT ROW`

</details>

## সারাংশ

- `SUM(x) OVER (ORDER BY d)`: চলমান মোট। `PARTITION BY` দিলে প্রতি দলে
- Item Ledger: `UNION ALL` + `SUM(in - out) OVER`
- Frame ঠিক করে কোন রো: `ROWS BETWEEN ... AND ...`
- ডিফল্ট `RANGE`-এ সমান মান একসাথে আসে, তাই চলমান মোটে `ROWS` আর ইউনিক `ORDER BY`
- `FIRST_VALUE` সোজা, `LAST_VALUE`-এ Frame লাগে
