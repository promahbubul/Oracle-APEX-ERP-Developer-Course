- `LAG`: আগের রো-র মান

## ১. LAG (৪০ মিনিট)

ক্লাস ৪৪-এর হোমওয়ার্কে Self Join দিয়ে "আগের দিনের প্রোডাকশন" দেখেছিলে। **LAG** এই কাজ অনেক সহজে করে।

`LAG(কলাম, কত রো আগে, না পেলে কী)`

### আজকের টেবিল

```sql
CREATE TABLE w12_line_output (
    line_id       NUMBER(5),
    entry_date    DATE,
    produced_qty  NUMBER(8),
    CONSTRAINT w12_line_output_pk PRIMARY KEY (line_id, entry_date)
);

INSERT INTO w12_line_output VALUES (1, DATE '2027-01-03', 1000);
INSERT INTO w12_line_output VALUES (1, DATE '2027-01-04', 1150);
INSERT INTO w12_line_output VALUES (1, DATE '2027-01-05', 1140);
INSERT INTO w12_line_output VALUES (1, DATE '2027-01-06', 1200);
INSERT INTO w12_line_output VALUES (2, DATE '2027-01-03', 1200);
INSERT INTO w12_line_output VALUES (2, DATE '2027-01-04', 1100);
INSERT INTO w12_line_output VALUES (2, DATE '2027-01-05', 1300);
INSERT INTO w12_line_output VALUES (2, DATE '2027-01-06', 1250);
COMMIT;
```

### এক লাইনের জন্য

```sql
SELECT entry_date,
       produced_qty,
       LAG(produced_qty) OVER (ORDER BY entry_date) AS previous_qty
FROM   w12_line_output
WHERE  line_id = 1
ORDER  BY entry_date;
```

| ENTRY_DATE | PRODUCED_QTY | PREVIOUS_QTY |
|---|---|---|
| 2027-01-03 | 1000 | NULL |
| 2027-01-04 | 1150 | 1000 |
| 2027-01-05 | 1140 | 1150 |
| 2027-01-06 | 1200 | 1140 |

প্রথম রো-র আগে কিছু নেই, তাই NULL। **`ORDER BY` বাধ্যতামূলক,** নাহলে "আগের" কথাটার মানে থাকে না।

### পার্থক্য

```sql
SELECT entry_date,
       produced_qty,
       LAG(produced_qty) OVER (ORDER BY entry_date) AS previous_qty,
       produced_qty - LAG(produced_qty) OVER (ORDER BY entry_date) AS change_qty
FROM   w12_line_output
WHERE  line_id = 1
ORDER  BY entry_date;
```

`change_qty`: NULL, +150, −10, +60।

### কত রো আগে, আর ডিফল্ট

```sql
SELECT entry_date,
       produced_qty,
       LAG(produced_qty, 1)    OVER (ORDER BY entry_date) AS one_before,
       LAG(produced_qty, 2)    OVER (ORDER BY entry_date) AS two_before,
       LAG(produced_qty, 1, 0) OVER (ORDER BY entry_date) AS one_before_or_0
FROM   w12_line_output
WHERE  line_id = 1;
```

তৃতীয় মান হলো ডিফল্ট: আগের রো না থাকলে কী দেবে। প্রথম রো-তে `0`।

### প্রতি লাইনের জন্য: PARTITION BY

```sql
SELECT line_id,
       entry_date,
       produced_qty,
       LAG(produced_qty) OVER (PARTITION BY line_id ORDER BY entry_date) AS previous_qty,
       produced_qty - LAG(produced_qty) OVER (PARTITION BY line_id ORDER BY entry_date) AS change_qty
FROM   w12_line_output
ORDER  BY line_id, entry_date;
```

লাইন ২-এর প্রথম রো-তে NULL, কারণ প্রতি লাইনে নতুন করে। `PARTITION BY` না দিলে লাইন ১-এর শেষ রো-র মান লাইন ২-এর আগের হিসেবে আসত, যা ভুল।

**লাইন ২:** NULL, −১০০, +২০০, −৫০।

## ২. LEAD (২৫ মিনিট)

**LEAD** হলো LAG-এর উল্টো: পরের রো।

```sql
SELECT entry_date,
       produced_qty,
       LEAD(produced_qty) OVER (ORDER BY entry_date) AS next_qty
FROM   w12_line_output
WHERE  line_id = 1
ORDER  BY entry_date;
```

`next_qty`: ১১৫০, ১১৪০, ১২০০, NULL।

### কোথায় কাজে লাগে: সময়কাল

"পরের ঘটনা কবে?" থেকে দুই ঘটনার মধ্যের সময় বের করা যায়।

```sql
-- একই কপি, এক ইস্যু থেকে পরের ইস্যু: কত দিন (learn_freepdb1)
SELECT copy_id,
       issue_id,
       issue_date,
       LEAD(issue_date) OVER (PARTITION BY copy_id ORDER BY issue_date) AS next_issue,
       LEAD(issue_date) OVER (PARTITION BY copy_id ORDER BY issue_date) - issue_date AS days_to_next
FROM   lib_book_issue
ORDER  BY copy_id, issue_date;
```

### দামের সময়সীমা

একটা আইটেমের দাম কবে থেকে কবে পর্যন্ত, এই ডিজাইনে `effective_date` থেকে পরের `effective_date`-এর আগের দিন পর্যন্ত:

```sql
CREATE TABLE w12_item_price (
    item_id         NUMBER(5),
    effective_date  DATE,
    unit_price      NUMBER(8,2),
    CONSTRAINT w12_item_price_pk PRIMARY KEY (item_id, effective_date)
);

INSERT INTO w12_item_price VALUES (1, DATE '2026-01-01', 4.00);
INSERT INTO w12_item_price VALUES (1, DATE '2026-06-01', 4.20);
INSERT INTO w12_item_price VALUES (1, DATE '2026-11-15', 4.50);
INSERT INTO w12_item_price VALUES (2, DATE '2026-03-01', 3.10);
COMMIT;

SELECT item_id,
       effective_date AS valid_from,
       LEAD(effective_date) OVER (PARTITION BY item_id ORDER BY effective_date) - 1 AS valid_to,
       unit_price
FROM   w12_item_price
ORDER  BY item_id, valid_from;
```

| ITEM_ID | VALID_FROM | VALID_TO | UNIT_PRICE |
|---|---|---|---|
| 1 | 2026-01-01 | 2026-05-31 | 4.00 |
| 1 | 2026-06-01 | 2026-11-14 | 4.20 |
| 1 | 2026-11-15 | NULL | 4.50 |
| 2 | 2026-03-01 | NULL | 3.10 |

NULL মানে এখনো চলছে। বাস্তব ERP-তে এই ছাঁচ খুব আসে: ইউনিট প্রাইস, বেতন, Exchange Rate।

## ৩. বৃদ্ধি ও তুলনা (৩০ মিনিট)

### আগের মাসের সাথে

```sql
CREATE TABLE w12_monthly_ship (
    ship_month  DATE CONSTRAINT w12_monthly_ship_pk PRIMARY KEY,
    ship_qty    NUMBER(10) NOT NULL
);

INSERT INTO w12_monthly_ship VALUES (DATE '2026-01-01', 10000);
INSERT INTO w12_monthly_ship VALUES (DATE '2026-02-01', 12000);
INSERT INTO w12_monthly_ship VALUES (DATE '2026-03-01', 9000);
INSERT INTO w12_monthly_ship VALUES (DATE '2026-04-01', 15000);
INSERT INTO w12_monthly_ship VALUES (DATE '2026-05-01', 11000);
INSERT INTO w12_monthly_ship VALUES (DATE '2026-06-01', 13000);
COMMIT;

SELECT TO_CHAR(ship_month, 'Mon-YYYY') AS ship_mon,
       ship_qty,
       LAG(ship_qty) OVER (ORDER BY ship_month) AS prev_qty,
       ship_qty - LAG(ship_qty) OVER (ORDER BY ship_month) AS change_qty,
       ROUND((ship_qty - LAG(ship_qty) OVER (ORDER BY ship_month))
             / LAG(ship_qty) OVER (ORDER BY ship_month) * 100, 2) AS growth_pct
FROM   w12_monthly_ship
ORDER  BY ship_month;
```

| SHIP_MON | SHIP_QTY | PREV_QTY | CHANGE_QTY | GROWTH_PCT |
|---|---|---|---|---|
| Jan-2026 | 10000 | NULL | NULL | NULL |
| Feb-2026 | 12000 | 10000 | 2000 | 20 |
| Mar-2026 | 9000 | 12000 | -3000 | -25 |
| Apr-2026 | 15000 | 9000 | 6000 | 66.67 |
| May-2026 | 11000 | 15000 | -4000 | -26.67 |
| Jun-2026 | 13000 | 11000 | 2000 | 18.18 |

ড্যাশবোর্ডের "গত মাসের চেয়ে ১৮.১৮% বেশি" ঠিক এটাই। `LAG` শূন্য হতে পারলে ভাগে `NULLIF` দাও (ক্লাস ৩৬)।

### GROUP BY-এর উপর LAG

লেনদেন থেকে মাসভিত্তিক করে `LAG`:

```sql
-- লাইব্রেরির মাসভিত্তিক ইস্যু: ২০২৬-০৯ 11, ২০২৬-১০ 4, ২০২৬-১১ 5, তারপর তুমি যখন চালিয়েছ
SELECT TO_CHAR(issue_date, 'YYYY-MM') AS issue_month,
       COUNT(*) AS issues,
       LAG(COUNT(*)) OVER (ORDER BY TO_CHAR(issue_date, 'YYYY-MM')) AS prev_issues
FROM   lib_book_issue
GROUP  BY TO_CHAR(issue_date, 'YYYY-MM')
ORDER  BY issue_month;
```

`GROUP BY`-এর পরে Analytic চলে, তাই `LAG(COUNT(*))` ঠিক আছে।

### শর্ত দিয়ে: "কমে গেছে"

```sql
-- যে দিন আগের দিনের চেয়ে কমেছে: লাইন ১ ৫ জানু; লাইন ২ ৪ জানু, ৬ জানু
SELECT line_id, entry_date, produced_qty, previous_qty
FROM  (SELECT line_id, entry_date, produced_qty,
              LAG(produced_qty) OVER (PARTITION BY line_id ORDER BY entry_date) AS previous_qty
       FROM   w12_line_output) x
WHERE  produced_qty < previous_qty
ORDER  BY line_id, entry_date;
```

Analytic তাই `WHERE`-এ না, Inline View।

## ৪. অন্য কাজ (২০ মিনিট)

### ফেরত আর পরের ইস্যুর মাঝে কত দিন

```sql
-- কপি পড়ে ছিল কত দিন: ৫টা রো। কপি ১ → 8, ২ → 11, ৩ → 19, ৪ → 22, ৫ → 15
SELECT copy_id, issue_id, issue_date, prev_return,
       issue_date - prev_return AS idle_days
FROM  (SELECT copy_id, issue_id, issue_date,
              LAG(return_date) OVER (PARTITION BY copy_id ORDER BY issue_date) AS prev_return
       FROM   lib_book_issue) x
WHERE  prev_return IS NOT NULL
ORDER  BY copy_id;
```

### ফাঁকা নম্বর খোঁজা

Sequence-এ ফাঁকা আছে কি? (ক্লাস ৫৩)

```sql
SELECT prev_id + 1 AS gap_from, id_value - 1 AS gap_to
FROM  (SELECT buyer_id AS id_value,
              LAG(buyer_id) OVER (ORDER BY buyer_id) AS prev_id
       FROM   w11_buyer) x
WHERE  id_value - prev_id > 1;
```

ইনভয়েস নম্বরের ধারাবাহিকতা অডিটে ঠিক এভাবে দেখা হয়।

### HR-এ

```sql
-- বেতনের ক্রমে আগের জনের সাথে পার্থক্য
SELECT last_name, salary,
       LAG(salary) OVER (ORDER BY salary DESC) - salary AS gap_to_above
FROM   employees
WHERE  department_id = 60;
```

ফল: NULL, ৩০০০, ১২০০, ০, ৬০০।

### Self Join বনাম LAG

| | Self Join | `LAG` |
|---|---|---|
| "আগের রো" মানে | তারিখ + ১ দিয়ে মেলানো | আসলেই আগের রো |
| মাঝে ফাঁকা দিন | মেলে না, রো হারায় | ঠিক কাজ করে |
| লেখা | লম্বা | ছোট |
| গতি | সাধারণত ধীর | সাধারণত দ্রুত |

**ফাঁকা দিন:** শুক্রবার বাদে কাজ হলে `date - 1`-এর Self Join শনিবারের "আগের দিন" পায় না, `LAG` বৃহস্পতিবার পায়।

GROUP  BY TO_CHAR(issue_date, 'YYYY-MM')
ORDER  BY issue_month;

## সারাংশ

- `LAG` আগের রো, `LEAD` পরের রো। `ORDER BY` বাধ্যতামূলক
- `LAG(কলাম, কত আগে, ডিফল্ট)`
- একাধিক দলে `PARTITION BY` দিতেই হবে
- আগের মাসের সাথে তুলনা, শতকরা বৃদ্ধি: ড্যাশবোর্ডের নিয়মিত কাজ
- `LEAD` দিয়ে দামের `valid_to` বের হয়
- ফাঁকা দিনে Self Join ভুল করে, `LAG` করে না

**পরের ক্লাস:** Running Total: SUM() OVER, FIRST_VALUE, LAST_VALUE।
